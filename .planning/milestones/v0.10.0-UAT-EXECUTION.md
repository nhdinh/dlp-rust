## Prerequisites

### Hardware

- [ ] Physical Windows 11 host (build 22000+; Pro or Enterprise recommended)
- [ ] USB 3.0 flash drive (for Category E scenarios)
- [ ] SD card + reader (for Category E scenarios)
- [ ] Optical drive (internal or USB) OR ability to mount ISO (for Category E scenarios)
- [ ] Network printer OR Microsoft Print to PDF (for Category D scenarios)
- [ ] SSD strongly recommended for consistent disk I/O during CRIT-04 benchmark

### Software

- [ ] PowerShell 5.1+ (verify with `$PSVersionTable.PSVersion`)
- [ ] Windows SDK installed (provides `signtool.exe` for J01)
- [ ] Rust toolchain installed (for CRIT-04 cargo build benchmark)
- [ ] DLP v0.10.0 installed and Authenticode-signed
- [ ] OneDrive client installed and signed in (for C01)
- [ ] Google Drive for Desktop installed and signed in (for C02)
- [ ] Dropbox client installed and signed in (for C03)
- [ ] Box Drive installed and signed in (for C04)
- [ ] Microsoft Word installed (for I02 benchmark)
- [ ] Process Hacker or Process Explorer (for A01-A04, G01 screenshots)

### Account / Privilege

- [ ] Local Administrator account (script requires `-RunAsAdministrator`)
- [ ] Domain account with DLP Admin privileges (for admin TUI scenarios)
- [ ] Access to EDR console (for J02 if applicable)

### Documents

- [ ] `RELEASE_NOTES.md` from the v0.10.0 release (for J05 hash verification)
- [ ] `.planning/milestones/v0.10.0-UAT.md` (this document's source of scenario truth)
- [ ] This guide printed or open on a second screen

## Pre-Flight Checklist

Execute these steps in order before running the UAT script.

### 1. Stop Non-Essential Processes

Close all applications except:
- PowerShell (elevated)
- This guide (browser or PDF viewer)
- Windows Explorer (needed for some scenarios)

Specifically close:
- Visual Studio / VS Code
- Heavy file-sync tools (besides the cloud clients being tested)
- Games, streaming software, video conferencing
- Windows Update (check Settings > Windows Update > Pause updates)

### 2. Verify Agent Service Status

```powershell
Get-Service dlp-agent
```

Expected: `Status = Running` or `Stopped` (the script will toggle it).
If the service is missing, reinstall DLP v0.10.0 before proceeding.

### 3. Verify EDR Allowlist

If an EDR is installed (Defender, CrowdStrike, SentinelOne, etc.):
1. Open the EDR console.
2. Verify exclusions exist for:
   - `C:\Program Files\DLP\`
   - `dlp_agent.exe`
   - `dlp_hook_dll.dll`
   - `dlp_admin_cli.exe`
   - `dlp_user_ui.exe`
   - `dlp_server.exe`
3. Document the EDR version for the Environment table.

### 4. Verify Policy Bundle

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:9090/health" -TimeoutSec 5
```

Expected: JSON response with `status: healthy`.
If the server is not running, start it:
```powershell
Start-Service dlp-server
```

### 5. Create Test Directories

```powershell
New-Item -ItemType Directory -Path "C:\Protected\Test" -Force
New-Item -ItemType Directory -Path "C:\Temp\UAT" -Force
```

### 6. Create T1/T2/T4 Test Files

```powershell
# T1 (Public)
"T1 test content" | Set-Content -Path "C:\Temp\UAT\t1_test.txt"

# T2 (Internal)
"T2 test content" | Set-Content -Path "C:\Temp\UAT\t2_test.txt"

# T4 (Restricted)
"T4 test content" | Set-Content -Path "C:\Protected\Test\t4_test.txt"
```

**Classification:** Ensure the DLP policy engine classifies these paths correctly. If the auto-classifier is not configured, manually assign tiers via the admin TUI before proceeding.

### 7. Verify Peripherals

| Peripheral | Check |
|------------|-------|
| USB 3.0 flash drive | Insert and confirm it appears in File Explorer |
| SD card + reader | Insert and confirm it appears in File Explorer |
| Optical drive / blank disc | Insert disc or confirm ISO mount capability |
| Printer | Print a test page from Word |
| Network share | Confirm `\\server\share` is reachable |

If a peripheral is absent, mark related scenarios N/A during execution.

### 8. Verify Cloud Clients

| Client | Check |
|--------|-------|
| OneDrive | File Explorer shows OneDrive folder; sync is active |
| Google Drive | File Explorer shows Google Drive folder; sync is active |
| Dropbox | Dropbox tray icon shows "Up to date" |
| Box Drive | Box Drive virtual drive letter is visible |

If a cloud client is not installed or not signed in, mark related scenarios N/A.

### 9. Reboot Host

Perform a clean reboot to ensure:
- Hook DLL is freshly injected
- ETW buffers are clear
- No stale handles or locks

After reboot, wait 60 seconds for agent initialization before starting UAT.

## Script Execution Guide

### Running the Script

1. Open **PowerShell as Administrator**.
2. Navigate to the script directory:
   ```powershell
   cd "C:\Path\To\dlp-rust\scripts"
   ```
3. Execute:
   ```powershell
   .\Uat-Execute-v0.10.0.ps1
   ```

### What to Expect

The script will:
1. **Validate prerequisites** (admin, Windows 11, dlp-agent, signtool)
2. **Create artifact directories** at `C:\UAT\v0.10.0\`
3. **Capture environment data** to `environment.json`
4. **Iterate through categories A-J**, one scenario at a time

For each scenario, the script:
- Prints the scenario ID and description
- Shows prerequisites and expected result
- **Pauses and prompts:**
  ```
  Enter result [P]ass / [F]ail / [N]-A (or type notes after space)
  ```
- Captures the last 100 lines of the agent log to the category folder
- Appends the result to `results.json`

### How to Respond at Prompts

| Input | Meaning | When to Use |
|-------|---------|-------------|
| `P` or `p` | **Pass** | Scenario behaved exactly as expected |
| `F` or `f` | **Fail** | Scenario did not behave as expected; include notes |
| `N` or `n` | **N/A** | Peripheral or prerequisite missing; include justification |
| `P works fine` | Pass with notes | Pass, but include observation |
| `F access denied not shown` | Fail with notes | Specific failure detail for investigation |
| `N no optical drive` | N/A with justification | Hardware absent; does not count against pass rate |

### N/A Protocol

If a peripheral is absent:
1. Mark the scenario **N/A**.
2. Provide a brief justification (e.g., "no optical drive", "Dropbox not installed").
3. The scenario does **not** count toward the pass/fail ratio.
4. If a category has **>50% N/A scenarios**, escalate to the engineering lead for a partial-ship decision.
5. Document the absent peripheral in the Known Limitations section of the summary.

### Between Categories

The script will print a separator between categories. **Recommended:** Reboot the host between major categories to prevent cross-test contamination. The script does not force reboots; the operator decides based on time constraints.

If not rebooting:
- At minimum, restart the agent service:
  ```powershell
  Restart-Service dlp-agent; Start-Sleep -Seconds 30
  ```
- Archive agent logs between categories for clean artifact isolation.

## Manual Screenshot Guide

The script automates log capture and result recording, but **cannot** capture UI interactions. The following scenarios require manual screenshots. Save them to the appropriate `C:\UAT\v0.10.0\{Category}\` folder with the naming convention:

```
UAT-57-{CATEGORY}{NN}_screenshot_{YYYYMMDD_HHMMSS}.png
```

### Category A: Hook Injection

#### A01 — Process Hacker showing injected DLL
1. Launch Notepad.
2. Open **Process Hacker** (run as Administrator).
3. Find `notepad.exe` in the process list.
4. Double-click to open process properties.
5. Go to the **Modules** tab.
6. Scroll to find `dlp_hook_dll.dll`.
7. **Screenshot:** The Modules tab showing `dlp_hook_dll.dll` with path and load address.

#### A02 — Process Hacker showing allowlisted process modules
1. In Process Hacker, find `MsMpEng.exe` (Defender) or your EDR process.
2. Open process properties > Modules tab.
3. Verify **no** `dlp_hook_dll.dll` is present.
4. **Screenshot:** Modules tab showing absence of DLP DLL.

#### A03 — Process Hacker showing x86 DLL in 32-bit process
1. Launch `C:\Windows\SysWOW64\notepad.exe`.
2. In Process Hacker, find the 32-bit Notepad process.
3. Open Modules tab.
4. Verify `dlp_hook_dll_x86.dll` is loaded (not the x64 DLL).
5. **Screenshot:** Modules tab showing `dlp_hook_dll_x86.dll`.

### Category E: USB/SD/Optical/Virtual

#### E01-E04 — Windows Explorer / Device Manager screenshots
1. After inserting the peripheral (USB, SD, optical disc, or mounting VHDX), open **File Explorer**.
2. Verify the new drive letter appears.
3. **Screenshot:** File Explorer showing the new drive.
4. Open **Device Manager** (devmgmt.msc).
5. Find the device under the appropriate category (Disk drives, DVD/CD-ROM drives, etc.).
6. **Screenshot:** Device Manager showing the device properties.

### Category F: DACL Tripwire

#### F01 — icacls output
1. Open elevated Command Prompt or PowerShell.
2. Run:
   ```cmd
   icacls "C:\Protected\Test"
   ```
3. **Screenshot:** Console showing the ACL list with Deny ACE visible.

### Category G: ETW Bypass

#### G01 — Process Hacker unload screenshot, Notepad save dialog
1. Launch Notepad, confirm hook is injected (A01).
2. In Process Hacker, right-click `dlp_hook_dll.dll` in Notepad's Modules tab.
3. Select **Unload** (or **Eject DLL** depending on version).
4. **Screenshot:** Process Hacker showing the unload confirmation.
5. In Notepad, attempt File > Save As to `C:\Protected\Test\bypass_test.txt`.
6. **Screenshot:** The save dialog or error message that appears.

### Category H: Monitor Mode

#### H01-H03 — Admin TUI screenshots (policy mode dropdown)
1. Open admin TUI: `dlp-admin-cli.exe`.
2. Navigate to **Policies** screen.
3. Select the test policy.
4. **Screenshot:** The policy detail view showing the **Enforcement Mode** dropdown (Audit / Block / AuditAndBlock).
5. For H03 (global override), navigate to **System Config** or the banner showing **Global Override: Audit**.
6. **Screenshot:** The global override banner or setting.

### Category J: Operational Verification

#### J01 — signtool verify output
1. Open elevated PowerShell.
2. Run:
   ```powershell
   signtool verify /pa "C:\Program Files\DLP\dlp-agent.exe"
   ```
3. **Screenshot:** Console showing `Successfully verified` output.
4. Repeat for each binary: `dlp-server.exe`, `dlp-admin-cli.exe`, `dlp-user-ui.exe`, `dlp_hook_dll.dll`, `dlp_hook_dll_x86.dll`.

#### J02 — EDR console screenshot
1. Open your EDR console (Defender Security Center, CrowdStrike Falcon, etc.).
2. Navigate to **Detections** or **Quarantine** history.
3. Filter by process name containing `dlp`.
4. **Screenshot:** Empty detection list or explicit "No detections found" message.

#### J04 — Confirm-SecureBootUEFI output
1. Open elevated PowerShell.
2. Run:
   ```powershell
   Confirm-SecureBootUEFI
   ```
3. **Screenshot:** Console showing `True` or `False` output.

## CRIT-04 Benchmark Protocol

The CRIT-04 benchmark measures wall-clock overhead introduced by the DLP hook DLL on representative workloads. The target is **<= 25% overhead**.

### Prerequisites for Benchmark

- [ ] Close **all** other applications (especially browsers, IDEs, file sync tools)
- [ ] Pause Windows Updates
- [ ] Ensure host is on AC power (not battery)
- [ ] SSD strongly recommended for consistent disk I/O
- [ ] No other users logged in

### Protocol

#### 1. Warm-Up Run (Discarded)

Before any measured runs, perform one unmeasured warm-up to populate caches:

```powershell
# Stop agent for baseline warm-up
Stop-Service dlp-agent
cargo clean
cargo build --workspace --release
# Discard timing — this is just warm-up
```

#### 2. Baseline Measurements (Agent STOPPED)

```powershell
Stop-Service dlp-agent
Start-Sleep -Seconds 5

# Run 3 times, record TotalMilliseconds from Measure-Command
$baseline = @()
for ($i = 1; $i -le 3; $i++) {
    $m = Measure-Command { cargo build --workspace --release }
    $baseline += [math]::Round($m.TotalSeconds, 2)
    Write-Host "Baseline run $i`: $($baseline[-1])s"
}
```

#### 3. With-Hooks Measurements (Agent STARTED)

```powershell
Start-Service dlp-agent
Start-Sleep -Seconds 30  # Critical: allow hooks to settle

$hooked = @()
for ($i = 1; $i -le 3; $i++) {
    $m = Measure-Command { cargo build --workspace --release }
    $hooked += [math]::Round($m.TotalSeconds, 2)
    Write-Host "Hooked run $i`: $($hooked[-1])s"
}
```

#### 4. Compute Median and Overhead

```powershell
function Get-Median($Values) {
    $sorted = $Values | Sort-Object
    $count = $sorted.Count
    if ($count % 2 -eq 1) {
        return $sorted[[math]::Floor($count / 2)]
    }
    return ($sorted[$count/2 - 1] + $sorted[$count/2]) / 2.0
}

$baselineMedian = Get-Median $baseline
$hookedMedian   = Get-Median $hooked
$overhead = [math]::Round((($hookedMedian - $baselineMedian) / $baselineMedian) * 100, 2)

Write-Host "Baseline median: ${baselineMedian}s"
Write-Host "Hooked median:   ${hookedMedian}s"
Write-Host "Overhead:        ${overhead}%"
Write-Host "Target:          <= 25%"
Write-Host "Status:          $(if ($overhead -le 25) { 'PASS' } else { 'FAIL' })"
```

#### 5. Word Launch Benchmark (I02)

Use the same 3+3 protocol but with Word COM automation:

```powershell
$wordPath = Join-Path $env:ProgramFiles 'Microsoft Office\root\Office16\WINWORD.EXE'
if (-not (Test-Path $wordPath)) {
    $wordPath = Join-Path ${env:ProgramFiles(x86)} 'Microsoft Office\root\Office16\WINWORD.EXE'
}

# Baseline
Stop-Service dlp-agent
$baselineWord = @()
for ($i = 1; $i -le 3; $i++) {
    $m = Measure-Command {
        $word = New-Object -ComObject Word.Application
        $word.Visible = $false
        $doc = $word.Documents.Open("C:\Protected\Test\t4_template.docx")
        $doc.Save()
        $doc.Close()
        $word.Quit()
    }
    $baselineWord += [math]::Round($m.TotalSeconds, 2)
}

# With hooks
Start-Service dlp-agent
Start-Sleep -Seconds 30
$hookedWord = @()
for ($i = 1; $i -le 3; $i++) {
    $m = Measure-Command {
        $word = New-Object -ComObject Word.Application
        $word.Visible = $false
        $doc = $word.Documents.Open("C:\Protected\Test\t4_template.docx")
        $doc.Save()
        $doc.Close()
        $word.Quit()
    }
    $hookedWord += [math]::Round($m.TotalSeconds, 2)
}

# Compute median and overhead as above
```

## Troubleshooting

### Issue 1: Agent Service Not Starting

**Symptoms:** `Start-Service dlp-agent` fails; service status shows `Stopped` immediately.

**Resolution:**
1. Check Windows Event Viewer > Application log for `dlp-agent` errors.
2. Verify `C:\ProgramData\DLP\agent-config.toml` exists and is valid TOML.
3. Check if the agent binary is quarantined by EDR (see J02).
4. Try manual start to see console output:
   ```powershell
   & "C:\Program Files\DLP\dlp-agent.exe" --console
   ```
5. If `SeSystemProfilePrivilege` is missing, grant it via Group Policy or `ntrights.exe`.

### Issue 2: Hook Not Injecting into New Processes

**Symptoms:** A01 fails; Notepad modules do not show `dlp_hook_dll.dll`.

**Resolution:**
1. Verify agent is running: `Get-Service dlp-agent`.
2. Check agent log for injection errors (`Injected PID` entries should appear).
3. Verify the hook DLL exists:
   ```powershell
   Test-Path "C:\Program Files\DLP\dlp_hook_dll.dll"
   Test-Path "C:\Program Files\DLP\dlp_hook_dll_x86.dll"
   ```
4. If Secure Boot is enabled, verify AppInit_DLLs is inert and ETW+CreateRemoteThread fallback is active (see J04).
5. Check if the target process is allowlisted (A02 logic).
6. Restart the agent service and wait 30 seconds before retrying.

### Issue 3: EDR Quarantine

**Symptoms:** Agent service stops unexpectedly; EDR console shows detection for `dlp-agent.exe` or `dlp_hook_dll.dll`.

**Resolution:**
1. **Do not proceed with UAT** if the EDR has quarantined DLP binaries.
2. Restore quarantined files from the EDR console.
3. Re-apply allowlist exclusions per `docs/operations/deployment-guide.md` Section 3.
4. Verify exclusions cover:
   - File/folder path: `C:\Program Files\DLP\`
   - Process names: all 6 binaries
   - Certificate hash (if hash-based exclusion is supported)
5. Restart agent service after EDR exclusion is applied.
6. Re-run J02 to confirm zero detections before continuing UAT.

### Issue 4: Missing Peripheral (USB, SD, Optical, Printer)

**Symptoms:** Category E or D scenarios cannot be executed.

**Resolution:**
1. Mark the scenario **N/A** with justification (e.g., "no SD card reader on this laptop").
2. The scenario does not count against the pass rate.
3. If >50% of a category is N/A, escalate to engineering lead for partial-ship decision.
4. For printers: Microsoft Print to PDF is an acceptable substitute for D01 (print blocking) but not for physical watermark verification.
5. For optical drives: ISO mount via Explorer right-click is an acceptable substitute.

### Issue 5: Benchmark Variance / CRIT-04 Overhead >25%

**Symptoms:** CRIT-04 shows overhead >25% or high variance between runs.

**Resolution:**
1. Ensure no other processes are running (browser tabs, file sync, Windows Update).
2. Run the benchmark on AC power with high-performance power plan.
3. Increase the number of runs from 3 to 5 or 7 for better median stability:
   ```powershell
   # Edit the script or run manually with more iterations
   ```
4. Check if the cargo target directory is on an SSD (HDD will show higher variance).
5. If overhead is consistently >25%:
   - Capture agent log during benchmark runs.
   - Note the specific workload (cargo vs. Word) that fails.
   - Document as **blocking ship defect** and notify engineering lead.
   - Do not override the 25% gate without written approval.

### Issue 6: Cloud Sync Client Not Blocking T4 Files

**Symptoms:** C01-C04 fail; T4 file appears in cloud portal.

**Resolution:**
1. Verify the cloud client is actually running and signed in (not just installed).
2. Verify the test file is in the correct sync folder path:
   - OneDrive: `C:\Users\<user>\OneDrive\Test\`
   - Google Drive: `C:\Users\<user>\Google Drive\Test\` (or G: drive)
   - Dropbox: `C:\Users\<user>\Dropbox\Test\`
   - Box: `C:\Users\<user>\Box\Test\` (or Box drive letter)
3. Check agent log for `CloudSyncBlocked` events — if absent, the hook may not be intercepting the cloud client's I/O.
4. Some cloud clients use background services with different PIDs; verify the service process is also hooked.
5. Force sync manually via the cloud client's tray icon menu.

### Issue 7: Admin TUI Navigation Issues

**Symptoms:** Cannot reach the Protected Paths or Bypass Alerts screen; keyboard shortcuts not working.

**Resolution:**
1. Verify terminal supports ANSI escape sequences (Windows Terminal recommended, not legacy conhost).
2. Ensure the terminal window is large enough (minimum 80x24).
3. Use arrow keys and Enter to navigate; Esc to go back.
4. If the TUI crashes, check `dlp-admin-cli` log in `C:\ProgramData\DLP\logs\`.
5. Verify the server is reachable: `Invoke-RestMethod http://127.0.0.1:9090/health`.
