# Plan 39-01: Extend AppIdentity and AppField for UWP

## Objective

Extend the core `AppIdentity` struct with UWP-specific fields and add `Aumid` and `PackageFamilyName` variants to the `AppField` enum so the ABAC system can reason about UWP application identity.

## Background

`AppIdentity` in `dlp-common/src/endpoint.rs` currently captures only Win32-desktop identity: `image_path`, `publisher`, `trust_tier`, `signature_state`. UWP apps distributed via the Microsoft Store have an Application User Model ID (AUMID) like `Microsoft.Windows.Photos_8wekyb3d8bbwe!App` and a Package Family Name. These must be first-class identity fields.

`AppField` in `dlp-common/src/abac.rs` defines which application attributes policies can match against. It currently has `Publisher`, `ImagePath`, `TrustTier`. We need `Aumid` and `PackageFamilyName` for UWP-aware policies.
