# Plan 39-03: ABAC Evaluator and TUI Conditions Builder Update

## Objective

Update the ABAC evaluator to handle `Aumid` and `PackageFamilyName` app fields, and add these fields to the admin TUI conditions builder.

## Background

The ABAC evaluator in `dlp-server/src/policy_store.rs` has `app_identity_matches()` which handles `SourceApplication` and `DestinationApplication` conditions. It matches against `AppField` variants. We need to add branches for `Aumid` and `PackageFamilyName`.

The TUI conditions builder in `dlp-admin-cli` has an `AppField` picker that lets admins choose which application attribute to match. We need to add the two new variants.

<action>
In `dlp-server/src/policy_store.rs`, extend `app_identity_matches()` to handle `AppField::Aumid` and `AppField::PackageFamilyName`:

For `AppField::Aumid`:
```rust
AppField::Aumid => identity.aumid.as_deref().unwrap_or(""),
```

For `AppField::PackageFamilyName`:
```rust
AppField::PackageFamilyName => identity.package_family_name.as_deref().unwrap_or(""),
```

Add these branches in the same `match field` block alongside existing `Publisher`, `ImagePath`, `TrustTier` branches.

Ensure operators work correctly:
- `eq` / `ne` — exact string match against AUMID or PFN
- `contains` — substring match (useful for matching package family prefixes)

Verify that `None` values (non-UWP apps evaluated against AUMID condition) fail closed — `unwrap_or("")` returns empty string which won't match any non-empty condition value.
</action>
