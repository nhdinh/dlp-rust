# Plan 40-04: Integration — ABAC Evaluation, UI Alert, and Audit

## Objective

Wire the DragDropEnforcer into the agent's event loop, add UI notifications for blocked drops, and ensure audit events capture drag-and-drop operations with full app identity.

## Tasks

<task>
<read_first>
- dlp-agent/src/interception/mod.rs (event loop, how clipboard/USB checks are wired)
- dlp-agent/src/service.rs (service lifecycle, hook install/uninstall)
- dlp-agent/src/audit_emitter.rs (emit function signature)
- dlp-user-ui/src/main.rs (how ClipboardAlert is handled)
- dlp-common/src/audit.rs (AuditEvent structure)
</read_first>

<action>
1. In `dlp-agent/src/interception/mod.rs`:
   - Add `drag_drop: Option<drag_drop::DragDropEnforcer>` to `InterceptionEngine`
   - In `new()`, initialize the drag_drop field
   - In `start()`, call `drag_drop.install()`
   - In `stop()`, call `drag_drop.uninstall()`

2. In `dlp-agent/src/service.rs`:
   - Ensure the service lifecycle installs/uninstalls the drag-drop hook
   - Add drag-drop to the shutdown cleanup sequence

3. In `dlp-agent/src/audit_emitter.rs`:
   - Add `emit_drag_drop_event()` function that creates an `AuditEvent` with:
     - `action: Action::DRAG_DROP`
     - `source_application: Option<AppIdentity>`
     - `destination_application: Option<AppIdentity>`
     - `decision: Decision`
     - `resource_path` from dropped file(s)
   - Call this from the drag-drop hook when a drop is blocked

4. In `dlp-user-ui/src/main.rs`:
   - Add handling for `Pipe3AgentMsg::DragDropAlert` alongside `ClipboardAlert`
   - Show a toast notification: "Drag-and-drop blocked: {classification} data from {source_app}"

5. In `dlp-common/src/audit.rs`:
   - Verify `AuditEvent` already has `source_application` and `destination_application` fields
   - No schema changes needed

6. Add integration tests:
   - `test_drag_drop_audit_event_has_app_identity` — verify AuditEvent serialization includes both app identities
   - `test_drag_drop_alert_round_trip` — Pipe3AgentMsg::DragDropAlert serde round-trip
</action>

<acceptance_criteria>
- InterceptionEngine installs drag-drop hook on start and uninstalls on stop
- Blocked drops emit AuditEvent with source_application, destination_application, action=DRAG_DROP
- Blocked drops send DragDropAlert to UI via Pipe 3
- UI shows toast notification for blocked drag-and-drop
- `cargo check --all` passes
- `cargo clippy --all -- -D warnings` passes
- `cargo test -p dlp-agent --lib` passes
</acceptance_criteria>
</task>
