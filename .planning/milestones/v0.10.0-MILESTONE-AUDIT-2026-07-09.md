## Summary

Since the 2026-07-06 audit, **Phase 58.7 closed the DACL-01..DACL-05 wiring gap**. The bypass correlator, DACL watcher/repair watcher, classification cache T3/T4 roots, staged removal table, and runtime reinit path now all consume the server-pushed `AgentConfig.protected_paths` field with canonical normalization and migration.

The milestone **still cannot be shipped as-is** due to four remaining blockers:

1. **OPS-04** — Physical Windows 11 UAT has not been executed.
2. **DIFF-01** — Hook DLL deny paths still do not emit `IpcPayloadV1::RequestOverride`; the agent-side handler exists but is never triggered from the DLL.
3. **DIFF-04** — `GET /admin/health` is missing in `dlp-server/src/admin_api.rs` and `diagnostic_store` is `None` in production `AppState`.
4. **Phase 58.5 UAT Test 7** — Live Windows DLL unload verification remains pending after the 58.5-08 fixes.

In addition, Phase 58.6 (targeted hook injection) has not started.

## Closed Items

### DACL-01..DACL-05 (Phase 58.7)

Phase 58.7 verification (`58.7-VERIFICATION.md`) passed with 22/22 must-haves verified. All protected-path consumers in `dlp-agent/src/service.rs` now read from `AgentConfig.protected_paths`:

- `BypassCorrelator::with_protected_paths` seeded from `protected_paths` (`service.rs:2309`).
- `ClassificationCache::prepopulate_t3_t4_roots` seeded from `protected_paths` (`service.rs:1832-1836`).
- `init_dacl_watcher` and `init_dacl_watcher_without_staging` iterate normalized `protected_paths` (`service.rs:3125-3135`).
- Staging table uses canonical keys via `normalize_protected_path`; `migrate_staging_keys` runs on startup (`dacl_staging.rs:249-257`).
- Runtime reinit on `protected_paths` or `global_enforcement_mode` change via `DaclWatcherManager` (`service.rs:1108-1122`, `service.rs:2944-2980`).

Security audit `SECURITY.md` created and committed (`406f3232`).
