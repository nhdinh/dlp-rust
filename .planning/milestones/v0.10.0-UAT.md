## Test Isolation Strategy

To prevent cross-test contamination and ensure reproducible results, apply the following isolation strategy:

1. **Reboot between major categories:** After completing all scenarios in one category (e.g., Category A: Hook Injection), reboot the host before starting the next category. This clears injected state, cached handles, and ETW buffers.

2. **Clean baseline checkpoints:** Use Windows System Restore or a VM snapshot (if testing in a VM for non-peripheral categories) to establish a clean baseline. Restore to this baseline between categories when possible.

3. **Agent state reset:** Between scenarios within the same category, restart the `dlp-agent` service (`Restart-Service dlp-agent`) and wait 30 seconds for full initialization before proceeding.

4. **Log rotation:** Archive agent logs (`C:\ProgramData\DLP\logs\dlp-agent.log`) between categories to ensure per-category artifact isolation.

5. **Policy reset:** After Category H (Monitor Mode), restore the policy bundle to its production configuration before proceeding to Category I (Performance) to avoid audit-mode interference with benchmark results.
