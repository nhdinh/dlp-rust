## Summary

The v0.10.0 milestone **cannot be shipped as-is**. A critical regression was discovered during this audit: **two `HookIpcServer` instances compete for the same named pipe**, and the second server uses a stub handler that bypasses ABAC evaluation.

### Critical Finding: Double HookIpcServer / ABAC Bypass

`dlp-agent/src/service.rs` constructs the hook IPC server twice:

1. **Line 1441** — `spawn_hook_ipc_server(...)` creates a server that calls `offline.offline_decision()` for real ABAC evaluation. Its handle is stored in the local `blocking_threads.hook_ipc` field but is **not** propagated to `RunLoopContext`.
2. **Line 1837** — A second `HookIpcServer::new(...)` is created with a stub handler that only checks `ApprovalCache` and then returns `ALLOW` unconditionally with reason `"stub"`. This handle is stored in `RunLoopContext.hook_ipc_handle`.

Both servers listen on the same pipe (`\\.\\pipe\\DlpHookIpcV1`). Depending on startup timing, hook DLL requests may be serviced by the stub server, causing **all file operations to be allowed regardless of policy**.

### Other Blockers

- **DRIVE-03/DRIVE-04**: `spawn_hook_ipc_server` hard-codes `source_volume_class` and `destination_volume_class` as `None`, so volume-class policies are not enforced even when the real ABAC server wins the pipe race.
- **DIFF-02/DIFF-03/DIFF-04**: The `DiagnosticAggregator`, `HealthAggregator`, and `hash_compute.rs` modules exist but are **not invoked from deny paths** in `dlp-hook-dll/src/trampolines.rs`.
- **OPS-04**: UAT has not been executed on physical Windows 11 hardware; results placeholders remain in `v0.10.0-UAT.md`.
