# Phase 58.6: Targeted Hook Injection — Only File-Operation Processes - Research

**Researched:** 2026-07-03
**Domain:** Windows user-mode process classification, PE import-table analysis, ETW Kernel-File lazy injection, DLP/EDR selective-hooking architecture
**Confidence:** MEDIUM

## Summary

Phase 58.6 replaces the Phase 49 universal-injection policy (inject every non-allowlisted user process within 500 ms of `ProcessStart`) with a targeted policy: inject only processes that are likely to perform file operations on T3/T4 paths. The goal is to reduce agent footprint, lower compatibility risk, and preserve enforcement coverage.

Research shows that no single static signal is reliable enough. A practical system needs three complementary signals:

1. **Static PE import-table classification** before injection. DLLs such as `kernel32.dll` + `shell32.dll` strongly imply file/directory operations; direct `ntdll.dll` imports may indicate low-level file syscalls that bypass higher-level API hooks [CITED: learn.microsoft.com/win32/etw/fileio].
2. **Known-application basename/command-line heuristics**. Office suites, browsers, cloud-sync clients, IDEs, file managers, compression tools, and email clients are the dominant consumers of user files [ASSUMED].
3. **Runtime ETW Kernel-File fallback**. When an unhooked PID touches a T3/T4 path, emit a lazy injection attempt [CITED: github.com/repnz/etw-providers-docs].

The existing `UniversalInjector`, `ProcessRegistry`, `AllowlistMatcher`, `HookInjector`, and `EtwKernelFileConsumer` can be reused. The main new component is a `ProcessClassifier` that runs before `HookInjector::inject` and decides whether a process is *file-operation likely*. A second new path, `LazyInjector`, listens to the existing ETW Kernel-File channel and injects processes that have already performed a file operation but are not yet hooked.

**Primary recommendation:** Build a hybrid classifier: PE import-table score + known-category basename/command-line match triggers immediate injection; everything else is left unhooked until an ETW Kernel-File event for a T3/T4 path arrives. Keep universal injection available behind a config flag for customers who prioritize coverage over footprint.

## Project Constraints (from CLAUDE.md)

The following directives from the project `CLAUDE.md` constrain this phase:

- **No kernel driver / no minifilter**: the architecture must stay entirely in user-mode. The ETW Kernel-File consumer is the closest the agent gets to the kernel.
- **NTFS = coarse-grained enforcement, ABAC = fine-grained dynamic control**: targeted injection is an optimization of the *enforcement delivery* mechanism, not a replacement for NTFS DACL tripwires or ABAC evaluation.
- **Default deny for sensitive data**: if classification is uncertain, the conservative default is to inject (fail-closed on coverage) rather than skip, unless the operator explicitly enables a monitor-only mode.

### Pattern 1: PE Import-Table Classification with `goblin`

**What:** Read the target executable from disk and score its import table for file-operation likelihood.

**When to use:** Primary signal at process-start time, before deciding to inject.

**Example:**

```rust
// Source: goblin docs.rs + project conventions
use goblin::pe::PE;
use std::collections::HashSet;

const FILE_IO_DLLS: &[&str] = &[
    "kernel32.dll", "kernelbase.dll", "shell32.dll", "shlwapi.dll",
    "ntdll.dll", "advapi32.dll", "ole32.dll", "comdlg32.dll",
];

fn file_io_score(image_bytes: &[u8]) -> anyhow::Result<u32> {
    let pe = PE::parse(image_bytes)?;
    let mut score = 0u32;
    if let Some(imports) = pe.imports {
        for import in imports {
            let dll = import.dll.to_lowercase();
            if FILE_IO_DLLS.iter().any(|d| dll == *d) {
                score += 1;
                // Bonus for ntdll direct file syscalls (NtCreateFile, NtOpenFile, NtWriteFile)
                if dll == "ntdll.dll" {
                    for sym in import.symbols.iter().flatten() {
                        let name = sym.to_lowercase();
                        if name.starts_with("ntcreatefile") || name.starts_with("ntopenfile") || name.starts_with("ntwritefile") {
                            score += 2;
                        }
                    }
                }
            }
        }
    }
    Ok(score)
}
```

### Pattern 2: Remote Command-Line Retrieval via PEB

**What:** Use `NtQueryInformationProcess(ProcessBasicInformation)` to get the remote PEB address, then `ReadProcessMemory` to read `RTL_USER_PROCESS_PARAMETERS.CommandLine`.

**When to use:** Secondary signal to detect file paths, extensions, or known file-handling flags in the command line.

**Example:**

```rust
// Source: Microsoft Learn winternl.h + project windows-rs patterns
use windows::Win32::Foundation::HANDLE;
use windows::Win32::System::Threading::{NtQueryInformationProcess, PROCESS_BASIC_INFORMATION, PROCESS_QUERY_LIMITED_INFORMATION};
use windows::Win32::System::Diagnostics::Debug::ReadProcessMemory;

fn remote_command_line(handle: HANDLE) -> anyhow::Result<String> {
    let mut pbi = PROCESS_BASIC_INFORMATION::default();

            handle,
            0, // ProcessBasicInformation
```

### Pattern 3: Lazy ETW Kernel-File Injection Path

**What:** Reuse the existing `EtwKernelFileConsumer` receiver. For each event whose path resolves to T3/T4 and whose PID is not already `Injected`/`Skipped`, attempt injection.

**When to use:** Backstop for processes that were not classified as file-operation likely at start but then touch sensitive data.

**Example:**

```rust
// Source: existing etw_kernel_file.rs + dlp-common classification helpers
while let Ok(event) = file_event_rx.recv() {
    let key = ProcessKey { pid: event.pid, creation_time: resolve_creation_time(event.pid) };
    if registry.should_skip(key) {
        continue;
    }
    if classification_cache.is_t3t4(&event.file_name) {
        if let Err(e) = lazy_injector.inject(key, event.pid).await {
            tracing::warn!(pid = event.pid, error = %e, "lazy injection failed");
        }
    }
}
```

### Pattern 4: Hybrid Decision Gate

**What:** Combine static and dynamic signals with an explicit precedence:

1. Allowlist/PPL/WoW64/system-critical checks first (existing).
2. PE import score >= threshold, or basename in known file-handling category, or command line contains T3/T4 path -> inject immediately.
3. Otherwise, record `Skipped(LowConfidence)` and rely on lazy ETW fallback.
4. If `targeted_injection.fallback_universal = true`, periodic sweep still injects remaining processes (Phase 49 behavior).

### Anti-Patterns to Avoid

- **Relying solely on lazy injection:** leaves a race window where the first T3/T4 file operations complete unobserved.
- **Parsing the PE of a running process instead of the on-disk file:** the in-memory image may be packed, patched, or relocated.
- **Ignoring PPL/protected processes:** lazy injection attempts on PPL will fail with `AccessDenied`; classify failures as expected skips, not errors.
- **Injecting based only on basename:** trivially bypassed by renaming `malware.exe` to `notepad.exe`.
- **Removing the universal-injection code path:** breaks backward compatibility and complicates rollback.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| On-disk PE import parsing | Custom unsafe parser copied from `dlp-hook-dll/pe_utils.rs` | `goblin` or `pelite` | They handle PE32/PE32+, bound checks, forwarded imports, and section alignment correctly |
| Remote process command line | `CreateRemoteThread` + `GetCommandLineW` | `NtQueryInformationProcess` + `ReadProcessMemory` on PEB | Cross-session issues make remote `GetCommandLineW` unreliable; PEB read is the documented user-mode technique |
| ETW Kernel-File session setup | Raw `StartTrace`/`EnableTraceEx2` FFI | `ferrisetw` | `ferrisetw` already provides safe Rust abstractions and schema parsing used elsewhere in the project |
| Process lifecycle tracking | `std::sync::Mutex<HashMap<u32, State>>` | Existing `DashMap<ProcessKey, ProcessEntry>` | Already lock-free, PID-reuse-safe, and integrated with telemetry |
| T3/T4 path classification | Inline string matching in classifier | Existing `classification_cache.rs` / ABAC evaluation pipeline | Centralizes tier logic and respects policy updates |

**Key insight:** The classifier runs in the agent, not inside the target process. It is therefore allowed to be more complex and use third-party crates than the hook DLL, where every line of code increases host-process crash risk.

## Common Pitfalls

### Pitfall 1: Lazy Injection Race Window

**What goes wrong:** A process opens, writes, and closes a T4 file before the agent can inject the hook DLL.

**Why it happens:** ETW event delivery, tokio scheduling, DLL path resolution, `CreateRemoteThread`, and `DllMain` patching all take time. On a busy endpoint this can exceed 100 ms.

**How to avoid:** Never rely on lazy injection alone. Use it only as a backstop for processes that the static classifier skipped. Inject immediately for processes that are clearly file-handling.

**Warning signs:** Telemetry shows `unhooked_t3t4_event_count` > 1% of total T3/T4 events.

### Pitfall 2: PE Import Table Is Necessary but Not Sufficient

**What goes wrong:** A process imports `kernel32.dll` but never touches user files (e.g., a background service), or a file-handling process dynamically resolves APIs via `GetProcAddress` and has a sparse import table.

**Why it happens:** The import table only lists statically linked imports. Many modern apps load file APIs at runtime, and some packers strip imports.

**How to avoid:** Combine import scoring with basename/command-line heuristics and the ETW fallback. Tune thresholds with telemetry rather than treating the score as deterministic.

**Warning signs:** High false-positive injection rate into non-file processes, or missed file operations from dynamically loaded apps.

### Pitfall 3: PEB Command-Line Read Fails on Protected Processes

**What goes wrong:** `NtQueryInformationProcess` or `ReadProcessMemory` on the PEB returns `AccessDenied` for protected/PPL processes.

**Why it happens:** Protected processes restrict cross-process VM reads even with `PROCESS_QUERY_LIMITED_INFORMATION`.

**How to avoid:** Treat PEB read failure as "unknown command line" and fall back to PE import/basename classification. Never escalate privileges to read protected processes.

**Warning signs:** Error logs showing repeated PEB read failures for the same PIDs.

### Pitfall 4: ETW Kernel-File Event Loss / PID Reuse

**What goes wrong:** The agent sees a file event for PID 1234, but by the time it injects, PID 1234 has exited and a new, unrelated process holds it.

**Why it happens:** ETW events are delivered asynchronously, and Windows reuses PIDs quickly.

**How to avoid:** Always use `(PID, creation_time)` composite keys (already in `ProcessRegistry`). Verify `creation_time` via `OpenProcess` + `GetProcessTimes` before injecting.

**Warning signs:** Injection attempts into PIDs whose `creation_time` does not match the registry entry.

### Pitfall 5: Breaking Existing Universal-Injection Assumptions

**What goes wrong:** Tests, UAT scripts, or the Phase 57 deployment guide assume every user process is injected. Switching to targeted injection silently breaks those assumptions.

**Why it happens:** Universal injection was the documented v0.10.0 baseline.

**How to avoid:** Keep `universal_injection_enabled = true` as the default initially. Make targeted injection opt-in per config, and update UAT/allowlist documentation before changing the default.

**Warning signs:** UAT coverage telemetry drops below 99% after enabling targeted mode.

## Open Questions

1. **Should targeted injection be opt-in or default?**
   - What we know: The v0.10.0 baseline is universal injection; changing the default risks UAT failure.
   - What's unclear: Operator appetite for reduced footprint vs. maximum coverage.
   - Recommendation: Add `[targeted_injection] mode = "universal"` default. Ship targeted as opt-in for one milestone, then evaluate telemetry before making it default.

2. **How should the classifier handle child processes?**
   - What we know: Many file handlers spawn helpers (e.g., OfficeClickToRun, browser renderer processes).
   - What's unclear: Whether child processes inherit file-operation likelihood from the parent.
   - Recommendation: Inherit classification for child PIDs for 30 seconds after parent injection, unless overridden by allowlist/PPL.

3. **What is the maximum acceptable lazy-injection latency?**
   - What we know: DLL load + IAT patch takes tens of milliseconds; ETW delivery adds buffering latency.
   - What's unclear: Exact p95/p99 on production endpoints.
   - Recommendation: Emit per-event latency histograms and set an alert threshold at 500 ms.

4. **How do we prove >= 99% T3/T4 file-event coverage?**
   - What we know: We can count T3/T4 ETW events where the PID is `Injected` vs. not.
   - What's unclear: Whether "injected" means IAT patched or just DLL loaded.
   - Recommendation: Count a file event as covered if the PID is in `Injected` state with `hello_received_at` set. The hook DLL should acknowledge injection via the existing pipe hello.

### Known Threat Patterns for the Targeted-Hook Stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Process rename to spoof file-handling basename | Spoofing | Combine basename with PE import score and command-line heuristic; do not inject on basename alone |
| Direct syscall bypass of hook DLL | Tampering | Existing Phase 51 ntdll trampolines (gated) cover injected processes; DACL tripwire covers T3/T4 root paths regardless of hook state |
| Memory-mapped file writes bypassing hooked APIs | Tampering | ETW Kernel-File still observes paging writes at file-object level; DACL tripwire provides kernel backstop |
| Lazy injection race: exfiltrate before hook installs | Elevation of privilege / bypass | Keep immediate injection for high-likelihood processes; lazy fallback is defense-in-depth, not primary control |
| Adversary triggers injection into itself to exhaust agent | Denial of service | Rate-limit lazy injection attempts per PID; reuse existing `ProcessRegistry` to avoid duplicate work |
| Tampered on-disk executable swapped after scan, before injection | Tampering | Re-scan image via file ID/hash if injection is delayed; or read imports from the same file handle used for signer extraction |
