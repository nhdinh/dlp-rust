# Phase 55.1 Plan 01: Read global_enforcement_mode in BypassCorrelator — Summary

## Objective

Add `enforcement_mode: EnforcementMode` to `CorrelatorConfig` and `BypassCorrelator`, then wire `agent_config.enforcement.global_mode` through `service.rs` at correlator construction time. This is the structural prerequisite for Audit-mode suppression logic (Plan 55.1-02).

## Tasks Executed

### Task 1: Extend CorrelatorConfig with enforcement_mode field

**Files modified:** `dlp-agent/src/bypass_correlator.rs`

- Added `use dlp_common::abac::EnforcementMode;` import at top of file
- Added `pub enforcement_mode: EnforcementMode` field to `CorrelatorConfig` struct
- Updated `Default` impl to set `enforcement_mode: EnforcementMode::default()` (resolves to `Block`)
- Added doc comment: "Phase 55.1: Global enforcement mode to suppress bypass alerts in Audit mode. Only Audit suppresses; PerPolicy, Block, and AuditAndBlock continue emitting alerts."
- Added `test_correlator_config_default_mode_is_block` verifying backward compatibility

**Verification:** `cargo test -p dlp-agent test_correlator_config_default_mode_is_block` passes (1 test). `cargo clippy -p dlp-agent -- -D warnings` clean.

### Task 2: Wire global_mode into CorrelatorConfig in service.rs

**Files modified:** `dlp-agent/src/service.rs`

- At correlator construction site (line ~1615), added `enforcement_mode: agent_config.enforcement.global_mode` to the `CorrelatorConfig` struct literal before `..Default::default()`
- Ensures the correlator receives the live global mode from the agent config (populated by server policy_sync per Phase 55 D-02)

**Verification:** `cargo test -p dlp-agent service` passes (29 tests). `cargo clippy -p dlp-agent -- -D warnings` clean.

### Task 3: Add wiring test verifying global_mode reaches CorrelatorConfig

**Files modified:** `dlp-agent/src/service.rs`

- Added `test_correlator_config_receives_global_mode_from_agent_config` to the `#[cfg(test)] mod tests` block in service.rs
- Constructs `AgentConfig` with `global_mode = Audit`, `PerPolicy`, and `Block`, then builds `CorrelatorConfig` using the same pattern as production code
- Asserts all three modes propagate correctly
- Prevents silent regressions where `..Default::default()` would mask a missing field

**Verification:** `cargo test -p dlp-agent test_correlator_config_receives_global_mode_from_agent_config` passes (1 test). `cargo clippy -p dlp-agent -- -D warnings` clean.

## Threat Model Verification

| Threat ID | Category | Component | Disposition | Verified |
|-----------|----------|-----------|-------------|----------|
| T-55.1-01 | Tampering | Attacker modifies agent-config.toml to set Audit mode | accept | Agent config file is in ProgramData and requires admin write access; same threat model as all other config fields |
| T-55.1-02 | Information Disclosure | Audit-mode suppression hides real bypasses from SIEM | mitigate | Only Audit mode suppresses; Block and AuditAndBlock continue emitting alerts. Suppression is intentional per operator choice (monitoring mode). |
| T-55.1-03 | Denial of Service | Default Block mode means existing deployments without explicit config continue blocking | mitigate | Default is Block (backward compatible); only explicit Audit mode changes behavior |

## Design Invariants Documented

1. **Default backward compatibility:** `CorrelatorConfig::default()` uses `EnforcementMode::default()` (Block), not a hardcoded value. This ties the default to the enum's `#[default]` attribute, preventing drift.
2. **Wiring propagation:** `service.rs` explicitly passes `agent_config.enforcement.global_mode` into `CorrelatorConfig`, preventing silent fallback to `Default::default()`.
3. **Test coverage:** Three modes (Audit, PerPolicy, Block) are verified in the wiring test, ensuring no mode is silently dropped.
