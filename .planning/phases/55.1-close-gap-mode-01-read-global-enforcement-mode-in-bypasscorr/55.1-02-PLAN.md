<objective>
Add Audit-mode suppression guards to the three bypass alert emission paths in BypassCorrelator: handle_etw_event (efficiency — skips correlation), submit_bypass_alert (defense in depth for hook IPC), and emit_alert (final safety net). Add unit tests covering Audit suppression, Block/AuditAndBlock allowance, and backward-compatible default config.

Purpose: Close the MODE-01 gap identified in v0.10.0 milestone audit (INT-WARN-02). In Audit global mode, the hook DLL returns ALLOW for all operations, so the absence of a hook journal is expected behavior — not a bypass. Without this fix, the correlator emits false-positive NoHookJournal alerts in monitoring mode.
Output: Guarded alert emission paths + 4+ unit tests verifying suppression behavior per mode.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55.1-04 | Elevation of Privilege | Attacker unloads hook DLL and relies on Audit mode to avoid alerts | accept | Even in Audit mode, the absence of a journal is expected (hook returns ALLOW). The operator chose monitor mode. Real bypasses in Block mode still trigger alerts. |
| T-55.1-05 | Denial of Service | Operator misses real bypass because Audit mode suppresses all alerts | mitigate | Only Audit mode suppresses. Block and AuditAndBlock continue emitting alerts. The mode is operator-configurable and defaults to Block. |
| T-55.1-06 | Tampering | Attacker forces Audit mode by modifying config file | accept | Same threat model as all other config fields; requires admin access to ProgramData. Server-side policy_sync reverts unauthorized changes on next cadence. |
| T-55.1-07 | Repudiation | No audit trail of suppressed bypass alerts in Audit mode | mitigate | The trace! log line records suppression. If the operator wants full forensics, they should use AuditAndBlock mode, which emits both alerts and audit events. |
