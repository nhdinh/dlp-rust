## Objective

Update the hook DLL's `classify_path_with_volume_class` function to populate the `source_volume_class` and `destination_volume_class` fields on `HookRequest` instead of discarding them. Update `classify_and_log_path` to forward volume class parameters. This is the hook-side data flow that carries volume class information into the IPC payload.

Purpose: The hook DLL already resolves volume class at interception time (via `volume_class_cache::resolve_volume_class_from_path`), but the `classify_path_with_volume_class` function currently constructs a `HookRequest` with `..Default::default()` which drops the volume class data. After Plan 01 adds the fields to `HookRequest`, this plan makes the hook DLL actually populate them.

Output: Hook DLL trampolines that carry volume class through the IPC pipe.
