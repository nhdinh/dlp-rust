## Objective

Verify that the hook DLL's `classify_path_with_volume_class` function populates the `source_volume_class` and `destination_volume_class` fields on `HookRequest`, that `classify_and_log_path` forwards volume class parameters, and that all trampoline call sites pass resolved volume classes. This plan is a verification pass — the population logic was added during Phase 56 execution and must be confirmed present before Plan 03 proceeds.

Purpose: The hook DLL already resolves volume class at interception time (via `volume_class_cache::resolve_volume_class_from_path`), but we must confirm that `classify_path_with_volume_class` constructs a `HookRequest` with the volume class data populated. After Plan 01 confirms the fields exist on `HookRequest`, this plan verifies the hook DLL actually fills them.

Output: Verified hook DLL trampolines that carry volume class through the IPC pipe.
