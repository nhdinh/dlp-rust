# Phase 56.1: Close gap DRIVE-03/04 — add volume class fields to HookRequest and ABAC path - Context

**Gathered:** 2026-06-18
**Status:** Ready for planning
**Source:** Beads issue dlp-rust-5ih

<domain>
## Phase Boundary

This gap-closure phase carries the volume-class classification that the hook DLL already determines locally across the IPC boundary into the agent's ABAC evaluation.

The hook DLL currently determines source/destination volume class locally but discards those parameters before constructing `HookRequest`. `HookRequest` has no volume-class fields, so the agent's ABAC evaluation cannot evaluate actual volume class.

**Downstream effect:** Policies that should distinguish `LocalDisk`, `Removable`, `Optical`, `Network`, `Virtual` (e.g., SD/optical/virtual drive exfiltration rules) cannot fire correctly.

**Scope:**
- Add source/destination volume class fields to the IPC `HookRequest` payload
- Populate those fields in the hook DLL instead of discarding them
- Update agent ABAC evaluation to pass volume class into policy conditions
- Add tests covering SD/optical/virtual drive policy decisions
- Run Nyquist tasks and mark complete

</domain>

<decisions>
## Implementation Decisions

### IPC Payload
- Add `source_volume_class` and `destination_volume_class` fields to `HookRequest`
- Use the existing volume-class enum/descriptor already known to the hook DLL
- Preserve backward compatibility in the IPC protocol where possible

### Hook DLL
- Populate `source_volume_class` and `destination_volume_class` from the local volume-class determination logic
- Do not discard the parameters when constructing `HookRequest`

### Agent ABAC
- Thread volume class through to ABAC condition evaluation
- Expose volume class as an ABAC attribute available to policy conditions

### Tests
- Add unit/integration tests covering SD, optical, and virtual drive policy decisions
- Verify that volume class affects the ABAC decision outcome

### Nyquist
- Run applicable Nyquist tasks and mark them complete

### Claude's Discretion
- Exact field types and enum variants (reuse existing internal types)
- Specific policy condition syntax for volume class
- Placement of new tests within the existing test modules

</decisions>
