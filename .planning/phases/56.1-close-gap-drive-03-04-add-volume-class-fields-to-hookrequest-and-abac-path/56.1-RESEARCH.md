# Phase 56.1: Close gap DRIVE-03/04 — add volume class fields to HookRequest and ABAC path - Research

**Researched:** 2026-06-18
**Domain:** Windows DLP Hook IPC, ABAC Policy Evaluation, Rust
**Confidence:** HIGH

## Summary

This phase closes a critical integration gap: the hook DLL already resolves source/destination volume class for every intercepted file operation, but the `HookRequest` IPC payload lacks fields to carry this data, and the agent's hook IPC handler uses a placeholder heuristic instead of real ABAC evaluation. The result is that volume-class ABAC policies (e.g., "deny T4 copy to Optical") never fire for hook-intercepted operations.

The fix is a three-part change: (1) add `source_volume_class` and `destination_volume_class` fields to `HookRequest` in `dlp-common/src/hook_ipc.rs`, (2) populate those fields in the hook DLL's `classify_path_with_volume_class` instead of discarding them, and (3) wire the agent's hook IPC handler to perform real ABAC evaluation using the volume class data from the request. The ABAC infrastructure (`AbacContext`, `PolicyCondition`, `volume_class_matches`) is already fully implemented — this phase is purely about data flow plumbing.

**Primary recommendation:** Add `#[serde(default)]` fields to `HookRequest`, populate them in `classify_path_with_volume_class`, and convert `HookRequest` to `EvaluateRequest` inside the agent's `HookHandler` so volume class reaches `PolicyStore::evaluate`.

### Pattern 1: Serde Default for Backward-Compatible IPC Fields
**What:** Add new optional fields to an existing IPC struct with `#[serde(default)]` so old peers deserialize successfully.
**When to use:** Any time the IPC protocol gains new fields that old hook DLLs won't send.
**Example:**
```rust
// Source: dlp-common/src/hook_ipc.rs (existing pattern)
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Default)]
pub struct HookRequest {
    pub path: String,
    pub action: String,
    #[serde(default)]
    pub cache_version: u64,
    #[serde(default = "default_protocol_version")]
    pub protocol_version: u8,
    #[serde(default)]
    pub op: HookOp,
    // NEW FIELDS (Phase 56.1):
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub source_volume_class: Option<VolumeClass>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub destination_volume_class: Option<VolumeClass>,
}
```

### Pattern 2: HookRequest → EvaluateRequest Conversion
**What:** Convert the lightweight `HookRequest` (from hook DLL) into a full `EvaluateRequest` (for ABAC evaluation) by resolving identity and mapping fields.
**When to use:** The hook IPC path needs real ABAC evaluation instead of placeholder heuristics.
**Example:**
```rust
// Source: dlp-agent/src/hook_ipc.rs (new code)
fn hook_request_to_evaluate_request(req: &HookRequest) -> EvaluateRequest {
    let (user_sid, user_name) = resolve_current_user(); // or from session map
    EvaluateRequest {
        subject: Subject {
            user_sid,
            user_name,
            groups: vec![],
            device_trust: DeviceTrust::Unknown,
            network_location: NetworkLocation::Unknown,
            device_health: current_health(),
        },
        resource: Resource {
            path: req.path.clone(),
            classification: Classification::T2, // or resolve from label service
        },
        environment: Environment {
            timestamp: chrono::Utc::now(),
            session_id: 0,
            access_context: AccessContext::Local,
        },
        action: map_hook_action_to_abac(&req.action),
        source_volume_class: req.source_volume_class,      // ← NEW
        destination_volume_class: req.destination_volume_class, // ← NEW
        ..Default::default()
    }
}
```

### Pattern 3: Fail-Closed Volume Class Evaluation
**What:** When `source_volume_class` or `destination_volume_class` is `None`, volume-class conditions evaluate to `false`.
**When to use:** Always — this is the existing behavior in `volume_class_matches`.
**Example:**
```rust
// Source: dlp-server/src/policy_store.rs (already implemented)
fn volume_class_matches(op: &str, expected: &VolumeClass, actual: Option<VolumeClass>) -> bool {
    let Some(actual) = actual else {
        return false; // fails closed
    };
    match op {
        "eq" => actual == *expected,
        "ne" => actual != *expected,
        "in" => actual == *expected,
        _ => false,
    }
}
```

### Anti-Patterns to Avoid
- **Defaulting `None` to `LocalNTFS`:** The hook DLL or agent must NEVER default an unclassifiable path to `LocalNTFS`. `None` means "we don't know" and must fail closed. [VERIFIED: dlp-common/src/abac.rs docs]
- **Using `bincode` without `#[serde(default)]`:** Bincode requires exact field layout match. Without `serde(default)`, an old peer's serialized `HookRequest` (missing new fields) will fail to deserialize. [VERIFIED: dlp-common/src/hook_ipc.rs existing pattern]
- **Duplicating volume class resolution in the agent:** The hook DLL already resolves volume class at interception time. The agent should use the value from `HookRequest`, not re-resolve from the path (which may race with drive removal). [VERIFIED: trampolines.rs resolve_volume_class_from_path calls]

## Common Pitfalls

### Pitfall 1: Bincode Backward Compatibility Break
**What goes wrong:** Adding fields to `HookRequest` without `#[serde(default)]` causes old hook DLLs to produce frames that fail deserialization, triggering `PipeError::Malformed` and fail-closed denials.
**Why it happens:** Bincode is not self-describing; it expects exact field order and count.
**How to avoid:** Always add `#[serde(default)]` or `#[serde(default = "...")]` on new fields. Test by serializing an old `HookRequest` (without new fields) and deserializing with the new struct.
**Warning signs:** All hook DLL requests suddenly return `Malformed` after agent update; `test_old_request_deserializes_with_defaults` test fails.

### Pitfall 2: Volume Class Lost in `EvaluateRequest` → `AbacContext` Conversion
**What goes wrong:** `EvaluateRequest` gains `source_volume_class` fields but `impl From<EvaluateRequest> for AbacContext` still hardcodes `None`.
**Why it happens:** The conversion in `dlp-common/src/abac.rs` currently sets `source_volume_class: None, destination_volume_class: None`.
**How to avoid:** Update the `From` impl to forward the volume class fields from `EvaluateRequest` to `AbacContext`.
**Warning signs:** Policy evaluation returns `ALLOW` when it should `DENY`; `matched_policy_id` is `None` despite all other conditions matching.

### Pitfall 3: Hook DLL Still Discards Volume Class After Code Change
**What goes wrong:** `classify_path_with_volume_class` is updated but trampolines still call `classify_and_log_path` (the old function) instead of the new one.
**Why it happens:** Most trampolines call `classify_and_log_path` directly; only the `Degraded` retry path and `RESYNC` recovery path call `classify_path_with_volume_class`.
**How to avoid:** Update `classify_and_log_path` to accept and forward volume class parameters, OR update all trampoline call sites to pass volume classes through.
**Warning signs:** `source_volume_class` is always `None` in agent logs despite hook DLL resolving it.

### Pitfall 4: Agent's `HookHandler` Still Uses Placeholder Heuristic
**What goes wrong:** `HookRequest` now carries volume class, but the agent's `inner_handler` still returns decisions based on `build_cache_hint` path heuristics instead of real ABAC.
**Why it happens:** `handle_hook_request` delegates to `inner_handler(req.clone())` which is a mock/placeholder in tests and a heuristic in production.
**How to avoid:** Replace the placeholder `HookHandler` with one that converts `HookRequest` → `EvaluateRequest` and calls `offline.evaluate(&request).await`.
**Warning signs:** Volume class policies work in `volume_class_integration.rs` tests but not in hook IPC roundtrip tests.

## Open Questions

1. **How should the agent's `HookHandler` perform real ABAC evaluation?**
   - What we know: `HookHandler` is `Arc<dyn Fn(HookRequest) -> HookResponse + Send + Sync>`. The agent's `run_event_loop` uses `OfflineManager::evaluate` which is async. The hook IPC server runs on a blocking `std::thread`.
   - What's unclear: Whether to use `tokio::runtime::Handle::current().block_on()` inside the handler, or pre-build a synchronous evaluator, or spawn a Tokio task for each request.
   - Recommendation: Use `block_on` with the existing Tokio runtime (available in `service.rs` startup), or convert the `HookHandler` to return a future. Document the threading model carefully.

2. **Should `EvaluateRequest` gain volume class fields, or should they be added only to `AbacContext`?**
   - What we know: `AbacContext` already has the fields. `EvaluateRequest` → `AbacContext` conversion currently hardcodes `None`.
   - What's unclear: Whether the wire format `EvaluateRequest` (sent to Policy Engine REST API) should also carry volume class, or if only the in-process `AbacContext` needs them.
   - Recommendation: Add fields to `EvaluateRequest` so the hook path can populate them; the REST API will then carry them to the Policy Engine. This is consistent with how `source_application` and `source_origin` were added.

3. **How do copy/move trampolines pass both source and destination volume classes?**
   - What we know: `classify_and_log_path` currently takes both parameters but only passes them to `classify_path_with_volume_class` in the `Degraded` retry path. Most trampolines call `classify_and_log_path` with `source_volume_class` and `None` for destination.
   - What's unclear: Whether copy/move trampolines should call `classify_and_log_path` twice (once per path) or once with both volume classes.
   - Recommendation: For copy/move, the source path classification should carry `source_volume_class`, and the destination path classification should carry `destination_volume_class`. The policy condition distinguishes them. Two separate calls may be needed unless the policy is evaluated at the operation level (not per-path).
