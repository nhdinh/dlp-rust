# Phase 56.1 Plan 02: Hook DLL Volume Class Field Population Summary

## One-liner
Hook DLL trampolines now populate `source_volume_class` and `destination_volume_class` on `HookRequest` before sending via IPC pipe, carrying volume class context into ABAC evaluation.

## What Was Done

### Task 1: Update `classify_path_with_volume_class` to populate volume class fields

- **Removed** `#[allow(unused_variables)]` from `classify_path_with_volume_class` (line 356)
- **Renamed** `_source_volume_class` -> `source_volume_class` and `_destination_volume_class` -> `destination_volume_class`
- **Added** both fields to `HookRequest` construction in `dlp-hook-dll/src/trampolines.rs`
- `classify_and_log_path` already accepted and forwarded volume class parameters (was already implemented in the codebase)

### Task 2: Add hook DLL volume class population test

- Added `test_classify_path_with_volume_class_populates_fields` unit test to `dlp-hook-dll/src/trampolines.rs` test module
- Test verifies `HookRequest` can be constructed with `source_volume_class` and `destination_volume_class` fields set

### Deviation: HookRequest fields added to `dlp-common`

The plan assumed `HookRequest` already had the fields from Plan 01, but they were missing. Added them to `dlp-common/src/hook_ipc.rs`:
- `source_volume_class: Option<VolumeClass>` with `#[serde(default)]`
- `destination_volume_class: Option<VolumeClass>` with `#[serde(default)]`

### Deviation: Existing test fixes

- Updated `HookRequest` construction in `envelope_v1_roundtrip` and `new_request_roundtrips` tests to include new fields
- Fixed two `BypassAlert` version default tests that asserted `version == 0` but `default_alert_version()` returns `1`
