# Phase 56.1 Plan 01: Add volume class fields to HookRequest and ABAC path Summary

**Volume class fields (source_volume_class, destination_volume_class) added to HookRequest and EvaluateRequest with serde backward compatibility, and From<EvaluateRequest> for AbacContext now forwards these fields instead of hardcoding None.**

## Accomplishments

- HookRequest carries source_volume_class and destination_volume_class fields with serde(default) for JSON backward compatibility and bincode round-trip safety
- EvaluateRequest carries the same two fields with serde(default, skip_serializing_if) for clean JSON wire format
- From<EvaluateRequest> for AbacContext forwards req.source_volume_class and req.destination_volume_class (was hardcoded None)
- 5 new tests verify round-trip serialization, backward compatibility, and field forwarding
- Existing tests updated to include new fields where struct literals were constructed

- `dlp-common/src/abac.rs` — Added source_volume_class and destination_volume_class fields to EvaluateRequest; updated From impl to forward fields; added 3 new tests (serde round-trip + From forwarding + JSON backward compat)

## Decisions Made

- **HookRequest uses #[serde(default)] only** (no skip_serializing_if) because bincode v1 does not support skip_serializing_if on struct fields — attempting to use it causes UnexpectedEof during deserialization when Option fields are None. This is a critical deviation from the plan's stated pattern.
- **EvaluateRequest keeps #[serde(default, skip_serializing_if = "Option::is_none")]** because it is a JSON-only REST wire format and skip_serializing_if produces cleaner payloads.
- **Two serialization patterns established:** bincode-facing structs use serde(default) only; JSON-facing structs use serde(default, skip_serializing_if).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Removed skip_serializing_if from HookRequest volume class fields**
- **Found during:** Task 2 (test execution)
- **Issue:** The plan specified `#[serde(default, skip_serializing_if = "Option::is_none")]` for HookRequest fields, matching the EvaluateRequest pattern. However, bincode v1 does not support skip_serializing_if on struct fields — when Option fields are None, bincode skips serializing them but deserialization still expects them, causing UnexpectedEof.
- **Fix:** Changed HookRequest fields to use `#[serde(default)]` only (no skip_serializing_if). EvaluateRequest fields kept the full pattern because they are JSON-only.
- **Files modified:** dlp-common/src/hook_ipc.rs
- **Verification:** bincode round-trip tests pass (test_hook_request_volume_class_roundtrip, envelope_v1_roundtrip, new_request_roundtrips)
- **Committed in:** 339377f (Task 2 commit)

**2. [Rule 3 - Blocking] Added volume class fields to existing test struct literals**
- **Found during:** Task 2 (cargo test execution)
- **Issue:** Adding fields to HookRequest broke existing tests (envelope_v1_roundtrip, new_request_roundtrips) that constructed HookRequest without the new fields. The struct derives Default but the fields are not optional in struct literal construction.
- **Fix:** Added source_volume_class: None and destination_volume_class: None to the two existing test struct literals.
- **Files modified:** dlp-common/src/hook_ipc.rs
- **Verification:** All dlp-common tests pass except 2 pre-existing BypassAlert failures unrelated to this change
- **Committed in:** 339377f (Task 2 commit)
