# Phase 58.8: Fix DIFF-01 and DIFF-04

## Goal

Close the two remaining cross-phase wiring blockers identified in the v0.10.0
milestone re-audit (`.planning/milestones/v0.10.0-MILESTONE-AUDIT-2026-07-09.md`):

1. **DIFF-01** — The hook DLL deny path never emits `IpcPayloadV1::RequestOverride`,
   so users cannot initiate an override from a blocked file operation. The
   agent-side handler and approval workflow infrastructure exist, but the DLL
   trigger is missing.

2. **DIFF-04** — The dlp-admin-cli self-health dashboard calls `GET /admin/health`,
   but `dlp-server/src/admin_api.rs` does not define that route. In addition,
   `diagnostic_store` is initialized to `None` in all production `AppState`
   construction sites, so `GET /admin/diagnostics` returns empty snapshots.

## Scope

- `dlp-hook-dll/src/trampolines.rs` and related deny-path helpers:
  - Emit `IpcPayloadV1::RequestOverride` when a DENY decision is returned and the
    user opts to request an override.
  - Preserve fail-closed semantics: the original operation is still denied while
    the override request is submitted asynchronously.
  - Integrate with the existing `HookResponse.approval_override` path if an
    approved override is already cached.

- `dlp-server/src/admin_api.rs`:
  - Add `GET /admin/health` route returning the latest self-health snapshot and
    recent history.
  - Ensure the route is mounted on the admin router with JWT protection.

- `dlp-server/src/main.rs` (and any other production `AppState` construction
  sites):
  - Initialize `diagnostic_store` from the persisted diagnostic repository so
    `GET /admin/diagnostics` and `GET /admin/health` return real data.

## Out of Scope

- OPS-04 physical Windows 11 UAT execution (remains Phase 58.3).
- Phase 58.5 UAT Test 7 live DLL unload re-test.
- Phase 58.6 targeted hook injection.

## Success Criteria

- [ ] Hook DLL unit/integration tests prove `RequestOverride` is sent on the
      deny path with correct metadata.
- [ ] Agent-side override handler receives and forwards the request to the user
      UI and server approval API.
- [ ] `dlp-admin-cli get_self_health()` succeeds against a running server and

- [ ] `GET /admin/diagnostics` returns real snapshots when diagnostics have been
      ingested.
- [ ] Full workspace tests, clippy, formatting, and sonar-scanner Quality Gate
