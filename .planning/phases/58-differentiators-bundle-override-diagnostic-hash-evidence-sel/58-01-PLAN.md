# Plan 58-01: Foundational Hook DLL Modules

## Objective

Create diagnostic_snapshot.rs and content_hasher.rs modules in the hook DLL with a versioned IPC envelope (IpcPayloadV2), wall-clock timestamps for cross-process sorting, and non-blocking hash computation with saturation fallback. Address all HIGH review concerns from cross-AI review.

## Background

The original plan appended new variants directly to IpcPayloadV1, breaking bincode deserialization when old agents talk to new hook DLLs. The revised plan introduces IpcPayloadV2 as a versioned envelope. Reviewers identified critical issues: ArrayQueue capacity was 64 instead of D-07's mandated 1000, hash boundary ambiguity between 100MB and 1GB, missing hash_skipped_reason enum, missing version field in DiagnosticSnapshot, and non-monotonic ordering. This plan fixes all of them.

## must_haves

- truths:
  - IpcPayloadV2 uses a versioned envelope pattern; bincode compatibility is preserved
  - DiagnosticSnapshot includes timestamp_utc for wall-clock display and severity derived from enforcement_mode
  - ContentHasher uses non-blocking submission with hash_skipped fallback on saturation
  - ENTRY_EXPIRY uses SystemTime, not raw QPC ticks
  - ArrayQueue capacity is 1000 entries per D-07, with explicit pop-then-push overwrite semantics
  - HashSkippedReason enum captures why hashing was skipped (TooLarge, ChannelFull, Timeout)
  - DiagnosticSnapshot includes version: u8 for future evolution
  - Monotonic sequence numbers (AtomicU64) provide deterministic ordering
  - Hash boundary: skip if >100MB, stream-hash if <=1GB, abort if >1GB

- Use sha2::Sha256 from the sha2 crate (add to Cargo.toml if missing).
- Use a bounded crossbeam channel (bounded(16)) for hash job submission instead of rayon::install.
- Spawn a single background thread (via std::thread::spawn) that receives (Vec<u8>, oneshot::Sender<(String, HashSkippedReason)>) jobs from the channel.
- Use OnceLock to lazily initialize the channel sender and background thread from trampoline context.
- Provide fn compute_hash_async(buffer: Vec<u8>) -> (Option<String>, bool, Option<HashSkippedReason>, Option<u64>) that:
  - If buffer.len() > 1_000_000_000 (1GB), returns (None, true, Some(HashSkippedReason::TooLarge), None) — safety boundary per Pitfall 3
  - If buffer.len() > 100_000_000 (100MB), stream-hash the first 100MB and set hash_skipped_reason = Some(HashSkippedReason::TooLarge) with truncated result
  - If channel is full (16 pending jobs), returns (None, true, Some(HashSkippedReason::ChannelFull), None)
  - Otherwise sends job, waits up to 50ms on the oneshot receiver, returns (Some(hex_hash), false, None, Some(elapsed_us)) on success or (None, true, Some(HashSkippedReason::Timeout), None) on timeout
- Provide fn compute_hash_sync(buffer: &[u8]) -> String for small buffers (<= 64KB) that computes directly on the calling thread.
- Add hex crate dependency to Cargo.toml for hex encoding.
- Add unit tests:
  - test_small_buffer_hash_sync
  - test_large_buffer_truncated_at_100mb
  - test_1gb_buffer_rejected
  - test_channel_full_fallback
  - test_timeout_returns_reason
</action>

## <threat_model>

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| Bincode deserialization break | Tampering | Versioned envelope (IpcPayloadV2) with V1 fallback |
| Buffer overread during hash | Denial of Service | 1GB absolute maximum cap + 100MB stream-hash cap |
| Diagnostic data exfiltration | Information Disclosure | In-memory only, no disk persistence, 1-hour lazy eviction |
| Ring buffer memory leak | Denial of Service | 1000-entry cap bounds memory to ~1MB per process |
| Hook thread blocking on hash | Denial of Service | Bounded channel (16) with timeout (50ms) + skip fallback |
| Cross-process timestamp spoofing | Spoofing | Monotonic AtomicU64 sequence numbers + QPC for intra-machine ordering |
</threat_model>
