# Plan 58-05: Admin TUI Screens

## Objective

Build Diagnostic List and Self-Health Dashboard screens in `dlp-admin-tui` that read from the server's cached endpoints (`GET /admin/diagnostics` and `GET /admin/health`). Use the `severity` and `timestamp_utc` fields from `DiagnosticSnapshot`. Add detail popup showing all 18 DiagnosticSnapshot fields per D-02. Add empty-state widgets. Define sparkline metric. Keep SystemMenu lists in `dispatch.rs` and `render.rs` synchronized.

## Background

The original plan invented a `severity` field that did not exist on `DiagnosticSnapshot` and used QPC timestamps for relative time display. The revised plan uses the actual `severity` and `timestamp_utc` fields added in 58-01. It also ensures both `dispatch.rs` and `render.rs` SystemMenu lists are updated together.

Reviewers identified critical issues: Diagnostic List omits full decision tree fields (D-02 requires hook name, classification age, ABAC subject/resource/action/environment), missing empty-state widgets, and undefined sparkline metric. This plan fixes all of them.

## must_haves

- truths:
  - Diagnostic List uses GET /admin/diagnostics with severity filtering
  - Self-Health Dashboard uses GET /admin/health with sparkline history
  - timestamp_utc drives relative time display ("2m ago")
  - Detail popup (Enter key) shows all 18 DiagnosticSnapshot fields per D-02
  - Empty-state widgets display when no diagnostics or no agents
  - Sparkline metric is cache_hit_rate as primary trend
  - SystemMenu in dispatch.rs and render.rs are synchronized
  - Four-file pattern (constants, dispatch, render, client) is followed

## <threat_model>

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| Detail popup information disclosure | Information Disclosure | Only shows data already in DiagnosticSnapshot; no additional secrets |
| Empty state confusion | Denial of Service | Clear messages guide operator to check agents/policies |
| Large dataset TUI performance | Denial of Service | Default limit of 100 snapshots; pagination not needed for MVP |
| Menu order drift | Tampering | Unit test `test_system_menu_order_matches_dispatch` catches regression |
| Clock skew in relative time | Spoofing | Uses server-provided timestamp_utc; TUI displays relative to local clock |
| Sparkline metric misinterpretation | Information Disclosure | Documented as cache_hit_rate; color-coded thresholds |
</threat_model>
