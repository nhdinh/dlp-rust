# Plan 58-02: Trampoline Integration

## Objective

Wire diagnostic snapshot capture and hash computation into all 12 trampolines. Refactor `classify_and_log_handle` to return a `DecisionContext` struct containing all fields needed for diagnostic snapshots. Increment `injected_pids` and `patched_modules` counters at their respective entry points.

## Background

The original plan assumed `classify_and_log_handle` returned enough context to populate `DiagnosticSnapshot`, but its current `Option<DenyReturn>` signature lacks `classification_source`, `classification_age_ms`, `matched_policy_id`, `enforcement_mode`, and `decision_latency_us`. This plan introduces `DecisionContext` as a richer return type. It also removes the incorrect `check_approval_cache` from the hook DLL (the agent is authoritative) and documents the `WriteFileEx` hash latency tradeoff.

## must_haves

- truths:
  - classify_and_log_handle returns DecisionContext with all diagnostic fields
  - DiagnosticSnapshot is pushed on every DENY for all 12 trampolines
  - SHA-256 is computed only on WriteFile/WriteFileEx DENY paths (D-12)
  - injected_pids counter increments at injection time
  - patched_modules counter increments when ntdll stubs are patched
  - Approval cache check lives in agent, NOT hook DLL

Update all 12 trampoline files in `crates/dlp-hook-dll/src/trampoline/` to push diagnostic snapshots on DENY:

- For each trampoline (writefile, writefileex, createfile, createfileex, readfile, readfileex, deletefile, deletefileex, movefile, movefileex, copyfile, copyfileex):
  - After calling `classify_and_log_handle` and receiving `DecisionContext`, if `ctx.deny_return.is_some()`:
    1. Construct `DiagnosticSnapshot` from `ctx` fields
    2. Set `pid` to `std::process::id()`
    3. Set `agent_id` to the current agent ID (from existing agent connection state)
    4. Set `timestamp_qpc` to current QPC counter
    5. Set `timestamp_utc` to `Utc::now()`
    6. For WriteFile and WriteFileEx ONLY: call `content_hasher::compute_hash_async(buffer)` and populate `content_hash`, `hash_skipped`, `hash_latency_us`
    7. For all other trampolines: set `content_hash: None`, `hash_skipped: false`, `hash_latency_us: None`
    8. Call `diagnostic_snapshot::push_snapshot(snapshot)`

- Document in code comments that WriteFileEx hash computation happens BEFORE calling the original API to ensure buffer validity, adding latency to the async I/O path. This is an intentional tradeoff per D-17.

- Ensure `diagnostic_snapshot::init_diagnostic_ring()` and `content_hasher::init_hasher()` are called once from `trampoline/mod.rs` entry point (not per-trampoline).
</action>
