# Plan 58-04: Server API and Schema

## Objective

Add server endpoints for diagnostics and health with an agent-push ingestion model. The server maintains an in-memory cache of diagnostic snapshots and health status received from the agent via HTTP POST. Add `GET /admin/health` endpoint. Implement actual `AuditEvent` INSERT functions in `audit_repository.rs`. Address all HIGH review concerns about authentication, rate limiting, and audit event persistence.

## Background

The original plan put `DiagnosticAggregator` directly in `AppState`, which only works when server and agent share a process. The revised plan uses an agent-push model: the agent periodically POSTs aggregated data to the server, which stores it in an `Arc<DashMap>` cache. The TUI reads from this cache via `GET /admin/diagnostics` and `GET /admin/health`.

Reviewers identified critical issues: missing authentication on POST /agent/diagnostics, AuditEvent INSERT was documentation-only instead of actual implementation, no per-agent rate limiting, and no GET /admin/diagnostics/{snapshot_id} endpoint. This plan fixes all of them.

## must_haves

- truths:
  - Server never reads agent memory directly; all data arrives via HTTP POST
  - GET /admin/diagnostics serves cached diagnostic snapshots with filtering
  - GET /admin/health serves cached health status
  - POST /agent/diagnostics requires existing agent JWT auth
  - Per-agent rate limit: max 1000 snapshots per push, max 1 push per 30s
  - AuditEvent INSERT functions exist in audit_repository.rs (not just documented)
  - GET /admin/diagnostics/{snapshot_id} returns single snapshot detail

## <threat_model>

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| Unauthenticated agent push | Spoofing | Require existing agent JWT auth on POST /agent/diagnostics |
| Agent memory exhaustion | Denial of Service | Per-agent rate limit: 1000 snapshots/push, 1 push/30s |
| Cache memory exhaustion | Denial of Service | 300s stale pruning + per-agent snapshot limits |
| Missing audit trail | Repudiation | AuditEvent INSERT functions persist to SQLite |
| Large response payloads | Denial of Service | Default limit of 100 snapshots on GET /admin/diagnostics |
| Snapshot ID enumeration | Information Disclosure | GET /admin/diagnostics/{snapshot_id} requires admin JWT auth |
</threat_model>
