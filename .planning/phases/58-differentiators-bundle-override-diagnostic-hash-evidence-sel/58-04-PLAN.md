# Plan 58-04: Server API and Schema

## Objective

Add server endpoints for diagnostics and health with an agent-push ingestion model. The server maintains an in-memory cache of diagnostic snapshots and health status received from the agent via HTTP POST. Add `GET /admin/health` endpoint. Identify specific audit repository functions for `AuditEvent` persistence.

## Background

The original plan put `DiagnosticAggregator` directly in `AppState`, which only works when server and agent share a process. The revised plan uses an agent-push model: the agent periodically POSTs aggregated data to the server, which stores it in an `Arc<DashMap>` cache. The TUI reads from this cache via `GET /admin/diagnostics` and `GET /admin/health`.

## must_haves

- truths:
  - Server never reads agent memory directly; all data arrives via HTTP POST
  - GET /admin/diagnostics serves cached diagnostic snapshots
  - GET /admin/health serves cached health status
  - POST /agent/diagnostics accepts push from agent with authentication
  - AuditEvent INSERT location is explicitly identified in audit_repository.rs
