# Plan 58-03: Agent-Side Aggregation

## Objective

Build `DiagnosticAggregator` in `dlp-agent` with correct 5-minute history scanning for health thresholds, audit event emission (not `alert_router::send`), a `connected_pipes` registry for agent-initiated polling, and PID reuse protection via process start time. Address all HIGH review concerns about polling frequency, health thresholds, concurrent polling, and pipe eviction.

## Background

The original plan computed health status from a single snapshot, violating D-21's requirement to check "pipe_round_trips > 0 in last 5 min." It also incorrectly called `alert_router::send` from the agent (cross-crate violation), reversed the `PullDiagnostics` directionality (hook DLL should respond to agent-initiated polls, not send them), and used 60s polling instead of D-07's mandated 30s. This plan fixes all three issues.

Reviewers identified critical issues: polling frequency is 60s but D-07 mandates 30s, health threshold logic marks idle processes as degraded, no concurrent pipe polling exists, and there's no per-pipe last_seen eviction. This plan fixes all of them.

## must_haves

- truths:
  - Health status scans the last 5 entries in history (5-minute window)
  - Health threshold logic requires N>=3 entries; idle processes (>=0 round trips) are healthy; 300s without round trips = disconnected
  - Agent emits AuditEvent via existing audit pipeline, never calls alert_router
  - PullDiagnostics and PullHealth are agent-initiated polls TO hook DLLs every 30s
  - connected_pipes registry tracks active hook DLL connections with last_seen timestamps
  - Pipes not seen in 5 minutes are evicted from the registry
  - Diagnostic keys use (pid, process_start_time) to prevent PID reuse collisions
  - Concurrent pipe polling uses tokio::task::JoinSet to avoid head-of-line blocking

Create `crates/dlp-agent/src/diagnostic_aggregator.rs`:

- Define `pub struct DiagnosticAggregator` with fields:
  - `per_dll: DashMap<(u32, u64), PerDllDiagnostics>` where key is `(pid, process_start_time)`
  - `health_transition_threshold: u8` (consecutive degraded snapshots before alerting, default: 3)

- Define `pub struct PerDllDiagnostics` with fields:
  - `history: VecDeque<DiagnosticSnapshot>` (capacity: 12, stores 12 minutes of snapshots)
  - `consecutive_degraded: u8`
  - `last_alerted_status: Option<HealthStatus>`
  - `process_start_time: u64` (from Windows GetProcessTimes or equivalent)

- Define `pub enum HealthStatus { Healthy, Degraded, Failed, Disconnected }`

- Implement `impl DiagnosticAggregator`:
  - `fn new() -> Self`
  - `fn ingest_snapshot(&self, snapshot: DiagnosticSnapshot) -> Option<HealthStatusTransition>`:
    1. Look up key `(snapshot.pid, process_start_time)` in `per_dll`
    2. If not found, create new `PerDllDiagnostics` with `process_start_time` from OS
    3. Push snapshot to `history`, evict oldest if > 12 entries
    4. Compute health status by scanning last 5 entries in `history`:
       - Require at least 3 entries (N>=3); if fewer, return `Healthy` (insufficient data)
       - `cache_hits >= 0` (idle processes are healthy, not degraded — addresses review concern)
       - `fail_state == "healthy"` across all 5 entries
       - `pipe_round_trips >= 0` across all 5 entries (idle is healthy)
       - If no round trips in last 300s (5 minutes): `Disconnected` (addresses review concern)
       - If all three conditions met: `Healthy`
       - If cache_hit_rate < 0.80 OR fail_state != "healthy": `Degraded`
       - If fail_state == "failed": `Failed`
    5. If status changed from previous and `consecutive_degraded >= health_transition_threshold`, return `Some(HealthStatusTransition { from, to, pid, agent_id })`
    6. Update `consecutive_degraded` counter
  - `fn get_snapshots(&self, pid: Option<u32>) -> Vec<DiagnosticSnapshot>`:
    - If pid specified, return all snapshots for that PID sorted by `sequence` descending (monotonic ordering)
    - If None, return all snapshots across all DLLs sorted by `sequence` descending
  - `fn get_health_status(&self, pid: Option<u32>) -> Vec<(u32, HealthStatus)>`:
    - Return current health status for each tracked DLL
  - `fn evict_disconnected(&self, pid: u32)`:
    - Remove all entries for the given PID (called when pipe disconnects)

- Add unit tests:
  - `test_healthy_status_all_conditions_met`
  - `test_degraded_low_cache_hit_rate`
  - `test_idle_process_is_healthy` (addresses review concern: idle != degraded)
  - `test_disconnected_no_round_trips_300s` (addresses review concern: 300s threshold)
  - `test_failed_state`
  - `test_history_window_exactly_5_minutes`
  - `test_pid_reuse_different_start_time`
  - `test_evict_disconnected`
  - `test_insufficient_data_returns_healthy` (N<3 returns Healthy)
</action>
