# Plan 58-03: Agent-Side Aggregation

## Objective

Build `DiagnosticAggregator` in `dlp-agent` with correct 5-minute history scanning for health thresholds, audit event emission (not `alert_router::send`), a `connected_pipes` registry for agent-initiated polling, and PID reuse protection via process start time.

## Background

The original plan computed health status from a single snapshot, violating D-21's requirement to check "pipe_round_trips > 0 in last 5 min." It also incorrectly called `alert_router::send` from the agent (cross-crate violation) and reversed the `PullDiagnostics` directionality (hook DLL should respond to agent-initiated polls, not send them). This plan fixes all three issues.

## must_haves

- truths:
  - Health status scans the last 5 entries in history (5-minute window)
  - Agent emits AuditEvent via existing audit pipeline, never calls alert_router
  - PullDiagnostics and PullHealth are agent-initiated polls TO hook DLLs
  - connected_pipes registry tracks active hook DLL connections
  - Diagnostic keys use (pid, process_start_time) to prevent PID reuse collisions

Create `crates/dlp-agent/src/diagnostic_aggregator.rs`:

- Define `pub struct DiagnosticAggregator` with fields:
  - `per_dll: DashMap<(u32, u64), PerDllDiagnostics>` where key is `(pid, process_start_time)`
  - `health_transition_threshold: u8` (consecutive degraded snapshots before alerting, default: 3)

- Define `pub struct PerDllDiagnostics` with fields:
  - `history: VecDeque<DiagnosticSnapshot>` (capacity: 12, stores 12 minutes of snapshots)
  - `consecutive_degraded: u8`
  - `last_alerted_status: Option<HealthStatus>`
  - `process_start_time: u64` (from Windows GetProcessTimes or equivalent)

- Define `pub enum HealthStatus { Healthy, Degraded, Failed }`

- Implement `impl DiagnosticAggregator`:
  - `fn new() -> Self`
  - `fn ingest_snapshot(&self, snapshot: DiagnosticSnapshot) -> Option<HealthStatusTransition>`:
    1. Look up key `(snapshot.pid, process_start_time)` in `per_dll`
    2. If not found, create new `PerDllDiagnostics` with `process_start_time` from OS
    3. Push snapshot to `history`, evict oldest if > 12 entries
    4. Compute health status by scanning last 5 entries in `history`:
       - `cache_hit_rate >= 0.80` across all 5 entries
       - `fail_state == "healthy"` across all 5 entries
       - `pipe_round_trips_60s > 0` across all 5 entries
       - If all three: `Healthy`; if cache_hit_rate < 0.80 OR fail_state != "healthy": `Degraded`; if fail_state == "failed": `Failed`
    5. If status changed from previous and `consecutive_degraded >= health_transition_threshold`, return `Some(HealthStatusTransition { from, to, pid, agent_id })`
    6. Update `consecutive_degraded` counter
  - `fn get_snapshots(&self, pid: Option<u32>) -> Vec<DiagnosticSnapshot>`:
    - If pid specified, return all snapshots for that PID sorted by `timestamp_utc` descending
    - If None, return all snapshots across all DLLs sorted by `timestamp_utc` descending
  - `fn get_health_status(&self, pid: Option<u32>) -> Vec<(u32, HealthStatus)>`:
    - Return current health status for each tracked DLL
  - `fn evict_disconnected(&self, pid: u32)`:
    - Remove all entries for the given PID (called when pipe disconnects)

- Add unit tests:
  - `test_healthy_status_all_conditions_met`
  - `test_degraded_low_cache_hit_rate`
  - `test_degraded_no_pipe_round_trips`
  - `test_failed_state`
  - `test_history_window_exactly_5_minutes`
  - `test_pid_reuse_different_start_time`
  - `test_evict_disconnected`
</action>

- Add `pub static CONNECTED_PIPES: OnceLock<Arc<DashMap<u32, PipeHandle>>> = OnceLock::new();`
- Add `fn init_connected_pipes()` that initializes the DashMap via `OnceLock::get_or_init`

- On pipe connection (when a hook DLL connects to the agent):
  - Insert into `CONNECTED_PIPES`: `pid -> PipeHandle { pid, pipe, last_seen: Instant::now() }`
  - Extract PID from pipe client info (using `GetNamedPipeClientProcessId` or equivalent)

- On pipe disconnect or error:
  - Remove the PID from `CONNECTED_PIPES`
  - Call `DiagnosticAggregator::evict_disconnected(pid)`

- Add `fn poll_all_diagnostics() -> Vec<DiagnosticSnapshot>` that:
  1. Iterates over `CONNECTED_PIPES`
  2. For each entry, sends `IpcPayloadV2::V2(IpcPayloadV2Inner::PullDiagnostics { request_id })` over the pipe
  3. Waits up to 500ms for `DiagnosticsResponse`
  4. If response received, calls `diagnostic_aggregator.ingest_snapshot(response.snapshot)`
  5. Updates `last_seen` for the pipe handle
  6. Returns all collected snapshots

- Add `fn poll_all_health() -> Vec<(u32, HealthStatus)>` with same pattern but using `PullHealth` / `HealthResponse`

- Spawn a background tokio task in `main.rs` that calls `poll_all_diagnostics()` every 60 seconds and `poll_all_health()` every 60 seconds (staggered by 30s).

- Add unit tests (using mock pipes):
  - `test_connected_pipes_registry_insert_remove`
  - `test_poll_diagnostics_sends_pull_message`
