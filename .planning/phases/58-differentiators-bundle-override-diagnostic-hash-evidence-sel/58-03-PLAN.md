<objective>
Build the agent-side aggregation and polling infrastructure for DIFF-02 (diagnostics) and DIFF-04 (self-health). The agent polls hook DLLs via named pipe, aggregates data in-memory, and emits alerts on health degradation.

Purpose: The hook DLL captures data but cannot serve it to the admin TUI directly. The agent bridges hook DLL in-memory data to the admin API.
Output: Two new aggregator modules, modified interception handler, and health alert emission.
</objective>

    1. Use std::collections::VecDeque for 12-snapshot history per host.
    2. Use std::sync::{Arc, Mutex} for shared state.
    3. Define HealthStatus enum: Healthy, Degraded, Critical (maps to D-21 thresholds)
    4. Define HealthAggregator struct:
       - history: Arc<Mutex<VecDeque<HookHealthSnapshot>>> with max_len = 12
       - last_status: Arc<Mutex<HealthStatus>>
       - consecutive_degraded: Arc<Mutex<u32>> (counts consecutive Degraded polls)
    5. Implement HealthAggregator::new() -> Self
    6. Implement pub fn ingest_snapshot(&self, snapshot: HookHealthSnapshot):
       - Push to back of VecDeque
       - If len > 12, pop_front
       - Compute new status from snapshot:
         - Healthy: cache_hit_rate_60s >= 0.80 AND current_fail_state == 0 (Healthy) AND pipe_round_trips_60s > 0
         - Degraded: cache_hit_rate_60s < 0.80 OR current_fail_state == 1 (Degraded)
         - Critical: current_fail_state == 2 (Isolated) OR pipe_round_trips_60s == 0
       - Compare with last_status
       - If new_status == Degraded AND last_status was Healthy:
         - Increment consecutive_degraded
         - If consecutive_degraded >= 2, emit audit event at warn severity (D-22)
       - If new_status == Critical:
         - Emit audit event at crit severity AND route through alert_router (D-22)
         - Reset consecutive_degraded to 0
       - If new_status == Healthy:
         - Reset consecutive_degraded to 0
       - Update last_status
    7. Implement pub fn get_current_status(&self) -> Option<(HealthStatus, HookHealthSnapshot)>:
       - Return last_status + most recent snapshot from history (if any)
    8. Implement pub fn get_history(&self) -> Vec<HookHealthSnapshot>:
       - Return Vec copy of VecDeque contents
    9. Implement fn emit_health_audit_event(&self, severity: &str, snapshot: &HookHealthSnapshot, old_status: HealthStatus, new_status: HealthStatus):
       - Create AuditEvent with EventType::Alert (or a new EventType if needed — use EventType::Alert for simplicity)
       - Set severity via policy_mode or a custom field
       - Include snapshot fields in the event
       - Call alert_router::send if severity is "crit"
       - Always route to SIEM via routed_to_siem()
    10. Add module declaration to dlp-agent/src/lib.rs: pub mod health_aggregator;

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent -> Hook DLL pipe | Agent polls read-only data; hook DLL cannot be commanded by agent |
| Agent -> Server API | Trusted internal network; JWT authenticated |
| Agent -> Alert router | Trusted; alert_router is local to agent process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58-08 | Information Disclosure | Diagnostic aggregator | mitigate | In-memory only; no persistence; filtered by admin API |
| T-58-09 | Denial of Service | Health alert flooding | mitigate | 60-second poll interval limits alert rate; consecutive_degraded threshold (2 polls = 2 min) prevents flapping |
| T-58-10 | Spoofing | Fake health snapshots from rogue DLL | accept | DLL runs in same trust boundary as process; rogue DLL implies process compromise |
