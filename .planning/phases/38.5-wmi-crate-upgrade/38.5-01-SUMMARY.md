# Phase 38.5 Plan 01: WMI Crate Upgrade Summary

**One-liner:** Upgraded wmi 0.14 to 0.18+ in dlp-agent, eliminating 115 lines of raw CoSetProxyBlanket FFI and windows-core 0.59 direct dependency while preserving all 20 encryption tests and zero behavior change.

---

## What Was Built

### Task 1: Update Cargo.toml dependencies
- Bumped `wmi` from `0.14` to `0.18` (resolved to `0.18.4`)
- Removed `windows-core = "0.59"` direct dependency
- Removed `"Win32_System_Com"` from the `windows` crate features list
- Verified dependency resolution: `windows = "0.62"` is compatible with wmi 0.18's `windows = ">=0.59, <0.63"` range

### Task 2: Rewrite open_bitlocker_connection and remove raw FFI
- Removed `upgrade_to_pkt_privacy` unsafe function (~55 lines) including:
  - `#[link(name = "ole32")]` extern block with `CoSetProxyBlanket` raw FFI
  - All Win32 ABI constants (RPC_C_AUTHN_WINNT, RPC_C_AUTHZ_NONE, etc.)
- Rewrote `open_bitlocker_connection` to use wmi 0.18 native API:
  - `WMIConnection::with_namespace_path(&str)` — no COMLibrary parameter
  - `conn.set_proxy_blanket(wmi::AuthLevel::PktPrivacy)` — typed, safe call
- Updated `classify_wmi_connection_error` for wmi 0.18 error shape:
  - Primary match on `WMIError::HResultError { hres }` with `WBEM_E_INVALID_NAMESPACE = -2147217402`
  - Preserved fallback string heuristic for robustness
- Updated `ComInitFailed` doc comment to reflect wmi 0.18 auto-COM-init behavior
- Preserved `EncryptableVolume` serde DTO unchanged — compatible with wmi 0.18

### Task 3: Run tests and verify no behavior change
- `cargo test -p dlp-agent --lib detection::encryption`: **12 passed**
- `cargo test -p dlp-agent --test encryption_integration`: **8 passed**
- `cargo clippy -p dlp-agent -- -D warnings`: **0 issues**
- `cargo fmt --check -p dlp-agent`: encryption.rs clean (unrelated files have pre-existing diffs)
