Extend the existing Phase 50 background thread to also verify ntdll trampoline integrity every 30 seconds. Detect when EDR overwrites our trampolines, emit HookOverwritten alerts, and mark stubs as permanently skipped.

Purpose: EDR may load after our patcher runs and overwrite our trampolines. Without re-verification, we would silently lose direct-syscall coverage. This plan adds the detection and alerting layer per D-11, D-12, D-13.
Output: Extended background_thread.rs with trampoline verification, ntdll_patcher.rs additions for integrity checking.

    1. Add `verify_stub_integrity(fn_name: &str) -> StubIntegrity` method to `NtdllPatcher`:
       ```rust
       pub enum StubIntegrity {
           Clean,           // First 5 bytes match our JMP pattern
           Overwritten,     // Bytes don't match — EDR or other hook
           NotPatched,      // Stub was never patched (Unpatched, SkippedEdr, SkippedRaced state)
           Unknown,         // Could not read stub bytes
       }
       ```

    2. Implementation of `verify_stub_integrity`:
       - Look up stub state by name.
       - If state is not `Patched`, return `StubIntegrity::NotPatched`.
       - Read first 5 bytes from `stub_addr` atomically (x64: read 8 bytes as u64; x86: read 8 bytes).
       - Compare against `original_ntdll_bytes` from the `HookDescriptor` — NO, per D-12 compare against the EXPECTED JMP pattern (the 5 bytes we wrote), not the original bytes.
       - Actually per D-12: "verify they match our JMP pattern (not original syscall prologue, not EDR JMP)". So compare the first 5 bytes against the JMP rel32 bytes that retour wrote.
       - To get the expected JMP bytes: when we created the RawDetour, retour computed the JMP target. We can reconstruct the expected bytes by reading the detour's internal state, OR we can simply verify the first byte is 0xE9 AND the target matches our trampoline. Simpler approach: verify first byte is 0xE9 and the rel32 offset points into our trampoline's address range.
       - Even simpler per RESEARCH.md Pattern 2: read first 5 bytes, verify first byte is 0xE9. If not 0xE9, it's been overwritten. This is sufficient because:
         - Original ntdll stub starts with `mov r10, rcx` = 0x4C 0x8B 0xD1 (not 0xE9)
         - EDR JMP also starts with 0xE9 but targets EDR code, not our trampoline
         - To distinguish EDR JMP from our JMP: calculate target from rel32 and check if it falls within our trampoline function's address range. If not, it's EDR.
       - Recommended approach (balance of safety and simplicity):
         a. Read first byte. If not 0xE9, return `Overwritten`.
         b. Read rel32, calculate target. If target is within our trampoline function range, return `Clean`. Otherwise return `Overwritten` (EDR replaced our JMP with theirs).

    3. Add `mark_stub_overwritten(fn_name: &str)` method:
       - Set stub state to `StubPatchState::Overwritten`.
       - Log via `debug_log`.
       - Emit `BypassAlert { reason: BypassReason::HookOverwritten, stub_name: fn_name.to_string(), pid: std::process::id(), timestamp_secs: ... }`.

    4. Add `verify_all_stubs() -> Vec<(&str, StubIntegrity)>` method:
       - Iterate all 4 stubs.
       - Call `verify_stub_integrity` for each.
       - Return results as vector.

    5. Per D-07: On `HookOverwritten` detection, emit alert and mark stub as "EDR-controlled, skip permanently." Do NOT re-patch. The `mark_stub_overwritten` method sets state to `Overwritten` which is treated as permanently skipped.

    6. Per D-13: Per-stub granularity — `verify_all_stubs` checks each stub independently. One stub can be clean while another is overwritten.

    7. Add `#[cfg(test)]` tests:
       - `verify_stub_integrity_not_patched` — Unpatched stub returns NotPatched
       - `verify_stub_integrity_overwritten_byte` — stub with first byte != 0xE9 returns Overwritten
       - `verify_stub_mark_overwritten` — verify mark_stub_overwritten sets state and emits alert

    Note: Testing the "Clean" case requires an actual patched stub, which cannot be done in unit tests without real ntdll. The chaos test (Plan 06) covers the full integration.
