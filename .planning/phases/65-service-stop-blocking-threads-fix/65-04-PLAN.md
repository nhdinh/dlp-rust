Current initiate_stop() spawns a thread with the body directly:
```rust
std::thread::spawn(move || {
    debug_log("=== initiate_stop START ===");
    // ... spawn UI, poll file, verify password ...
});
```

If any operation panics (e.g., bcrypt::verify on malformed hash), the thread dies
and STOP_CONFIRMED is never set. The 120s timeout would normally call abort_stop(),
but if the panic happens in the same thread, the timeout never fires either.

CRITICAL REVIEW FIX — Two-phase lifecycle (Codex HIGH concern):
The original plan called request_shutdown() immediately in the Stop control handler.
This is WRONG because:
1. Password verification has not succeeded yet
2. If the stop is cancelled or fails, the service must return to Running
3. Global shutdown may already have torn down IPC, health, Chrome, and session threads
4. The verification thread may exit/abort before the user can complete password verification

The correct lifecycle:
```
SCM Stop received
  -> Set SERVICE_STATE = StopPending
  -> initiate_stop() (spawns password verification thread)
  -> Password verified -> STOP_CONFIRMED = true
  -> run_loop sees STOP_CONFIRMED -> exits
  -> run_service continues to shutdown sequence
  -> request_shutdown() called ONLY after password verified
  -> threads.shutdown_and_join() called
  -> STOPPED reported
```

The Stop control handler must NOT call request_shutdown(). The shutdown signal
is only set after password verification succeeds and run_loop has exited.

AssertUnwindSafe safety justification:
The closure captures:
- request_id: String (Send, UnwindSafe — immutable after capture)
- response_path: String (Send, UnwindSafe — immutable after capture)
- STOP_STATE: Mutex<StopState> (not held across panic point)
- STOP_CONFIRMED: AtomicBool (not held across panic point)
- AUTH_HASH: Mutex<Option<String>> (not held across panic point)

The closure does NOT capture any MutexGuard, RwLockReadGuard, or other RAII guard.
All shared state is accessed via short-lived lock acquisitions. If a panic occurs,
the lock is poisoned (for std::sync::Mutex) or released (for parking_lot::Mutex).
Since we use parking_lot::Mutex (which does not poison), the state remains consistent.

The only operations inside catch_unwind that could panic are:
- get_auth_hash() -> may panic on malformed data (the bug we're fixing)
- bcrypt::verify() -> may panic on malformed hash string
- std::fs operations -> unlikely to panic, return Result

After catch_unwind returns Err, we call abort_stop() which resets all state.
This is safe because abort_stop() acquires its own locks and resets state atomically.

PowerShell improvements (both reviewers flagged as under-specified):
- Detect StopPending before calling Stop-Service
- After Stop-Service, poll every 1 second for up to 30 seconds
- Report final state: Stopped, Running (reverted), or StopPending (stuck)
- Provide escalation guidance: psexec -s taskkill /F /IM dlp-agent.exe, or reboot
- Distinguish timeout, access denied, missing service, wrong password/cancel, already stopped

        if state.pending {

        state.attempts = 0;

        *AUTH_HASH.lock() = None;

        set_pending_request(&request_id);

        let response_path = format!(
            r"C:\ProgramData\DLP\logs\stop-response-{}.json",
            request_id
        );
        let _ = std::fs::create_dir_all(r"C:\ProgramData\DLP\logs");
        let _ = std::fs::remove_file(&response_path);

        std::thread::spawn(move || {
            // SAFETY: AssertUnwindSafe is correct here because:
            // 1. The closure captures only String values (request_id, response_path)
            //    which are Send + UnwindSafe and immutable after capture.
            // 2. No MutexGuard, RwLockReadGuard, or other RAII guard is held across

                    abort_stop();
                }
            }

            // Clean up response file if it still exists
            let _ = std::fs::remove_file(&response_path);
        });
    }

    function Stop-DlpAgentService {
        $svc = Get-CurrentService
        if (-not $svc) {
            Write-Status "Service '$ServiceName' is not installed." -Level INFO
            return
        }

        # State pre-checks
        if ($svc.Status -eq 'StopPending') {
            Write-Status "Service is already stopping (StopPending)." -Level WARN
            Write-Status "The dlp-admin may be entering the password. Wait or cancel from the UI." -Level INFO
            Write-Status "If stuck for >2 minutes, escalation options:" -Level INFO
            Write-Status "  1. Restart the machine (guaranteed)" -Level INFO
            Write-Status "  2. From SYSTEM context: psexec -s taskkill /F /IM dlp-agent.exe" -Level INFO
            Write-Status "  3. Then re-register: sc.exe delete $ServiceName; .\Manage-DlpAgentService.ps1 -Action Install" -Level INFO
            return
        }

        if ($svc.Status -eq 'Stopped') {
            Write-Status "Service is already stopped." -Level OK
            return
        }

        Write-Status "Stopping service '$ServiceName' (password challenge may add delay)..." -Level INFO
        Write-Status "The dlp-admin must confirm the stop in the UI dialog (up to 3 attempts, 30 s each)." -Level INFO

        try {
            Stop-Service -Name $ServiceName -Force -ErrorAction Stop
            Write-Status "Stop command sent. Waiting for service to stop..." -Level INFO
        }
        catch {
            Write-Status "Failed to send stop command: $_" -Level FAIL
            return
        }

        # Poll every 1 second for up to 30 seconds
        $maxWaitSeconds = 30
        $pollIntervalSeconds = 1
        $elapsed = 0
        $finalState = $null

        while ($elapsed -lt $maxWaitSeconds) {
            Start-Sleep -Seconds $pollIntervalSeconds
            $elapsed += $pollIntervalSeconds

            $svc = Get-CurrentService
            if (-not $svc) {
                $finalState = 'Removed'
                break
            }

            if ($svc.Status -eq 'Stopped') {
                $finalState = 'Stopped'
                break
            }

            if ($svc.Status -eq 'Running') {
                # Service returned to Running — stop was cancelled or failed
                $finalState = 'Running'
                break
            }

            # Still StopPending — continue polling
        }

        # Report final state
        switch ($finalState) {
            'Stopped' {
                Write-Status "Service stopped successfully (${elapsed}s)." -Level OK
            }
            'Running' {
                Write-Status "Service returned to Running — stop was cancelled or password failed." -Level WARN
            }
            'Removed' {
                Write-Status "Service was removed during stop." -Level WARN
            }
            default {
                # Timeout — still StopPending or unknown state
                $svc = Get-CurrentService
                if ($svc) {
                    Write-Status "Service did not stop within ${maxWaitSeconds}s — current state: $($svc.Status)" -Level FAIL
                } else {
                    Write-Status "Service did not stop within ${maxWaitSeconds}s — service no longer found." -Level FAIL
                }
                Write-Status "The service may be stuck in StopPending. Escalation options:" -Level INFO
                Write-Status "  1. Restart the machine (guaranteed recovery)" -Level INFO
                Write-Status "  2. From SYSTEM context: psexec -s taskkill /F /IM dlp-agent.exe" -Level INFO
                Write-Status "  3. Then re-register: sc.exe delete $ServiceName; .\Manage-DlpAgentService.ps1 -Action Install" -Level INFO
            }
        }
    }
