<objective>
Add shutdown signal polling to all three IPC pipe accept loops. Each pipe server checks `crate::service::shutdown_requested()` between client connections. If shutdown is requested, the server closes its current pipe handle and exits cleanly. This allows the worker thread to terminate so run_service can join it.
</objective>

Current accept_loop pattern in all three pipes:
```rust
fn accept_loop(first_pipe: HANDLE) -> Result<()> {
    let mut pipe = first_pipe;
    loop {
        if let Err(e) = unsafe { ConnectNamedPipe(pipe, None) } {
            // ... error handling, recreate pipe on non-535 ...
        }
        handle_client(pipe);
        pipe = create_pipe()?;
    }
}
```

The problem: `ConnectNamedPipe` blocks until a client connects. If no client ever connects (or the client is already connected and we're in ReadFile), the thread blocks forever.

The fix: Check shutdown_requested() BEFORE each ConnectNamedPipe call. If shutdown is requested, close the pipe and return Ok(()) to exit the thread.

```rust
fn accept_loop(first_pipe: HANDLE) -> Result<()> {
    let mut pipe = first_pipe;
    loop {
        if crate::service::shutdown_requested() {
            let _ = unsafe { CloseHandle(pipe) };
            info!(pipe = PIPE_NAME, "shutdown requested — exiting accept loop");
            return Ok(());
        }
        // ... ConnectNamedPipe ...
    }
}
```

Note: We do NOT check shutdown_requested() DURING handle_client. An in-flight request should complete. The check is only between connections.
</context>
