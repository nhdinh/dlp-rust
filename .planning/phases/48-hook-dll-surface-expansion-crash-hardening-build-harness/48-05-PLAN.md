  <action>
    Create `.github/workflows/release.yml` with the following structure (per D-17, D-18, D-19, D-20, D-21):

    ```yaml
    name: Release

    on:
      push:
        tags:
          - 'v*'

    jobs:
      build-and-sign:
        name: Build and Sign
        runs-on: windows-latest
        steps:
          - name: Checkout
            uses: actions/checkout@v4

          - name: Install Rust toolchain
            uses: dtolnay/rust-toolchain@stable
            with:
              targets: i686-pc-windows-msvc

          - name: Cache cargo registry
            uses: actions/cache@v4
            with:
              path: |
                ~/.cargo/registry
                ~/.cargo/git
                target
              key: ${{ runner.os }}-cargo-${{ hashFiles('**/Cargo.lock') }}

          - name: Build workspace (release)
            run: cargo build --workspace --release
            env:
              RUSTFLAGS: "-D warnings"

          - name: Build x64 hook DLL (release)
            run: cargo build --release -p dlp-hook-dll --target x86_64-pc-windows-msvc
            env:
              RUSTFLAGS: "-D warnings"

          - name: Build x86 hook DLL (release)
            run: cargo build --release -p dlp-hook-dll --target i686-pc-windows-msvc
            env:
              RUSTFLAGS: "-D warnings"

          - name: Decode signing certificate
            run: |
              $pfxBytes = [Convert]::FromBase64String('${{ secrets.AUTHENTICODE_PFX }}')
              [IO.File]::WriteAllBytes('${{ runner.temp }}\cert.pfx', $pfxBytes)
            shell: pwsh

          - name: Sign binaries (DigiCert primary)
            id: sign_primary
            continue-on-error: true
            run: |
              $binaries = @(
                'target\release\dlp-agent.exe',
                'target\release\dlp-user-ui.exe',
                'target\release\dlp-admin-cli.exe',
                'target\release\dlp-server.exe',
                'target\x86_64-pc-windows-msvc\release\dlp_hook_dll.dll',
                'target\i686-pc-windows-msvc\release\dlp_hook_dll.dll'
              )
              foreach ($bin in $binaries) {
                if (Test-Path $bin) {
                  signtool sign /f '${{ runner.temp }}\cert.pfx' /p '${{ secrets.AUTHENTICODE_PASSWORD }}' `
                    /tr http://timestamp.digicert.com /td sha256 /fd sha256 `
                    "$bin"
                  if ($LASTEXITCODE -ne 0) { exit 1 }
                } else {
                  Write-Host "Warning: $bin not found"
                }
              }
            shell: pwsh

          - name: Sign binaries (Sectigo fallback)
            if: steps.sign_primary.outcome == 'failure'
            run: |
              $binaries = @(
                'target\release\dlp-agent.exe',
                'target\release\dlp-user-ui.exe',
                'target\release\dlp-admin-cli.exe',
                'target\release\dlp-server.exe',
                'target\x86_64-pc-windows-msvc\release\dlp_hook_dll.dll',
                'target\i686-pc-windows-msvc\release\dlp_hook_dll.dll'
              )
              foreach ($bin in $binaries) {
                if (Test-Path $bin) {
                  signtool sign /f '${{ runner.temp }}\cert.pfx' /p '${{ secrets.AUTHENTICODE_PASSWORD }}' `
                    /tr http://timestamp.sectigo.com /td sha256 /fd sha256 `
                    "$bin"
                  if ($LASTEXITCODE -ne 0) { exit 1 }
                }
              }
            shell: pwsh

          - name: Verify signatures
            run: |
              $binaries = @(
                'target\release\dlp-agent.exe',
                'target\release\dlp-user-ui.exe',
                'target\release\dlp-admin-cli.exe',
                'target\release\dlp-server.exe',
                'target\x86_64-pc-windows-msvc\release\dlp_hook_dll.dll',
                'target\i686-pc-windows-msvc\release\dlp_hook_dll.dll'
              )
              foreach ($bin in $binaries) {
                if (Test-Path $bin) {
                  signtool verify /pa "$bin"
                  if ($LASTEXITCODE -ne 0) { exit 1 }
                }
              }
            shell: pwsh

          - name: Upload signed artifacts
            uses: actions/upload-artifact@v4
            with:
              name: signed-binaries-${{ github.ref_name }}
              path: |
                target/release/dlp-agent.exe
                target/release/dlp-user-ui.exe
                target/release/dlp-admin-cli.exe
                target/release/dlp-server.exe
                target/x86_64-pc-windows-msvc/release/dlp_hook_dll.dll
                target/i686-pc-windows-msvc/release/dlp_hook_dll.dll
    ```

    IMPORTANT notes:
    1. The x86 DLL output name from the Rust compiler will be `dlp_hook_dll.dll` (not `dlp_hook_dll_x86.dll`). The rename/copy to `dlp_hook_dll_x86.dll` happens in the installer or a post-build step. For the signing step, sign the file at its build location.
    2. Per D-19, dlp-e2e binaries are NOT listed in the signing step (the requirement says "dlp-e2e binaries are also signed" but these are test harnesses, not shipped binaries). If the user wants them signed, they can be added. For now, sign only the 6 shipped binaries listed in D-21.
    3. The `continue-on-error: true` on the primary sign step allows the fallback to run. The verify step will catch any actual failure.
    4. The workflow triggers ONLY on tags matching `v*` (per D-17).
    5. Add a comment at the top of the file explaining the secrets requirement:
       ```yaml
       # Release workflow — Authenticode signing
       #
       # Prerequisites:
       #   - AUTHENTICODE_PFX: Base64-encoded PFX file (repository secret)
       #   - AUTHENTICODE_PASSWORD: PFX password (repository secret)
       #
       # Trigger: push of a tag matching 'v*' (e.g., v0.10.0)
       ```
  </action>

| Boundary | Description |
|----------|-------------|
| CI runner -> GitHub secrets | PFX and password are exposed to the workflow; secrets must be repository-scoped. |
| Signed binary -> End user | Unsigned or incorrectly signed DLL triggers AV/EDR false positive. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-14 | Repudiation | release.yml | mitigate | `signtool verify /pa` blocking gate ensures every shipped binary has a valid Authenticode signature with timestamp |
| T-48-15 | Denial of Service | release.yml | mitigate | DigiCert primary + Sectigo fallback timestamp servers; if both fail, the release build fails rather than shipping unsigned binaries |
| T-48-16 | Information Disclosure | release.yml | mitigate | PFX password is read from GitHub secrets (`secrets.AUTHENTICODE_PASSWORD`); never logged or committed |
</threat_model>
