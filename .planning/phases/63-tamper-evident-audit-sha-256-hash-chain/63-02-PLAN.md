    3. Modify `AuditEmitter::emit()` to compute and attach the chain hash BEFORE serializing to JSON, and update `last_chain_hash` only after successful write AND flush:
       ```rust
       pub fn emit(&self, event: &mut AuditEvent) -> Result<(), AuditError> {
           // Phase 63: compute chain hash before serialization
           let last_hash = self.last_chain_hash.lock().clone();
           let chain_hash = dlp_common::audit::compute_chain_hash(&last_hash, event)
               .map_err(AuditError::SerializationFailed)?;
           event.prev_hash = Some(last_hash);
           event.chain_hash = Some(chain_hash.clone());

           let json = serde_json::to_string(event)?;
           // ... existing write logic ...
           // After write + flush succeeds:
           *self.last_chain_hash.lock() = chain_hash;
           Ok(())
       }
       ```
       **Concurrency note:** `std::sync::Mutex<String>` serializes all emit operations through the mutex lock. This is acceptable because `emit()` is synchronous and the critical section (hash compute + write + flush + hash update) is brief. If the agent becomes a high-throughput bottleneck, consider an async channel-based queue. Document this in code comments.

    4. Update the free-function `emit(event: &AuditEvent)` signature to accept `&mut AuditEvent`. This is a **breaking API change**.
       ```rust
       pub fn emit(event: &mut AuditEvent) -> Result<(), AuditError> {
           EMITTER.emit(event)
       }
       ```
       **Blast radius:** Search all call sites in `dlp-agent/src/` for `emit(` and `EMITTER.emit`. Update each to pass a mutable reference. The main callers are:
       - `emit_audit()` (already takes `&mut AuditEvent` — no change needed)
       - Any direct `emit(event)` calls in enforcement modules — change to `emit(&mut event)`
       Document the migration path in the plan summary.

    5. Update `emit_audit()` to call `EMITTER.emit(event)` directly after the identity enrichment step (it already takes `&mut AuditEvent`).

    Do NOT change the JSONL format beyond adding the two optional fields (serde will include them now that they are Some).

    1. Add a helper function (module-level, not a method) to read the last valid event from a JSONL file with backward-scan fallback for truncated lines:
       ```rust
       /// Reads the last valid line of `path` and attempts to parse it as an AuditEvent.
       /// Scans backward up to `MAX_RECOVERY_LINES` (10) to handle a partially-written final line.
       /// Returns the event's `chain_hash` if present, otherwise None.
       const MAX_RECOVERY_LINES: usize = 10;

       fn recover_last_hash_from_log(path: &Path) -> Option<String> {
           use std::io::{BufRead, BufReader};
           let file = std::fs::File::open(path).ok()?;
           let reader = BufReader::new(file);
           let mut candidates: Vec<String> = reader
               .lines()
               .filter_map(|line| line.ok())
               .collect();
           // Scan backward from the end for the first valid JSON line with a chain_hash
           candidates
               .iter()
               .rev()
               .take(MAX_RECOVERY_LINES)
               .filter_map(|line| serde_json::from_str::<dlp_common::AuditEvent>(line).ok())
               .filter_map(|event| event.chain_hash)
               .next()
       }
       ```

    2. Modify `AuditEmitter::open()` to attempt recovery after opening the file, with explicit logging on fallback:
       ```rust
       let last_chain_hash = if log_path.exists() {
           match recover_last_hash_from_log(&log_path) {
               Some(hash) => hash,
               None => {
                   tracing::error!(log_path = %log_path.display(), "failed to recover chain hash from JSONL; falling back to genesis. This may indicate log corruption or an empty file.");
                   dlp_common::audit::genesis_hash()
               }
           }
       } else {
           dlp_common::audit::genesis_hash()
       };
       Ok(Self {
           writer: Mutex::new(BufWriter::new(file)),
           log_path,
           max_bytes,
           events_since_check: Mutex::new(0),
           last_chain_hash: Mutex::new(last_chain_hash),
       })
       ```
       **Recovery semantics:** If recovery fails (corrupted JSONL, no valid lines in last 10), the emitter falls back to genesis and logs a critical error. This chooses availability over security (the chain continues rather than halting), which is appropriate for an endpoint agent where stopping audit logging is worse than a potential chain reset. Document this trade-off in a code comment.

    3. Consider a more efficient tail-read implementation if the JSONL file is large. If the file size is > 1 MiB, seek to near-end and read the last complete line instead of streaming all lines. The simple backward-scan implementation is acceptable for the initial implementation; document that optimization is deferred.
