<objective>
Persist the SHA-256 hash chain in the server database. This plan adds `prev_hash` and `chain_hash` columns to the `audit_events` table, provides an idempotent migration path for existing installations, creates an index for efficient per-agent chain lookup, and extends the repository to read/write the new fields. It also introduces the query primitives (`get_last_chain_hash`, `get_chain_breaks`) required by Plans 03 and 04.

**Prerequisite state:** dlp-common types are already extended — `AuditEvent` has `prev_hash`/`chain_hash`, `EventType::ChainBreakDetected` exists, and `genesis_hash()`/`compute_chain_hash()` helpers are available. This plan focuses on the server-side persistence layer only.
</objective>

    **Ordering guarantee note:** Chain ordering is determined by `id` (SQLite INTEGER PRIMARY KEY auto-increment). This guarantees monotonic insertion order per server instance. Concurrent agents each have independent chains; per-agent ordering is preserved because each agent's events are inserted sequentially by that agent's connection. If future designs introduce batch ingestion from the same agent across multiple connections, a dedicated `sequence` column must be added.

       - Use `conn.query_row` and return `Ok(row.get(0)?)` — `Option<String>` is returned naturally when no row matches.
       - The `idx_audit_events_agent_latest` index (agent_id, id DESC) makes this efficient.

    2. `get_chain_breaks(pool: &Pool, since_id: Option<i64>, limit: usize) -> rusqlite::Result<Vec<serde_json::Value>>`
       - Return rows where the chain continuity is broken, time-bounded and paginated to avoid full-table scans.
       - Use a window-function query (SQLite 3.25+) for correct "previous row" semantics:
         ```sql
         SELECT id, agent_id, prev_hash, chain_hash,
                LAG(chain_hash) OVER (PARTITION BY agent_id ORDER BY id) AS expected_prev
         FROM audit_events
         WHERE chain_hash IS NOT NULL
           AND (?1 IS NULL OR id > ?1)
         ORDER BY id
         LIMIT ?2
         ```
       - Filter rows where `prev_hash != expected_prev` (and `expected_prev IS NOT NULL`) in Rust.
       - Return JSON objects via `serde_json::json!` for each row.
       - If the SQLite version does not support window functions, fall back to the self-join with a `MAX(id)` subquery, but document the performance limitation.

    Add a lightweight validation helper:
    - `is_valid_hash_format(hash: &str) -> bool` — returns true if the string is exactly 64 hex characters.
