<objective>
Persist the SHA-256 hash chain in the server database. This plan adds `prev_hash` and `chain_hash` columns to the `audit_events` table, provides an idempotent migration path for existing installations, creates an index for efficient per-agent chain lookup, and extends the repository to read/write the new fields. It also introduces the query primitives (`get_last_chain_hash`, `get_chain_breaks`) required by Plans 03 and 04.

**Prerequisite state:** dlp-common types are already extended — `AuditEvent` has `prev_hash`/`chain_hash`, `EventType::ChainBreakDetected` exists, and `genesis_hash()`/`compute_chain_hash()` helpers are available. This plan focuses on the server-side persistence layer only.
</objective>

    2. `get_chain_breaks(pool: &Pool) -> rusqlite::Result<Vec<serde_json::Value>>`
       - Return rows where the chain continuity is broken. For the initial implementation, return events where `chain_hash IS NOT NULL` and `prev_hash IS NOT NULL` but the `prev_hash` does not equal the previous event's `chain_hash` for the same agent.
       - A self-join query is acceptable:
         ```sql
         SELECT a.id, a.agent_id, a.prev_hash, a.chain_hash, b.chain_hash AS expected_prev
         FROM audit_events a
         LEFT JOIN audit_events b
           ON b.agent_id = a.agent_id
           AND b.id = (
             SELECT MAX(id) FROM audit_events c
             WHERE c.agent_id = a.agent_id AND c.id < a.id AND c.chain_hash IS NOT NULL
           )
         WHERE a.chain_hash IS NOT NULL
           AND a.prev_hash IS NOT NULL
           AND b.chain_hash IS NOT NULL
           AND a.prev_hash != b.chain_hash
         ```
       - Return JSON objects via `serde_json::json!` for each row.
