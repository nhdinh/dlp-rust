## Implementation Notes / Deviations Observed

1. **Unhook wait budget value changed.** Plan 58.5-03 declared
   `UNHOOK_WAIT_BUDGET` as 5 s within a 10 s `SHUTDOWN_TIMEOUT`. The implemented
   code uses `UNHOOK_WAIT_BUDGET = 30 s` and raised `SHUTDOWN_TIMEOUT` to 35 s
   (`dlp-agent/src/service.rs:86/94`). The total shutdown is still bounded by the
   outer `tokio::time::timeout(SHUTDOWN_TIMEOUT, run_loop_shutdown)` at
   `service.rs:1303`, so the DoS threat (T-58.5-08) remains closed.

2. **Watchdog reconciliation uses `record_exited` instead of `record_unhooked`.**
   For matched evidence, `dlp-agent/src/service.rs:2488` calls
   `registry.record_exited(ProcessKey { ... })`. The security outcome is the same
   (the registry entry moves out of `Injected`), but it deviates from the PLAN's
   stated use of `record_unhooked`.

3. **`self_unload` fallback handle.** `dlp-hook-dll/src/lib.rs:894-898` falls
   back to `GetModuleHandleW(None)` if `DLL_INSTANCE` was not captured. The PLAN
   verification criterion stated `self_unload` must use the DllMain-captured
   HINSTANCE and never `GetModuleHandleW(None)`. This is a deviation from the
   plan's verification checklist, not a declared threat.

**Open threat:** T-58.5-04 — watchdog false-positive unhooks healthy hooks.
The control thread used a single 30 s timeout since the last successful agent
response and did not implement the declared consecutive-failure + grace-window
mitigation.

### 2026-07-01 — Remediation verified

| Metric | Count |
|--------|-------|
| Threats found | 14 |
| Closed | 14 |
| Open | 0 |

**Fix:** `dlp-hook-dll/src/control_thread.rs` was updated to track
`consecutive_failures` and `first_failure_time`. The watchdog now self-unloads
only after `MAX_FAILURES` (3) consecutive poll failures **and** the cumulative
grace window (`WATCHDOG_TIMEOUT_MS`, 30 s) has elapsed. Successful polls reset
the counter and grace timer. Unit tests `control_poll_thread_triggers_after_grace_and_failures`
and `control_poll_thread_resets_on_success` pass; `cargo clippy -p dlp-hook-dll -- -D warnings`
and `cargo fmt --check` are clean.
