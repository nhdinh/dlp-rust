# Phase 58.5 Plan 08: Close UAT Test 7 DLL unload blocker

**Hard-success control-thread injection, parallel shutdown reconciliation, and atomic `FreeLibraryAndExitThread` self-unload eliminate the causes of `dlp_hook_dll.dll` remaining loaded after the agent stops.**

## Performance

- **Duration:** continued from prior session
- **Started:** 2026-07-03
- **Completed:** 2026-07-03
- **Tasks:** 3
- **Files modified:** 3

## Accomplishments

- Made control-thread start a hard success criterion in `HookInjector`; `inject` and `inject_into_process` now return `Err` if the remote `StartDlpControlThread` thread cannot be started.
- Added `ensure_control_thread` as an idempotent, `LoadLibraryW`-free primitive used by sweeps and the shutdown reconciliation pass.
- Prevented DLL reference-count inflation by guarding sweeps and `inject` with `is_module_loaded`, recording already-loaded processes with the architecture returned by `target_architecture(pid)`.
- Added a parallel reconciliation pass in `request_unhook_from_injected` that, before arming `UNHOOK_ALL_REQUESTED`, checks every `Injected` registry entry and either starts its control thread or records it as unhooked if the module is gone.
- Kept the reconciliation pass within the unhook budget using a `tokio::sync::Semaphore(32)` and 2-second per-process timeouts.
- Replaced any remaining in-DLL `FreeLibrary` loop intent with the atomic `FreeLibraryAndExitThread` path and documented why reference-count loops from inside the DLL are unsafe.
- Added unit tests for active-call drain, captured instance accessor, reconciliation outcomes, and control-thread hard-failure paths.

## Files Created/Modified

- `dlp-agent/src/hook_injector.rs` - `is_module_loaded` instance method, hard-success `start_remote_control_thread`, `ensure_control_thread`, `HookError::ModuleBaseNotFound`, and mock seams.
- `dlp-agent/src/service.rs` - Double-load guard in `startup_sweep`/`backstop_sweep`, parallel reconciliation pass in `request_unhook_from_injected`, and reconciliation unit tests.
- `dlp-hook-dll/src/lib.rs` - `self_unload` documentation and safety comments, plus unit tests for the active-call drain guard and captured-instance accessor.

## Decisions Made

- **Fast-fail ordering in `inject`:** DLL path validation runs before `is_module_loaded` so that missing or over-long paths fail immediately, and so tests are not misrouted when a prior test leaves the DLL loaded in the test process.
- **Bounded concurrency matches sweep concurrency:** The reconciliation pass uses the same `Semaphore(32)` as `startup_sweep` and `backstop_sweep` to keep resource usage predictable and within the unhook budget.
- **Legacy elevated reference counts are out of scope:** Once the agent-side `is_module_loaded` guard is active, no new double-loads can occur. Pre-existing inflated reference counts will age out as processes restart.
