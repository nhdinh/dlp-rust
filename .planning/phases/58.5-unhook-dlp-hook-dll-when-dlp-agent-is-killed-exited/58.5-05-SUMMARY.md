## Decisions Made

- Rust `OnceLock<Mutex<NtdllPatcher>>` cannot be reset at runtime; `reset_hook_globals()` instead clears the `NTDLL_PATCHING_ENABLED` flag and unpatches any already-initialized stubs. This is safe because tests that need a fully patched state re-initialize through the normal code path.
- Kept the default parallel test runner and used the crate-wide mutex to serialize only the subset of tests that mutate shared global state, preserving overall suite throughput.
- Moved the lock out of the inline `tests` module so every module can import `crate::PHASE_58_5_TEST_LOCK` directly, avoiding module-path fragility.

## Issues Encountered

- **`OnceLock` reset limitation:** `NTDLL_PATCHER` is a `OnceLock<Mutex<NtdllPatcher>>` and therefore cannot be cleared. Resolved by disabling the patching flag and calling `unpatch_all_stubs()` when the patcher is already initialized.
- **Dead-code warnings during Task 1:** New reset helpers were flagged as unused during the first `cargo check -p dlp-hook-dll --tests`. This resolved naturally once Task 2 called the helpers.
- **`perf_telemetry.rs` edit precision:** An initial broad `Edit` replacement failed to match; resolved by using a smaller, unique anchor around the public counter accessors.
