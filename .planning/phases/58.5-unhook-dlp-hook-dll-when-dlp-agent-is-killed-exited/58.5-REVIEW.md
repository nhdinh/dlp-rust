# Phase 58.5: Code Review Report

**Reviewed:** 2026-07-01T06:00:00Z
**Depth:** standard
**Files Reviewed:** 21
**Status:** issues_found

## Summary

This is a post-fix re-review of Phase 58.5. The two critical issues from the previous review have been resolved: the hook DLL now sends the raw `FILETIME` value for `creation_time` (matching the agent registry key), and the agent validates the named-pipe client PID before acting on an `UnhookAck`. The shutdown ordering, unhook wait budget, error sanitization, and watchdog timer fixes are also in place and covered by tests.

A standard-depth adversarial pass still found **five warnings** and **three info-level items**. The warnings cover audit-evidence loss on PID reuse, a residual use-after-free risk during forced self-unload, a bypass-correlator memory/handle leak for exited/unhooked processes, silent deletion of stale watchdog evidence, and a misleading resource identifier in the `AgentShutdownUnhook` audit event. No new critical issues were identified.

## Warnings

### WR-01: Watchdog evidence file overwritten when PID is reused before reconciliation

**File:** `dlp-hook-dll/src/control_thread.rs:371`
**Issue:** `persist_watchdog_evidence` writes evidence to `{pid}.evidence.json` using only the PID as the filename. If Windows reuses that PID and the newly created process also self-unloads before the agent reconciles the directory, `File::create` truncates and overwrites the original evidence file. This silently destroys audit evidence for the earlier self-unload, violating the project's "Explicit Auditability" principle.

**Fix:** Include the process creation time (or a UUID) in the filename so each self-unload produces a unique file. Update reconciliation to match and remove files by `(pid, creation_time)` rather than by PID alone.

```rust
let path = dir.join(format!("{}_{}.evidence.json", pid, creation_time));
```

### WR-02: `self_unload` may free the DLL image while active calls remain

**File:** `dlp-hook-dll/src/lib.rs:869-898`
**Issue:** `self_unload` performs a bounded 5-second final drain of `ACTIVE_CALLS`, but if the drain times out it logs a warning and calls `FreeLibraryAndExitThread` anyway. Threads that entered a hooked API just before `SHUTTING_DOWN` was raised can still be executing trampoline code inside the DLL image. Freeing the image while those threads are mid-call is a use-after-free risk that can crash the host process.

**Fix:** Do not unload if active calls remain. Instead, remain loaded (which keeps the hooks in place) and continue trying to drain, or escalate to a non-destructive failure path. If unrecoverable, terminate the host process cleanly rather than leaving it with a dangling library mapping.

```rust
if ACTIVE_CALLS.load(Ordering::SeqCst) > 0 {
    // Do not free the image. Log critically and stay loaded.
    debug_log("[dlp-hook] self_unload: active calls remain -- aborting unload\0");
    return;
}
```

### WR-03: Bypass correlator leaks `JournalReader` entries for unhooked/exited processes

**File:** `dlp-agent/src/bypass_correlator.rs:326` and `dlp-agent/src/process_registry.rs:278-285`
**Issue:** `BypassCorrelator` stores an open shared-memory `JournalReader` for each PID in a `DashMap<u32, JournalReader>`. Entries are only evicted on PID reuse detection. When a process transitions to `Exited` after cooperative unhook or normal exit, no cleanup hook removes its reader. Over long agent uptime this leaks memory and keeps file-mapping handles open for every injected process that ever ran.

**Fix:** Add a process-exit/unhook channel or registry observer and remove the corresponding `JournalReader` (and `pending_journals` entry) when the registry records `Exited`.

```rust
// In the registry observer / channel consumer:
correlator.remove_journal(key.pid);
```

### WR-04: Stale watchdog evidence is deleted without an audit event

**File:** `dlp-agent/src/service.rs:2392-2397`
**Issue:** Evidence files older than the 7-day retention window are removed with only a `warn!` log. No `WatchdogSelfUnload` audit event is emitted, so a process that self-unloaded while the agent was down for an extended period leaves no durable record.

**Fix:** Emit a `WatchdogSelfUnload` audit event with `untracked=true` and `stale=true` before deleting the file, so the self-unload is recorded even when the matching registry entry is gone.

```rust
if timestamp_secs.is_some_and(|ts| ts < retention_cutoff) {
    event.justification = Some(format!("reason={}; stale=true; pid={}", reason, evidence.pid));
    crate::audit_emitter::emit_audit(audit_ctx, &mut event);
    let _ = std::fs::remove_file(&path);
    continue;
}
```

### WR-05: `AgentShutdownUnhook` audit event uses the agent's own PID as the resource

**File:** `dlp-agent/src/service.rs:193-199`
**Issue:** `request_unhook_from_injected` emits `AgentShutdownUnhook` with `pid = std::process::id()` (the agent PID), producing `resource_path = "pid=<agent_pid>"`. The event represents a bulk operation against injected processes, but the primary resource identifier implies the agent itself was unhooked. The target count is only present in `justification`, making SIEM queries and forensic correlation harder.

**Fix:** Use a sentinel resource path such as `"agent://<agent_pid>/unhook_request"` and include the full target PID list (or count) in `justification`.

```rust
let resource_path = format!("agent://{}/unhook_request", std::process::id());
let error = Some(format!("injected_count={}; target_pids=[{}]", injected_before, pid_list));
```

## Info

### IN-01: Tests write watchdog evidence to a system-wide directory

**File:** `dlp-hook-dll/src/control_thread.rs:89-90`
**Issue:** Test builds use `C:\ProgramData\DLP\WatchdogSelfUnload_Test`. Parallel test runs or tests executed without elevation can conflict or fail to create the directory.

**Fix:** Use a per-test temporary directory or inject the evidence path as a test-only parameter.

### IN-02: `emit_unhook_audit` accepts any `EventType`

**File:** `dlp-agent/src/audit_emitter.rs:542-548`
**Issue:** The helper documents that `event_type` should be one of three unhook-related variants, but the signature accepts any `EventType`. A future caller could accidentally emit an unrelated event type through this helper.

**Fix:** Restrict the input type to a new `UnhookEventType` enum or add a runtime/debug assertion for the allowed variants.

### IN-03: `WatchdogEvidence.reason` is not validated

**File:** `dlp-agent/src/service.rs:2319-2323`
**Issue:** The `reason` field is deserialized as a free-form `String` and embedded directly in the audit justification. The file-size cap limits abuse, but unexpected values are still forwarded without validation against the known enum (`watchdog_timeout`).

**Fix:** Validate the reason against an allowlist and fall back to `"unknown"` for unrecognized values before emitting the audit event.
