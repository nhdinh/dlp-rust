# Phase 58.5: Code Review Report

**Reviewed:** 2026-07-01T14:00:00Z
**Depth:** standard
**Files Reviewed:** 21
**Status:** issues_found

## Summary

This standard-depth adversarial review of the Phase 58.5 cooperative unhook implementation found one critical correctness issue, six warnings, and three informational items. The critical issue is a use-after-free/crash risk when the hook DLL self-unloads while hook calls are still executing. The warnings cover state leaks on panic, bypass-correlator resource leaks, audit-evidence loss or misidentification, and weak validation of untrusted hook-to-agent strings. The informational items are test-hygiene and API-signature concerns.

## Critical Issues

### CR-01: `self_unload` may free the DLL image while active calls remain

**File:** `dlp-hook-dll/src/lib.rs:882-897`
**Issue:** `self_unload` performs a bounded 5-second drain of `ACTIVE_CALLS`, but if the drain times out it logs a warning and calls `FreeLibraryAndExitThread` anyway. Threads that entered a hooked API just before `SHUTTING_DOWN` was raised can still be executing trampoline/classification code inside the DLL image. Freeing the library mapping while those threads are mid-call is a use-after-free that can crash the host process or corrupt the stack.

**Fix:** Do not free the image when active calls remain. Change `self_unload` from a diverging function to one that returns a result so callers can abort the unload and remain loaded (or escalate safely).

```rust
pub unsafe fn self_unload() -> bool {
    const FINAL_DRAIN_TIMEOUT_MS: u64 = 5_000;
    const FINAL_DRAIN_POLL_US: u64 = 100;
    let deadline =
        std::time::Instant::now() + std::time::Duration::from_millis(FINAL_DRAIN_TIMEOUT_MS);
    while ACTIVE_CALLS.load(Ordering::SeqCst) > 0 && std::time::Instant::now() < deadline {
        std::thread::sleep(std::time::Duration::from_micros(FINAL_DRAIN_POLL_US));
    }
    if ACTIVE_CALLS.load(Ordering::SeqCst) > 0 {
        debug_log("[dlp-hook] self_unload: active calls remain -- aborting unload\0");
        return false;
    }
    let instance = DLL_INSTANCE
        .lock()
        .ok()
        .and_then(|g| *g)
        .map(|raw| HINSTANCE(raw as *mut std::ffi::c_void))
        .unwrap_or_else(|| {
            GetModuleHandleW(None).unwrap_or_default().into()
        });
    FreeLibraryAndExitThread(instance.into(), 0);
}
```

## Warnings

### WR-01: Panic inside `with_reentrancy_guard` leaks active-call and reentrancy state

**File:** `dlp-hook-dll/src/crash_guard.rs:225-236` / `dlp-hook-dll/src/trampolines.rs:697-733`
**Issue:** Trampolines wrap `with_reentrancy_guard` inside `guard_trampoline(..., catch_unwind(...))`. If the guarded hook body panics after `enter_hook_call()` has incremented `ACTIVE_CALLS` and `REENTRANT` has been set to `true`, the unwind is caught but neither flag is reset. On that thread all future hook calls bypass classification, and `ACTIVE_CALLS` remains inflated forever, causing every subsequent `UnhookAll` drain to time out.

**Fix:** Make `with_reentrancy_guard` panic-safe, for example by using a struct whose `Drop` resets both flags.

```rust
struct ReentrancyGuard;
impl Drop for ReentrancyGuard {
    fn drop(&mut self) {
        REENTRANT.set(false);
        crate::exit_hook_call();
    }
}
```

### WR-02: Bypass correlator leaks `JournalReader` entries for unhooked/exited processes

**File:** `dlp-agent/src/bypass_correlator.rs:326,329`
**Issue:** `BypassCorrelator` stores an open shared-memory `JournalReader` for each PID in a `DashMap<u32, JournalReader>` and pending-journal metadata in `DashMap<u32, (Instant, u32)>`. Entries are evicted only on PID reuse. When a process transitions to `Exited` after cooperative unhook or normal exit, no cleanup hook removes its reader. Over long agent uptime this leaks memory and keeps file-mapping handles open for every injected process that ever ran.

**Fix:** Add a registry observer or cross-component channel and remove the corresponding `JournalReader` and `pending_journals` entry when `ProcessRegistry::record_unhooked` / `record_exited` fires.

```rust
// In the observer / channel consumer:
correlator.journals.remove(&key.pid);
correlator.pending_journals.remove(&key.pid);
```

### WR-03: Watchdog evidence file overwritten when PID is reused before reconciliation

**File:** `dlp-hook-dll/src/control_thread.rs:371`
**Issue:** `persist_watchdog_evidence` writes evidence to `{pid}.evidence.json` using only the PID as the filename. If Windows reuses that PID and the newly created process also self-unloads before the agent reconciles the directory, `File::create` truncates and overwrites the original evidence file. This silently destroys audit evidence for the earlier self-unload.

**Fix:** Include the process creation time in the filename and reconcile by `(pid, creation_time)`.

```rust
let path = dir.join(format!("{}_{}.evidence.json", pid, creation_time));
```

### WR-04: Stale watchdog evidence is deleted without an audit event

**File:** `dlp-agent/src/service.rs:2392-2397`
**Issue:** Evidence files older than the 7-day retention window are removed with only a `warn!` log. No `WatchdogSelfUnload` audit event is emitted, so a process that self-unloaded while the agent was down for an extended period leaves no durable audit record.

**Fix:** Emit a `WatchdogSelfUnload` audit event with a `stale=true` marker before deleting the file.

```rust
if timestamp_secs.is_some_and(|ts| ts < retention_cutoff) {
    event.justification = Some(format!(
        "reason={}; stale=true; pid={}; creation_time={}",
        reason, evidence.pid, evidence.creation_time
    ));
    crate::audit_emitter::emit_audit(audit_ctx, &mut event);
    let _ = std::fs::remove_file(&path);
    continue;
}
```

### WR-05: `AgentShutdownUnhook` audit event uses the agent's own PID as the resource

**File:** `dlp-agent/src/service.rs:193-199`
**Issue:** `request_unhook_from_injected` emits `AgentShutdownUnhook` with `pid = std::process::id()` (the agent PID), producing `resource_path = "pid=<agent_pid>"`. The event represents a bulk operation against injected processes, but the primary resource identifier implies the agent itself was unhooked. The target count is only present in `justification`, making SIEM queries and forensic correlation harder.

**Fix:** Use a sentinel resource path and include the target count/PIDs in `justification`.

```rust
let resource_path = format!("agent://{}/unhook_request", std::process::id());
let error = Some(format!("injected_count={}; target_pids=[...]", injected_before));
crate::audit_emitter::emit_unhook_audit(
    audit_ctx,
    dlp_common::EventType::AgentShutdownUnhook,
    std::process::id(),
    true,
    error,
);
```

### WR-06: `UnhookAck.error` truncation uses Unicode scalar count, not byte length

**File:** `dlp-agent/src/hook_ipc.rs:350-360`
**Issue:** `sanitize_unhook_error` limits the error string to `MAX_UNHOOK_ERROR_LEN` (256) Unicode scalar values via `.chars().count()` and `.chars().take()`. A compromised hook DLL can still smuggle a 256-character string of multi-byte characters that exceeds 256 bytes when serialized to JSON or forwarded to SIEM, undermining the stated anti-injection bound.

**Fix:** Bound by byte length after UTF-8 encoding.

```rust
fn sanitize_unhook_error(error: Option<String>) -> Option<String> {
    error.and_then(|e| {
        let trimmed = e.trim().to_string();
        if trimmed.is_empty() {
            None
        } else {
            let mut out = trimmed;
            while out.len() > MAX_UNHOOK_ERROR_LEN {
                out.pop();
            }
            Some(out)
        }
    })
}
```

## Info

### IN-01: Tests write watchdog evidence to a system-wide directory

**File:** `dlp-hook-dll/src/control_thread.rs:89-90`
**Issue:** Test builds use `C:\ProgramData\DLP\WatchdogSelfUnload_Test`. Parallel test runs or tests executed without elevation can conflict or fail to create the directory.

**Fix:** Use a per-test temporary directory or inject the evidence path as a test-only parameter.

### IN-02: `emit_unhook_audit` accepts any `EventType`

**File:** `dlp-agent/src/audit_emitter.rs:542-548`
**Issue:** The helper documents that `event_type` should be one of three unhook-related variants, but the signature accepts any `EventType`. A future caller could accidentally emit an unrelated event type through this helper.

**Fix:** Restrict the input type to a new `UnhookEventType` enum or add a debug assertion for the allowed variants.

### IN-03: `WatchdogEvidence.reason` is not validated

**File:** `dlp-agent/src/service.rs:2319-2323`
**Issue:** The `reason` field is deserialized as a free-form `String` and embedded directly in the audit justification. The file-size cap limits abuse, but unexpected values are still forwarded without validation against the known enum (`watchdog_timeout`).

**Fix:** Validate the reason against an allowlist and fall back to `"unknown"` for unrecognized values before emitting the audit event.
