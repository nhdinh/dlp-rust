## Decisions Made

- Introduced a single crate-wide `PHASE_58_5_TEST_LOCK` to serialize all `dlp-hook-dll` tests that touch process-global hook state. This eliminated the `STATUS_ACCESS_VIOLATION` crashes caused by concurrent IAT restore, ntdll unpatching, control thread lifecycle, and shared-memory mapping mutations.
- Kept all mocks behind `#[cfg(test)]` so they are stripped from release builds.
- Used a separate test mapping name (`Local\DlpClassificationCache_TestPhase58_5_Direct`) for direct cache tests to avoid colliding with the global `CACHE_LOOKUP` slot used by other tests.
- Chose to document the SonarCloud Quality Gate project-wide metric failure rather than expand scope beyond Phase 58.5; coverage/duplication debt is tracked by existing beads issue `dlp-rust-vv9`.
- Removed `#[cfg(test)]` from `audit_test_lock`/`AuditTestGuard`/`drain_stale_test_events` so integration tests in `dlp-agent/tests/` can use the serialisation guard. Integration tests compile as a separate crate and cannot call the library's `#[cfg(test)]` items. The helpers remain harmless in production builds.
