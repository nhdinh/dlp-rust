<objective>
Implement the agent-side unhook orchestration using the polling protocol: on graceful shutdown, set a global `UNHOOK_ALL_REQUESTED` flag so the hook IPC server replies to incoming `PollControl` frames with `UnhookCommand` only for known injected processes; route returning `UnhookAck` frames to update the `ProcessRegistry` only when the ack reports success; emit `AgentShutdownUnhook` and `UnhookFailure` audit events; keep the total wait within the existing service shutdown budget; and reconcile watchdog self-unload evidence from a service-visible global path.

Purpose: This is the agent-side orchestration of the cooperative unhook protocol. Because the agent hosts the named-pipe server and the hook DLL is the client, the agent cannot directly send commands to each injected process. The polling model reuses the existing pipe and lets every injected DLL discover the shutdown signal on its next poll. Addresses Cycle 2 review concerns: UnhookAck.success must be honored, PollControl must validate callers, and watchdog evidence must be service-visible with audit for unmatched evidence.
Output: Extended agent service with registry accessors, validated PollControl/UnhookAck routing, audit wiring, and passing unit tests.
</objective>

          let injected_before = registry.iter_injected().len();
          if injected_before > 0 {
              crate::password_stop::debug_log("run_loop: requesting unhook from injected processes");
              crate::audit_emitter::emit_unhook_audit(
