# Phase 58.5 Plan 06: Immediate Control-Thread Start and Shutdown Budget Summary

**Idle injected processes now start the hook DLL control-poll thread immediately after LoadLibraryW, and the agent shutdown path caps cooperative unhook wait inside SHUTDOWN_TIMEOUT.**

## Performance

- **Duration:** 25 min
- **Started:** 2026-07-02T04:55:10Z (resumed from Task 3 uncommitted state)
- **Completed:** 2026-07-02T05:20:00Z
- **Tasks:** 3
- **Files modified:** 6

## Accomplishments
- Extended `HookInjector::inject_into_process` to launch a second remote thread at the `StartDlpControlThread` export RVA after successful `LoadLibraryW`, so idle processes poll immediately instead of waiting for a hooked API call.
- Added export-RVA caching in `HookInjector::new` using `LoadLibraryExW` with `DONT_RESOLVE_DLL_REFERENCES` to avoid repeated local DLL loading.
- Added remote module-base enumeration to recover the full 64-bit `HMODULE` on x64, because `GetExitCodeThread` only returns a `DWORD`.
- Made the agent shutdown sequence track `shutdown_start` and cap the cooperative unhook budget to the remaining `SHUTDOWN_TIMEOUT`, preventing the per-process wait from exceeding the SCM deadline.
- Added an integration test that spawns an idle child process, injects the hook DLL, and verifies the agent receives a `PollControl` frame with the real process creation time.

## Decisions Made
- Followed the plan's recommendation to keep export-start failure as a logged warning rather than failing injection, preserving the lazy-start fallback.
- Chose to enumerate remote modules to obtain the real module base instead of relying on the truncated `LoadLibraryW` return code, avoiding 64-bit address truncation bugs.
