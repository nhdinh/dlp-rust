## Fixed Issues

### CR-01: `self_unload` may free the DLL image while active calls remain

**Files modified:** `dlp-hook-dll/src/lib.rs`, `dlp-hook-dll/src/control_thread.rs`
**Commit:** 6e6d1ccc
**Applied fix:** Changed `self_unload` from a diverging function (`-> !`) to `-> bool`. If active hook calls remain after the 5-second drain, it logs the condition and returns `false` without freeing the image. Callers in `control_thread.rs` now abort or continue safely when the unload is aborted, leaving the DLL loaded to avoid a use-after-free crash.
**Status:** fixed: requires human verification

### WR-01: Panic inside `with_reentrancy_guard` leaks active-call and reentrancy state

**Files modified:** `dlp-hook-dll/src/crash_guard.rs`
**Commit:** c2c0b46e
**Applied fix:** Introduced a `ReentrancyGuard` struct whose `Drop` implementation clears the thread-local `REENTRANT` flag and decrements `ACTIVE_CALLS`. `with_reentrancy_guard` now creates this guard after entering, so a panic during the hook body still resets both flags when the unwind runs the destructor.
**Status:** fixed

### WR-02: Bypass correlator leaks `JournalReader` entries for unhooked/exited processes

**Files modified:** `dlp-agent/src/process_registry.rs`, `dlp-agent/src/bypass_correlator.rs`, `dlp-agent/src/service.rs`
**Commit:** 8e7c7169
**Applied fix:** Added a lifecycle notification channel to `ProcessRegistry`. `record_exited` and `record_unhooked` now send the process key on this channel. `BypassCorrelator::run` accepts the channel receiver and spawns a lifecycle task that calls `remove_pid`, dropping the `JournalReader` and `pending_journals` entry for the exited/unhooked PID. `service.rs` creates the channel and wires it between the registry and correlator.
**Status:** fixed: requires human verification

### WR-03: Watchdog evidence file overwritten when PID is reused before reconciliation

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commit:** 5848d28e
**Applied fix:** Changed the persisted evidence filename from `{pid}.evidence.json` to `{pid}_{creation_time}.evidence.json`, disambiguating evidence when Windows reuses a PID.
**Status:** fixed

### WR-04: Stale watchdog evidence is deleted without an audit event

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** f765cb1f
**Applied fix:** Moved `AuditEvent` construction before the retention-window check. When evidence is older than the 7-day cutoff, the function now emits a `WatchdogSelfUnload` audit event with `stale=true` in the justification before deleting the file, preserving a durable audit record.
**Status:** fixed: requires human verification

### WR-05: `AgentShutdownUnhook` audit event uses the agent's own PID as the resource

**Files modified:** `dlp-agent/src/audit_emitter.rs`, `dlp-agent/src/service.rs`, `dlp-agent/src/hook_ipc.rs`
**Commit:** 17619395
**Applied fix:** Extended `emit_unhook_audit` with an optional `resource_path` parameter that defaults to `pid={pid}`. `request_unhook_from_injected` now passes `agent://{agent_pid}/unhook_request` and includes both `injected_count` and a `target_pids` list in the justification. Callers for per-process `UnhookFailure` events continue to use the default `pid={pid}` path. Updated the corresponding unit test expectation.
**Status:** fixed: requires human verification

### WR-06: `UnhookAck.error` truncation uses Unicode scalar count, not byte length

**Files modified:** `dlp-agent/src/hook_ipc.rs`
**Commit:** 34e20d46
**Applied fix:** Rewrote `sanitize_unhook_error` to truncate by byte length after UTF-8 encoding, repeatedly calling `pop()` until `out.len() <= MAX_UNHOOK_ERROR_LEN`. This enforces the stated 256-byte anti-injection bound against multi-byte character payloads.
**Status:** fixed
