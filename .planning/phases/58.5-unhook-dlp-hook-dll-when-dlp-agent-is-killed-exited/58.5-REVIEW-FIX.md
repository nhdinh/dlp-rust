## Fixed Issues

### CR-01: `creation_time` unit mismatch breaks PID-reuse-safe unhook matching

**Files modified:** `dlp-hook-dll/src/control_thread.rs`, `dlp-common/src/hook_ipc.rs`
**Commit:** `bc5dc16`
**Applied fix:** `process_creation_time()` now returns the raw 64-bit FILETIME value instead of converting to Unix seconds, so it matches the agent registry's `ProcessKey.creation_time`. Doc comments for `UnhookAck.creation_time` and `PollControl.creation_time` were tightened to describe the value as a raw FILETIME.

### CR-02: Pipe DACL allows any authenticated user to spoof `UnhookAck`

**Files modified:** `dlp-agent/src/hook_ipc.rs`
**Commit:** `2857a2e`
**Applied fix:** Added server-side validation of the pipe client's PID using `GetNamedPipeClientProcessId`. The agent now rejects any `UnhookAck` whose sender PID does not match the claimed `ack.pid`, preventing a low-privilege process from spoofing unhook acknowledgments for another process. The hook pipe must remain accessible to authenticated user processes because injected DLLs run as the interactive user, so caller-PID validation is the anti-spoofing control.

### WR-03: Matched 5-second budgets cause false unhook failures

**Files modified:** `dlp-agent/src/config.rs`, `dlp-agent/src/service.rs`
**Commit:** `6baed88`, `8ddcda3`
**Applied fix:** Added `unhook_wait_budget_ms` to `AgentConfig`. `request_unhook_from_injected` now reads the configured budget (defaulting to 30,000 ms and clamped to a minimum of 1,000 ms). The fallback `UNHOOK_WAIT_BUDGET` constant was increased from 5 s to 30 s to match the hook DLL watchdog timeout, and `SHUTDOWN_TIMEOUT` was increased from 10 s to 35 s so the unhook wait plus remaining cleanup steps fit within the internal shutdown watchdog. Persistence of pending unhook requests for cross-restart reconciliation is left as future hardening.

### WR-04: Hook DLL self-unloads even when `UnhookAck` reports failure

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commit:** `2128b52`
**Applied fix:** `handle_unhook_command` now only calls `self_unload()` when `unhook_ok` is true. On failure the DLL remains loaded and continues the control loop so the agent can retry or escalate.

### WR-05: `FreeLibraryAndExitThread` race with active hook calls

**Files modified:** `dlp-hook-dll/src/lib.rs`
**Commit:** `99192f9`
**Applied fix:** `self_unload()` now performs a bounded final drain of `ACTIVE_CALLS` (up to 5 s) before calling `FreeLibraryAndExitThread`. Because `SHUTTING_DOWN` blocks new hook entries, this ensures threads already inside trampolines finish before the DLL image is freed.

### WR-07: `UnhookAck.error` string is forwarded to audit logs without validation

**Files modified:** `dlp-agent/src/hook_ipc.rs`
**Commit:** `b06178c`
**Applied fix:** Added `sanitize_unhook_error()`, which trims whitespace, discards empty strings, and truncates the error to 256 characters before forwarding it to `emit_unhook_audit`. This limits log injection and SIEM noise from a compromised hook DLL.

### WR-08: Unhook audit events are emitted after the audit flush task has been stopped

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** `bd95ff7`
**Applied fix:** Moved `request_unhook_from_injected` to run before the audit buffer flush task is stopped in `run_loop_shutdown`. This ensures `AgentShutdownUnhook` and any `UnhookFailure` events generated during the handshake are included in the final flush.

### WR-09: Watchdog timer truncation on 32-bit targets

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commit:** `2128b52` (shared commit with WR-04)
**Applied fix:** `control_thread_loop` and the test helper now compute the watchdog deadline from `last_agent_response + watchdog_timeout_ms()` and wait for the smaller of the remaining time and `CONTROL_POLL_INTERVAL_MS`. This removes the ~1 s polling granularity delay and avoids repeatedly casting `as_millis()` to `u64`.

## Skipped Issues

### WR-01: Duration underflow panic in `wait_for_unhook_acks`

**File:** `dlp-agent/src/service.rs:152-168`
**Reason:** Already fixed in current code. The function checks `if elapsed >= budget { return remaining; }` before computing `budget - elapsed`, so no underflow can occur.
**Original issue:** The shutdown helper computed `budget - elapsed` without guarding against `elapsed > budget`.

### WR-02: Race between watchdog timeout and `UnhookFailure` emission

**File:** `dlp-agent/src/service.rs:181-214`
**Reason:** Already fixed in current code. `request_unhook_from_injected` iterates `registry.iter_injected()` after `wait_for_unhook_acks` returns and emits one `UnhookFailure` audit event per remaining injected process.
**Original issue:** When the shutdown budget expired, `wait_for_unhook_acks` returned the remaining count but did not itself emit `UnhookFailure` events.

### WR-06: Bypass correlator is not notified when processes unhook

**File:** `dlp-agent/src/bypass_correlator.rs`, `dlp-agent/src/hook_ipc.rs:580-613`
**Reason:** Requires cross-component plumbing that is not present in the current architecture. The `BypassCorrelator` runs in its own async task and consumes `ProcessEvent`/`BypassAlert` channels; `ProcessRegistry::record_unhooked`/`record_process_exited` has no reference to the correlator and no channel to notify it. Implementing this properly requires adding a process-exit channel or registry observer and wiring it through service startup, which is beyond a localized fix.
**Original issue:** `bypass_correlator` maintains a `DashMap<u32, JournalReader>` keyed by PID. When a process transitions to `Exited` after unhook, no cleanup hook removes its reader, leaking entries over long agent uptime.
