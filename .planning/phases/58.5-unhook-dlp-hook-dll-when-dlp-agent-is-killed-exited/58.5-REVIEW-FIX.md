## Fixed Issues

### CR-01: Watchdog self-unload ignores `UnhookAll()` result

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commit:** `2af402fd`
**Applied fix:** Replaced the unchecked `crate::UnhookAll()` call in the watchdog path with `crate::unhook_all_internal()` and check its return value. If unhook fails, the control thread logs the failure and breaks, leaving the DLL loaded but unhooked. Only on success does it proceed to `self_unload()`.
**Status:** fixed: requires human verification

### WR-01: Lifecycle notifications can be silently dropped under load

**Files modified:** `dlp-agent/src/process_registry.rs`
**Commit:** `0db52353`
**Applied fix:** Replaced `let _ = tx.try_send(...)` in `record_exited` and `record_unhooked` with an explicit `if let Err(e)` branch that logs a `tracing::warn!` when the bounded lifecycle channel drops a notification.
**Status:** fixed

### WR-02: Registry eviction can leak bypass-correlator resources

**Files modified:** `dlp-agent/src/process_registry.rs`
**Commit:** `39686298`
**Applied fix:** In `enforce_cap`, before removing a selected victim entry, inspect its state. If the victim is `Injected`, send its `ProcessKey` over `lifecycle_tx` (with a warning on drop) so the bypass correlator can release `JournalReader` and `pending_journals` resources.
**Status:** fixed

### WR-03: Classification cache is mapped with write access

**Files modified:** `dlp-hook-dll/src/classification_cache.rs`
**Commit:** `67c71e59`
**Applied fix:** Changed `OpenFileMappingW` and `MapViewOfFile` to use `FILE_MAP_READ` instead of `FILE_MAP_ALL_ACCESS`. Updated the security doc comment to state that the cache is opened read-only because the DLL is a consumer of agent-authored data.
**Status:** fixed

### WR-04: Watchdog evidence `reason` field is not validated

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** `cf61273f`
**Applied fix:** Added an allowlist match on `evidence.reason.as_str()`. Known value `watchdog_timeout` is preserved; anything else is logged as a warning and replaced with `"unknown"` before inclusion in the audit justification.
**Status:** fixed

### WR-05: `emit_unhook_audit` accepts any `EventType`

**Files modified:** `dlp-agent/src/audit_emitter.rs`, `dlp-agent/src/service.rs`, `dlp-agent/src/hook_ipc.rs`
**Commit:** `4da3a3c4`
**Applied fix:** Introduced a `UnhookEventType` enum with the three permitted variants. Changed `emit_unhook_audit` to accept `UnhookEventType` and map it to the corresponding `dlp_common::EventType` internally. Updated all call sites and unit tests to use the new enum.
**Status:** fixed: requires human verification

### WR-06: Tests write watchdog evidence to a system-wide directory

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commits:** `cfdaef4e`, `2154410a`
**Applied fix:** Replaced the fixed `WATCHDOG_EVIDENCE_DIR` constant with a `watchdog_evidence_dir()` function. Non-test builds continue to use `C:\ProgramData\DLP\WatchdogSelfUnload`; test builds use `%TEMP%\dlp-watchdog-test\{pid}`. A follow-up commit corrected `create_dir_all` to borrow the `PathBuf` instead of moving it.
**Status:** fixed

### WR-07: `self_unload` fallback cannot free the correct module

**Files modified:** `dlp-hook-dll/src/lib.rs`
**Commit:** `6ec0d093`
**Applied fix:** Removed the `GetModuleHandleW(None)` fallback in `self_unload`. If `DLL_INSTANCE` cannot provide the DLL handle, the function logs the failure and returns `false` instead of freeing the host executable module.
**Status:** fixed

### WR-08: `AgentShutdownUnhook` audit emitted before `UNHOOK_ALL_REQUESTED` is set

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** `20672b6e`
**Applied fix:** Moved `UNHOOK_ALL_REQUESTED.store(true, Ordering::Release)` to run before `emit_unhook_audit(..., AgentShutdownUnhook, ...)`, so a crash between arming the flag and emitting the audit cannot produce an audit record without a corresponding `UnhookCommand` being sent.
**Status:** fixed: requires human verification

### WR-09: No tests exercise the watchdog self-unload path

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commit:** `2154410a`
**Applied fix:** Added `watchdog_fires_after_max_failures_and_grace_window`, which uses `run_control_loop_for_test` to feed three consecutive pipe failures and a short watchdog timeout, asserting that the watchdog path triggers.
**Status:** fixed
