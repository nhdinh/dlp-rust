### BL-01: Universal injection subsystem is initialized twice with mismatched registries

**Files modified:** `dlp-agent/src/service.rs`

**Applied fix:** Removed the second `init_universal_injection` call so the registry and handles created before `spawn_hook_ipc_server` are the same ones stored in `RunLoopContext` and used during shutdown/reconciliation.

### BL-02: Control-thread shutdown event handle is closed twice

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commit:** `7f7d058`
**Applied fix:** Removed the explicit `CloseHandle(event)` in `shutdown_control_thread`; the `ControlThread` `Drop` now owns the handle lifecycle exclusively.

### BL-03: `read_frame` ignores its timeout, blocking the watchdog path

**Files modified:** `dlp-hook-dll/src/pipe_client.rs`
**Commit:** `17eb565`
**Applied fix:** Replaced the blocking `read_exact` implementation with `read_exact_with_timeout`, which uses overlapped `ReadFile` + `WaitForSingleObject` + `CancelIoEx` and returns `PipeError::Timeout` when no data arrives within `timeout_ms`.

### WR-01: `UnhookAck` failure audit uses a hard-coded `EmitContext`

**Files modified:** `dlp-agent/src/hook_ipc.rs`, `dlp-agent/src/service.rs`
**Commit:** `37d1032` (plumbing), `b26fb50` (test-only `HookIpcServerConfig` update)
**Applied fix:** Added `audit_ctx` to `HookIpcServer`, threaded it through `accept_loop`/`handle_connection`, and wired the production server in `service.rs` to use the service's real `EmitContext` for `UnhookFailure` audits.

### WR-02: Hook journal sequence counter is advanced on a local copy only

**Files modified:** `dlp-hook-dll/src/hook_journal.rs`
**Commit:** `2fea9dd`
**Applied fix:** Added `HookJournal::advance_seq()` to increment `next_seq` on the authoritative global instance while the `JOURNAL` lock is held, and called it after each `journal.write(...)`.

### WR-03: DACL staging GC and removal-application shutdown senders are dropped

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** `a5a3f46`
**Applied fix:** Changed `init_dacl_watcher` and `init_dacl_watcher_without_staging` to return the GC and removal shutdown senders, stored them in `RunLoopContext`, and wired `run_loop_shutdown` to signal both tasks.

### WR-04: `CONTROL_THREAD_STOPPING` is never reset in production after shutdown

**Files modified:** `dlp-hook-dll/src/control_thread.rs`
**Commit:** `a152922`
**Applied fix:** Reset `CONTROL_THREAD_STOPPING` to `false` in `start_control_thread` before spawning, and in `shutdown_control_thread` after joining (or when no thread was running).

### WR-06: `UNHOOK_ALL_REQUESTED` is not reset at service startup

### WR-07: Watchdog evidence reconciliation reads unbounded untrusted files

### WR-08: Default audit context hard-codes SYSTEM/session values

**Commit:** `c235c4e`

**Commit:** `0fd4c8b`

## Skipped Issues

### WR-05: Watchdog self-unload path has no explicit loop exit

**File:** `dlp-hook-dll/src/control_thread.rs:261-276`
**Reason:** `crate::self_unload()` is declared as `pub unsafe fn self_unload() -> !`, i.e., it diverges and cannot return. The type system already guarantees the loop cannot continue after `self_unload()`. Adding `return;` would be unreachable code and would fail the `-D warnings` quality gate. No code change applied.
**Original issue:** In the watchdog timeout branch, the production build calls `crate::self_unload()`. The test build `break`s, but in production there is no `break` or `return` after `self_unload`. `self_unload` is expected to terminate the thread via `FreeLibraryAndExitThread`, but if that ever changes or returns, the loop would continue executing code from a DLL that has been unloaded.
