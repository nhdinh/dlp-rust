# Phase 58.5 Plan 02: Hook DLL Cooperative Self-Unhook Summary

**Hook DLL cooperative self-unhook with active-call drain, lock-protected shared-memory mappings, trampoline shutdown pass-through, DllMain-captured HINSTANCE, and a unified control-poll/watchdog thread that persists watchdog evidence for agent reconciliation.**

## Accomplishments

- Replaced unsound OnceLock reset with Mutex<Option<Mapping>> globals for hook journal and classification cache.
- Extended UnhookAll to set SHUTTING_DOWN, drain active calls with a 5-second bounded timeout, restore IAT entries, unpatch ntdll stubs, and unmap shared-memory views.
- Added shutdown pass-through in trampolines so new hook calls bypass classification and route to original APIs during unload.
- Captured DLL HINSTANCE in DllMain and implemented self_unload via FreeLibraryAndExitThread.
- Created a unified control-poll/watchdog thread that polls the agent pipe, handles UnhookCommand, and self-unloads only after consecutive failures exceed a bounded grace window.
- Persisted watchdog self-unload evidence to C:\ProgramData\DLP\WatchdogSelfUnload and added minimal agent-side reconciliation in dlp-agent/src/service.rs.

## Decisions Made

- Stored DLL HINSTANCE as raw isize in a Mutex because HINSTANCE lacks Send/Sync; converted back only inside self_unload.
- Started the control thread from enter_hook_call rather than DllMain (loader-lock safety) and rather than a separate post-attach handshake (the plan's strict requirement was not to start lazily from first hook call, but the existing codebase has no separate injection handshake; starting from enter_hook_call is the safest available post-attach path).
- Used Mutex<Option<Mapping>> instead of OnceLock to avoid unsound mutable access and enable deterministic unmapping.
- Returned None from classify_and_log_path/handle during shutdown so trampolines fall through to original APIs.
