# Phase 58.5 Plan 07: Unhook-first shutdown ordering and protected budget

**Cooperative unhook now runs first in graceful shutdown, the hook IPC server keeps serving PollControl during the unhook window, and a 5-second cleanup reserve protects the remaining teardown budget.**

## Accomplishments

- Moved `request_unhook_from_injected` to the very beginning of `run_loop_shutdown`, before file monitor stop, heartbeat teardown, config polls, DACL/WFP cleanup, or any other subsystem stop.
- Extracted `compute_unhook_budget` to cap the unhook budget to `SHUTDOWN_TIMEOUT - CLEANUP_RESERVE` and clamp to a positive minimum.
- Added `pub fn unhook_requested()` as the canonical accessor for `UNHOOK_ALL_REQUESTED`.
- Updated `accept_loop` to continue serving `PollControl` frames while `unhook_requested()` is true, even if `shutdown_requested()` is already true.
- Added `reset_unhook_signal()` immediately before the hook IPC server stop block so the accept loop exits cleanly once the unhook window closes.
- Added automated tests for budget calculation, shutdown audit emission, unhook failure path, and PollControl serving during the unhook window.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Existing unhook tests used multi-threaded tokio runtime, losing audit events**
- **Found during:** Task 3 (running new and existing unhook tests together)
- **Issue:** `request_unhook_from_injected` emits audit events from async code. With `Runtime::new()`, the continuation after `tokio::time::sleep` can run on a worker thread that lacks the test thread-local capture token, causing the existing `test_request_unhook_from_injected_sets_flag_and_emits` to see zero `AgentShutdownUnhook` events.
- **Fix:** Switched all four unhook tests to `tokio::runtime::Builder::new_current_thread().enable_time().build().unwrap()` so the capture token stays on the test thread.
- **Files modified:** `dlp-agent/src/service.rs`
- **Verification:** `cargo test -p dlp-agent --lib unhook -- --nocapture` passes; full `cargo test -p dlp-agent --lib` passes.
- **Committed in:** `522ead5`

**2. [Rule 2 - Missing Critical] Multi-threaded test suite hung due to leaked UNHOOK_ALL_REQUESTED**
- **Found during:** Task 2/3 verification (`cargo test -p dlp-agent --lib`)
- **Issue:** The production change to `accept_loop` makes it continue running while `unhook_requested()` is true. The non-serial `test_spawn_hook_ipc_server_starts_named_thread` could run while `UNHOOK_ALL_REQUESTED` was still true from a serial unhook test, causing the server to ignore `request_shutdown()` and the test's `join()` to hang indefinitely, eventually crashing the test runner.
- **Fix:** Added `reset_unhook_signal()` at the start of `test_spawn_hook_ipc_server_starts_named_thread` and marked the test `#[serial_test::serial]` so it does not run concurrently with other tests that mutate global shutdown/unhook state. Also added a `SignalGuard` Drop guard in the new `hook_ipc_serves_poll_control_during_unhook` test to restore both signals even on panic.
- **Files modified:** `dlp-agent/src/service.rs`, `dlp-agent/src/hook_ipc.rs`
- **Verification:** `cargo test -p dlp-agent --lib` passes (928 tests).
- **Committed in:** `522ead5`
