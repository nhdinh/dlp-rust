<objective>
Implement cooperative self-unhook inside the hook DLL: integrate ntdll detour disable and real shared-memory unmapping into `UnhookAll()`, add a shutdown pass-through flag used by trampolines, capture the DLL HINSTANCE in `DllMain` for correct self-unload, and add a unified control-poll/watchdog thread that receives `UnhookCommand` from the agent during graceful shutdown and self-unloads if the agent pipe becomes unreachable.

Purpose: This is the in-process side of the unhook protocol. It ensures that when the agent is stopped or killed, every injected process can restore original IAT/ntdll stubs and release shared memory without crashing. Addresses review concerns: shared-memory cleanup must release OS resources, self_unload must use the DLL handle, trampolines must honor shutdown state, and the IPC topology requires a DLL-initiated poll rather than agent-initiated send.
Output: Extended hook DLL with complete self-unhook capability and unit tests verifying UnhookAll state transitions.
</objective>

    - Test 3: After UnhookAll, classification cache shared-memory view is unmapped and the mapping handle is closed
    - Test 4: UnhookAll does not panic when called before init (existing regression test still passes)
    - Test 5: A failure in one IAT restore does not abort the remaining restores
  </behavior>
  <action>
    Addresses review concerns C1 and C5: shared-memory globals must own their OS resources and UnhookAll must be infallible per stub.

    In `dlp-hook-dll/src/hook_journal.rs`:
    - Add a private `JournalMapping { handle: HANDLE, view: *mut c_void }` struct that owns the mapping handle and view pointer.
    - Change `HookJournal` to store `mapping: JournalMapping` instead of relying on the view staying mapped for process lifetime.
    - Update `try_init()` to create a `JournalMapping`, store it in the `HookJournal`, and remove the comment about intentionally leaving the handle open.
    - Add `pub fn unmap_journal()` that takes the `OnceLock` value, calls `UnmapViewOfFile` on the view, calls `CloseHandle` on the handle, and resets the `OnceLock`. Use a safe wrapper that returns `Option<HookJournal>` from `JOURNAL.get()` and clears it with `OnceLock::take` (or an equivalent safe reset if the Rust version supports it; otherwise document the safety invariant that no concurrent access occurs after `SHUTTING_DOWN` is set).

    In `dlp-hook-dll/src/classification_cache.rs`:
    - Add a private `CacheMapping { handle: HANDLE, view: *mut c_void }` struct.
    - Change `CacheLookup` to store `mapping: CacheMapping` and remove the `#[allow(dead_code)]` on the handle field.
    - Update `try_init()` to create a `CacheMapping`.
    - Add `pub fn unmap_cache()` with the same resource-release semantics as `unmap_journal`.

    In `dlp-hook-dll/src/lib.rs`, extend `UnhookAll()` to:
    1. Set a global `SHUTTING_DOWN` AtomicBool to true at the start (defined near `INITIALISED`).
    2. Sleep a short grace period (50 ms) so in-flight trampoline calls can observe the flag and pass through.
    3. Restore all IAT entries. Wrap each `restore_iat` call in a check that logs and continues on failure instead of aborting.
    4. Disable ntdll detours:
       ```rust
       if let Some(patcher) = NTDLL_PATCHER.get() {
           if let Ok(mut guard) = patcher.lock() {
               guard.unpatch_all_stubs();
           }
       }
       ```
    5. Unmap shared-memory views:
       ```rust
       crate::hook_journal::unmap_journal();
       crate::classification_cache::unmap_cache();
       ```
    6. Log completion.

    Do NOT wrap `UnhookAll()` in `std::panic::catch_unwind`. Instead, make every individual restore/unpatch/unmap step log and continue on error. Return a `bool` or a small result struct indicating overall success so `handle_unhook_command` can set `UnhookAck.success` accurately.

    Add unit tests in `dlp-hook-dll/src/lib.rs` `#[cfg(test)]` module:
    - `unhook_all_unpatches_ntdll_stubs` — initialize a test patcher, patch, call UnhookAll, assert states are Unpatched
    - `unhook_all_unmaps_shared_memory` — set up mock mappings, call UnhookAll, assert handles/views are cleared
    - `unhook_all_infallible_per_stub` — corrupt one hook entry so its restore would fail, call UnhookAll, assert the function returns false but does not panic and other hooks are still restored
  </action>

    Addresses review concerns: agent cannot directly send to injected DLLs over the existing pipe, so the DLL must poll; watchdog must not start from DllMain due to loader-lock sensitivity.

    In `dlp-hook-dll/src/pipe_client.rs`:
    - Add `pub fn send_unhook_ack(pipe_name: &str, ack: &UnhookAck) -> Result<(), PipeError>` that serializes an `IpcEnvelope::V1(IpcPayloadV1::UnhookAck(...))` and sends it via `send_raw_oneway`.
    - Add `pub fn poll_control(pipe_name: &str, pid: u32, creation_time: u64, timeout_ms: u32) -> Result<ControlResponse, PipeError>` that connects to the pipe, sends `IpcPayloadV1::PollControl`, reads the response frame, and deserializes it as `IpcEnvelope::V1(IpcPayloadV1::ControlResponse(...))`.

    In `dlp-hook-dll/src/lib.rs`:
    - Add `pub fn handle_unhook_command(command: &UnhookCommand)` that:
      1. Logs the reason.
      2. Calls `UnhookAll()` and captures its overall success boolean.
      3. Constructs `UnhookAck { pid, creation_time, success, error }` where `creation_time` is obtained from the DLL's own process creation time (query once and cache, or use 0 if unavailable in tests).
      4. Calls `pipe_client::send_unhook_ack` with the ack.
      5. If successful, calls `self_unload()`.
    - Add a unified control-poll/watchdog thread state machine similar to `background_thread.rs` (NotStarted / Starting / Running). Use a Windows event handle for clean shutdown.
    - Add `pub fn spawn_control_poll_thread(pipe_name: &'static str)` that:
      - Is idempotent (no-op if already running)
      - Spawns a thread that loops every `POLL_INTERVAL_MS` (1000 ms)
      - Calls `pipe_client::poll_control` with the current PID and creation_time
      - On success: reset failure counter; if the response contains `UnhookCommand`, call `handle_unhook_command`
      - On failure: increment failure counter; after `MAX_FAILURES` (3) consecutive failures, call `handle_unhook_command` with reason `WatchdogTimeout` and return
      - Checks a shutdown event each iteration so the thread can exit cleanly on DLL detach
    - Call `spawn_control_poll_thread(DEFAULT_PIPE_NAME)` lazily from the first hook call path (e.g., inside `classify_and_log_path` when it first needs the pipe), NOT from `DllMain` or `init()`.

    - `handle_unhook_command_sends_failure_ack` — mock UnhookAll to report failure, assert ack.success == false
    - `control_poll_thread_triggers_after_three_failures` — mock poll_control to fail 3 times, assert a test-only `WATCHDOG_TRIGGERED` flag is set
    - `control_poll_thread_resets_on_success` — mock poll_control to fail twice then return a no-op response, assert watchdog is not triggered
    - `control_poll_thread_handles_unhook_command` — mock poll_control to return ControlResponse with UnhookCommand, assert handle_unhook_command is invoked
  </action>
