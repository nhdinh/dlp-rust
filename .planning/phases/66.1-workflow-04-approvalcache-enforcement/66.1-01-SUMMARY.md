**One-liner:** Added `EvaluateResponse.matched_label_id` and `EventType::ApprovalOverride` with backward-compatible serde, SIEM routing, and alert suppression — providing the type-level contracts for downstream ApprovalCache enforcement integration.

## What Changed

### Task 1: EvaluateResponse.matched_label_id (abac.rs)

- Added `matched_label_id: Option<String>` field to `EvaluateResponse` struct with `#[serde(default, skip_serializing_if = "Option::is_none")]` for backward compatibility.
- Updated `default_deny()` and `default_allow()` constructors to initialize `matched_label_id: None`.
- Updated existing `test_evaluate_response_backward_compat` to assert `matched_label_id.is_none()` on old JSON deserialization.
- Added `test_evaluate_response_with_matched_label_id` verifying round-trip serialization/deserialization with the field populated.

### Task 2: EventType::ApprovalOverride (audit.rs)

- Added `ApprovalOverride` variant to `EventType` enum with doc comment: "An approval token was used to override an ABAC DENY decision at enforcement time. Emitted when ApprovalCache::check() grants an override."
- Updated `ApprovalUse` doc comment to clarify RESERVED/UNUSED status: "Reserved for future use. ApprovalOverride is the enforcement-time event for successful overrides."
- Added `Self::ApprovalOverride` to `routed_to_siem()` (returns `true`).
- `ApprovalOverride` correctly excluded from `triggers_alert()` (returns `false`), preventing false-positive alert storms.
- Added 3 unit tests:
  - `test_approval_override_routed_to_siem`
  - `test_approval_override_does_not_trigger_alert`
  - `test_approval_override_serde_round_trip`
