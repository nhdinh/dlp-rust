# Phase 66.1 Plan 04: ApprovalCache Enforcement Wiring Summary

**One-liner:** Wired ApprovalCache::check() into the file monitor enforcement path as Stage 3 of the pipeline, added approver_sid/approval_expiry audit fields, and structurally prepared the hook DLL path for future override integration.

## What Was Built

### Task 1: get_sid_for_pid utility (identity.rs)
- Added `pub fn get_sid_for_pid(pid: u32) -> Option<String>` for arbitrary PID-to-SID resolution
- Uses `OpenProcess(PROCESS_QUERY_INFORMATION)` -> `OpenProcessToken` -> `GetTokenInformation(TokenUser)` -> `ConvertSidToStringSidW`
- Closes both handles on all paths (success and error)
- Non-Windows cfg returns `None` for test compatibility
- Documents fail-closed behavior (`None` on `OpenProcess` failure)
- Unit test verifies `get_sid_for_pid(current_pid) == get_current_process_sid()`

### Task 2: Approval override in file monitor path (interception/mod.rs + audit.rs)
- Added `approver_sid` and `approval_expiry` fields to `AuditEvent` in dlp-common
- Added builder methods `with_approver_sid()` and `with_approval_expiry()`
- Wired approval cache override as Stage 3 in `run_event_loop`:
  - Only runs when `effective_mode.is_blocking() && final_decision.is_denied()`
  - Audit mode short-circuits before override (avoids unnecessary JWT verification)
  - Override granted: emits `EventType::ApprovalOverride` with approver SID, approval expiry, justification, and `would_have_denied=true`
  - Override missed with `matched_label_id`: annotates reason with "no active approval"
  - No label match (offline mode): skips cache check, keeps original reason
- Extracted `compute_override_decision()` as a pure testable function
- Added 5 unit tests covering: no cache, empty cache, audit mode skip, no label_id skip, ALLOW bypass
- Fixed `dlp-server/src/alert_router.rs` AuditEvent struct literals for new fields

### Task 3: Hook IPC structural wiring (hook_ipc.rs + service.rs)
- Added `HookIpcServer::with_approval_cache()` constructor (avoids collision with existing `with_cache()`)
- Updated `handle_hook_request` signature with optional `approval_cache` parameter
- Added `TODO(WORKFLOW-04-followup)` comment block documenting deferred hook-path override requirements
- Hook path remains fail-closed: override check is NOT activated
- Added TODO in `service.rs` documenting where `with_approval_cache` should be used when `HookIpcServer` is constructed
- Added 3 unit tests: constructor, deferred override keeps DENY, backward compat with `with_cache`

- **Fix:** Added both fields to `AuditEvent` struct in `dlp-common/src/audit.rs`, initialized them in `new()`, and added builder methods. Fixed 6 struct literals in `dlp-server/src/alert_router.rs`.
