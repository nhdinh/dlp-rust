<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ABAC evaluation -> approval override | The override is the FINAL decision stage; no further checks after override |
| Hook DLL -> agent IPC | HookRequest lacks PID; path-based SID resolution is a best-effort fallback |
| Audit emitter -> SIEM relay | ApprovalOverride events must not trigger false-positive alerts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66.1-07 | Elevation of Privilege | Hook DLL path uses path-based SID resolution | mitigate | Document limitation; path-based resolution matches existing run_event_loop pattern; incorrect SID leads to cache miss (fail-closed) |
| T-66.1-08 | Repudiation | ApprovalOverride event missing approver_sid or justification | mitigate | Audit event builder sets all required fields from ApprovalClaims; would_have_denied=true per D-03.2 |
| T-66.1-09 | Tampering | check_approval_override returns ALLOW without claims for audit | mitigate | Return (EvaluateResponse, ApprovalClaims) tuple so caller can enrich audit event |
| T-66.1-10 | Denial of Service | JWT re-verification on every DENY in hook DLL hot path | accept | ~50us per check; only runs when decision is DENY; audit mode short-circuits before check |
</threat_model>
