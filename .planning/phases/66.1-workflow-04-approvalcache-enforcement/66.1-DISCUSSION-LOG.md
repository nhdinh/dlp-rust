## data_object_id resolution

| Option | Description | Selected |
|--------|-------------|----------|
| 1 | Add `matched_label_id` to `EvaluateResponse` — server returns matched label ID; agent reuses it for `ApprovalCacheKey`. Minimal change, no new cache subsystem. | ✓ |
| 2 | Build agent-side label cache — agent polls labels from server and maps paths locally. More code but removes server round-trip. | |
| 3 | Use file path as `obj_id` proxy — simple but breaks folder inheritance (child paths under inherited label get different keys). | |

**User's choice:** Asked for recommendation; accepted Option 1.
**Notes:** User accepted the rationale that server already resolves path → label during ABAC evaluation, so returning the matched label ID is trivial additive change with `#[serde(default)]` for backward compat. Offline mode (no `matched_label_id`) correctly falls back to tier-gated fail semantics.

## Integration points — file monitor vs hook DLL

| Option | Description | Selected |
|--------|-------------|----------|
| A | Wire both file monitor `run_event_loop` and hook DLL `handle_hook_request` paths. Both are live enforcement paths; skipping either leaves a bypass hole. | ✓ |
| B | Prioritize hook DLL path only — v0.10.0 real-time blocking is primary enforcement. | |
| C | Prioritize file monitor path only — simpler but hook DLL bypasses it. | |

**User's choice:** Asked for recommendation; accepted Option A.
**Notes:** Both paths follow the same pattern. The approval cache check is a 3-line insertion in each path. `DashMap` is lock-free and Ed25519 verification is ~50µs, so both paths can afford the latency.

## Audit event on approval override

| Option | Description | Selected |
|--------|-------------|----------|
| A | Emit standard `EventType::Access` with `would_have_denied=true` and approval ID in `policy_id`. | |
| B | Emit dedicated `EventType::ApprovalOverride` with full metadata (approver SID, approval ID, expiry, justification). | ✓ |
| C | Emit both — would-have-blocked event plus override event. | |

**User's choice:** Asked for recommendation; accepted Option B.
**Notes:** Dedicated event type enables SIEM rules to detect unusual override rates and potential abuse (compromised Data Owner account). Event carries approver_sid, approval_id (JTI), expiry, justification. Routes through SIEM with `triggers_alert = false` (legitimate override, not a security incident).
