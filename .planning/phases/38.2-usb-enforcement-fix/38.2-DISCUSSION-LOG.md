# Discussion Log: Phase 38.2 - USB Enforcement Fix (Reopened)

**Date:** 2026-05-06
**Participants:** User (Hung Dinh), Claude (Principal Security Architect)

---

## Background

Phase 38.2 was originally archived as part of v0.7.0 with the belief that USB enforcement was fixed via:
1. Thread-affinity correction (CreateWindowExW + message loop on same thread)
2. DACL defense-in-depth fallback (`set_volume_deny_all`)

User reported that USB devices are still NOT blocked in production. Code analysis was performed.

---

## Analysis Performed

### Files Examined
- `dlp-agent/src/detection/device_watcher.rs` - Message loop and WM_DEVICECHANGE dispatch
- `dlp-agent/src/detection/usb.rs` - `apply_tier_enforcement`, `on_usb_device_arrival`, `scan_existing_usb_identities`
- `dlp-agent/src/device_controller.rs` - `disable_usb_device`, `set_volume_deny_all`
- `dlp-common/src/usb.rs` - `parse_usb_device_path`, instance ID parsing logic

### Root Cause Identified

**BUG 1: Instance ID Mismatch (Primary)**
- `DeviceController::disable_usb_device` constructs CM instance ID as: `USB\VID_{vid}&PID_{pid}\{serial}`
- Actual CM instance IDs are location-based: `USB\VID_0951&PID_1666\5&12345678&0&0`
- `CM_Locate_DevNodeW` fails with `CR_NO_SUCH_DEVNODE` (0xD)
- Code silently returns `Ok(())` on this "error" — device is NOT disabled

**BUG 2: `(none)` Serial Poisoning**
- Devices without serial descriptors get `serial = "(none)"`
- Constructed ID: `USB\VID_X&PID_Y\(none)` — never matches any real device

**BUG 3: Silent DACL Failure**
- `set_volume_deny_all` requires admin privileges
- If both PnP disable AND DACL fail, no hard error surfaced

---

## Decisions Reached

### Fix Strategy
1. **Use SetupDi to resolve actual CM instance ID** from the device interface path, not construct it from VID/PID/serial
2. **Surface hard failures** — if PnP disable fails, log ERROR and return Err
3. **Handle `(none)` serial** via fallback location-based matching (match by VID+PID only)
4. **Integrate DACL result** — if both layers fail, return unified Err

### Scope
- Fix ONLY the PnP disable path
- Touch DACL layer only for error integration
- Apply to both hot-plug and startup scan paths
- No changes to disk enforcement, ABAC, or registry

### Reopened Status
User chose **Option B** (reopen 38.2) over creating a new phase or folding into 38.6.
