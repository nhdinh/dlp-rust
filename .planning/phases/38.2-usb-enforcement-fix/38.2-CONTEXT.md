# Phase 38.2: USB Enforcement Fix - PnP Disable Actually Works - Context

**Gathered:** 2026-05-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the USB enforcement gap where `CM_Disable_DevNode` fails silently because the constructed instance ID (`USB\VID_X\&PID_Y\SERIAL`) does not match Windows' actual location-based CM instance ID (e.g., `USB\VID_0951\&PID_1666\5\&12345678\&0\&0`). Ensure blocked USB devices are actually disabled at the PnP level so file I/O fails with OS-level access-denied.

This phase REOPENS the previously-archived Phase 38.2 because the original fix (thread-affinity correction + DACL defense-in-depth) did not address the fundamental instance ID mismatch that causes `CM_Locate_DevNodeW` to fail on every blocked device.

</domain>

<decisions>
## Implementation Decisions

### Root Cause Fix: Instance ID Resolution
- **D-01:** `DeviceController::disable_usb_device` MUST NOT construct the CM instance ID from VID/PID/serial. Instead, it MUST resolve the actual CM instance ID via SetupDi by matching the arriving device's interface path (`dbcc_name`) against the live device tree.
- **D-02:** Use `SetupDiGetClassDevsW(GUID_DEVINTERFACE_USB_DEVICE)` + `SetupDiEnumDeviceInfo` to enumerate present USB devices, then match by VID/PID/serial. The matched `SP_DEVINFO_DATA.DevInst` yields the correct device instance handle — OR use `CM_Get_Device_IDW` on the matched devinst to get the real instance ID string for `CM_Locate_DevNodeW`.
- **D-03:** If SetupDi enumeration fails or no matching device is found, log at `ERROR` level and return `Err` — do NOT silently return `Ok(())`. The only acceptable `Ok(())` case is when the device was already removed (`CR_NO_SUCH_DEVNODE` after a successful initial locate).

### `(none)` Serial Handling
- **D-04:** Devices with synthesized serials (`(none)`) MUST fall back to location-based matching. When serial is `(none)`, match only by VID + PID, then use the first matching device node's `DevInst` directly. Log a `warn` that enforcement is proceeding with a potentially ambiguous match.
- **D-05:** If multiple devices share the same VID+PID and both have `(none)` serial, log `ERROR` and return `Err` — do not disable an arbitrary device.

### Error Handling and Observability
- **D-06:** If PnP disable (`CM_Disable_DevNode`) fails, the DACL defense-in-depth layer (`set_volume_deny_all`) MUST still attempt. But if BOTH layers fail, the overall operation MUST return `Err` with a descriptive message.
- **D-07:** All enforcement outcomes (PnP disable success/failure, DACL success/failure, both-failure) MUST emit a structured `tracing::info!` or `tracing::error!` span with fields: `vid`, `pid`, `serial`, `drive_letter`, `tier`, `pnp_result`, `dacl_result`.

### Scope Constraints
- **D-08:** This phase fixes ONLY the PnP disable path. The DACL layer (`set_volume_deny_all`) is touched only to integrate its result into the unified error return. No changes to disk enforcement, disk registry, or ABAC evaluation.
- **D-09:** The fix applies to both hot-plug arrivals (via `device_watcher_wndproc` → `dispatch_usb_device_arrival`) and startup scan (`scan_existing_usb_identities`).

</decisions>

<specifics>
## Specific Ideas

- The correct approach is to pass the `dbcc_name` device path all the way through to `DeviceController`, then use SetupDi to resolve the actual `DevInst` or instance ID from that path. The current signature `disable_usb_device(vid, pid, serial)` discards the path too early.
- Consider changing `disable_usb_device` signature to accept either the full `DeviceIdentity` (with a new `instance_id` field) or the raw `dbcc_name` string.
- `enumerate_connected_usb_devices_windows()` in `dlp-common` already does the hard work of walking the PnP tree. Extract the "find devinst by VID/PID/serial" logic into a shared helper.

</specifics>

<deferred>
## Deferred Ideas

- Refactoring the entire `DeviceController` to use `DevInst` handles directly instead of instance ID strings — would eliminate string matching entirely but is a larger refactor than needed for this bug fix.
- Improving the DACL SDDL strings for more granular permissions — out of scope; current SDDL is sufficient for defense-in-depth.
- Adding a "test mode" where PnP disable is simulated without actually disabling devices — useful for UAT but belongs in a testing infrastructure phase.

</deferred>
