<objective>
Close the agent-side wiring gap identified in the v0.10.0 milestone audit: all consumers of the protected-path list must read from the server-pushed `AgentConfig.protected_paths` field instead of `AgentConfig.monitored_paths`. Also fix the path-normalization inconsistency between the staging table and the watcher so legitimate removals do not trigger spurious tamper alerts.

Purpose: Without this fix, admin-created protected paths are ignored by the NTFS DACL tripwire, repair watcher, bypass severity mapping, and hook-DLL classification cache, leaving the DPAPI-recovery backstop and real-time blocking layers ineffective.

Output: Modified `dlp-agent/src/service.rs` and `dlp-agent/src/dacl_staging.rs` with new unit tests proving the wiring and normalization.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server -> AgentConfig | HTTP/JSON config payload is the authoritative protected-path source |
| AgentConfig -> Enforcement subsystems | In-memory config field selection determines which paths receive NTFS/ABAC backstop protection |
| Agent -> NTFS | `SetFileSecurityW` writes Deny ACEs to disk based on the selected path list |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58.7-01 | Tampering | init_dacl_watcher path source | mitigate | Read `agent_config.protected_paths` instead of `monitored_paths`; verify with unit tests that monitored_paths is ignored (DACL-04). |
| T-58.7-02 | Elevation of Privilege | BypassCorrelator severity mapping | mitigate | Seed `with_protected_paths` from `cfg.protected_paths` so only admin-registered paths elevate bypass severity to crit (DACL-01). |
| T-58.7-03 | Denial of Service | Staging key mismatch | mitigate | Normalize paths to uppercase with trailing backslash before staging and watcher registration, preventing spurious `DaclTamperDetected` during legitimate removals (DACL-03). |
| T-58.7-04 | Information Disclosure | Log messages in watcher/cache | mitigate | Continue logging field names only; do not log full protected path values in info/warn messages. |
| T-58.7-05 | Spoofing | Classification cache root source | mitigate | `prepopulate_t3_t4_roots` uses `cfg.protected_paths` so hook DLL fail-closed decisions align with server-pushed backstop scope (CACHE-04). |
| T-58.7-SC | Tampering | npm/pip/cargo installs | accept | No new external packages are required; all dependencies are already declared and locked in Cargo.lock. |
</threat_model>
