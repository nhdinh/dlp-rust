<objective>
Close the agent-side wiring gap identified in the v0.10.0 milestone audit: all consumers of the protected-path list must read from the server-pushed `AgentConfig.protected_paths` field instead of `AgentConfig.monitored_paths`. Fix the path-normalization inconsistency between the staging table and the watcher so legitimate removals do not trigger spurious tamper alerts, validate server-pushed paths to reject traversal attempts, and migrate existing staging rows so in-flight removals are not orphaned by the new canonical key format.

Purpose: Without this fix, admin-created protected paths are ignored by the NTFS DACL tripwire, repair watcher, bypass severity mapping, and hook-DLL classification cache, leaving the DPAPI-recovery backstop and real-time blocking layers ineffective. Without migration and validation, an upgrade could leave stale staging rows unreachable or allow a path-traversal payload to escape the intended root.

Output: Modified `dlp-agent/src/service.rs` and `dlp-agent/src/dacl_staging.rs` with new unit tests proving the wiring, normalization, validation, and migration.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server -> AgentConfig | HTTP/JSON config payload is the authoritative protected-path source |
| AgentConfig -> Enforcement subsystems | In-memory config field selection determines which paths receive NTFS/ABAC backstop protection |
| Agent -> NTFS | `SetFileSecurityW` writes Deny ACEs to disk based on the selected path list |
| Server-pushed path -> normalize_protected_path | Untrusted string crosses into the agent before ACL application |

| T-58.7-02 | Elevation of Privilege | BypassCorrelator severity mapping | mitigate | Seed `with_protected_paths` from `cfg.protected_paths` so only admin-registered paths elevate bypass severity to crit (DACL-01). |
| T-58.7-03 | Denial of Service | Staging key mismatch | mitigate | Normalize paths to uppercase with trailing backslash before staging and watcher registration, preventing spurious `DaclTamperDetected` during legitimate removals (DACL-03). |
| T-58.7-04 | Information Disclosure | Log messages in watcher/cache | mitigate | Continue logging field names only; do not log full protected path values in info/warn messages. |
| T-58.7-05 | Spoofing | Classification cache root source | mitigate | `prepopulate_t3_t4_roots` uses `cfg.protected_paths` so hook DLL fail-closed decisions align with server-pushed backstop scope (CACHE-04). |
