<objective>
Refactor the DACL watcher lifecycle into a structured, shutdown-capable bundle and route protected_paths changes and graceful shutdown through a manager actor, establishing the compile-clean structural foundation required for runtime reinitialization.

Purpose: The current watcher init functions return a 9-tuple and the run loop stores nine individual DACL fields, making it impossible to atomically replace the watcher set at runtime. Without this structural refactor, Plan 58.7-03 cannot safely shut down the old watcher and create a new one when protected_paths changes.

Output: `dlp-agent/src/service.rs` contains `DaclWatcherBundle`, `DaclManagerCommand`, the `DaclWatcherManager` skeleton, updated `RunLoopContext` fields, and a passing compile-check gate.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server config push -> Agent | HTTP/JSON carries the authoritative protected_paths list |
| Agent internal -> DaclWatcherManager | Command channel crosses from config poll task to watcher lifecycle task |
| DaclWatcherManager -> NTFS | Reinit applies/removes Deny ACEs on disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58.7-06 | Denial of Service | DaclWatcherManager reinit loop | mitigate | `try_send` is used from config_poll_loop so a stuck manager cannot block config polling; shutdown awaits handles with bounded service shutdown timeout. |
| T-58.7-07 | Tampering | Old watcher left running after reinit | mitigate | `DaclWatcherBundle::shutdown` signals and awaits removal, gc, repair, and poll tasks before the manager replaces the bundle; `unregister_all` is invoked via shutdown. |
| T-58.7-SC | Tampering | npm/pip/cargo installs | accept | No new external packages are required; all dependencies are already declared and locked in Cargo.lock. |
</threat_model>
