# Phase 58.7 Plan 01: DACL protected_paths wiring gap closure

**Canonical protected-path normalization and migration, with all DACL watcher, bypass correlator, and classification-cache consumers wired to `AgentConfig.protected_paths`.**

## Performance

- **Duration:** 12 min
- **Started:** 2026-07-08T10:37:19Z
- **Completed:** 2026-07-08T10:49:52Z
- **Tasks:** 3
- **Files modified:** 2

## Accomplishments

- Added `NormalizeError` enum and `normalize_protected_path` helper that converts paths to uppercase with trailing backslash, rejects `..` segments as `Traversal`, and rejects relative paths as `NotAbsolute`.
- Updated `DaclStaging` mutation and query methods to use normalized keys, eliminating case/trailing-slash mismatches between the staging table and the watcher.
- Added `DaclStaging::migrate_staging_keys` invoked on construction to re-key existing raw-path staging rows to the canonical form.
- Wired `init_dacl_watcher` and `init_dacl_watcher_without_staging` to iterate `AgentConfig.protected_paths` instead of `AgentConfig.monitored_paths`.
- Wired `BypassCorrelator::with_protected_paths` and `ClassificationCache::prepopulate_t3_t4_roots` to `AgentConfig.protected_paths`.
- Added unit tests for normalization, migration, watcher source selection, traversal rejection, correlator wiring, and cache root wiring.

## Files Created/Modified

- `dlp-agent/src/service.rs` - Wired `init_dacl_watcher`, `init_dacl_watcher_without_staging`, `apply_payload_to_config`, `spawn_removal_application_task`, `BypassCorrelator`, and classification cache to `AgentConfig.protected_paths`; added unit tests.

## Decisions Made

- **Single canonical normalization helper:** All consumers call `normalize_protected_path` so the staging table, watcher, and cache agree on the same key format.
- **Automatic staging migration on startup:** `DaclStaging::new` calls `migrate_staging_keys` so existing in-flight removals remain reachable after the key-format change.
- **Graceful invalid-path handling:** Server-pushed relative or traversal paths are logged as audit warnings and filtered out rather than crashing the agent startup path.
