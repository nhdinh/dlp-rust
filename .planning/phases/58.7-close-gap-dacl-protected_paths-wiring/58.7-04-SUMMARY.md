# Phase 58.7 Plan 04: Agent-side DLP Deny ACE removal under per-path lock

**The agent now restores the original NTFS ACL from the stored canonical snapshot when a protected path is removed, with the full snapshot-lookup -> tripwire-removal -> mark-applied -> unregister sequence serialized under the per-path lock.**

## Accomplishments

- Added public `DaclWatcher::get_snapshot(&self, path: &Path) -> Option<CanonicalAclSnapshot>` that clones and returns the stored canonical snapshot for a registered path.
- Updated `spawn_removal_application_task` to normalize each staged removal path, acquire the per-path lock, retrieve the snapshot, call `remove_tripwire_from_path`, mark the staging row applied, and unregister the watcher.
- Made `DaclStaging::with_path_lock` public and introduced `mark_applied_locked` so the removal task can hold a single lock across the entire state transition without reentrancy.
- Added unit tests proving snapshot retrieval behavior and the removal task orchestration, including a concurrent repair/removal lock-scope test.

## Decisions Made

- **Single lock scope for the entire removal sequence:** `with_path_lock` covers `get_snapshot`, `remove_tripwire_from_path`, `mark_applied_locked`, and `unregister`, preventing races with the repair task.
- **`spawn_blocking` for the synchronous lock + Win32 ACL call:** The per-path lock and `SetFileSecurityW` are synchronous, so the async removal task offloads the work to a blocking thread.
- **Continue on tripwire removal error:** A failure to restore the ACL is logged but does not block `mark_applied` and `unregister`, avoiding an unbounded backlog of stuck staging rows.
