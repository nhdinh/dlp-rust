<objective>
Resolve the open research question about Deny ACE ownership by making the agent responsible for removing the DLP Deny ACE when a protected path is deleted. The removal application task currently assumes the server/TUI already restored the ACL; this plan closes that assumption gap by using the canonical ACL snapshot stored in `DaclWatcher` to drive `remove_tripwire_from_path` before the staging row is marked applied and the watcher is unregistered.

Purpose: Without agent-side removal, a deleted protected path can retain a lingering Deny ACE that blocks legitimate access even though the path is no longer in the policy. This undermines UAT F03 and leaves the system in an inconsistent state after operator-initiated removal.

Output: `dlp-agent/src/dacl_repair_watcher.rs` gains a public `get_snapshot` helper, and `dlp-agent/src/service.rs` `spawn_removal_application_task` removes the tripwire before finalizing staged removals.
</objective>
