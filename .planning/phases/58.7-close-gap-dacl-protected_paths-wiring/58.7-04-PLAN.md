<objective>
Resolve the open research question about Deny ACE ownership by making the agent responsible for removing the DLP Deny ACE when a protected path is deleted. The removal application task currently assumes the server/TUI already restored the ACL; this plan closes that assumption gap by using the canonical ACL snapshot stored in `DaclWatcher` to drive `remove_tripwire_from_path` before the staging row is marked applied and the watcher is unregistered. The entire per-path sequence runs under the per-path lock so a concurrent repair task cannot observe a partial state.

Purpose: Without agent-side removal, a deleted protected path can retain a lingering Deny ACE that blocks legitimate access even though the path is no longer in the policy. Without a defined lock scope, the repair task could race with removal and consume a snapshot that is removed by `unregister` before it finishes. This undermines UAT F03 and leaves the system in an inconsistent state after operator-initiated removal.

Output: `dlp-agent/src/dacl_repair_watcher.rs` gains a public `get_snapshot` helper, and `dlp-agent/src/service.rs` `spawn_removal_application_task` removes the tripwire under the per-path lock before finalizing staged removals.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Staging table -> removal task | SQLite row drives destructive ACL change |
| Removal task -> NTFS | `SetFileSecurityW` restores ACL based on stored snapshot |
| Repair task -> Removal task | Both touch the same path's snapshot and staging state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58.7-12 | Tampering | Staging table spoofed remove row | mitigate | Existing staging table is local SQLite; only `apply_payload_to_config` inserts rows after diffing protected_paths (DACL-03). |
| T-58.7-13 | Denial of Service | `remove_tripwire_from_path` fails and blocks removal loop | mitigate | Log the error and continue; mark applied so the row does not block future GC. |
| T-58.7-14 | Information Disclosure | Snapshot SDDL logged | mitigate | Log only path count and operation result; never log the SDDL string or full path values. |
| T-58.7-15 | Elevation of Privilege | Snapshot missing -> ACE left behind | mitigate | If `get_snapshot` returns None, log a warning and still mark applied/unregister; a subsequent Audit-mode reinit or manual runbook can clean the ACE. |
| T-58.7-16 | Tampering | Repair task races removal task on the same path | mitigate | The entire `get_snapshot` -> `remove_tripwire_from_path` -> `mark_applied` -> `unregister` sequence runs under `DaclStaging::with_path_lock`, serializing with the repair task. |
| T-58.7-SC | Tampering | npm/pip/cargo installs | accept | No new external packages are required; all dependencies are already declared and locked in Cargo.lock. |
</threat_model>
