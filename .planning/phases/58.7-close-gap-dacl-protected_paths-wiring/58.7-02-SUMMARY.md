# Phase 58.7 Plan 02: DACL watcher bundle and manager actor wiring

**Structured, shutdown-capable DaclWatcherBundle replaces the 9-tuple return type, and the run loop routes protected_paths changes and graceful shutdown through a manager actor.**

## Performance

- **Duration:** 48 min
- **Started:** 2026-07-08T10:58:44Z
- **Completed:** 2026-07-08T11:46:30Z
- **Tasks:** 3
- **Files modified:** 1

## Accomplishments

- Added `DaclWatcherBundle` with ten named `Option` fields covering watcher, repair task, polling backstop, staging, GC, and removal application handles.
- Added `DaclWatcherBundle::empty()` and async `shutdown()` that signals and awaits removal, GC, repair, and poll subsystems in lifecycle order.
- Changed `init_dacl_watcher` and `init_dacl_watcher_without_staging` to return `DaclWatcherBundle`, retaining the previously discarded poll backstop shutdown sender.
- Defined `DaclManagerCommand` enum with `Reinit` and `Shutdown` variants.
- Added `DaclWatcherManager` skeleton and `spawn_dacl_watcher_manager` helper that own the bundle and read commands from an mpsc channel.
- Replaced the nine individual `dacl_*` fields in `RunLoopContext` with `dacl_manager_tx` and `dacl_manager_handle`.
- Extended `spawn_config_poll_task` and `config_poll_loop` to accept and forward an `Option<mpsc::Sender<DaclManagerCommand>>`, signalling `Reinit` when `changed_fields` contains `"protected_paths"`.
- Updated `run_loop_shutdown` to send `Shutdown` to the manager and await its handle instead of shutting down individual watcher fields.
- Added unit tests for bundle empty/shutdown, return-type contract, Reinit signalling, unchanged-field guard, and RunLoopContext manager fields.

## Decisions Made

- **Bundle lifecycle ownership:** All watcher handles are grouped in `DaclWatcherBundle` so `DaclWatcherManager` can atomically own and replace the entire subsystem in Plan 58.7-03.
- **Non-blocking command signalling:** `try_send` is used for `Reinit` and `Shutdown` so config polling and service shutdown cannot be blocked by a stuck manager task.
- **Poll backstop retained:** The previously discarded `poll_shutdown` sender is now stored in the bundle, enabling full graceful shutdown.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `DaclWatcherManager::run` dropped the bundle before the loop**
- **Found during:** Task 1
- **Issue:** The initial skeleton assigned `let _ = bundle;` at the start of `run`, which meant `Shutdown` could not actually shut down the bundle even though the structural wiring compiled.
- **Fix:** Removed the `let _ = bundle;` placeholder so the manager owns the bundle for the loop lifetime; shutdown will be implemented in Plan 58.7-03 when `Shutdown` replaces the bundle and calls `bundle.shutdown().await`.
- **Files modified:** `dlp-agent/src/service.rs`
