**Notes:**
- One new MISSING test was identified: `test_removal_task_failure_retries` for the post-fix behavior where a failed `remove_tripwire_from_path` leaves the staging row unapplied so the next interval retries.
- This behavior is exercised in production code paths but lacks a dedicated unit test. Because failure injection into `remove_tripwire_from_path` requires mocking or a synthetic snapshot that the Windows API rejects, adding a fully hermetic test would require refactoring the removal task to accept a pluggable removal function (out of scope for validation-only work and would modify implementation files, which the auditor must not do).
- The retry behavior was verified manually via code inspection: `mark_applied_locked` and `watcher.unregister` are only called inside the `Ok(())` branch; `Err(_)` logs and returns, leaving `applied_at` null and the row eligible for the next poll cycle.
- All other verification rows are green.
