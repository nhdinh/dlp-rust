## Fixed Issues

### CR-01: `DaclWatcherBundle::shutdown` never stops watcher OS threads

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** 2cdfce23
**Applied fix:** Added `watcher.unregister_all()` after awaiting the repair, GC, watcher, and poll task handles in `DaclWatcherBundle::shutdown`, ensuring `ReadDirectoryChangesW` OS threads and directory handles are released on reinit/shutdown.

### CR-02: Staged removal rows are not cleared when a path is re-added

**Files modified:** `dlp-agent/src/service.rs`, `dlp-agent/src/dacl_staging.rs`
**Commit:** 65be52b0
**Applied fix:** Introduced `clear_staged_removals` in `dacl_staging.rs` and called it from `apply_payload_to_config` for every path in the computed `additions` set. Stale `operation='remove'` rows are now deleted when a path re-enters `protected_paths`, preventing a later removal task from silently unprotecting it.

### CR-03: `global_enforcement_mode` changes do not trigger DACL reinit

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** 79f41996
**Applied fix:** Extended `signal_dacl_reinit_if_needed` to also emit `DaclManagerCommand::Reinit` when `changed_fields` contains `"global_enforcement_mode"`, so Audit/Block transitions apply or remove tripwires at runtime.

### WR-01: `normalize_protected_path` rejects UNC paths with forward slashes

**Files modified:** `dlp-agent/src/dacl_staging.rs`
**Commit:** d81069c8
**Applied fix:** Moved the `path.replace('/', r"\")` slash conversion before the absolute-path check so that `//server/share/data` is recognised as a valid UNC path after normalization.

### WR-02: `BypassCorrelator::set_protected_paths` does not normalize inputs

**Files modified:** `dlp-agent/src/bypass_correlator.rs`
**Commit:** b59e64df
**Applied fix:** `set_protected_paths` now normalises each input with `crate::dacl_staging::normalize_protected_path` and drops invalid paths before storing them, ensuring the severity mapping uses canonical forms.

### WR-03: Failed tripwire removal still marks the staging row applied

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** 31f93add
**Applied fix:** Restructured `spawn_removal_application_task` so `mark_applied_locked` and `watcher.unregister` are only called when `remove_tripwire_from_path` succeeds. On failure the staging row remains unapplied and the task retries on the next interval.

### WR-04: `try_send` for `Reinit` can silently drop commands

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** f1fdd3e7
**Applied fix:** Replaced the bounded `tokio::sync::mpsc::channel::<DaclManagerCommand>(4)` with an unbounded `tokio::sync::mpsc::unbounded_channel` and changed all `try_send` calls to `send`. This guarantees `Reinit` and `Shutdown` commands are never dropped due to channel capacity.
