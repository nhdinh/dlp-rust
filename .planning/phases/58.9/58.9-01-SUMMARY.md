# Phase 58.9 Plan 01: Agent diagnostics producer primitives Summary

**Destructive `DiagnosticAggregator::drain_all` (owned, newest-first, guard-free across await) plus authenticated `ServerClient::submit_diagnostic_snapshot` POSTing `{pid, snapshots}` to `POST /agents/{id}/diagnostics` — the drain source and transport that Plan 03's periodic push loop wires together.**

## Accomplishments

- `DiagnosticAggregator::drain_all(&self) -> Vec<DiagnosticSnapshot>` (destructive, `#[must_use]`, full doc comment): collects keys, pre-sizes the output, `remove`s every `{pid}_{agent_id}` key, appends, and sorts by `timestamp_qpc` descending. After the call `dll_count()==0` and `total_snapshot_count()==0`; a second call is empty (proves at-most-once forwarding to the append-only store — RESEARCH Pitfall 2). No `DashMap` guard is held across a remove and none is returned, so callers may `.await` the HTTP push without a non-`Send` guard (Pitfall 4).
- `ServerClient::submit_diagnostic_snapshot(&self, agent_id, pid, snapshots) -> Result<(), ServerClientError>`: POSTs a lifetime-tied `DiagnosticsPayload<'a> { pid, snapshots }` (no batch clone) to `{base_url}/agents/{agent_id}/diagnostics` with header `Authorization: DLP-AGENT {agent_id}:{agent_auth_hash}`. Any non-2xx (incl. 429 and 5xx) maps to the existing `ServerClientError::ServerError { status, body }` — non-fatal; the 60 s loop retries next interval (A4). Logs only `agent_id`/`pid`/`count`, never snapshot contents (CLAUDE.md 9.13, T-58.9-01).
- Four unit tests added and green: `test_drain_all` (sorted-desc + emptied map + empty second drain + non-destructive `get_snapshots` unchanged) and three `submit_diagnostic_snapshot_*` tests on a local axum mock + the existing `unreachable_client()` harness (unreachable→Err; body has top-level `pid`+`snapshots` and round-trips a `DiagnosticSnapshot`; `Authorization` header equals `DLP-AGENT <id>:<hash>`).
- Crate gate green: `cargo test -p dlp-agent --lib test_drain_all` (1 passed), `cargo test -p dlp-agent --lib server_client` (43 passed incl. the 3 new + 3 health), `cargo clippy -p dlp-agent -- -D warnings` (clean), `cargo fmt -p dlp-agent --check` (clean).

## Decisions Made

- **`&self` (not `&mut self`) for `drain_all`:** matches the plan's signature and the DashMap interior-mutability model; Plan 03's loop calls it through an `Arc<DiagnosticAggregator>` shared reference, so `&mut self` would have forced an unnecessary exclusive borrow.
- **Non-fatal 429/5xx via existing `ServerError` variant:** reused `ServerClientError::ServerError { status, body }` for every non-2xx (including 429). No new variant and no `.context()` (CLAUDE.md 9.5 / 58.8-03 acceptance rule). Per RESEARCH A4, the per-agent rate limit is honored by the 60 s push cadence (Plan 03) plus this non-fatal mapping; the client stays a single-shot POST mirroring `submit_health_snapshot`.
- **Lifetime-tied `DiagnosticsPayload<'a>`:** borrows the drained slice for serialization instead of cloning the batch (big-O / allocation discipline per CLAUDE.md 9.11).
- **DIFF-04 NOT marked complete in REQUIREMENTS.md:** the requirement spans Plans 01-04; only Plan 04 proves criterion 3 end-to-end. Marking it complete now would overstate coverage. It will be marked complete at phase close.
