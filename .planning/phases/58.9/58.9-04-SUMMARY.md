## Decisions Made

- **Reuse, don't duplicate, test helpers:** the new 401/400 tests reuse `agent_auth_header`, `build_test_app`, `TEST_AGENT_ID`, `TEST_AGENT_AUTH_HASH` from `health_api_integration.rs`. Edits are confined to the single file in `files_modified`; no helper redeclaration, no new test file.
- **400 ≠ 401 (status-boundary discipline):** the mismatched-identity test asserts `BAD_REQUEST` (handler `agent_id != path_agent_id` at admin_api.rs:5668), explicitly NOT `UNAUTHORIZED`. The middleware owns 401 (no/wrong `Authorization`); the handler owns 400 (valid identity, wrong path id). Conflating them would mask an auth-layer regression (T-58.9-18 / Pitfall 3).
- **Field-level over presence:** the strengthened 200 test asserts per-field equality on the retrieved snapshot, so a future `diagnostic_store` change that drops/transforms a field fails the test immediately (T-58.9-20). Presence-only would let a structurally-broken but non-empty response pass.
- **No `REQUIREMENTS.md` update:** `.planning/REQUIREMENTS.md` does not exist (consistent with STATE decisions #339/#342/#348). DIFF-04 completion is tracked in ROADMAP.md; this plan supplies the end-to-end proof (criterion 3) that was the only outstanding item across Plans 01-04.
- **Scoped close-out over cosmetic churn:** the workspace fmt/clippy/test red legs are in files 58.9 never touched (3 fmt files + the `if_same_then_else` clippy file + 2 thread_suspender tests), and the one in-scope fmt nit (trampolines.rs:378) is rustfmt-version drift in safety-critical FFI code. Rather than reformat unrelated/safety-critical files in a bookkeeping commit, the failures are recorded transparently and filed as follow-ups. This honors scoped-commit discipline and the project's treatment of sonar as a non-gating environment blocker.
