<objective>
Implement the producer side of the cross-crate DIFF-04 feed (RESEARCH A1, IN-SCOPE): teach `dlp-hook-dll` to drain its lock-free `diagnostic_ring` on the existing pipe round-trip cadence and push the snapshots to the agent as a one-way `IpcPayloadV1::DiagnosticsResponse` frame. This is the only way `GET /admin/diagnostics` can ever become non-empty in production — the agent is the named-pipe **server** and cannot pull from the DLL, and `DiagnosticAggregator` is currently never fed. This plan is `dlp-hook-dll`-only and is parallelizable with Plan 01 (the agent client primitives).

Purpose: Without this emit, ROADMAP criterion 3 (end-to-end observability) cannot become TRUE regardless of the agent-side drain/push. The emit reuses the verified `HealthResponse` one-way transport (58.4) so it adds no new IPC surface and no bincode discriminant churn.
Output: `pipe_client::send_diagnostics`; `DIAGNOSTIC_EMIT_INTERVAL`/`DIAGNOSTIC_EMIT_COUNTER` (+ reset); extended `record_pipe_round_trip_and_maybe_emit`; tests proving best-effort, non-blocking emit.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hooked user process -> in-process `diagnostic_ring` | Deny-path producers write snapshots (paths/SIDs) into a lock-free ring shared inside the injected DLL. |
| hook DLL (named-pipe CLIENT) -> agent (named-pipe SERVER) | One-way `DiagnosticsResponse` frame crosses the process boundary over the named pipe; no response is read. |
| snapshot content (file paths / SIDs) | Sensitive per CLAUDE.md 9.13; must not be written to logs at info+ on either side. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58.9-05 | Spoofing | one-way `DiagnosticsResponse` from an arbitrary pipe client | mitigate (server side in Plan 03) | The agent keys ingest by `named_pipe_client_pid(pipe)` (the connecting client's REAL PID), never a DLL-supplied field; frame is non-authoritative telemetry. |
| T-58.9-06 | Tampering | forged/replayed one-way frame | accept | Frames are best-effort telemetry; deny decisions are NOT derived from them (mirrors `HealthResponse`/`BypassAlert` disposition). No integrity tag added to avoid new crypto surface. |
| T-58.9-07 | Denial of Service | deny path blocked on pipe I/O | mitigate | Emit is fire-and-forget via `send_raw_oneway`; bincode failure -> `PipeError::Malformed`, pipe failure swallowed by caller; never `await`/block the hooked file op. |
| T-58.9-08 | Information Disclosure | snapshot contents in DLL logs | mitigate | `debug_log` carries only the error string and a count-equivalent (`[dlp-hook] diagnostics send failed: {e}`); never log paths/SIDs. |
| T-58.9-09 | Denial of Service | unbounded ring drain per cadence tick | mitigate | `drain_snapshots(1000)` caps the batch to the ring capacity; empty drain short-circuits the send. |
| T-58.9-10 | Tampering | new IPC variant shifting bincode discriminants cross-crate | mitigate | Reuse `IpcPayloadV1::DiagnosticsResponse` (A2); NO new variant — preserves the DLL<->agent protocol and cross-crate (de)serialization. |
| T-58.9-SC | Tampering | cargo installs | mitigate | No new external packages; all dependencies already locked (RESEARCH Package Legitimacy Audit: N/A). |
</threat_model>
