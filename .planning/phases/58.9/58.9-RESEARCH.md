# Phase 58.9: Close gap: DIFF-04 — agent diagnostics producer - Research

**Researched:** 2026-07-10
**Domain:** Rust workspace — `dlp-agent` background push task + `dlp-hook-dll` one-way IPC emit + `dlp-common` IPC frame reuse, feeding the existing `dlp-server` `POST /agents/{id}/diagnostics` ingest (shipped in 58.8-02/04)
**Confidence:** HIGH (server contract + health template read directly from source) / MEDIUM (the cross-crate feed mechanism requires a planner scope decision — see Open Questions)

## Summary

Phase 58.8 shipped the authenticated server half of DIFF-04 (`POST /agents/{id}/diagnostics`, `DiagnosticSnapshotStore`, `GET /admin/diagnostics`, and the `dlp-admin-cli` self-health verification), and Phase 58.8-03 landed the agent health push template (`ServerClient::submit_health_snapshot` + `health_push_loop` + `watch`-based shutdown). The diagnostics producer is entirely missing: **nothing in `dlp-agent` drains `DiagnosticAggregator` to the server**, and — more fundamentally — **the agent's `DiagnosticAggregator` is never populated in production**. The hook DLL pushes deny-path snapshots into its own lock-free `diagnostic_ring` (`dlp-hook-dll/src/diagnostic_ring.rs`) but there is no one-way IPC frame carrying them to the agent and no `.ingest()` call site on the agent aggregator outside its own unit tests.

The verified, already-working template for this exact problem is the health path: DLL emits a one-way `IpcPayloadV1::HealthResponse` via `pipe_client::send_raw_oneway` (every `HEALTH_EMIT_INTERVAL = 100` round-trips and on fail-state transitions); the agent's `HookIpcServer` dispatch ingests it into `HealthAggregator` (`hook_ipc.rs:650-672`); `health_push_loop` reads `get_current_status()` every 60 s and POSTs via `submit_health_snapshot`; `run_loop_shutdown` signals a `watch::Sender<bool>` and joins the handle with a 5 s timeout. Phase 58.9 should mirror this end-to-end for diagnostics.

**Primary recommendation:** Implement diagnostics as a structural clone of the verified health pipeline across three crates: (1) `dlp-hook-dll` drains `diagnostic_ring` on the existing round-trip cadence and emits a one-way `IpcPayloadV1::DiagnosticsResponse{snapshots}` (reuse the existing variant — no bincode discriminant churn); (2) `dlp-agent` adds a `DiagnosticsResponse` dispatch arm that calls `diagnostic_aggregator.ingest(agent_id, pid, snapshots)` (pid from the existing `named_pipe_client_pid(pipe)` anti-spoof helper), a `DiagnosticAggregator::drain_all()` method, `ServerClient::submit_diagnostic_snapshot`, a `diagnostic_push_loop`, and shutdown wiring; (3) reuse `dlp-server/tests/health_api_integration.rs` as the round-trip test template and add diagnostics-specific 401/400 cases.

### Pattern 1: One-way IPC push (DLL → agent) — the established transport
**What:** The DLL builds an `IpcEnvelope::V1(IpcPayloadV1::X(...))`, bincode-serializes, length-prefixes, and writes via `send_raw_oneway`; it does not read a response. The agent dispatch returns a dummy ACK but the DLL has already closed the pipe.
**When to use:** Any fire-and-forget telemetry from DLL → agent where blocking the hooked file operation is unacceptable.
**Verified precedent:** `HealthResponse` (`hook_ipc.rs:648-672`), `BypassAlert` (`ntdll_patcher.rs:692-709`), `HashEvidence` (`pipe_client.rs:165-196`), `RequestOverride` (`trampolines.rs:247-306`). Diagnostics should be the fifth one-way frame, reusing `IpcPayloadV1::DiagnosticsResponse`.

### Pattern 2: Periodic drain-and-push with `watch` shutdown — the agent lifecycle
**What:** A `tokio::select!` loop over `interval.tick()` and `shutdown.changed()`; drain the aggregator, POST, log-and-continue on error; on shutdown do a final flush then return.
**When to use:** Every best-effort telemetry mirror from agent → server.
**Verified precedent:** `health_push_loop` (`service.rs:1721-1748`) + spawn (`service.rs:2303-2322`) + stop (`service.rs:5126-5138`).

### Anti-Patterns to Avoid
- **Non-destructive read for an append log:** Using `get_snapshots()` (clones, non-destructive, `diagnostic_aggregator.rs:108`) for the push would re-POST the same snapshots every interval. The server store is append-only with no dedup → `GET /admin/diagnostics` fills with duplicates. Use a destructive `drain_all()` (or a pushed-QPC high-water mark).
- **New IPC variant instead of reuse:** Adding `IpcPayloadV1::DiagnosticSnapshots` shifts every subsequent bincode discriminant and breaks cross-crate (de)serialization for the hook DLL ↔ agent protocol. Reuse `DiagnosticsResponse` (the project already does response-as-one-way for `HealthResponse`).
- **Blocking the deny path on pipe I/O:** The DLL emit must be fire-and-forget with errors swallowed (like health, `trampolines.rs:343-346`). Never `await`/block the hooked `WriteFile` on a pipe write.
- **Holding a `DashMap` guard across `.await`:** `DiagnosticAggregator` uses `DashMap`; its guards are not `Send` across await (see STATE decision on `DashMap` snapshots). `drain_all()` must collect into a `Vec` and drop guards before the push loop awaits the HTTP call.
- **Forgetting `RunLoopContext` literals:** Adding two fields breaks every `RunLoopContext { ... }` literal (production `run_loop_init` return ~`service.rs:2815-2880`, test literals ~`service.rs:6561-6620`, ~`7244-7255`). Discover with `rg "health_push_handle"` and update all — the 58.8-04 plan hit the analogous `AppState` literal problem across 12 files.

## Common Pitfalls

### Pitfall 1: Aggregator is never fed (the hidden half of the gap)
**What goes wrong:** A drain+push loop is added, the server round-trip test passes (it POSTs directly), but `GET /admin/diagnostics` stays empty in production because `DiagnosticAggregator` has no producer.
**Why it happens:** The deny path pushes to the DLL's `diagnostic_ring`, not the agent's aggregator; there is no `.ingest()` call on the agent aggregator in `dlp-agent/src` outside unit tests (verified by grep). The audit flags exactly this (`v0.10.0-MILESTONE-AUDIT.md:58`).
**How to avoid:** Treat the DLL one-way emit + agent ingest arm as in-scope for criterion 3 (see Open Questions). Add an agent-side assertion/test that a pushed `DiagnosticsResponse` frame increments `total_snapshot_count()`.
**Warning signs:** `total_snapshot_count()` is 0 after a deny workload; `diagnostic_push_loop` logs "no snapshots" every tick.

### Pitfall 2: Duplicate snapshots from non-destructive drain
**What goes wrong:** Using `get_snapshots()` for the push re-POSTs identical snapshots every 60 s; `GET /admin/diagnostics` grows without bound with repeats.
**Why it happens:** `get_snapshots` clones (`diagnostic_aggregator.rs:108-120`); the server store is append-only (`diagnostic_store.rs`, "pure INSERT").
**How to avoid:** Implement `drain_all()` that removes entries (or track `last_pushed_qpc` per key and filter `timestamp_qpc > last_pushed_qpc`).
**Warning signs:** Server `total_snapshot_count` climbs by the full agent count every interval even with no new denies.

### Pitfall 3: 401 vs 400 confusion in the auth contract
**What goes wrong:** Tests assert the wrong status for the two distinct rejections.
**Why it happens:** Two layers reject: `agent_auth_middleware` returns **401** for missing/wrong hash (`admin_api.rs:125-190`); the handler returns **400** for `agent_id != path` (`admin_api.rs:5668-5671`).
**How to avoid:** Mirror `health_api_integration.rs`: `post_agent_health_rejects_unauthenticated`→401 (no header), `post_agent_health_rejects_mismatched_agent_id`→400 (`DLP-AGENT different-agent:hash`). Add the diagnostics equivalents.
**Warning signs:** A 401 test that sends a mismatched-but-valid header (that's a 400, not 401).

### Pitfall 4: `DashMap` guard across `.await`
**What goes wrong:** `drain_all` holds a `dashmap::mapref` guard while the caller awaits `submit_diagnostic_snapshot` → compile error (`Guard` is not `Send`) or deadlock.
**Why it happens:** `DashMap` guards are not `Send` (STATE decision log).
**How to avoid:** `drain_all` returns an owned `Vec<DiagnosticSnapshot>` and drops all guards before any await; the push loop then awaits only on the `Vec`.
**Warning signs:** `future cannot be sent between threads safely` pointing at the push loop spawn.

### Pitfall 5: Cross-crate `RunLoopContext` / `HookIpcServer` literal drift
**What goes wrong:** Adding fields breaks compilation in tests and in `dlp-user-ui`-adjacent code that constructs these structs.
**Why it happened before:** 58.8-04 updated 13 `AppState` literals; 58.8-03 hit `RunLoopContext` test-initializer drift (58.8-03-SUMMARY deviation #2).
**How to avoid:** `rg "health_push_handle|with_health_aggregator|fn handle_connection"` and update every site in the same commit.
**Warning signs:** `cargo check -p dlp-agent` passes but `cargo test -p dlp-agent --no-run` fails on struct-literal field errors.

### Drain primitive to add on `DiagnosticAggregator` (mirrors `get_snapshots`, but destructive)
```rust
// Source: dlp-agent/src/diagnostic_aggregator.rs (storage shape lines 46-52, get_snapshots 108-120)
/// Removes and returns every buffered snapshot across all DLL keys.
///
/// Used by the periodic server-push task so each snapshot is forwarded exactly
/// once (the server store is append-only and does not deduplicate).
///
/// # Returns
///
/// All previously buffered snapshots, sorted by QPC timestamp descending
/// (most recent first). Empty keys are removed from the backing map.
#[must_use]
pub fn drain_all(&self) -> Vec<DiagnosticSnapshot> {
    // Collect keys first so we never hold a DashMap guard across a remove.
    let keys: Vec<String> = self.snapshots.iter().map(|e| e.key().clone()).collect();
    let total = keys.iter().map(|k| self.snapshots.get(k).map(|v| v.len()).unwrap_or(0)).sum();
    let mut out: Vec<DiagnosticSnapshot> = Vec::with_capacity(total);
    for key in keys {
        if let Some((_, mut v)) = self.snapshots.remove(&key) {
            out.append(&mut v);
        }
    }
    out.sort_by(|a, b| b.timestamp_qpc.cmp(&a.timestamp_qpc));
    out
}
```

### Server client method (mirror `submit_health_snapshot`)
```rust
// Source: dlp-agent/src/server_client.rs:443-481
pub async fn submit_diagnostic_snapshot(
    &self,
    agent_id: &str,
    pid: u32,
    snapshots: &[dlp_common::hook_ipc::DiagnosticSnapshot],
) -> Result<(), ServerClientError> {
    let url = format!("{}/agents/{}/diagnostics", self.base_url, agent_id);

    #[derive(Serialize)]
    struct DiagnosticsPayload<'a> {
        pid: u32,
        snapshots: &'a [dlp_common::hook_ipc::DiagnosticSnapshot],
    }

    let resp = self
        .client
        .post(&url)
        .header("Authorization", format!("DLP-AGENT {}:{}", agent_id, self.agent_auth_hash))
        .json(&DiagnosticsPayload { pid, snapshots })
        .send()
        .await?;

    if !resp.status().is_success() {
        let status = resp.status().as_u16();
        let body = resp.text().await.unwrap_or_else(|_| "<no body>".to_string());
        // 429 (rate-limited) and 5xx are non-fatal: the loop retries next interval.
        return Err(ServerClientError::ServerError { status, body });
    }
    debug!(agent_id = %agent_id, pid, count = snapshots.len(), "diagnostic snapshots submitted");
    Ok(())
}
```

```rust
// Source: dlp-agent/src/service.rs:1705-1748 (loop) and 5126-5138 (shutdown)
const DIAGNOSTIC_PUSH_INTERVAL: Duration = Duration::from_secs(60);

async fn diagnostic_push_loop(
    server_client: crate::server_client::ServerClient,
    diagnostic_aggregator: Arc<crate::diagnostic_aggregator::DiagnosticAggregator>,
    agent_id: String,
    interval: Duration,
    mut shutdown: tokio::sync::watch::Receiver<bool>,
) {
    let mut interval = tokio::time::interval(interval);
    loop {
        tokio::select! {
            _ = interval.tick() => {
                let snapshots = diagnostic_aggregator.drain_all();
                if snapshots.is_empty() {
                    debug!("no diagnostic snapshots to push");
                    continue;
                }
                // Attribute the batch to pid 0 (aggregate) — server keys per {pid}_{agent_id};
                // individual per-pid attribution is preserved inside each snapshot's abac fields.
                if let Err(e) = server_client
                    .submit_diagnostic_snapshot(&agent_id, 0, &snapshots)
                    .await
                {
                    warn!(error = %e, count = snapshots.len(), "failed to submit diagnostics");
                }
            }
            _ = shutdown.changed() => {
                // Flush-and-stop: forward whatever is buffered before exiting.
                let snapshots = diagnostic_aggregator.drain_all();
                if !snapshots.is_empty() {
                    let _ = server_client
                        .submit_diagnostic_snapshot(&agent_id, 0, &snapshots)
                        .await;
                }
                debug!("diagnostic push loop shutting down");
                return;
            }
        }
    }
}
```
Spawn/stop wiring is a line-for-line mirror of `service.rs:2303-2322` and `service.rs:5126-5138` with renamed fields (`diagnostic_push_shutdown`, `diagnostic_push_handle`).

### Known Threat Patterns for {Rust agent↔server ingest + named-pipe IPC}

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Forged diagnostics from a non-agent | Spoofing | `agent_auth_middleware` requires the enrolled `DLPAuthHash`; spoofing needs the secret |
| Agent posts snapshots for another agent | Tampering / EoP | Handler `agent_id == path` check (400) |
| Flooding `POST /agents/{id}/diagnostics` | DoS | `rate_limiter::per_agent_config()` (429) + 60 s client cadence + server per-DLL/key caps |
| Hooked process spoofs another pid's snapshots | Spoofing | Agent keys ingest by `named_pipe_client_pid(pipe)` (the connecting client's real PID), not a DLL-supplied field |
| Snapshot contents (file paths/SIDs) leaked in logs | Information Disclosure | Log counts/ids only; snapshot bodies at `debug` or not at all (CLAUDE.md 9.13) |
| Replayed one-way IPC frame | Tampering | Frames are best-effort telemetry (non-authoritative); deny decisions are not derived from them — accept (mirrors `HealthResponse`/`BypassAlert` disposition) |
