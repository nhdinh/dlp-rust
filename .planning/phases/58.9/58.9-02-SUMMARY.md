## Decisions Made

- **Reuse, don't extend, `IpcPayloadV1`:** the emit constructs the existing `IpcPayloadV1::DiagnosticsResponse` variant (a "response" variant used as a one-way push — the `HealthResponse` precedent from 58.8-03). Adding a new variant (e.g. `DiagnosticSnapshots`) would shift bincode discriminants for the entire DLL<->agent protocol and break cross-crate (de)serialization. `dlp-common/src/hook_ipc.rs` is therefore byte-for-byte unchanged (verified: empty `git diff -- dlp-common/src/hook_ipc.rs`).
- **Best-effort, non-blocking by construction:** `send_raw_oneway` already caps connect at 50 ms and reads no reply; `send_diagnostics` maps bincode failure to `PipeError::Malformed`; the cadence site calls it inside `if let Err(e) = ... { debug_log(...) }` and never propagates the error to the hooked operation. The deny path's latency and decision logic are unaffected.
- **Bounded drain:** `drain_snapshots(1000)` caps each tick at the ring capacity and the `if !snapshots.is_empty()` guard skips the send entirely when the ring is empty, so a quiet process pays only one `fetch_add` + one `is_multiple_of` per round-trip.
- **DIFF-04 not marked complete:** consistent with the phase decision recorded in STATE.md (`[Phase 58.9]: DIFF-04 not marked complete ... after Plan 01`) — DIFF-04 spans Plans 01-04 and criterion 3 (end-to-end `GET /admin/diagnostics`) is only proven by Plan 04. There is also no main-repo `REQUIREMENTS.md` to update (it exists only inside a worktree). Marking complete now would overstate coverage.
- **Two-commit split despite Task-1-in-isolation `dead_code`:** Task 1 introduces `pub` items that Task 2 consumes; compiled alone they trip `-D dead_code` under `-D warnings`. The plan-mandated gate runs on the FINAL tree (both commits landed), which is clippy-clean. Committing in dependency order (Task 1 -> Task 2) keeps each commit a coherent logical unit; the intermediate state is not required to pass clippy (see Issues).
