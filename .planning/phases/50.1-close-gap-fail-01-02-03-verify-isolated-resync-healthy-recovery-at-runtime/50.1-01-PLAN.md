## Review Feedback Addressed

- **CacheHeader ABI divergence (HIGH):** Agent CacheHeader gains `allowlist_offset: u64` and `allowlist_count: u64` fields, shrinking `_reserved` from `[u8; 40]` to `[u8; 24]` to match hook-dll exactly. Both `compute_checksum` implementations XOR the same fields in the same order. Verified by static assertions that `size_of::<CacheHeader>() == 128` in both crates.
- **Background thread lifecycle (HIGH):** `shutdown_background_thread()` now joins the thread with a 5-second timeout using `JoinHandle::join()` (not just `SetEvent` + drop). A test-only `reset_background_thread_for_test()` helper uses `unsafe` pointer write to reset the `OnceLock` inner cell, making sequential tests safe. Addresses review concern: "sequential tests would leave a dangling thread polling unmapped memory."
- **Hardcoded CACHE_NAME (MEDIUM):** `#[cfg(test)] const CACHE_NAME: &str = "Global\\DlpClassificationCache_TestPhase50_1"` added to hook-dll. Agent gains `ClassificationCache::new_with_name(name: &str)` constructor for test use. Prevents test/live agent collision.
- **Staleness test scope (MEDIUM):** `stale_cache_triggers_isolated` test validates `is_cache_stale()` helper directly. The full pipe-client-driven staleness transition (where the pipe client checks staleness before each operation and calls `record_pipe_failure`) is documented as a deferred gap in the plan rationale — it requires plumbing the staleness check into the pipe client hot path, which is out of scope for this test-only phase.
- **Timing assertions (LOW):** All background-thread detection timeouts increased from 500ms to 2000ms, with comments explaining the 100ms polling interval (worst case = 20 polls + scheduling jitter).
