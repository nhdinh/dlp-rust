## Fixed Issues

### CR-01: CacheHeader ABI alignment depends on manual field ordering

**Files modified:** `dlp-common/src/classification_cache.rs`, `dlp-common/src/lib.rs`, `dlp-agent/src/classification_cache.rs`, `dlp-hook-dll/src/classification_cache.rs`
**Commit:** 4012f9e
**Applied fix:** Extracted `CacheHeader`, `PrefixEntry`, and `HashEntry` into `dlp-common::classification_cache` as a single source of truth. Both `dlp-agent` and `dlp-hook-dll` now import the same struct definitions. Compile-time static assertions (`size_of == 128`, `align_of == 8`, etc.) are defined in `dlp-common` and apply to all consumers. This eliminates the latent risk of silent ABI drift from copy-pasted definitions.

### CR-02: THREAD_STARTED flag can desynchronize from BACKGROUND_THREAD state

**Files modified:** `dlp-hook-dll/src/background_thread.rs`, `dlp-hook-dll/src/lib.rs`, `dlp-hook-dll/Cargo.toml`
**Commit:** 4fc0e67 (fixed in prior run)
**Applied fix:** Replaced the split `AtomicBool` + `Mutex<Option<...>>` design with a single `Mutex<ThreadState>` enum (`NotStarted | Starting | Running(BackgroundThread)`). All state transitions are now atomic, preventing split-brain between the flag and the mutex. This prevents leaked threads or double-starts during DLL lifecycle.

### WR-01: shutdown_background_thread busy-waits for 5 seconds

**Files modified:** `dlp-hook-dll/src/background_thread.rs`
**Commit:** 4fc0e67 (fixed in prior run)
**Applied fix:** Replaced the busy-wait loop (`while start.elapsed().as_secs() < 5 { sleep(10ms) }`) with `WaitForSingleObject` on the thread handle with a timeout. On timeout expiration, a warning is logged and the thread is detached rather than blocking forever. This is more efficient and precise.

### WR-02: reset_background_thread_for_test is not gated by #[cfg(test)]

**Files modified:** `dlp-hook-dll/src/background_thread.rs`, `dlp-hook-dll/src/lib.rs`, `dlp-hook-dll/Cargo.toml`
**Commit:** 4fc0e67 (fixed in prior run)
**Applied fix:** Gated `reset_background_thread_for_test` behind `#[cfg(any(test, feature = "test-helpers"))]`. The `test-helpers` feature is enabled in `[dev-dependencies]` so integration tests can access it, but production builds exclude the function entirely. This prevents accidental production calls that would shut down the background thread mid-operation.

### WR-03: is_cache_stale ignores tier-specific budgets and always uses T4

**Files modified:** `dlp-hook-dll/src/fail_mode.rs`, `dlp-hook-dll/tests/isolated_resync_recovery.rs`
**Commit:** 210ca51
**Applied fix:** Added `classification: Classification` parameter to `is_cache_stale` and replaced the hardcoded `STALENESS_BUDGETS[3]` (T4=30s) with `staleness_budget_for(classification)`. All call sites (unit tests and integration tests) were updated to pass `Classification::T4` to maintain existing behavior. This enables correct tier-specific staleness decisions (T1=30min, T2=5min, T3=60s, T4=30s) and prevents unnecessary fail-closed denials for lower-tier data.
