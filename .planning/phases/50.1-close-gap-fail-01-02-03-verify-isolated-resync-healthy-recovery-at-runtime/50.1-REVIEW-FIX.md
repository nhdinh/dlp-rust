## Fixed Issues

### CR-01: Race Condition - Shutdown Silently Ignored During Thread Startup

**Files modified:** `dlp-hook-dll/src/background_thread.rs`
**Commit:** cc9d162
**Applied fix:** Kept the mutex locked across the entire startup sequence (event creation, thread spawn, and Running state transition) instead of dropping it in the middle. This eliminates the window where `shutdown_background_thread` could see `Starting` and return early while the thread was about to be spawned.

### CR-02: Use-After-Free Risk in Background Thread Cache Header Access

**Files modified:** `dlp-hook-dll/src/background_thread.rs`, `dlp-hook-dll/src/trampolines.rs`, `dlp-hook-dll/tests/isolated_resync_recovery.rs`
**Commit:** 8c3052b
**Applied fix:** Added an optional `Arc<AtomicBool>` `mapping_valid` parameter to `start_background_thread()` and `background_thread_loop()`. The thread checks this flag with `Ordering::Acquire` before dereferencing the cache header. Callers pass `None` when the mapping lifetime is managed externally (current behavior). This provides a hook for future callers to signal mapping invalidation safely.

### CR-03: Thread Handle Leak and Struct Inconsistency in Shutdown

**Files modified:** `dlp-hook-dll/src/background_thread.rs`
**Commit:** da4e5c7
**Applied fix:** Replaced `std::mem::replace` on just the `JoinHandle` with taking the entire `BackgroundThread` struct from the mutex and transitioning to `NotStarted` atomically. The placeholder thread is no longer spawned. Also explicitly closes the event handle after shutdown to prevent handle leaks.

### WR-01: Dead Code - decide_resync Never Called in Production

**Files modified:** `dlp-hook-dll/src/trampolines.rs`, `dlp-hook-dll/src/fail_mode.rs`
**Commit:** afbdc55
**Applied fix:** Wired `decide_resync()` into the RESYNC decision path in `classify_and_log_path()` in trampolines.rs, replacing the inline duplicated logic. Removed the `#[allow(dead_code)]` attribute from `decide_resync` since it is now called from production code.

### WR-02: Stale Cache Transition Not Wired into State Machine

**Files modified:** `dlp-hook-dll/src/fail_mode.rs`
**Commit:** 025f257
**Applied fix:** Added `transition_if_cache_stale()` method to `FailModeState` that checks cache staleness via `is_cache_stale()` and forces `DEGRADED -> ISOLATED` (or `HEALTHY -> ISOLATED`) when the cache exceeds the tier-specific budget. This wires the "failures >= 10 OR cache stale" guard into the state machine for callers that have access to cache header data.

### WR-03: Unsafe set_state Exposed as Public API Without Test Gating

**Files modified:** `dlp-hook-dll/src/fail_mode.rs`
**Commit:** 107e09f
**Applied fix:** Added `#[cfg(any(test, feature = "test-helpers"))]` to `set_state()` so it is only available in test builds. This prevents production code from bypassing the hysteresis and safety checks.

### WR-04: LRU Cache Count Not Decremented on Invalidation

**Files modified:** `dlp-hook-dll/src/classification_cache.rs`
**Commit:** 965788f
**Applied fix:** When `LruCache::get` finds a version mismatch, it now clears the entry fully (path, classification, version) and decrements `count` if greater than zero. This prevents `count` from monotonically growing to 128 and causing unnecessary full scans of cleared slots.

### WR-05: Missing Drop Implementation for BackgroundThread

**Files modified:** `dlp-hook-dll/src/background_thread.rs`
**Commit:** d827018
**Applied fix:** Implemented `Drop` for `BackgroundThread` that calls `CloseHandle` on the shutdown event. Changed struct fields to `Option<T>` so that `shutdown_background_thread` can use `std::mem::take` to extract ownership without moving out of a struct with `Drop`. This prevents event handle leaks if the struct is dropped without explicit shutdown.
