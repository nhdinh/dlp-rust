  <name>Task 1: Harden disk enumeration per-disk IOCTL error handling (OP-01)</name>
  <files>dlp-common/src/disk.rs, dlp-agent/src/detection/disk.rs</files>
  <behavior>
    - Test 1: enumerate_fixed_disks_windows continues enumeration when query_bus_type_ioctl fails for one disk (logs error with instance_id, skips disk, continues loop)
    - Test 2: disk_number_for_instance_id returns Err(DiskError::DeviceOpenFailed) when CreateFileW fails, instead of silently returning None
    - Test 3: find_drive_letter_for_instance_id returns None when disk_number_for_instance_id returns Err (no panic)
    - Test 4: spawn_disk_enumeration_task does not abort service when enumerate_fixed_disks returns Err (retries with backoff, continues to next poll)
  </behavior>
  <action>
    ## dlp-common/src/disk.rs changes:

    1. In `enumerate_fixed_disks_windows()`, wrap the per-disk IOCTL call (`query_bus_type_ioctl`) in error handling:
       - On `Err(e)`: emit `tracing::error!(instance_id = %instance_id, error = %e, "IOCTL_STORAGE_QUERY_PROPERTY failed for disk -- skipping")` and `continue` to next disk (do NOT push a DiskIdentity for this disk).
       - The existing `resolve_bus_type_with_pnp_override` call already handles `Err` from `query_bus_type_ioctl` by falling back to PnP walk. Keep that behavior but add explicit logging when BOTH signals fail.

    2. In `disk_number_for_instance_id()`, when `CreateFileW` returns `Err`, log the error with `tracing::warn!(instance_id = %instance_id, error = %e, "failed to open disk device handle")` and continue enumeration (do NOT return early).
       - When the loop completes without finding a disk number, return `Err(DiskError::DeviceOpenFailed(format!("could not open device handle for instance_id: {instance_id}")))`.

    3. In `find_drive_letter_for_instance_id()`, ensure the `match disk_number_for_instance_id(instance_id)` arm handles `Err` gracefully (already returns `None` with a warn log). Verify this is the case -- no changes needed if already correct.

    4. In `query_bus_type_for_handle()`, when `DeviceIoControl` fails, include the Win32 error code in the error message: `DiskError::IoctlFailed(format!("DeviceIoControl failed: {e}"))`.

    ## dlp-agent/src/detection/disk.rs changes:

    5. In `spawn_disk_enumeration_task()`, verify that the retry loop already handles `enumerate_fixed_disks()` failure without aborting service. The current code retries 3 times then emits an Alert and returns. Confirm this satisfies "Service startup does not abort if disk enumeration fails". Add a comment documenting this behavior explicitly.

    6. In `on_disk_arrival()`, the existing error handling already logs and returns on `enumerate_fixed_disks()` failure. Verify the log includes the `device_path` for troubleshooting. No changes needed if already correct.

    ## Key constraints:
    - NEVER use `.unwrap()` or `.expect()` on Win32 API results in the enumeration path.
    - Every error log MUST include the failing `instance_id`.
    - The enumeration loop MUST continue to the next disk on any per-disk failure.
  </action>

  <name>Task 2: Add structured tracing spans to USB enforcement (OP-02)</name>
  <files>dlp-agent/src/usb_enforcer.rs, dlp-agent/src/detection/usb.rs</files>
  <behavior>
    - Test 1: UsbEnforcer::check emits tracing::info! with device identity (vid, pid, serial), trust tier, file action variant, and decision when blocking an unregistered device
    - Test 2: UsbEnforcer::check emits tracing::info! with device identity and decision=ALLOW when a registered FullAccess device is encountered
    - Test 3: apply_tier_enforcement emits tracing::debug! for PnP disable attempt with NTSTATUS/Win32 error code on failure
    - Test 4: apply_tier_enforcement emits tracing::debug! for DACL operations with success/failure status
    - Test 5: Error cases in apply_tier_enforcement emit tracing::error! with structured context (vid, pid, serial, drive, tier, error)
  </behavior>
  <action>
    ## dlp-agent/src/usb_enforcer.rs changes:

    1. In `UsbEnforcer::check()`, add structured `tracing::info!` spans for ALL decision paths:

       a. **Unregistered device (default-deny path)** -- BEFORE returning `Some(UsbBlockResult)`:
          ```rust
          tracing::info!(
              vid = %identity.vid,
              pid = %identity.pid,
              serial = %identity.serial,
              drive = %drive,
              action = ?std::mem::discriminant(_action),
              tier = ?UsbTrustTier::Blocked,
              decision = ?Decision::DENY,
              rule = "default-deny: unregistered device",
              "USB enforcement decision"
          );
          ```

       b. **Registered device (allow path)** -- BEFORE returning `None` for registered devices, add:
          ```rust
          tracing::info!(
              vid = %identity.vid,
              pid = %identity.pid,
              serial = %identity.serial,
              drive = %drive,
              action = ?std::mem::discriminant(_action),
              tier = ?UsbTrustTier::FullAccess, // or the actual tier from registry
              decision = ?Decision::ALLOW,
              rule = "registered device: FullAccess",
              "USB enforcement decision"
          );
          ```
          NOTE: For registered devices, the actual tier is looked up by `registry.has_device()`. To get the tier, query `registry.trust_tier_for(&identity.vid, &identity.pid, &identity.serial)` and include it in the span. If the registry API does not expose tier lookup directly, use `has_device` result to infer: if registered, look up tier via `trust_tier_for`.

       c. **Known-USB-without-identity path** (defence-in-depth, `blocked_drives.contains(&drive)` but no identity):
          ```rust
          tracing::info!(
              drive = %drive,
              action = ?std::mem::discriminant(_action),
              tier = ?UsbTrustTier::Blocked,
              decision = ?Decision::DENY,
              rule = "default-deny: known USB without captured identity",
              "USB enforcement decision"
          );
          ```

    2. Add a helper method `resolve_tier_for_identity(&self, identity: &DeviceIdentity) -> UsbTrustTier` to `UsbEnforcer` that queries the registry cache for the tier, returning `UsbTrustTier::Blocked` if not registered.

    ## dlp-agent/src/detection/usb.rs changes:

    3. In `apply_tier_enforcement()`, enhance logging:

       a. **Before PnP disable attempt** (Blocked tier):
          ```rust
          tracing::debug!(
              vid = %identity.vid,
              pid = %identity.pid,
              serial = %identity.serial,
              drive = %letter,
              tier = "Blocked",
              action = "PnP disable",
              "applying tier enforcement"
          );
          ```

       b. **On PnP disable failure**: include the raw error in the existing `error!` log. The current code already logs at error level; ensure the error message includes the Win32/NTSTATUS context if available. Since `controller.disable_usb_device()` returns `Result<(), String>`, the error string IS the context -- log it as `error = %e`.

       c. **Before DACL deny-all attempt** (Blocked tier defense-in-depth):
          ```rust
          tracing::debug!(
              drive = %letter,
              action = "DACL deny-all",
              "applying tier enforcement defense-in-depth"
          );
          ```

       d. **On DACL failure**: the existing `error!` log already captures this. Ensure it includes `drive = %letter` and `error = %e`.

       e. **ReadOnly tier**: before `set_volume_readonly`, add:
          ```rust
          tracing::debug!(
              drive = %letter,
              action = "DACL read-only",
              "applying tier enforcement"
          );
          ```

       f. **FullAccess tier**: the existing `debug!` log is sufficient but enhance to include `action = "none"`.

    4. Ensure all `tracing::error!` calls in `apply_tier_enforcement` include the full structured context: `vid`, `pid`, `serial`, `drive`, `tier`, `error`.

    ## Key constraints:
    - Use `tracing::info!` for all `UsbEnforcer::check` decisions (both block and allow).
    - Use `tracing::debug!` for all `apply_tier_enforcement` internal operations (PnP disable, DACL ops).
    - Use `tracing::error!` for all failure paths with full context.
    - The `rule` field in info spans MUST be a human-readable string describing the decision rationale.
    - Do NOT change the return types or public API of any function.
