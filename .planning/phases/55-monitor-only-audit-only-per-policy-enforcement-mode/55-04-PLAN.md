<objective>
Make the DACL tripwire mode-aware so Audit-mode policies get no Deny ACE, while Block and AuditAndBlock policies continue to be kernel-enforced.

Purpose: Without this, Audit mode would still block at the kernel level via NTFS DACL, making monitor mode useless. This plan ensures the tripwire respects the same effective mode as the hook DLL.
Output: Tripwire filters protected paths by effective mode before writing Deny ACEs; repair watcher uses the same filter.
</objective>

  <files>dlp-agent/src/dacl_tripwire.rs</files>

  </read_first>
  <action>
    The tripwire currently operates on a list of `ProtectedPathConfig` items. The filtering should happen BEFORE calling tripwire functions, not inside them (per D-01 in CONTEXT.md: "Audit mode policies get no Deny ACE").

    Add a helper function `filter_protected_paths_by_mode(paths: &[ProtectedPathConfig], global_mode: &str) -> Vec<&ProtectedPathConfig>` to `dlp-agent/src/dacl_tripwire.rs`:
    - If global_mode == "Audit", return empty vec (no Deny ACEs for any path)
    - If global_mode == "Block" or "PerPolicy", return all paths (all get Deny ACEs)
    - If global_mode == "AuditAndBlock", return all paths (all get Deny ACEs)
    - Note: Per-policy granularity requires the agent to know each path's policy enforcement_mode. Since ProtectedPathConfig currently only has id/path/tier/source, and the agent receives policies via the hook IPC path (not directly for tripwire), the practical implementation is: global_mode="Audit" -> no ACEs; anything else -> all paths. Per-policy mode filtering for tripwire is deferred to when ProtectedPathConfig carries enforcement_mode (see deferred ideas in CONTEXT.md).

    However, per RESEARCH.md Pattern 1 and CONTEXT.md D-01, the agent DOES receive policies via policy_sync. The agent should filter protected paths by checking if any policy that covers that path is in Audit mode. For Phase 55, the simpler and correct approach per RESEARCH.md is:
    - The agent's `ProtectedPathConfig` items come from the server payload
    - The server already computes effective mode in PolicyStore::evaluate()
    - For the tripwire, the agent should filter the protected_paths list by checking the global_mode first, then by per-policy mode if available

    Since ProtectedPathConfig does NOT currently carry enforcement_mode, the Phase 55 implementation is:
    - Add `#[serde(default)] pub enforcement_mode: String` to `ProtectedPathConfig` in `dlp-server/src/admin_api.rs` (this was done in Plan 55-02 Task 2)
    - In the agent, filter: if global_mode == "Audit" -> empty; else if path.enforcement_mode == "Audit" -> skip; else -> include

    Update `apply_tripwire_to_path` and `apply_tripwire_recursive` signatures to accept an optional `effective_mode: EnforcementMode` parameter (or add a wrapper function). The simpler approach: add a free function `should_apply_tripwire_for_mode(global_mode: &str, path_mode: Option<&str>) -> bool` that returns false only when the effective mode is Audit.

    Add unit tests:
    - `test_should_apply_tripwire_audit_mode_returns_false`
    - `test_should_apply_tripwire_block_mode_returns_true`
    - `test_should_apply_tripwire_perpolicy_with_audit_path_returns_false`
    - `test_should_apply_tripwire_perpolicy_with_block_path_returns_true`
  </action>
  <verify>
    <automated>cargo test -p dlp-agent -- dacl_tripwire -- mode</automated>
  </verify>
  <done>should_apply_tripwire_for_mode helper correctly filters Audit-mode paths; all unit tests pass.</done>
  <acceptance_criteria>
    - `should_apply_tripwire_for_mode` function exists in `dacl_tripwire.rs`
    - Returns false when global_mode is "Audit"
    - Returns false when global_mode is "PerPolicy" and path_mode is "Audit"
    - Returns true for all other combinations (Block, AuditAndBlock)
