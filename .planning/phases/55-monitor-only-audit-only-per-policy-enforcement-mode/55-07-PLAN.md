  <action>
    Create or extend an integration test that verifies the full round-trip:

    1. Create a policy via `POST /admin/policies` with `enforcement_mode: "Audit"`
    2. Verify the response contains `enforcement_mode: "Audit"`
    3. Update the policy via `PUT /admin/policies/:id` with `enforcement_mode: "Block"`
    4. Verify the response contains `enforcement_mode: "Block"`
    5. Update the policy via `PUT /admin/policies/:id` with `enforcement_mode: "AuditAndBlock"`
    6. Verify the response contains `enforcement_mode: "AuditAndBlock"`
    7. Fetch the agent config via `GET /agent/config` and verify the policy in the payload has the correct `enforcement_mode`
    8. Set global_enforcement_mode to "Audit" via system_kv update
    9. Fetch agent config again and verify `global_enforcement_mode: "Audit"`
    10. Evaluate a request against the policy via the evaluate endpoint (if exposed) or verify the policy_store cache contains the correct mode

    The test should use the existing integration test harness (in-memory SQLite, test JWT tokens, etc.).

    Name the test `test_enforcement_mode_round_trip`.

    Also add a test `test_enforcement_mode_backward_compat`:
    - POST a policy WITHOUT enforcement_mode in the payload
    - Verify the response defaults to `enforcement_mode: "Block"`
  </action>
