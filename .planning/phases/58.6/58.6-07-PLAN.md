## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58.6-18 | Information Disclosure | Telemetry file paths | mitigate | Hash the triggering file/image path with SHA-256 before placing it in `AuditEvent::resource_path`; keep `application_path` empty and do not include raw paths in `details`. |
| T-58.6-19 | Denial of Service | Audit emit blocks injection/telemetry loop | mitigate | Audit emission is synchronous best-effort via `emit_audit`; failures are logged and ignored so they cannot delay enforcement or the periodic telemetry task. |
| T-58.6-20 | Repudiation | Missing coverage evidence | mitigate | Event-level `t3t4_event_covered`/`t3t4_event_missed` counters in `ProcessRegistry` and periodic `TargetedInjectionTelemetry` events provide tamper-evident coverage proof. |
| T-58.6-H03 | Information Disclosure | Server drops `details` payload | mitigate | Add `details` column to SQLite schema, `AuditEventRow`, `store_events_sync`, query responses, SIEM relay, and alert router. |
| T-58.6-R2 | Tampering | Audit schema change breaks deserialization | mitigate | `details` is optional with `serde(default)`; new `EventType` variants are appended and serialized as SCREAMING_SNAKE_CASE. |
| T-58.6-R7 | Information Disclosure | `details` included in chain hash | accept | Intentional: `details` contains operational telemetry with hashed paths and no raw PII, so including it in the chain strengthens tamper evidence. Documented in code comment per review finding. |
| T-58.6-R9 | Information Disclosure | SHA-256 path dictionary attack | accept | SHA-256 is the project-standard hash used elsewhere for audit path hashing; switching to HMAC is deferred to a hardening phase because it requires key distribution outside this phase's scope. |
</threat_model>
