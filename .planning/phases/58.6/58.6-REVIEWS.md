## Codex Review

### Summary

The phase is directionally strong: it decomposes targeted injection into sensible seams, keeps universal mode as the default, fixes known retry and ETW receiver-splitting problems, and adds observability. The main risks are compile/API mismatches across Windows vs non-Windows modules, a flawed lazy-injection coverage assumption, and under-specified classification-cache path normalization. GitNexus MCP resources were not available in this session, so this review is based on direct repo inspection.

### Cross-Plan Findings

#### HIGH: Non-Windows stubs will not compile as specified

Evidence: `hook_injector`, `process_registry`, `allowlist`, `process_watcher`, `etw_kernel_file`, `process_utils`, and `universal_injector` are currently Windows-only modules in `dlp-agent/src/lib.rs:151-181`.

Plans 01, 04, and 05 add non-Windows modules that reference types from those Windows-only modules, for example `InjectProcess` returning `crate::hook_injector::HookError`, and classifier stubs taking `ProcessKey`. On non-Windows, those modules are not exported, so `cargo check -p dlp-agent` will fail unless the plans also add non-Windows stubs for the referenced foundational modules or avoid those references.

Suggestion: Define a platform-neutral injection error in `inject_process.rs`, or add a non-Windows `hook_injector` stub. For classifier/lazy stubs, avoid `ProcessKey` unless `process_registry` is also exported cross-platform.

#### HIGH: Lazy-injection coverage math is wrong

Plan 05 says 100 T3/T4 events from 10 low-confidence processes should reach at least 99% coverage with "only the first event per process missed." That is 10 missed events and 90 covered events, so 90%, not 99%.

Evidence: the current ETW file stream is independent of process creation delivery: `EtwFileEvent` is produced by `EtwKernelFileConsumer` through its own channel in `dlp-agent/src/etw_kernel_file.rs:100-119`, while process events use a different `ProcessWatcher` channel in `dlp-agent/src/process_watcher.rs:43-62`. There is no ordering guarantee.

Suggestion: Either revise the success criterion to "event coverage converges after warm-up" with a realistic denominator, or lazy-inject on the first untracked T3/T4 event after performing allowlist/PPL checks. For a 99% test, use at least 1000 events for 10 processes or explicitly separate first-event-miss rate from steady-state coverage.

#### HIGH: ClassificationCache resolver risks path-hash mismatch

Evidence: cache rebuild hashes the raw provided path bytes at `dlp-agent/src/classification_cache.rs:509`, while `prepopulate_t3_t4_roots` stores raw `PathBuf` strings plus a trailing separator at `dlp-agent/src/classification_cache.rs:552-563`. Separately, `dlp_common::path_hash::path_hash` normalizes paths to uppercase and canonical separators before hashing at `dlp-common/src/path_hash.rs:58-139` and `dlp-common/src/path_hash.rs:191-193`.

Plan 05 says `resolve_tier` should compute the FNV hash of the normalized path. If writer and resolver do not use exactly the same normalization, exact path and prefix lookup can silently miss T3/T4 paths.

Suggestion: Make both cache writers and `resolve_tier` use the same `normalize_path`/`path_hash` contract, and add tests for case differences, forward slashes, trailing slashes, and NT-to-DOS converted paths.

### Plan-by-Plan Review

#### Plan 01

Strengths:
- Good foundation: config, mode enum, process states, and trait seam are the right first slice.
- Backward-compatible `record_injected` wrapper fits current call sites such as `record_injected` in `process_registry.rs:246-255`.

Concerns:
- HIGH: `InjectProcess` cannot reference `crate::hook_injector::HookError` on non-Windows unless `hook_injector` is also available there. Current `hook_injector` is `#[cfg(windows)]` only in `lib.rs:43-44`.
- MEDIUM: `PendingRetry` changes eviction and count matching. Current eviction matches every `ProcessState` explicitly at `process_registry.rs:171-184`; the plan should call out updating eviction priority for `PendingRetry`.

Suggestions:
- Add `PendingRetry` eviction priority explicitly, likely near `Discovered`.
- Use a platform-neutral error type for the trait seam or provide a non-Windows hook error stub.

Risk: MEDIUM-HIGH. The concept is good, but the non-Windows API shape is currently broken.

#### Plan 02

Strengths:
- Correctly distinguishes `None` score-unavailable from score `0`.
- Caps PE reads, which mitigates parser DoS.
- Synthetic PE fixture requirement avoids brittle System32-only tests.

Concerns:
- MEDIUM: Cache key hashing uses canonical image path, but the plan says `dlp_common::path_hash::fnv1a_64`; that function hashes bytes as-is. The path normalization policy should be explicit, as seen in `path_hash::path_hash` at `dlp-common/src/path_hash.rs:167-193`.
- LOW: `file_io_score` API details need to match `goblin 0.10` exactly; the plan's `pe.imports.unwrap_or_default()` may not match the actual type.

Suggestions:
- Define `cache_key_for_image_path()` and test case-insensitive path reuse.
- Include a compile check on both Windows and the current CI target.

Risk: MEDIUM.

#### Plan 03

Strengths:
- Good separation between basename and command-line signals.
- WoW64 guard is important; `HookInjector` already uses `IsWow64Process` for architecture selection at `hook_injector.rs:213-243`.

Concerns:
- HIGH: `CliClassification` cannot derive `Copy` if it contains `CommandLineStatus::Known(String)`.
- MEDIUM: PEB reading requires fragile structure definitions and `NtQueryInformationProcess`; the plan should specify exact structs and bounds checks.
- MEDIUM: The default known basename list is referenced as "Research A1" but not enumerated in this plan, which makes implementation non-deterministic.

Suggestions:
- Drop `Copy` from `CliClassification`.
- Make PEB read helpers injectable so WoW64/access-denied tests do not require impossible process states.
- Put the default basename list directly in Plan 01 or Plan 03.

Risk: MEDIUM-HIGH.

#### Plan 04

Strengths:
- Correct precedence: allowlist/PPL before injection signals. Current allowlist expects canonicalized image path and checks self/system/operator rules at `allowlist.rs:90-130`.
- `fallback_universal_sweep` preserves fail-safe behavior.

Concerns:
- HIGH: Non-Windows stub references are problematic because `process_registry` and `allowlist` are currently Windows-only exports in `lib.rs:157-181`.
- MEDIUM: Cache pruning says remove oldest inserted entry, but the proposed cache value only stores `(ClassificationDecision, Instant)`; that `Instant` is usable, but DashMap does not provide deterministic LRU. This should be "oldest cached_at best effort," not true LRU.
- LOW: PPL detection is duplicated unless the service integration fully removes legacy checks. Current `UniversalInjector::handle_event` runs allowlist/PPL internally at `universal_injector.rs:168-200`.

Suggestions:
- Keep `process_classifier` Windows-only unless cross-platform foundational stubs are added.
- Name the eviction policy accurately and test only the bound, not strict LRU order.

Risk: MEDIUM.

#### Plan 05

Strengths:
- `TierResolver` seam is the right way to test lazy injection without shared-memory cache.
- Making `CHANNEL_CAPACITY` public is justified; current constant is private at `etw_kernel_file.rs:111`.

Concerns:
- HIGH: The coverage test is mathematically invalid, as noted above.
- HIGH: Untracked PID behavior records a miss and does not inject, but ETW file events can race ahead of process classification because file and process events use separate channels.
- MEDIUM: The plan asks to scan `HashEntry` for a matching path, but `HashEntry` stores only `hash`, `tier`, and `ttl_secs` at `dlp-common/src/classification_cache.rs:83-95`; collision handling cannot verify the original path.
- MEDIUM: `LazyInjector::run` is blocking by design, so tests must close the sender or use a bounded runner. Plan 08 hints at this but Plan 05 should specify it.

Suggestions:
- Treat untracked T3/T4 events as a lazy-classification trigger, not only a miss.
- Use normalized path hash consistently and document collision semantics.
- Fix the 99% test scenario.

Risk: HIGH.

#### Plan 06

Strengths:
- Correctly targets real current bugs: failed retries are recorded as terminal skipped before queueing at `universal_injector.rs:245-252`, making `handle_retry` ineffective because `try_claim` returns `AlreadyClaimed` for occupied entries at `process_registry.rs:225-237`.
- Fixes ETW receiver work-sharing: current service clones the Kernel-File receiver for the correlator at `service.rs:2177`, which would split events if another consumer also clones it.
- Moves `audit_ctx` before injection init; current code builds it after `init_universal_injection` at `service.rs:1892-1901`.

Concerns:
- HIGH: The plan wants actual architecture recording, but `HookInjector::target_architecture` is private at `hook_injector.rs:213-243`, and `process_utils.rs` currently only exposes creation time at `process_utils.rs:15-47`. `files_modified` omits `process_utils.rs`.
- MEDIUM: The updated `init_universal_injection` steps use `agent_config` to build `ProcessClassifier::new(&agent_config, ...)`, but the proposed signature lists `targeted_config` and `classification_cache`, not `&AgentConfig`.
- MEDIUM: Current startup/backstop sweeps duplicate allowlist/PPL/inject logic at `service.rs:3303-3383` and `service.rs:3404-3495`; replacing them with `classify_and_inject` is right but large and high blast radius.

Suggestions:
- Add `process_utils.rs` to Plan 06 files and implement `target_process_architecture(pid)`.
- Pass `&AgentConfig` into `init_universal_injection`.
- Add focused tests for retry reclaim and startup/backstop behavior.

Risk: HIGH.

#### Plan 07

Strengths:
- Telemetry addresses the actual observability gap.
- Chain-hash behavior is understood: current canonical hash strips only `prev_hash` and `chain_hash` at `dlp-common/src/audit.rs:95-103`, so `details` will be included by default.
- New SIEM routing fits existing `EventType::routed_to_siem` and `triggers_alert` methods at `audit.rs:245-303`.

Concerns:
- MEDIUM: Adding `details` "after `chain_hash`" still requires initializing it in `AuditEvent::new`, whose struct literal currently ends at `chain_hash: None` in `audit.rs:514-553`.
- MEDIUM: There are many legacy deserialization tests for old `AuditEvent` JSON at `audit.rs:1010`, `1034`, `1146`, `1652`, `1826`, and `1919`; the plan mentions optional default, which is correct, but these tests should be explicitly part of acceptance.
- LOW: `hash_path_for_audit` using SHA-256 without a salt still permits dictionary attacks against common enterprise paths.

Suggestions:
- Add tests that `details` participates in `canonical_json_for_hash`.
- Consider HMAC or keyed hash if SIEM path privacy must resist guessing.

Risk: MEDIUM.

#### Plan 08

Strengths:
- Integration matrix covers the right modes: Targeted, Universal, Monitor, allowlist, PID reuse, counters, and audit capture.
- Uses existing audit test capture hooks; they exist at `audit_emitter.rs:217-263`.

Concerns:
- MEDIUM: Lazy-injection tests need to control `LazyInjector::run` shutdown. A blocking `recv()` loop will hang unless the sender is dropped or the runner has a single-event helper.
- MEDIUM: "Allowlist/PPL safety" is claimed, but the test outline only describes allowlist. PPL is harder because `detect_ppl` is a concrete function in `universal_injector.rs:289`; no PPL seam is planned.
- LOW: Sonar is reasonable as CI evidence, but local execution depends on `SONAR_TOKEN` and network availability.

Suggestions:
- Add a `process_protection` test seam or limit the success criterion to allowlist unless PPL can be mocked.
- Add a `run_until_channel_closed` test helper and always drop `tx` before joining.
- Include `cargo test --workspace`, not only `cargo test -p dlp-agent`, before final verification.

Risk: MEDIUM.

### Overall Risk Assessment

Overall risk: HIGH.

The design is coherent and addresses the phase goal, but implementation risk is high because Plans 01, 04, and 05 currently conflict with the crate's Windows-only module gating, Plan 05's coverage proof is mathematically wrong, and Plan 06 touches the service startup path, retry semantics, ETW fanout, sweeps, and injector ownership in one wave. Fixing the API/stub strategy and lazy-coverage model before execution would materially reduce the risk.

## Consensus Summary

Only Codex was invoked for this review cycle. The findings below reflect Codex's assessment.

### Agreed Strengths

- Sensible seam design: `InjectProcess`, `TierResolver`, `PeScoreSource`, and `CliSignalSource` traits make the classifier and lazy injector testable without real Windows internals.
- Universal mode remains the default, preserving backward compatibility with Phase 49.
- Plan 06 correctly targets known live bugs: retry-before-claim, ETW receiver splitting, and `audit_ctx` ordering.
- Telemetry plan (Plan 07) addresses observability gaps with hashed paths and SIEM-routed events.
- Plan 08 integration matrix covers Targeted, Universal, Monitor, lazy injection, allowlist safety, PID reuse, and counters.

### Agreed Concerns

- HIGH: Non-Windows stubs in Plans 01, 04, and 05 reference Windows-only modules/types (`HookError`, `ProcessKey`); `cargo check` on non-Windows targets will fail unless the API shape is fixed or foundational stubs are added.
- HIGH: Plan 05's lazy-injection coverage test is mathematically invalid (100 events / 10 processes with one miss each = 90% coverage, not 99%).
- HIGH: ClassificationCache `resolve_tier` path normalization must match the writer exactly or T3/T4 lookups will silently miss.
- HIGH: Plan 06 has high blast radius (service startup, retry semantics, ETW fanout, sweeps, injector ownership) and needs `process_utils.rs` extension for architecture queries.
- MEDIUM: Plan 03's `CliClassification` cannot derive `Copy` with `CommandLineStatus::Known(String)`.
- MEDIUM: Plan 04's cache eviction is described as LRU but DashMap does not provide deterministic LRU order.
- MEDIUM: Plan 07's `AuditEvent.details` field must be initialized in `AuditEvent::new` and tested for chain-hash participation.
- MEDIUM: Plan 08 lacks a PPL seam and a clean lazy-injector shutdown strategy for tests.

### Divergent Views

None.
