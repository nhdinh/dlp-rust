# Cross-AI Plan Review — Phase 58.6

## Notes

- `--codex` was requested. The default Codex model (`gpt-5.3-codex`) is not supported on this ChatGPT-linked account, so the review was run with `--model gpt-5.5`.
- GitNexus MCP resources were not available in this session; validation was performed by direct source inspection.

---

## Codex Review

### Summary

The plan set is technically strong and clearly responds to known Phase 58.6 risks: it keeps universal injection as a fallback, introduces test seams before integration, separates static classification from lazy ETW fallback, and adds telemetry for coverage proof. The main risks are cross-plan integration gaps: lazy injection needs process image-path recovery that is not currently available in the planned module, server audit schema work targets a non-existent file, fanout shutdown is underspecified, and the plans do not include the mandatory GitNexus impact-analysis workflow required by `AGENTS.md:10-21`.

---

### 58.6-01-PLAN.md

**Summary**: Good foundation plan. It correctly starts with config/state/trait seams before behavior. Risk is medium because it edits central registry/config types used broadly.

**Strengths**
- Correctly targets `AgentConfig`, which currently owns `universal_injection_enabled` and `allowlist_version` at `dlp-agent/src/config.rs:289-300`.
- Keeps existing `record_injected` as compatibility wrapper, important because many current tests and call sites use it (`dlp-agent/src/process_registry.rs:246-255`).
- Addresses the current missing retry state; existing `ProcessState` has no `PendingRetry` (`dlp-agent/src/process_registry.rs:65-78`).

**Concerns**
- **HIGH**: Plan does not require GitNexus impact analysis before editing central symbols, despite `AGENTS.md:10-18`.
- **MEDIUM**: Adding fields to `AgentConfig` will break exhaustive test literals unless every literal is updated; current literals are exhaustive at `dlp-agent/src/config.rs:710-742` and `760-790`.
- **LOW**: Verification commands with multiple test filters, such as `cargo test -p dlp-agent config::tests process_registry::tests`, should be split because Cargo accepts one test filter.

**Suggestions**
- Add explicit pre-edit steps: `gitnexus_impact` for `AgentConfig`, `ProcessState`, `try_claim`, `record_injected`.
- Split verification commands by filter.

**Risk Assessment**: **MEDIUM**. Scope is foundational but well-sequenced.

### 58.6-02-PLAN.md

**Summary**: Strong plan for static PE scoring and a valuable fix to classification-cache normalization. Risk is medium due to parser fixture complexity and cache-format sensitivity.

**Strengths**
- Correctly identifies existing cache writer mismatch: prefixes are stored from raw bytes at `dlp-agent/src/classification_cache.rs:491-495`, exact hashes use raw `fnv1a_64(path.as_bytes())` at `dlp-agent/src/classification_cache.rs:508-510`.
- Uses existing path-normalization contract from `dlp-common/src/path_hash.rs:58-193`.
- ScoreUnavailable as `None` is the right distinction for safe fallback.

**Concerns**
- **MEDIUM**: `classification_cache.rs` is Windows-gated in `lib.rs:151-152`; non-Windows checks around this module need care.
- **MEDIUM**: Synthetic PE fixture requirement is good but fragile; plan should specify how to validate it under goblin 0.10 API changes.
- **LOW**: The plan says use `path_hash` but also describes canonicalizing first; double-normalization is probably harmless, but should be defined precisely.

**Suggestions**
- Add a small compile-probe or unit test locking the goblin imports API.
- Keep `ClassificationCache` format changes backward-compatible and document whether old cache files are rebuilt.

**Risk Assessment**: **MEDIUM**. High-value work, but touches shared-memory cache semantics.

### 58.6-03-PLAN.md

**Summary**: Useful secondary signal plan, but remote PEB reading is the riskiest single implementation area.

**Strengths**
- Handles PPL/AccessDenied as expected operational outcomes.
- Explicitly avoids making basename alone sufficient, reducing spoofing risk.
- Tokenized command-line matching is stronger than raw substring matching.

**Concerns**
- **HIGH**: Plan references `windows::Wdk::System::Threading::NtQueryInformationProcess`, but current `windows` features in `dlp-agent/Cargo.toml:38-104` do not include WDK features.
- **MEDIUM**: It mentions `static_assertions` but does not add it to `Cargo.toml`.
- **MEDIUM**: Remote PEB layout fallback is still effectively hand-rolled; runtime assertions reduce risk but do not eliminate layout drift.

**Suggestions**
- Decide up front: add WDK feature support if available, or add a tiny Windows FFI wrapper with explicit tests.
- Add `static_assertions` if compile-time assertions are required.

**Risk Assessment**: **HIGH**. Cross-process memory parsing is brittle and Windows-version-sensitive.

### 58.6-04-PLAN.md

**Summary**: The classifier design is coherent and puts allowlist/PPL precedence in the right place.

**Strengths**
- Existing allowlist/PPL logic is currently duplicated in `UniversalInjector::handle_event` at `dlp-agent/src/universal_injector.rs:171-199`; centralizing it is appropriate.
- Cache keyed by `(ProcessKey, allowlist_version)` matches existing `allowlist_version` in `AgentConfig` (`dlp-agent/src/config.rs:294-300`).
- PPL test seam fixes current hard dependency on `detect_ppl` (`dlp-agent/src/universal_injector.rs:289-327`).

**Concerns**
- **MEDIUM**: Classifier cache can retain `SkipLowConfidence` after process behavior changes unless TTL is short enough.
- **MEDIUM**: Non-Windows stub shape differs from Windows `classify` signature per plan text, which can make downstream generic code awkward.

**Suggestions**
- Keep one trait/interface shape across platforms where possible.
- Add tests for config reload constructing a new classifier with updated `allowlist_version`.

**Risk Assessment**: **MEDIUM**. Design is sound; integration with existing injector is the real risk.

### 58.6-05-PLAN.md

**Summary**: Lazy injection is necessary, and the plan correctly treats first-event misses honestly. There is one concrete implementation gap.

**Strengths**
- Correctly fixes ETW gating; current consumer starts only when bypass correlator is enabled (`dlp-agent/src/etw_kernel_file.rs:130-151`).
- Correctly exposes channel capacity; it is currently private at `dlp-agent/src/etw_kernel_file.rs:111`.
- TierResolver seam avoids tying tests to shared-memory cache.

**Concerns**
- **HIGH**: `EtwFileEvent` has no process image path, only `pid`, `file_name`, `file_object`, `timestamp`, `op`, and `nt_path_converted` (`dlp-agent/src/etw_kernel_file.rs:64-79`). The plan says untracked PIDs are routed through `classifier.classify(..., &image_path, ...)`, but does not expose an image-path lookup helper.
- **MEDIUM**: `get_process_creation_time` returns `None` for invalid/exited PIDs (`dlp-agent/src/process_utils.rs:14-47`); using `unwrap_or(0)` risks creating bogus keys.
- **MEDIUM**: Existing `get_process_image_path` is private to `service.rs` (`dlp-agent/src/service.rs:3553-3580`).

**Suggestions**
- Move `get_process_image_path` into `process_utils.rs` before Plan 05, or add it to this plan.
- If creation time cannot be read for a lazy ETW event, count missed and skip injection.

**Risk Assessment**: **HIGH** until the image-path lookup gap is closed.

### 58.6-06-PLAN.md

**Summary**: This is the most important integration plan and it addresses real current bugs, especially retry semantics and receiver fanout.

**Strengths**
- Correctly fixes current retry bug: failures are recorded as skipped at `dlp-agent/src/universal_injector.rs:245-251`, then retry calls `handle_event`, whose `try_claim` returns already claimed (`dlp-agent/src/universal_injector.rs:263-272`).
- Correctly identifies current `Receiver::clone()` work-sharing risk at `dlp-agent/src/service.rs:2177`.
- Correctly moves audit context earlier; current `init_universal_injection` runs before `audit_ctx` creation (`dlp-agent/src/service.rs:1892-1901`).

**Concerns**
- **HIGH**: Fanout shutdown is underspecified. Dropping stored sender clones may not unblock a fanout thread that owns its own senders and is blocked on `send`.
- **HIGH**: Enablement logic must preserve cloud-hook use. Current HookInjector construction is gated by `cloud_hook_enabled` (`dlp-agent/src/service.rs:1851-1871`), while `init_universal_injection` disables if no injector or flag false (`dlp-agent/src/service.rs:3016-3055`).
- **MEDIUM**: `std::thread::JoinHandle` has no direct timeout join; the plan needs an implementable timeout pattern.

**Suggestions**
- Add a shutdown channel to the fanout loop and use `select!` with bounded sends.
- Abort/stop consumers before joining fanout, or make fanout sends timeout-aware.
- Add tests for cloud-hook enabled + universal disabled + targeted universal mode.

**Risk Assessment**: **HIGH**. Integration complexity and shutdown behavior are significant.

### 58.6-07-PLAN.md

**Summary**: Telemetry/audit intent is good, but server persistence paths need correction.

**Strengths**
- `details` as optional/defaulted is backward-compatible with existing `AuditEvent` serialization (`dlp-common/src/audit.rs:337-486`).
- Including details in chain hash is naturally supported because `canonical_json_for_hash` only removes `prev_hash` and `chain_hash` (`dlp-common/src/audit.rs:95-103`).
- Current server row drops anything not in `AuditEventRow`; adding details is necessary (`dlp-server/src/audit_store.rs:156-195`).

**Concerns**
- **HIGH**: `dlp-server/src/db/schema/audit_events.sql` does not exist. The actual schema lives in `dlp-server/src/db/mod.rs:92-111`, with migrations near `dlp-server/src/db/mod.rs:841-847`.
- **HIGH**: Query output currently selects only through `content_sha256` and omits `prev_hash`/`chain_hash` too (`dlp-server/src/db/repositories/audit_events.rs:196-238`). Details must be added consistently.
- **MEDIUM**: Exhaustive `AuditEvent` literals exist in `alert_router.rs:338-365` and more test literals; plan notes this but should require a workspace-wide compile after Task 1, not only Task 4.

**Suggestions**
- Replace the non-existent SQL file in `files_modified` with `dlp-server/src/db/mod.rs`.
- Add migration via existing `run_alter`.
- Add SIEM/syslog connector tests proving `details` survives serialization.

**Risk Assessment**: **HIGH** due to incorrect file target and multi-crate schema impact.

## Consensus Summary

Only Codex was invoked for this review cycle. The findings below reflect Codex's assessment.

### Agreed Strengths

- The plans decompose targeted injection into sensible seams (`InjectProcess`, `TierResolver`, `PeScoreSource`, `CliSignalSource`, `ProcessProtectionSource`) that make the classifier and lazy injector testable without real Windows internals.
- Universal mode remains the default, preserving backward compatibility with Phase 49.
- Plan 06 correctly targets known live bugs: retry-before-claim, ETW receiver splitting, duplicate `HookInjector` construction, and `audit_ctx` ordering.
- Plan 07 addresses observability gaps with optional `details` and SIEM-routed events.
- Plan 08's integration matrix covers Targeted, Universal, Monitor, lazy injection, allowlist safety, PID reuse, counters, and valid coverage math.

### Agreed Concerns

- **HIGH:** Plan 05 can violate the allowlist/PPL invariant for untracked PIDs because `LazyInjector` does not have access to an image-path lookup and therefore cannot run allowlist/PPL/classification checks before injecting.
- **HIGH:** Plan 05's lazy ETW path is gated by `bypass_correlator_enabled()` at `dlp-agent/src/etw_kernel_file.rs:142`; targeted lazy injection will not start when bypass correlation is disabled.
- **HIGH:** Plan 06 has high blast radius (service startup, retry semantics, ETW fanout, sweeps, injector ownership) and does not fully specify `try_claim`/shutdown lifecycle.
- **HIGH:** Plan 07's `AuditEvent.details` payload will be dropped by server persistence (`AuditEventRow`, `store_events_sync`) unless `dlp-server` schema/repository/API are updated.
- **HIGH:** Plan 03's hand-rolled PEB/WDK struct layout risks misreading remote process memory.
- **HIGH:** None of the plans include the mandatory GitNexus impact-analysis workflow required by `AGENTS.md:10-18`.
- **MEDIUM:** Plan 02's cache normalization claims are not aligned with current `ClassificationCache` writer behavior.
- **MEDIUM:** Plan 04's classifier cache invalidation is incomplete because it only includes `allowlist_version`, not targeted config fields.
- **MEDIUM:** Plan 08's integration module may fail on non-Windows CI unless dependencies are Windows-gated or stubbed.

### Divergent Views

None.
