    - Test: An event for an already `Injected` PID is ignored and increments `t3t4_event_covered`.
    - Test: An event for a non-existent PID is ignored.
    - Test: An event for a T1/T2 path is ignored.
    - Test: A second T3/T4 event for the same PID within the rate-limit window is ignored.
    - Test: PID reuse (same PID, different creation_time) is handled correctly using `ProcessKey`.
    - Test: A T3/T4 event for a PID not yet tracked increments `t3t4_event_missed`.
  </behavior>
  <action>
    Create `dlp-agent/src/lazy_injector.rs`.

    1. **`LazyInjectorConfig`** (derive Clone):
       - `rate_limit: Duration` (from `TargetedInjectionConfig::lazy_injection_rate_limit_ms`).
       - `enabled: bool` (from `TargetedInjectionConfig::enable_lazy_injection`).

    2. **`LazyInjector` struct**:
       - Fields:
         - `registry: Arc<ProcessRegistry>`
         - `injector: Arc<dyn InjectProcess>`
         - `config: LazyInjectorConfig`
         - `last_attempt: DashMap<ProcessKey, Instant>` (rate-limit cache)
         - `classification_cache: Option<Arc<ClassificationCache>>`
         - `emit_context: Option<Arc<crate::audit_emitter::EmitContext>>`

    3. **`new(registry, injector, config, classification_cache, emit_context) -> Self`**.

    4. **`pub fn run(&self, event_rx: Receiver<EtwFileEvent>)`** (synchronous, not async):
       - Loop on `event_rx.recv()` (blocking).
       - If `!config.enabled` or `classification_cache.is_none()`, continue.
       - Resolve the tier of `event.file_name` via `classification_cache.resolve_tier`. If `None` or `Classification::T1`/`T2`, continue.
       - Build `ProcessKey { pid: event.pid, creation_time: get_process_creation_time(event.pid).unwrap_or(0) }`.
       - Look up registry state:
         - If `Injected { .. }`, increment `t3t4_event_covered` and continue.
         - If `Skipped` for any reason other than `LowConfidence` (or if not `Discovered`/`Skipped(LowConfidence)`), increment `t3t4_event_missed` and continue.
         - If `Discovered` or `Skipped(LowConfidence)`, increment `t3t4_event_missed` and proceed to injection attempt.
       - Rate-limit check: if `last_attempt.get(&key)` exists and elapsed < rate_limit, continue.
       - Verify creation-time immediately before injection:
         - Query `get_process_creation_time(event.pid)` again; if it does not match `key.creation_time`, record `Skipped(Failed(InjectionFailure::Timeout))` and continue.
       - Attempt injection:
         - Call `injector.inject(event.pid)`.
         - On success, record `record_lazy_injected(key, "x64".into())`, update `last_attempt`, and emit `EventType::LazyInjectionAttempt` via `emit_context` if present.
         - On failure, log `tracing::warn!`, record `record_skipped(key, SkipReason::Failed(...))` to avoid repeated attempts, and emit `EventType::LazyInjectionFailure` via `emit_context` if present.

    5. **Non-Windows stub**: `run` returns immediately.

    6. **Tests**: Use a mock `ProcessRegistry`, mock `InjectProcess` spy, and a fake `Receiver<EtwFileEvent>` to verify all behaviors. For the classification cache, provide a test stub that returns T3/T4 for specific paths.
  </action>

    - Rate limiting and PID-reuse safety via `ProcessKey` work correctly.
