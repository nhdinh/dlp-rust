<task type="auto" tdd="true">
  <name>Task 1: Write targeted-injection integration tests</name>
  <files>dlp-agent/tests/targeted_injection_integration.rs</files>
  <behavior>
    - Test: In `ClassificationMode::Targeted`, a process with a high PE score is classified as `InjectImmediately` and the registry records `Injected(Immediate)`.
    - Test: In `ClassificationMode::Targeted`, a process with a low PE score and no basename/command-line signal records `Skipped(LowConfidence)`; a subsequent T3/T4 ETW event for the same PID records `Injected(Lazy)`.
    - Test: In `ClassificationMode::Universal`, a process with a low PE score is still injected immediately.
    - Test: In `ClassificationMode::Monitor`, no injection occurs and registry records `SkipMonitoring`.
    - Test: Allowlisted/PPL-skip processes are never injected in any mode.
    - Test: PID reuse (same PID, different creation_time) does not incorrectly reuse a previous classification decision.
    - Test: `ProcessCounts.classified_injected`, `lazy_injected`, and `skipped_low_confidence` match the integration scenario outcomes.
  </behavior>
  <action>
    Create `dlp-agent/tests/targeted_injection_integration.rs`.

    1. **Test fixtures**:
       - Build an `AgentConfig` with `targeted_injection.mode` set per test.
       - Build a `ProcessRegistry`, `AllowlistMatcher` (empty or with a test entry), and a spy `HookInjector` that records injected PIDs without calling real `CreateRemoteThread`.
       - Construct `PeImportScanner` and `CommandLineReader` from the config. For deterministic tests, wrap them in test doubles that return configurable scores/classifications rather than reading real PEs/PEBs. If the production structs are not easily mockable, add `#[cfg(test)]` constructors in `pe_import_scanner.rs` and `command_line_reader.rs` that accept pre-computed data.
       - Construct `ProcessClassifier` and `LazyInjector` from these test doubles.

    2. **Immediate-injection test**:
       - Create a `ProcessEvent` for a PID with a high file-IO score.
       - Call `classifier.classify(key, pid, image_path, &matcher)` and assert `InjectImmediately`.
       - Call `injector.inject(pid)` and assert the spy recorded the PID.
       - Assert registry state is `Injected { injection_path: Immediate, .. }`.

    3. **Lazy-injection test**:
       - Classify a PID with a low score as `SkipLowConfidence` and record it in the registry.
       - Send a synthetic `EtwFileEvent` with a T3/T4 file path through a crossbeam channel to `LazyInjector::run`.
       - Await until registry state transitions to `Injected { injection_path: Lazy, .. }` or timeout.
       - Assert the spy recorded the PID exactly once.

    4. **Mode regression tests**:
       - `Universal`: assert `InjectImmediately` even for low-score PIDs.
       - `Monitor`: assert `SkipMonitoring` and spy is empty.

    5. **Allowlist/PPL safety test**:
       - Insert an allowlist entry for a test image path.
       - Assert `SkipAllowlisted` for all three modes.

    6. **PID-reuse test**:
       - Classify PID 12345 with creation_time A as `InjectImmediately`.
       - Classify PID 12345 with creation_time B as `SkipLowConfidence` and assert the cache does not reuse the prior decision.

    7. **Counter test**:
       - After running a mixed scenario, call `registry.targeted_telemetry_snapshot()` and assert the counters equal the expected injected/skipped/lazy counts.
  </action>
  <verify>
    <automated>cargo test -p dlp-agent --test targeted_injection_integration</automated>
  </verify>
  <done>All integration tests pass; targeted, lazy, universal, and monitor modes behave as specified.</done>
</task>
