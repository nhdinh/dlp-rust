  <name>Task 2: Write the targeted-injection behavior matrix tests</name>
  <files>dlp-agent/src/targeted_injection_integration.rs</files>
  <behavior>
    - Test: `ClassificationMode::Targeted` with high PE score records `Injected { injection_path: Immediate }` and emits `TargetedImmediateInjection`.
    - Test: `ClassificationMode::Targeted` with only a basename match records `Skipped(LowConfidence)`; a subsequent T3 ETW event causes lazy injection and records `Injected { injection_path: Lazy }`.
    - Test: `ClassificationMode::Universal` injects a low-score process immediately (backward compat).
    - Test: `ClassificationMode::Monitor` records `Skipped(Monitoring)` and never injects.
    - Test: An allowlisted image path returns `SkipAllowlisted` and is never injected in any mode.
    - Test: PID reuse (same PID, different `creation_time`) does not reuse the previous classification cache entry.
    - Test: `ProcessCounts` and `TargetedInjectionTelemetry` match the mixed scenario outcomes.
  </behavior>
  <action>
    Implement the integration tests in `dlp-agent/src/targeted_injection_integration.rs`.

    1. **Immediate-injection test**:
       - Build a `Targeted` classifier with `pe_score` above threshold and `command_line_match = false`.
       - Build a `ProcessEvent` with a unique PID/image path.
       - Call `universal_injector.classify_and_inject(..., Etw, None, false, None).await`.
       - Assert the counting injector recorded the PID exactly once.
       - Assert registry state is `Injected { injection_path: Immediate, .. }`.
       - Enable audit capture, rerun, and assert a `TargetedImmediateInjection` event was captured.

    2. **Lazy-injection test**:
       - Build a `Targeted` classifier with `pe_score = 0` and no command-line match so it returns `SkipLowConfidence`.
       - Classify and record `Skipped(LowConfidence)` in the registry.
       - Build a `LazyInjector` using the same registry and counting injector, with a stub classification cache that returns `Some(Classification::T4)` for a test path.
       - Send a synthetic `EtwFileEvent { pid, file_name: test_t4_path, op: FileOp::Create }` through a crossbeam channel.
       - Call `lazy_injector.run(lazy_rx)` on a blocking thread or use a short receive timeout wrapper.
       - Assert the counting injector recorded the PID exactly once.
       - Assert registry state transitions to `Injected { injection_path: Lazy, .. }`.
       - Assert a `LazyInjectionAttempt` audit event was captured.

    3. **Mode regression tests**:
       - `Universal`: low PE score still results in immediate injection.
       - `Monitor`: high PE score results in `Skipped(Monitoring)` and zero injections.

    4. **Allowlist safety test**:
       - Add an allowlist entry matching the test image path.
       - For `Universal`, `Targeted`, and `Monitor`, assert the decision is `SkipAllowlisted` and the injector count remains zero.

    5. **PID-reuse test**:
       - Classify PID 12345 with `creation_time = 100` as immediate inject.
       - Classify PID 12345 with `creation_time = 200` as low confidence and assert the registry state for the second key is `Skipped(LowConfidence)`.

    6. **Counter test**:
       - Run a mixed scenario (two immediate, one lazy, one monitoring, one allowlist, one low-confidence skipped).
       - Assert `registry.counts()` and `registry.targeted_telemetry_snapshot()` reflect the expected values.

    Use `audit_emitter::enable_test_capture` and `drain_test_events` to assert audit events. Hold `audit_emitter::audit_test_lock()` when asserting to avoid interleaving with other tests.
