Create `dlp-common/src/path_norm.rs` with:

1. `pub fn normalize_path(input: &str) -> String` — Windows path canonicalization helper:
   - Strip `\\?\` long-path prefix if present
   - Strip `\\?\UNC\` prefix and convert to `\\server\share` format if present
   - Convert all forward slashes `/` to backslashes `\`
   - Collapse `.` and `..` segments (but do NOT resolve symlinks/junctions — that requires Win32 API calls)
   - Strip trailing backslash except for root drives (`C:\`) and UNC roots (`\\server\share`)
   - Uppercase drive letter (e.g., `c:` → `C:`)
   - Preserve case for path components (Windows is case-preserving, case-insensitive)
   - Handle drive-relative paths like `C:foo` → `C:\foo` (resolve to absolute)
   - Return the normalized String
   - Document behavior for edge cases: device paths, reserved names, alternate data streams are passed through unchanged (caller handles if needed)

2. `pub fn is_path_prefix_of(prefix: &str, path: &str) -> bool` — Secure prefix check:
   - Both inputs MUST be pre-normalized via `normalize_path()`
   - Returns true only if `prefix` is a proper parent directory of `path` at a component boundary
   - Example: `is_path_prefix_of("C:\\Data", "C:\\Data\\file.txt")` → true
   - Example: `is_path_prefix_of("C:\\Data", "C:\\Data2\\file.txt")` → false
   - Implementation: split both paths by `\`, compare component-by-component

3. `pub fn parent_components(path: &str) -> Vec<String>` — Returns all parent directory paths from most specific to root:

   - Used by LabelService for folder inheritance walk
   - Max depth: 20 levels (return empty Vec if exceeded, to prevent pathological paths)

## Trust Boundaries

| Boundary | Description |

| client→API | Untrusted admin input crosses here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-59-01 | Tampering | LabelCache | mitigate | LRU cache with TTL limits stale data window; invalidate on all CRUD; bounded capacity prevents unbounded memory growth |
| T-59-02 | Information Disclosure | LabelCache | accept | Cache holds tier only (not full label); no PII in tier values |
| T-59-03 | Denial of Service | resolve_tier path walk | mitigate | Path walk bounded by max depth (20 levels); no recursion; LRU prevents unbounded memory |
| T-59-04 | Elevation | Path prefix spoofing | mitigate | `is_path_prefix_of()` uses component-boundary check; `C:\Data2` cannot inherit from `C:\Data` |
| T-59-05 | Tampering | Stale cache after missed invalidation | mitigate | LRU + TTL provides automatic expiry even if invalidation is missed |
| T-59-06 | Information Disclosure | Cache metrics | accept | Metrics contain only counts (hits/misses/evictions), no path or tier data |
</threat_model>
