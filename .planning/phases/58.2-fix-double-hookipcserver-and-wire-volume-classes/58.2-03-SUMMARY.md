## Deviations from Plan

### Auto-fixed Issues

**None — plan executed with architectural adaptation.**

The plan specified using `spawn_hook_ipc_server` (private function) with `HookIpcServerConfig` and a mock `OfflineManager`. During execution, two issues were discovered:

1. `spawn_hook_ipc_server` is `fn` (private), not `pub fn`, so it cannot be called from integration tests (`dlp-agent/tests/`).
2. `HookIpcServerConfig.offline` expects `Arc<OfflineManager>` (concrete struct), not a trait object. `OfflineManager` requires a real `EngineClient` and `Cache`, making mock injection impractical without significant refactoring.

**Adaptation:** Instead of the private `spawn_hook_ipc_server`, the integration tests use the public `HookIpcServer` builder API directly (`HookIpcServer::new(...).with_diagnostics_handler(...).with_health_handler(...).with_override_handler(...)`). This exercises the same builder chain and routing logic, but with simpler mock handlers that don't require `OfflineManager` or `HookIpcServerConfig`. The tests still verify all four IpcPayloadV1 frame types route correctly, which is the core objective.

This deviation is documented as a decision in the frontmatter.

### Pre-existing Issues (out of scope)

- **7 flaky unit tests in `dlp-agent/src/hook_ipc.rs`** fail intermittently with "server did not become ready within 5s: Disconnected" or similar pipe disconnection errors. These are pre-existing timing-related failures unrelated to this plan's changes. They fail both before and after this work.
