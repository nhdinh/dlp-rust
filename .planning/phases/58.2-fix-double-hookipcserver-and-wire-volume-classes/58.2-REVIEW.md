## Warnings

### WR-01: Approval cache uses `std::sync::RwLock` instead of `parking_lot::RwLock`

**File:** `dlp-agent/src/approval_cache.rs:59`, `94`, `161`, `214`
**Issue:** `ApprovalCache` stores `verifying_key` in an `Arc<std::sync::RwLock<Option<ed25519_dalek::VerifyingKey>>>`. The codebase standard (per `CLAUDE.md` section 9.12 and pervasive use elsewhere) is `parking_lot::RwLock`, which is faster, more compact, and never poisons. Using `std::sync::RwLock` introduces the risk of poisoned locks (however unlikely) and is inconsistent with the rest of the agent. The `.expect("poisoned lock")` calls on lines 94, 161, and 214 are a smell that this was a conscious but suboptimal choice.
**Fix:**
```rust
use parking_lot::RwLock;

pub struct ApprovalCache {
    pub cache: Arc<DashMap<String, CachedApproval>>,
    verifying_key: Arc<RwLock<Option<ed25519_dalek::VerifyingKey>>>,
}
```
Remove all `.expect("poisoned lock")` calls and use plain `.read()` / `.write()`.

### WR-02: `println!` / `eprintln!` used in production code paths

**File:** `dlp-agent/src/hook_ipc.rs:764-767`
**Issue:** The `hook_ipc_roundtrip_test` unit test uses `println!` to emit latency statistics. While this is test code, the `CLAUDE.md` Rust standards (section 9.1) mandate `tracing::info!` instead of `println!` for all console output. More importantly, `dlp-agent/src/dacl_repair_watcher.rs:1233` and `dlp-agent/src/dacl_tripwire.rs` contain multiple `println!` calls in what appear to be test or error-handling paths that could leak into production builds. The `hook_ipc.rs` test also does not join the server thread, leaving it potentially running after the test exits.
**Fix:** Replace `println!` with `tracing::info!` in test code, and audit `dacl_repair_watcher.rs` / `dacl_tripwire.rs` for production `println!` usage. For the test, add a `#[should_panic]` or join-with-timeout pattern instead of abandoning the thread.

## Info

### IN-01: `VolumeDetector` has unnecessary `unsafe impl Send` / `unsafe impl Sync`

**File:** `dlp-agent/src/detection/usb.rs:689-690`
**Issue:** Manual `unsafe impl Send for VolumeDetector {}` and `unsafe impl Sync for VolumeDetector {}` are declared. The struct fields (`RwLock<HashSet<char>>`, `RwLock<HashMap<char, DeviceIdentity>>`, `Mutex<Option<DeviceIdentity>>`, `RwLock<HashMap<char, (VolumeClass, Instant)>>`) are all already `Send + Sync` because `parking_lot::RwLock` and `parking_lot::Mutex` implement these traits automatically. The manual impls are redundant and add unnecessary `unsafe` surface area.
**Fix:** Remove lines 689-690. The compiler will auto-derive `Send + Sync` for `VolumeDetector`.

### IN-02: `query_disk_for_letter` uses `.unwrap()` on single-drive fallback

**File:** `dlp-agent/src/detection/usb.rs:799`
**Issue:** In the WMI fallback path when only one disk drive exists, the code calls `drives.into_iter().next().unwrap()`. While this is logically safe because `drives.len() == 1` was just checked, it violates the project standard of avoiding `.unwrap()` in library code (section 9.4). A `.expect()` with a descriptive message, or better yet a safe extraction, is preferred.
**Fix:**
```rust
if drives.len() == 1 {
    return Ok(drives.into_iter().next());
}
```
Or use `if let Some(drive) = drives.into_iter().next()`.

### IN-03: `build_cache_hint` uses path-string heuristic instead of authoritative classification

**File:** `dlp-agent/src/hook_ipc.rs:573-609`
**Issue:** The `build_cache_hint` function falls back to ASCII substring matching on the path (`path.to_ascii_uppercase().contains("SECRET")`) when no `Classification` is provided. This is a heuristic that can be bypassed by renaming files and is not authoritative. The comment acknowledges this is a "simplified heuristic" and "in production this would query the policy store." However, the function is called from `handle_hook_request` with `classification: None`, meaning the fallback is always active for the hook path until real ABAC evaluation is wired.
**Fix:** This is already marked as a TODO/deferred item (line 508). Ensure the follow-up (WORKFLOW-04) is tracked and prioritized, as the current heuristic undermines the classification cache's accuracy.

### IN-04: `hook_ipc_integration.rs` tests use `eprintln!` for server errors instead of assertions

**File:** `dlp-agent/tests/hook_ipc_integration.rs:70-72`, `144-146`, `etc.`
**Issue:** Multiple integration tests use `eprintln!("Hook IPC server exited with error: {}", e)` inside the server thread closure. If the server exits with an error, the test thread will still pass unless an explicit assertion fails. This makes test failures silent and harder to diagnose in CI. The `serial_test::serial` attribute is correctly used, but error visibility is poor.
**Fix:** Use a shared `Arc<AtomicBool>` or `crossbeam_channel` to propagate server errors to the main test thread, and assert that the server exited cleanly. Alternatively, use `panic!` inside the thread on error when the test expects success.
