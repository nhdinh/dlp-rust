# Phase 58.2 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| hook DLL -> named pipe | Untrusted client input crosses here; HookIpcServer deserializes and routes frames | HookRequest frames with pid, path, action, volume classes |
| handler closure -> OfflineManager | ABAC evaluation runs synchronously on the hook IPC thread | EvaluateRequest with subject SID, resource path, action, volume classes |
| PID -> SID resolution | Windows API boundary; may fail for elevated or exited processes | Process PID in, caller SID string out (or None) |
| test mock -> real handler | Mock OfflineManager and stubs replace production dependencies; tests verify wiring only | Test-only IpcPayloadV1 frames |

## Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation | Status |
|-----------|----------|-----------|----------|-------------|------------|--------|
| T-58.2-01 | Tampering | Duplicate named-pipe listener | high | mitigate | Consolidate to single HookIpcServer; remove inline block and old spawn function; store sole handle in RunLoopContext::hook_ipc_handle | closed |
| T-58.2-02 | Information Disclosure | Diagnostics/health/override handlers lost | high | mitigate | Builder chain explicitly attaches .with_diagnostics_handler, .with_health_handler, .with_override_handler on the consolidated server | closed |
| T-58.2-03 | Denial of Service | Double-join on shutdown | medium | mitigate | Remove BlockingThreads::hook_ipc field and join path; rely solely on RunLoopContext::hook_ipc_handle | closed |
