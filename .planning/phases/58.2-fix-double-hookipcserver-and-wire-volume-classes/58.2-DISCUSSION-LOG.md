## Consolidate the two HookIpcServer instances

| Option | Description | Selected |
|--------|-------------|----------|

**User's choice:** Merge both into one new builder
**Notes:** Chosen because it groups all hook-IPC construction and eliminates the duplicate named-pipe listener.

## Wire volume class forwarding

| Option | Description | Selected |

| Destination only | Only forward the destination field; source stays None. Not recommended. | |

**User's choice:** Source and destination
**Notes:** Both fields are already populated by the hook DLL and are needed for COPY/MOVE policy enforcement.

| Option | Description | Selected |
|--------|-------------|----------|

**User's choice:** New hook_request_to_evaluate_request helper (as recommended)

---

| Option | Description | Selected |
|--------|-------------|----------|
| Keep other None fields out of scope | Leave them None. HookRequest does not carry these today, so forwarding is not possible without a protocol change. | Yes |
| Forward any matching HookRequest fields | Forward any matching fields that already exist on HookRequest (e.g. pid could become part of agent context). This risks scope creep. | |

**User's choice:** Keep other None fields out of scope (as recommended)
**Notes:** Out of scope for Phase 58.2; no protocol change for those fields.

---

| Option | Description | Selected |
|--------|-------------|----------|

## Resolve real user SID from hook PID

| Option | Description | Selected |
|--------|-------------|----------|
| Resolve from PID | Open the process token of req.pid and convert TokenUser.Sid to a string. | Yes |
| Keep S-1-5-18 | Keep the existing hardcoded SYSTEM SID. Not suitable for per-user ABAC policies. | |

**User's choice:** Resolve from PID
**Notes:** Required for per-user ABAC policy enforcement on the hook path.

---

| Option | Description | Selected |
|--------|-------------|----------|
| Inside hook_request_to_evaluate_request | Let the conversion helper call get_process_user_sid directly so the returned EvaluateRequest already has the correct subject. | |
| In the handler closure before conversion | Resolve in the handler closure and pass the SID string into the helper. Keeps the helper pure but splits identity logic. | |
| Dedicated get_caller_sid helper | Wrap get_process_user_sid into a small get_caller_sid(req) helper used by both the conversion and approval-cache paths. | Yes |

**User's choice:** Dedicated get_caller_sid helper (as recommended)
**Notes:** Centralizes identity resolution so both approval-cache and ABAC paths use the same caller SID.

---

| Option | Description | Selected |
|--------|-------------|----------|
| Deny if resolution fails | Return DENY with reason 'identity resolution failed'. Aligns with fail-closed and the existing inline stub behavior. | Yes |
| Fallback to SYSTEM SID | Fall back to S-1-5-18 and continue ABAC evaluation. Allows operation but may apply wrong user policy. | |
| Evaluate with empty SID | Evaluate with an empty subject SID. Will likely fail most ABAC conditions but is not explicit. | |

**User's choice:** Deny if resolution fails (as recommended)
**Notes:** Fail-closed is the correct security posture when identity cannot be established.

---

| Option | Description | Selected |
|--------|-------------|----------|
| Non-windows stub returning placeholder | Provide a non-windows stub for get_process_user_sid that returns S-1-5-18 so unit/integration tests compile and run on Linux/macOS. | Yes |

**Notes:** Keeps CI test coverage without changing the production Windows path.

## Claude's Discretion

The user deferred to Claude's recommendation for:

- Approval-cache override behavior on the hook path (preserve as pre-ABAC override).
- Consolidated server thread handle storage (only in `RunLoopContext`).
- `HookRequest` → `EvaluateRequest` conversion location (new helper).
- Other hardcoded `None` ABAC fields (keep out of scope).
- Missing volume class behavior (warn on `COPY`/`MOVE`).
- PID → SID resolution point (`get_caller_sid` helper).
- Identity resolution failure mode (deny).
- Non-Windows compilation strategy (placeholder stub).
- Identity resolution testability (rely on non-Windows stub via resolved `caller_sid` parameter).
- Hook IPC server integration test scope (end-to-end routing + single-instance).
- Volume-class validation strategy (both integration and PolicyStore tests).
