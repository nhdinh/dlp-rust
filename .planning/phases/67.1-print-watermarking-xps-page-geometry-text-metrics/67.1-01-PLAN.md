    2. `WatermarkGeometry` struct with fields: `origin_x: f64`, `origin_y: f64`, `font_em_size: f64`, `page_width: f64`, `page_height: f64`, `truncated_text: String`, `padding: f64`. Derive `Debug`, `Clone`, `PartialEq`.

    3. `FontMetrics` trait (per D-02.3): `pub trait FontMetrics: Send + Sync { fn measure(&self, text: &str, family: &str, em_size: f64) -> Result<(f64, f64)>; }`. Document that width and height are returned in XPS units (1/96 inch). Document that implementors may return `anyhow::Error` wrapped errors.

    4. `TestFontMetrics` struct (per D-02.3) with `char_width: f64`, `line_height: f64`. Implement `FontMetrics` returning `text.chars().count() as f64 * self.char_width` for width and `self.line_height` for height. Document that this is an approximation for CI on non-Windows runners and uses Unicode scalar value count (not grapheme clusters) as a deliberate simplification.

    5. `extract_page_geometry(xml: &[u8]) -> Result<(f64, f64)>` (per D-03): Use `quick_xml::Reader` streaming parse to find the first `FixedPage` start/empty event. Extract `Width` and `Height` attributes via `decode_and_unescape_value`. Parse with `f64::from_str`. If missing, log `tracing::warn!` and return `(816.0, 1056.0)` default. If `FixedPage` not found, return `Err`. Follow the exact error handling pattern from `print_xps_parser.rs::parse_page_text`.

    6. `build_watermark_text(username, timestamp, device_fingerprint_prefix, tier_label, approval_id) -> String` (per D-05.3): Format as `"{username} | {timestamp} | {fp_prefix} | {tier} | {approval_id}"`.

    7. `truncate_with_ellipsis(text, metrics, em_size, available_width) -> Result<String>` (per D-04.2, Pitfall 5): Iteratively remove the last character and re-measure (text + "...") until width <= available_width or only "..." remains (return "..."). Guard against infinite loop by checking if text is empty after removal. Log `tracing::warn!` if truncation reaches minimum. Add a max-iterations guard (e.g., `text.len() + 5`) with a clear comment explaining the O(n^2) nature is acceptable for bounded watermark strings (~80-120 chars).

    8. `compute_watermark_geometry(page_width, page_height, text, metrics, padding) -> Result<WatermarkGeometry>` (per D-03, D-04): Compute `em_size = pt_to_xps_units(8.0)` (8 pt -> XPS units = 10.6667). Measure text via `metrics.measure(text, "Arial", em_size)`. If width > `page_width - 2*padding`, call `truncate_with_ellipsis`. Re-measure truncated text. Compute `origin_x = page_width - padding - final_width`, `origin_y = page_height - padding`. Return `WatermarkGeometry`.

    9. All functions must have doc comments with `# Arguments`, `# Returns`, `# Errors`, and `# Examples` where applicable (per CLAUDE.md 9.3).

    10. No `.unwrap()` in library code; use `?` or `.context()` with `anyhow` (per CLAUDE.md 9.4, 9.5).

        - `extract_page_geometry` with no FixedPage element (returns Err)
        - `TestFontMetrics::measure` returns deterministic values
        - `compute_watermark_geometry` with text that fits (no truncation)
        - `compute_watermark_geometry` with text that overflows (truncation with ellipsis)
        - `compute_watermark_geometry` origin at bottom-right with 20-unit padding

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| XPS bytes (untrusted input) → `extract_page_geometry` / `inject_watermark` | Malformed ZIP/XML from any print job crosses here |
| DirectWrite COM → `DirectWriteFontMetrics` | External Windows OS service; font loading is attacker-controlled input surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67.1-01 | Denial of Service | `extract_page_geometry` (malformed ZIP) | mitigate | `zip` crate validates CRC and path safety; max page limit enforced by caller pattern from `print_xps_parser.rs` |
| T-67.1-02 | Denial of Service | `extract_page_geometry` (XML entity expansion / Billion Laughs) | mitigate | `quick-xml` disables DTD/entity expansion by default; streaming parser limits memory |
| T-67.1-03 | Tampering | `inject_watermark` (corrupting existing page markup) | mitigate | Streaming reader-writer copies all original events verbatim; only appends at `</FixedPage>` (deferred to Phase 67, but design locked per D-01) |
| T-67.1-04 | Denial of Service | `DirectWriteFontMetrics` (font loading failure / missing Arial) | mitigate | Fallback to Segoe UI per Claude's Discretion; error returned to caller, never panic |
| T-67.1-05 | Information Disclosure | Watermark text contains username/timestamp/approval_id | accept | This is intentional metadata embedding per WATERMARK-01/02 requirements; not a bug. Redaction rule (only metadata in audit events) still applies to logs. |
| T-67.1-SC | Tampering | `windows` crate (npm/pip/cargo installs) | mitigate | All packages pre-approved in RESEARCH.md Package Legitimacy Audit; no [ASSUMED] or [SUS] packages |
</threat_model>
