    Extend `dlp-agent/src/print_watermark.rs` (created in Plan 01) with the following public functions, following the streaming reader-writer pattern from RESEARCH.md Pattern 1 and the ZIP traversal pattern from `print_xps_parser.rs`:

    1. `find_font_uri_in_xps(xps_bytes: &[u8]) -> Option<String>`:
       - Open XPS as `zip::read::ZipArchive` from `Cursor::new(xps_bytes)`.
       - Scan all `.fpage` entries for the first `Glyphs` element with a `FontUri` attribute.
       - Return the `FontUri` value as `Some(String)` if found, `None` otherwise.
       - Document that this is a best-effort heuristic: Windows-generated XPS spool files typically embed a single font part referenced by all pages. If no `FontUri` is found, the watermark will rely on printer-driver font substitution (accepted risk per review consensus).
       - Use `quick_xml::Reader` streaming parse, same pattern as `extract_page_geometry`.

    2. `inject_watermark_into_fpage(xml: &[u8], geometry: &WatermarkGeometry, font_uri: Option<&str>) -> Result<Vec<u8>>`:
       - Create `quick_xml::Reader` from `xml` with `trim_text(true)`.
       - Create `quick_xml::Writer` backed by `Cursor::new(Vec::new())`.
       - Track `fixed_page_namespace: Option<String>` during streaming. When `Event::Start(e)` or `Event::Empty(e)` is encountered where `e.local_name().as_ref() == b"FixedPage"`, capture the namespace URI from `e.name().namespace()` (or `e.name().prefix()` if prefix is present) and store it for later injection.
       - On `Event::End(e)` where `e.local_name().as_ref() == b"FixedPage"` (use `local_name()`, NOT `name()`, to handle namespaced XPS per review HIGH concern):
         a. If `fixed_page_namespace` is `Some(ns)`, create the injected `Canvas` start tag with the namespace URI: `BytesStart::new("Canvas")` and push the namespace attribute `xmlns="{ns}"` (or use the same prefix if one was detected). If `fixed_page_namespace` is `None`, use unqualified `BytesStart::new("Canvas")`.
         b. Write `Event::Start(canvas_start)` with `Opacity="0.5"` attribute.
         c. Create `Glyphs` as `Event::Empty(BytesStart::new("Glyphs"))` with attributes:
            - `UnicodeString` = `geometry.truncated_text`
            - `FontRenderingEmSize` = `geometry.font_em_size` (format with sufficient precision, e.g., `format!("{:.4}", value)`)
            - `OriginX` = `geometry.origin_x` (format with sufficient precision)
            - `OriginY` = `geometry.origin_y` (format with sufficient precision)
            - `Fill` = `"#FF808080"` (per Claude's Discretion in CONTEXT.md)
            - `Opacity` = `"0.5"`
            - `FontUri` = `font_uri.unwrap_or("")` (if `font_uri` is `Some`, use the value; if `None`, omit the attribute entirely — do not emit an empty `FontUri=""`)
         d. Write `Event::End(BytesEnd::new("Canvas"))`.
         e. Then write the original `Event::End(e)`.
       - For all other events (including `Event::Start(FixedPage)`, `Event::Empty(...)`, text, etc.), pass through verbatim: `writer.write_event(e)?`.
       - On `Event::Eof`, break the loop.
       - On XML parse error, return `Err` with `anyhow::bail!` including buffer position.
       - Return the writer's inner `Vec<u8>`.
       - Document with doc comments: `# Arguments`, `# Returns`, `# Errors`. Document the namespace handling strategy explicitly.

    3. `rewrite_xps_with_watermark(xps_bytes: &[u8], geometry_builder: &dyn Fn(usize, f64, f64) -> Result<WatermarkGeometry>, font_uri: Option<&str>) -> Result<Vec<u8>>`:
       - Open XPS as `zip::read::ZipArchive` from `Cursor::new(xps_bytes)`.
       - Create output buffer and `zip::write::ZipWriter`.
       - Iterate all entries in the input archive. For each entry:
         a. Read the original entry's `compression()` method via `archive.by_index(i)?`.
         b. Copy non-`.fpage` entries verbatim to output using the SAME compression method and `SimpleFileOptions` matching the original entry's method (per review MEDIUM concern: preserve compression metadata).
         c. For `.fpage` entries (case-insensitive match on `.ends_with(".fpage")`):
            - Read XML bytes.
            - Call `extract_page_geometry(&xml_bytes)` to get `(width, height)`.
            - Call `geometry_builder(page_index, width, height)` to get `WatermarkGeometry` for this page. The `geometry_builder` closure receives the 0-based page index and the parsed dimensions.
            - Call `inject_watermark_into_fpage(&xml_bytes, &geometry, font_uri)`.
            - Write the rewritten XML bytes to the output ZIP with the same file name and `SimpleFileOptions::default().compression_method(zip::CompressionMethod::Stored)` (preserve stored compression for spooler compatibility).
       - Call `zip.finish()` and return `buf.into_inner()`.
       - Document that this preserves all non-page files (`.fdoc`, `.fdseq`, `[Content_Types].xml`, resources) verbatim with original compression.

    4. `inject_watermark(xps_bytes: &[u8], text: &str, metrics: &dyn FontMetrics) -> Result<Vec<u8>>` (convenience wrapper):
       - Call `find_font_uri_in_xps(xps_bytes)` to get an optional font URI.
       - Internally counts pages and calls `rewrite_xps_with_watermark` with a closure that:
         a. Calls `compute_watermark_geometry(page_width, page_height, text, metrics, 20.0)` (20 XPS units = 15 pt padding per D-03.2).
       - Returns the rewritten XPS bytes.
       - Document as the primary entry point for Phase 67 integration.
       - Document the font-substitution decision: "If the XPS package does not contain an embedded font part, the watermark `Glyphs` element will omit `FontUri` and rely on the printer driver's font substitution. This is an accepted risk for Windows spooler-generated XPS, which typically embeds at least one font. Full font embedding and OPC relationship updates are deferred to Phase 67 if production testing reveals substitution failures."

    5. `validate_xps_structure(xps_bytes: &[u8]) -> Result<()>`:
       - Open XPS as `zip::read::ZipArchive` from `Cursor::new(xps_bytes)`.
       - Verify the archive contains `[Content_Types].xml` at the root (required by OPC).
       - Verify at least one `.fpage` entry exists.
       - For each `.fpage` entry, verify it can be opened and contains a `<FixedPage` start tag (using `quick_xml::Reader` with `local_name()` matching).
       - Return `Ok(())` if all checks pass, or `Err` with descriptive message if any check fails.
       - Document as a post-rewrite validation helper for tests and Phase 67 integration.

    6. All functions must use `?` for error propagation, `anyhow::Context` for context, and `tracing::warn!` for non-fatal skips (e.g., unreadable page XML — but in this phase, unreadable pages should return Err to caller per D-06.1).

    7. No `.unwrap()` in library code (per CLAUDE.md 9.4).

    1. **FontUri strategy for Phase 67.1**: The watermark injection reuses an existing `FontUri` from the first `Glyphs` element found in any `.fpage`. If no `FontUri` is found, the `FontUri` attribute is omitted and the printer driver performs font substitution. This is an accepted risk because Windows spooler-generated XPS typically embeds at least one font.

    2. **OPC relationship updates deferred**: If a new font part were embedded (not implemented in Phase 67.1), the following OPC files would need updating:
       - `[Content_Types].xml`: Add `<Override PartName="/Documents/1/Resources/Fonts/Fallback.otf" ContentType="application/vnd.openxmlformats-officedocument.obfuscatedFont"/>` (or the appropriate font content type).

       - The font part itself must be added to the ZIP at the referenced path.
       - These updates are **deferred to Phase 67** if production testing reveals font-substitution failures.

    3. **Namespace handling**: The `inject_watermark_into_fpage` function detects the namespace URI from the `FixedPage` `BytesStart` event and propagates it to the injected `Canvas` element. If `FixedPage` has no namespace (uncommon), unqualified `Canvas`/`Glyphs` are used. This ensures the injected elements are valid children of the namespaced `FixedPage`.

    4. **Compression preservation**: Non-`.fpage` entries are copied with their original `CompressionMethod` to avoid changing spool file hashes or downstream tooling behavior.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-67.1-07 | Tampering | `rewrite_xps_with_watermark` (corrupting non-page files) | mitigate | Non-`.fpage` entries are copied verbatim byte-for-byte with original compression method preserved; no modification |
| T-67.1-08 | Denial of Service | `rewrite_xps_with_watermark` (zip bomb, oversized XPS) | mitigate | `zip` crate validates CRC and path safety; caller (Phase 67) controls max page count and can limit input size |
| T-67.1-09 | Information Disclosure | Watermark text in rewritten XPS | accept | Intentional per WATERMARK-01/02; watermark text is meant to be visible on printed output |
| T-67.1-10 | Denial of Service | `inject_watermark_into_fpage` (malformed XML causes panic) | mitigate | All XML errors return `Err` via `anyhow::bail!`; no `.unwrap()` in library code per CLAUDE.md 9.4 |
| T-67.1-11 | Tampering | `inject_watermark_into_fpage` (namespace mismatch causes invalid XPS) | mitigate | Uses `local_name()` matching for `FixedPage` end tag; namespace URI is detected from Start event and propagated to injected Canvas if needed |
