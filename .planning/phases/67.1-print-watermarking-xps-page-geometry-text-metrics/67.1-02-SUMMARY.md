## Decisions Made

- **FontUri reuse strategy:** Scan the first `Glyphs` element in any `.fpage` for an existing `FontUri`. If found, reuse it; if not, omit the `FontUri` attribute entirely and rely on printer driver font substitution. This is an accepted risk because Windows spooler-generated XPS typically embeds at least one font. Full font embedding and OPC relationship updates are deferred to Phase 67 if production testing reveals substitution failures.
- **Namespace propagation via FixedPageNs enum:** Parse `xmlns` and `xmlns:*` attributes from the `FixedPage` `BytesStart` event, then emit `Canvas`/`Glyphs` with matching qualification (unqualified, default namespace, or prefixed). This ensures injected elements are valid children regardless of how the XPS was namespaced.
- **Compression preservation:** Non-`.fpage` entries are copied with their original `CompressionMethod` to avoid changing spool file hashes or downstream tooling behavior. `.fpage` entries are intentionally rewritten as `CompressionMethod::Stored` because they are small XML files and spooler compatibility is prioritized over compression ratio.
- **trim_text(false):** Used in `inject_watermark_into_fpage` to preserve whitespace text nodes, ensuring verbatim XML preservation except at the injection point.
