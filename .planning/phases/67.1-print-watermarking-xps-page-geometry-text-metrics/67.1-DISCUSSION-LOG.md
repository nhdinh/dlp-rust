## Text overlay mechanism

| Option | Description | Selected |
|--------|-------------|----------|
| Glyphs XML injection (recommended) | Add a new `Canvas`/`Glyphs` element to each `.fpage` XML. Vector text survives printer rasterization, keeps file size small, and reuses the existing quick-xml parser. | ✓ |
| Vector Path outlines | Extract glyph outlines from a font file and emit `Path` elements. No font file reference needed at print time, but much more complex and requires outline parsing. | |
| Rasterized image overlay | Render the watermark to a bitmap and embed it as an `ImageBrush`. Easiest to position, but loses sharpness at high DPI and requires PNG/JPEG encoding. | |

**User's choice:** Glyphs XML injection (recommended)
**Notes:** User responded "all your recommendations", interpreted as accepting the recommended option.

## Font metrics source

| Option | Description | Selected |
|--------|-------------|----------|
| DirectWrite via windows-rs (recommended) | Call DirectWrite via windows-rs at runtime. Most accurate text measurement on Windows, matches the rasterizer that will render the watermark, but adds Win32 API calls and is harder to unit test. | ✓ |
| Pure Rust font crate | Use a pure-Rust crate like fontdue or ttf-parser. Easier to test offline and cross-platform, but metrics may not exactly match Windows' Arial rendering. | |
| Hardcoded metrics | Assume Arial 8 pt fixed metrics (e.g., width per character). Simplest and testable, but breaks with non-ASCII text or printer drivers that substitute fonts. | |

**User's choice:** DirectWrite via windows-rs (recommended)
**Notes:** Trait-based design (`FontMetrics`) will allow deterministic test stubs.

## Page geometry and coordinate system

| Option | Description | Selected |
|--------|-------------|----------|
| XPS native units (recommended) | Work in XPS units (1/96 inch) throughout. Parse `FixedPage/@Width|Height` directly, convert the 15 pt padding to 20 XPS units, and position the watermark using XPS coordinates. | ✓ |
| Points | Convert everything to points (1/72 inch). Matches the requirement wording ('15 pt padding', '8 pt font'), but requires constant conversion back to XPS units when emitting XML. | |
| Millimeters | Convert to millimeters. Familiar to operators, but adds another conversion layer and XPS/ODF use different DPI assumptions. | |

**User's choice:** XPS native units (recommended)
**Notes:** 15 pt padding = 20 XPS units; 8 pt font ≈ 10.6667 XPS units. Default letter page 816×1056 if dimensions missing.

---

## Watermark layout and overflow

| Option | Description | Selected |
|--------|-------------|----------|
| Single-line, truncate on overflow (recommended) | Single line at bottom-right. If measured width exceeds available space, truncate with an ellipsis. Simple, predictable, and matches the success criteria. | ✓ |
| Multi-line stacked | Split the watermark into multiple lines stacked at bottom-right. More readable on small pages, but increases page footprint and may overlap content. | |
| Scale to fit | Scale the font size down until the text fits. Keeps all information, but watermark size becomes unpredictable across jobs. | |

**User's choice:** Single-line, truncate on overflow (recommended)
**Notes:** Overflow handled by truncating with ellipsis; no scaling or wrapping in this phase.

## Claude's Discretion

- Font family: Arial with DirectWrite default fallback if unavailable.
- Opacity: 0.5 gray (`#FF808080`).
- Baseline alignment: `OriginY = page_height - padding`, `OriginX = page_width - padding - measured_width`.
- Transform handling: watermark injected as top-level peer; nested transforms not inverted in this phase.
