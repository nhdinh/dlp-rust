# Phase 67.1: Print Watermarking — XPS Page Geometry + Text Metrics - Research

**Researched:** 2026-06-12
**Domain:** Windows XPS spool file manipulation, DirectWrite text metrics, XML injection via quick-xml
**Confidence:** HIGH

## Summary

Phase 67.1 delivers the foundational modules for print watermarking in the DLP agent. The core challenge is: given an XPS spool file (a ZIP archive containing `.fpage` XML pages), extract page geometry, measure a Unicode watermark string using the system's Arial font via DirectWrite, compute the bottom-right placement origin with padding, and inject a `Canvas`/`Glyphs` watermark element into each page's XML without corrupting existing markup.

The existing codebase already parses XPS ZIP archives and extracts text from `.fpage` files using `quick-xml` 0.36 and `zip` 2.x. Phase 67.1 extends this to: (1) read `FixedPage/@Width` and `FixedPage/@Height` attributes, (2) add a `FontMetrics` trait with a DirectWrite implementation and a deterministic test stub, (3) compute watermark placement in XPS native units (1/96 inch), and (4) use `quick-xml::Writer` in a streaming reader-writer pattern to append a `Canvas` element containing a `Glyphs` child to each `.fpage` before rewriting the ZIP.

**Primary recommendation:** Implement a `WatermarkGeometry` struct, a `FontMetrics` trait with `DirectWriteFontMetrics` (Win32 COM) and `TestFontMetrics` (fixed per-char width), and a `quick-xml` streaming reader-writer that injects the watermark `Canvas` element just before each `FixedPage` end tag. All geometry in XPS units; 15 pt padding = 20 XPS units; 8 pt font = 10.6667 XPS units for `FontRenderingEmSize`.

### Pattern 1: Streaming XML Injection (Reader-Writer)
**What:** Use `quick_xml::Reader` to stream through `.fpage` XML events, and `quick_xml::Writer` to emit modified events. When the reader encounters the `</FixedPage>` end tag, the writer first emits the injected `Canvas`/`Glyphs` element, then emits the end tag.
**When to use:** For all `.fpage` rewrite operations. This preserves existing namespace declarations, attributes, and child elements without building a DOM.
**Example:**
```rust
// Source: quick-xml docs + project pattern in print_xps_parser.rs
use quick_xml::events::{Event, BytesStart, BytesEnd, BytesText};
use quick_xml::reader::Reader;
use quick_xml::writer::Writer;

fn inject_watermark_into_fpage(xml: &[u8], geometry: &WatermarkGeometry) -> Result<Vec<u8>> {
    let mut reader = Reader::from_reader(xml);
    reader.config_mut().trim_text(true);
    let mut writer = Writer::new(Cursor::new(Vec::new()));
    let mut buf = Vec::new();

    loop {
        match reader.read_event_into(&mut buf) {
            Ok(Event::End(e)) if e.name().as_ref() == b"FixedPage" => {
                // Inject watermark Canvas before closing FixedPage
                let canvas_start = BytesStart::new("Canvas");
                writer.write_event(Event::Start(canvas_start))?;

                let mut glyphs = BytesStart::new("Glyphs");
                glyphs.push_attribute(("UnicodeString", geometry.truncated_text.as_str()));
                glyphs.push_attribute(("FontRenderingEmSize", geometry.font_em_size.to_string().as_str()));
                glyphs.push_attribute(("OriginX", geometry.origin_x.to_string().as_str()));
                glyphs.push_attribute(("OriginY", geometry.origin_y.to_string().as_str()));
                glyphs.push_attribute(("Fill", "#FF808080"));
                glyphs.push_attribute(("Opacity", "0.5"));
                writer.write_event(Event::Empty(glyphs))?;

                writer.write_event(Event::End(BytesEnd::new("Canvas")))?;

                // Now emit the original </FixedPage>
                writer.write_event(Event::End(e))?;
            }
            Ok(Event::Eof) => break,
            Ok(e) => writer.write_event(e)?,
            Err(e) => anyhow::bail!("XML error: {:?}", e),
        }
        buf.clear();
    }
    Ok(writer.into_inner().into_inner())
}
```

### Pattern 2: Trait-Based Font Metrics (Testable Abstraction)
**What:** Define a `FontMetrics` trait with `measure(&self, text: &str, family: &str, em_size: f64) -> (f64, f64)`. Implement `DirectWriteFontMetrics` for production (Win32 COM) and `TestFontMetrics` for unit tests.
**When to use:** All text measurement calls go through the trait. Tests pass a `TestFontMetrics` with fixed per-character width.
**Example:**
```rust
// Source: project pattern (trait abstraction for testability)
pub trait FontMetrics: Send + Sync {
    /// Measure text width and height in XPS units (1/96 inch).
    fn measure(&self, text: &str, family: &str, em_size: f64) -> Result<(f64, f64)>;
}

/// Production implementation using DirectWrite via windows-rs.
pub struct DirectWriteFontMetrics;

impl FontMetrics for DirectWriteFontMetrics {
    fn measure(&self, text: &str, family: &str, em_size: f64) -> Result<(f64, f64)> {
        // SAFETY: DirectWrite COM calls. CoInitializeEx assumed called by caller thread.
        unsafe {
            let factory: IDWriteFactory = DWriteCreateFactory(DWRITE_FACTORY_TYPE_SHARED)?;
            let family_wide: Vec<u16> = family.encode_utf16().chain(Some(0)).collect();
            let text_format = factory.CreateTextFormat(
                PCWSTR(family_wide.as_ptr()),
                None, // default font collection
                DWRITE_FONT_WEIGHT_NORMAL,
                DWRITE_FONT_STYLE_NORMAL,
                DWRITE_FONT_STRETCH_NORMAL,
                em_size as f32,
                w!("en-us"),
            )?;
            let text_wide: Vec<u16> = text.encode_utf16().chain(Some(0)).collect();
            let layout = factory.CreateTextLayout(
                &text_wide[..text_wide.len() - 1], // exclude null
                &text_format,
                f32::MAX,
                f32::MAX,
            )?;
            let mut metrics = DWRITE_TEXT_METRICS::default();
            layout.GetMetrics(&mut metrics)?;
            Ok((metrics.width as f64, metrics.height as f64))
        }
    }
}

/// Test stub with deterministic per-character width.
pub struct TestFontMetrics {
    pub char_width: f64,
    pub line_height: f64,
}

impl FontMetrics for TestFontMetrics {
    fn measure(&self, text: &str, _family: &str, _em_size: f64) -> Result<(f64, f64)> {
        let width = text.chars().count() as f64 * self.char_width;
        Ok((width, self.line_height))
    }
}
```

### Pattern 3: Watermark Geometry Computation
**What:** Pure function that takes page dimensions, measured text, padding, and returns origin coordinates plus truncation decision.
**When to use:** Called once per page after metrics are known.
**Example:**
```rust
/// Compute watermark placement in XPS units.
///
/// # Arguments
///
/// * `page_width` — XPS page width (from FixedPage/@Width or default 816).
/// * `page_height` — XPS page height (from FixedPage/@Height or default 1056).
/// * `text` — The watermark string to render.
/// * `metrics` — A `FontMetrics` implementation for measurement.
/// * `padding` — Padding in XPS units (default 20 for 15 pt).
///
/// # Returns
///
/// `WatermarkGeometry` with origin, font size, and truncated text (if overflow).
pub fn compute_watermark_geometry(
    page_width: f64,
    page_height: f64,
    text: &str,
    metrics: &dyn FontMetrics,
    padding: f64,
) -> Result<WatermarkGeometry> {
    let em_size = 8.0_f64 * (96.0 / 72.0); // 8 pt -> XPS units = 10.6667
    let (measured_width, measured_height) = metrics.measure(text, "Arial", em_size)?;

    let available_width = page_width - 2.0 * padding;
    let truncated_text = if measured_width > available_width {
        truncate_with_ellipsis(text, metrics, em_size, available_width)?
    } else {
        text.to_string()
    };

    let final_width = metrics.measure(&truncated_text, "Arial", em_size)?.0;
    let origin_x = page_width - padding - final_width;
    let origin_y = page_height - padding;

    Ok(WatermarkGeometry {
        origin_x,
        origin_y,
        font_em_size: em_size,
        page_width,
        page_height,
        truncated_text,
        padding,
    })
}
```

### Anti-Patterns to Avoid
- **DOM-based XML rewriting:** Do not use `roxmltree` or `xml-rs` DOM for `.fpage` injection. The streaming reader-writer pattern is memory-efficient and already aligned with the existing `quick-xml` usage.
- **Hardcoded font metrics:** Do not assume fixed per-character widths in production. DirectWrite metrics vary by font, size, and Unicode character. Only use fixed metrics in the `TestFontMetrics` stub.
- **Modifying the original ZIP in-place:** Always write to a new in-memory buffer (`Cursor<Vec<u8>>`) and return the new bytes. The caller (Phase 67) will decide whether to overwrite the spool file.
- **Ignoring namespace prefixes:** If the `.fpage` uses a namespace prefix (e.g., `xps:FixedPage`), the injected element must use the same prefix or be fully qualified. However, XPS typically uses default namespaces, so unqualified `Canvas`/`Glyphs` are correct.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| ZIP archive read/write | Custom ZIP parser | `zip` crate | ZIP has complex directory structures, compression methods, and CRC checks. The `zip` crate handles all of this. |
| XML streaming parse/rewrite | Custom XML parser | `quick-xml` | XML attribute escaping, namespace handling, and entity resolution are error-prone. `quick-xml` is battle-tested and already in the project. |
| Font metrics measurement | Custom font rasterizer | DirectWrite via `windows-rs` | Font metrics depend on hinting, kerning, and glyph substitution. DirectWrite is the same rasterizer that will render the watermark, so metrics match exactly. |
| XPS unit conversion | Ad-hoc math | Standard formulas: `pt * 96/72 = XPS units` | XPS spec defines 1 unit = 1/96 inch. Using standard conversion ensures correctness. |

**Key insight:** The hardest part of this phase is not the geometry math (which is straightforward) but the streaming XML injection that preserves all existing markup. The `quick-xml` reader-writer pattern solves this cleanly without a DOM.

## Common Pitfalls

### Pitfall 1: DirectWrite COM Threading
**What goes wrong:** `DWriteCreateFactory` requires COM to be initialized on the calling thread. If `CoInitializeEx` was not called, the factory creation fails with `CO_E_NOTINITIALIZED`.
**Why it happens:** The print watcher thread is a `std::thread` spawned from a tokio runtime. COM is not auto-initialized.
**How to avoid:** Call `CoInitializeEx(None, COINIT_APARTMENTTHREADED)` at the start of the watcher thread (already done implicitly by other Win32 calls in the agent, but verify). If the thread already called `CoInitializeEx`, a second call returns `S_FALSE` — this is harmless.
**Warning signs:** `DWriteCreateFactory` returning `Err(CO_E_NOTINITIALIZED)` at runtime.

### Pitfall 2: quick-xml Writer Event Ordering
**What goes wrong:** Forgetting to emit the injected element before the `</FixedPage>` end tag causes the watermark to appear outside the page, or emitting it after the end tag creates malformed XML.
**Why it happens:** The reader-writer pattern requires careful state tracking. The injection point is the `Event::End(FixedPage)` event.
**How to avoid:** Use a single `match` arm for `Event::End(e) if e.name().as_ref() == b"FixedPage"` that first writes the injected element(s), then writes the original end event.
**Warning signs:** Unit tests with round-trip XML parsing fail, or the rewritten `.fpage` is rejected by the XPS viewer.

### Pitfall 3: XPS Default Page Size Assumption
**What goes wrong:** Assuming all pages are 816x1056 (US Letter) when `FixedPage` omits explicit `Width`/`Height` attributes. Some pages may be A4 (793.8x1122.56) or custom sizes.
**Why it happens:** The XPS spec allows omitting dimensions, defaulting to the document's `FixedDocument` size or the printer's default. However, in practice, most Windows spooler-generated XPS files include explicit dimensions.
**How to avoid:** Parse `Width` and `Height` attributes. If both are missing, log a warning and use the default 816x1056. Do not silently assume.
**Warning signs:** Watermark appears off-page or in the wrong position for non-letter pages.

### Pitfall 4: Unicode String Width in Test Stub
**What goes wrong:** The `TestFontMetrics` stub uses `text.chars().count()` which counts Unicode scalar values, not grapheme clusters. A multi-codepoint emoji or combining character will report an incorrect width.
**Why it happens:** The stub is intentionally simple, but tests with complex Unicode may fail.
**How to avoid:** For the test stub, use a fixed per-char width and document that it is an approximation. For production, DirectWrite handles grapheme clusters correctly.
**Warning signs:** Test assertions on measured width fail for strings with combining characters.

### Pitfall 5: Truncation Loop Infinite Recursion
**What goes wrong:** The ellipsis truncation logic repeatedly removes characters and re-measures, but if even a single character + ellipsis exceeds the available width, the loop never terminates.
**Why it happens:** No minimum width check before entering the truncation loop.
**How to avoid:** After each truncation step, check if the remaining text (plus ellipsis) is empty. If so, return just the ellipsis (or empty string) and log a warning.
**Warning signs:** Stack overflow or hung thread during watermark computation.

### DirectWrite Text Measurement (Production)
```rust
// Source: windows-rs docs + DirectWrite API reference
use windows::core::{w, Result as WinResult, PCWSTR};
use windows::Win32::Graphics::DirectWrite::{
    DWriteCreateFactory, DWRITE_FACTORY_TYPE_SHARED, DWRITE_FONT_STRETCH_NORMAL,
    DWRITE_FONT_STYLE_NORMAL, DWRITE_FONT_WEIGHT_NORMAL, IDWriteFactory,
    DWRITE_TEXT_METRICS,
};

/// Measure text width and height using DirectWrite.
///
/// # Safety
///
/// Caller must ensure COM is initialized on the current thread.
pub unsafe fn measure_text_directwrite(
    text: &str,
    family: &str,
    em_size: f32,
) -> WinResult<(f32, f32)> {
    let factory: IDWriteFactory = DWriteCreateFactory(DWRITE_FACTORY_TYPE_SHARED)?;

    let family_wide: Vec<u16> = family.encode_utf16().chain(Some(0)).collect();
    let text_format = factory.CreateTextFormat(
        PCWSTR(family_wide.as_ptr()),
        None,
        DWRITE_FONT_WEIGHT_NORMAL,
        DWRITE_FONT_STYLE_NORMAL,
        DWRITE_FONT_STRETCH_NORMAL,
        em_size,
        w!("en-us"),
    )?;

    let text_wide: Vec<u16> = text.encode_utf16().chain(Some(0)).collect();
    let layout = factory.CreateTextLayout(
        &text_wide[..text_wide.len().saturating_sub(1)],
        &text_format,
        f32::MAX,
        f32::MAX,
    )?;

    let mut metrics = DWRITE_TEXT_METRICS::default();
    layout.GetMetrics(&mut metrics)?;

    Ok((metrics.width, metrics.height))
}
```

### XPS Page Geometry Extraction
```rust
// Source: project pattern (quick-xml attribute extraction)
use quick_xml::events::Event;
use quick_xml::Reader;

/// Extract page width and height from a `.fpage` XML buffer.
///
/// Returns `(width, height)` in XPS units. If attributes are missing,
/// returns the default letter size `(816.0, 1056.0)` and logs a warning.
pub fn extract_page_geometry(xml: &[u8]) -> Result<(f64, f64)> {
    let mut reader = Reader::from_reader(xml);
    reader.config_mut().trim_text(true);
    let mut buf = Vec::new();

    loop {
        match reader.read_event_into(&mut buf) {
            Ok(Event::Empty(e)) | Ok(Event::Start(e)) => {
                if e.name().as_ref() == b"FixedPage" {
                    let mut width = None;
                    let mut height = None;
                    for attr in e.attributes() {
                        let attr = attr.context("invalid attribute")?;
                        match attr.key.as_ref() {
                            b"Width" => {
                                let val = attr.decode_and_unescape_value(reader.decoder())?;
                                width = val.parse().ok();
                            }
                            b"Height" => {
                                let val = attr.decode_and_unescape_value(reader.decoder())?;
                                height = val.parse().ok();
                            }
                            _ => {}
                        }
                    }
                    let w = width.unwrap_or_else(|| {
                        tracing::warn!("FixedPage missing Width, using default 816");
                        816.0
                    });
                    let h = height.unwrap_or_else(|| {
                        tracing::warn!("FixedPage missing Height, using default 1056");
                        1056.0
                    });
                    return Ok((w, h));
                }
            }
            Ok(Event::Eof) => break,
            Err(e) => anyhow::bail!("XML parse error: {:?}", e),
            _ => {}
        }
        buf.clear();
    }

    anyhow::bail!("FixedPage element not found in .fpage XML")
}
```

## Open Questions (RESOLVED)

1. **DirectWrite feature flag in `windows` crate** — RESOLVED

   - Resolution: Plan 67.1-01 Task 1 verifies `Win32_Graphics_DirectWrite` is present in `dlp-agent/Cargo.toml` and adds it if absent.

2. **Arial font availability on all endpoints** — RESOLVED
   - What we know: Arial is a standard Windows font, but may be removed in minimal installations.
   - Resolution: Plan 67.1-01 Task 3 implements Arial-first logic with Segoe UI fallback and a `tracing::warn!` on fallback, per Claude's Discretion.

3. **XPS namespace prefix handling** — RESOLVED
   - What we know: Most Windows-generated XPS uses default namespaces (`xmlns="..."`) with unqualified element names.
   - Resolution: Plan 67.1-02 uses unqualified `Canvas`/`Glyphs` element names, which is correct for default-namespace XPS. Prefixed XPS handling is deferred to Phase 67 if observed in production.

### Known Threat Patterns for XPS/Print Stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Malformed XPS ZIP (zip bomb, path traversal) | Denial of Service | `zip` crate validates CRC and path safety; max page limit already enforced in `extract_text` |
| XML entity expansion (Billion Laughs) | Denial of Service | `quick-xml` disables DTD/entity expansion by default; streaming parser limits memory |
| Watermark injection corrupting page markup | Tampering | Streaming reader-writer copies all original events verbatim; only appends at `</FixedPage>` |
| DirectWrite font loading failure | Denial of Service | Fallback to Segoe UI; error returned to caller, not panic |
