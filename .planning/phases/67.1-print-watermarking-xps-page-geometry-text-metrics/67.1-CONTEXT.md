# Phase 67.1: Print Watermarking — XPS Page Geometry + Text Metrics - Context

**Gathered:** 2026-06-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 67.1 delivers the foundational XPS page geometry and text-metric modules needed for print watermarking. It does **not** wire end-to-end spooler interception, approval-token lookup, or admin TUI policy configuration — those belong to the parent Phase 67.

This phase produces:
1. A Rust module that reads an XPS spool file (ZIP + `.fpage` XML) and extracts each page's width, height, and transform context.
2. A text-metrics module that measures a Unicode string using the system's Arial font at a given em-size via DirectWrite/windows-rs.
3. A function that computes the bottom-right watermark origin (with 15 pt padding) and decides whether the text must be truncated.
4. A function that rewrites a `.fpage` XML buffer by injecting a new `Canvas`/`Glyphs` watermark element without corrupting the existing page markup.
5. Unit tests with in-memory XPS fixtures and mocked/abstracted font metrics.

**Requirements:** WATERMARK-01, WATERMARK-02 (foundational portions only)

</domain>

<decisions>
## Implementation Decisions

### Text overlay mechanism (D-01)
- **D-01.1:** Watermark is embedded by **injecting new `Glyphs` XML elements** into each `.fpage` file inside the XPS ZIP package.
- **D-01.2:** This keeps text as vector data, survives printer-driver rasterization, avoids image encoding, and aligns with the existing `quick-xml` + `zip` parsing path.
- **D-01.3:** The injected element is wrapped in a `Canvas` so origin and opacity can be set in one place.

### Font metrics source (D-02)
- **D-02.1:** Text width and line height are measured at runtime using **DirectWrite via `windows-rs`** (`IDWriteFactory::CreateTextFormat` + `IDWriteTextLayout`).
- **D-02.2:** DirectWrite is preferred because it is the same rasterizer/stack that will render the page, so metrics match the printed output.
- **D-02.3:** For unit tests, introduce a `FontMetrics` trait with a DirectWrite implementation and a stub/test implementation that returns deterministic metrics.

### Page geometry and coordinate system (D-03)
- **D-03.1:** All internal geometry is computed in **XPS native units** (1/96 inch).
- **D-03.2:** The 15 pt padding required by Phase 67 success criteria is converted to XPS units: `15 pt × (96 / 72) = 20 XPS units`.
- **D-03.3:** The 8 pt font size is converted similarly: `8 pt × (96 / 72) ≈ 10.6667 XPS units` for `FontRenderingEmSize`.
- **D-03.4:** Page dimensions are read from `FixedPage/@Width` and `FixedPage/@Height`. If a page omits explicit dimensions, the default XPS size `816 × 1056` (letter, 8.5×11 in at 96 DPI) is used and logged as a warning.
- **D-03.5:** Existing `Canvas.RenderTransform` and nested transforms are **not** recursively inverted in this phase. The watermark is injected as a top-level peer of existing content; if transforms are present the watermark remains upright and aligned to the page origin. (Handling rotated/transformed watermark positioning is deferred to Phase 67 if needed.)

### Watermark layout and overflow (D-04)
- **D-04.1:** The watermark is a **single-line** string rendered at the bottom-right of the page.
- **D-04.2:** If the measured text width exceeds `page_width - 2 × padding`, the text is **truncated with an ellipsis** (`…`).
- **D-04.3:** No scaling or multi-line wrapping is implemented in Phase 67.1.

### Watermark content placeholders (D-05)
- **D-05.1:** Phase 67.1 defines the watermark string builder as a function of `(username, timestamp, device_fingerprint_prefix, tier_label, approval_id)`.
- **D-05.2:** Actual values for these fields are supplied by the caller in Phase 67. For unit tests, fixtures use literal placeholder values.
- **D-05.3:** The default format is: `{username} | {timestamp} | {fp_prefix} | {tier} | {approval_id}`.

### Error handling (D-06)
- **D-06.1:** Malformed ZIP, unreadable `.fpage` XML, missing `FixedPage` dimensions, or DirectWrite font-creation failures are returned as errors to the caller.
- **D-06.2:** Phase 67 (not 67.1) decides whether a failure emits `EventType::WatermarkFailure` and cancels the print job.

### Claude's Discretion
- Font family: default to **Arial** as specified in Phase 67 success criteria. If Arial is unavailable on the endpoint, fall back to the DirectWrite default font (Segoe UI) and log a warning.
- Opacity: default to semi-transparent (`Opacity="0.5"`) and gray color (`Fill="#808080"` or `#FF808080`) on the injected `Glyphs`.
- Baseline alignment: compute `OriginY = page_height - padding` and set `OriginX = page_width - padding - measured_width`.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `dlp-agent/src/print_xps_parser.rs` — Already opens XPS as a ZIP archive, locates `.fpage` entries, and parses `FixedPage` + `Glyphs` with `quick-xml` 0.36. The watermark writer can reuse the ZIP traversal and XML reader/writer patterns.
- `dlp-agent/src/print_job_info.rs` — `JobInfo` already exposes `job_id`, `document_name`, `user_name`, `datatype`, `pages`, and `status`. Phase 67 will extend this with watermark context.
- `dlp-agent/src/print_watcher.rs` — The watcher already reads the `.SPL` file path from `C:\Windows\System32\spool\PRINTERS\{job_id}.SPL` and evaluates policy before the job starts printing. This is the insertion point for the watermark rewrite.

### Established Patterns
- **In-memory redaction:** The existing parser reads XPS bytes in memory and never logs text content. The watermark writer must follow the same rule: only metadata in audit events.
- **Blocking Win32 calls from a std thread:** `PrintWatcher` runs in a dedicated `std::thread` and uses `runtime_handle.block_on(...)` for async policy evaluation. DirectWrite font metrics calls fit naturally in this thread.
- **Error → fallback → audit:** The parser returns `Err(...)` for malformed ZIP and the caller falls back to metadata classification. The watermark writer returns `Err(...)` for geometry/metric failures; Phase 67 will decide the enforcement consequence.

### Integration Points
- The output of Phase 67.1 is a library module with functions like `compute_watermark_geometry(page_width, page_height, text, metrics) -> WatermarkGeometry` and `inject_watermark(xps_bytes, geometry_builder) -> Result<Vec<u8>>`.
- Phase 67 will call these functions from `print_watcher.rs` after policy evaluation returns ALLOW for a T3/T4 print job and before `EndDocPrinter`/spooler despool.

</code_context>

<specifics>
## Specific Ideas

- Add a `WatermarkGeometry` struct holding `origin_x`, `origin_y`, `font_em_size`, `page_width`, `page_height`, `truncated_text`, and `padding`.
- Add a `FontMetrics` trait with methods `measure(&self, text: &str, family: &str, em_size: f64) -> (f64, f64)` returning `(width, height)`.
- Implement `DirectWriteFontMetrics` using `windows::Win32::Graphics::DirectWrite` (or the newer `windows::UI::Text` types if available in the pinned `windows` 0.62 dependency).
- Implement `TestFontMetrics` that returns fixed per-character width so unit tests are deterministic on non-Windows platforms.
- For XML injection, use `quick-xml::Writer` to append a `Canvas` element containing a single `Glyphs` element at the end of the `FixedPage` children.
- Preserve existing XML namespace declarations on `FixedPage`; do not redeclare them on the injected element unless required.

</specifics>
