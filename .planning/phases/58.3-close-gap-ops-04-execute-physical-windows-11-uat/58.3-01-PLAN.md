  <action>
    On the dedicated physical Windows 11 test host, perform the following prerequisite checks per D-17:

    1. Verify Windows 11: Run `Get-CimInstance Win32_OperatingSystem | Select-Object Caption, BuildNumber` and confirm build >= 22000.
    2. Verify administrator rights: Run `([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)` and confirm `$true`.
    3. Verify dlp-agent service: Run `Get-CimInstance Win32_Service -Filter "Name='dlp-agent'" | Select-Object Name, StartName, State, StartMode` and confirm the service exists. Record both `Name` and `StartName` fields. Per deployment guide Section 4.6, the service account may be `NT SERVICE\DlpAgent` (note case differences are usually equivalent on Windows, but document the exact value observed).
    4. Verify signtool.exe: Run `Get-Command signtool.exe` and confirm it resolves.
    5. Verify Windows Defender is installed and active: Run `Get-MpComputerStatus | Select-Object RealTimeProtectionEnabled` and confirm `$true`.
    6. Verify Microsoft Word is installed: Check for `WINWORD.EXE` in `$env:ProgramFiles\Microsoft Office\root\Office16\` or `${env:ProgramFiles(x86)}\Microsoft Office\root\Office16\`. If Word is absent, this is a critical prerequisite failure for I02; abort and escalate.
    7. Apply Windows Defender allowlist per docs/operations/deployment-guide.md Section 3: add a **path exclusion** for `C:\Program Files\DLP\` and **hash exclusions** for the three injection-related binaries (`dlp-agent.exe`, `dlp_hook_dll.dll`, `dlp-user-ui.exe`) using SHA-256 hashes from RELEASE_NOTES.md. Document the allowlist steps taken. Do NOT attempt hash exclusions for the remaining three binaries (dlp-server.exe, dlp-admin-cli.exe, dlp_hook_dll_x86.dll) as the deployment guide does not list them for individual hash exclusion (path exclusion covers the install folder). Per D-01, use the script exactly as-is; do not modify the script to accommodate host-specific adjustments.
    8. Verify Secure Boot state: Run `Confirm-SecureBootUEFI` and record the result (True/False/Not supported).
    9. Verify SeSystemProfilePrivilege: Run `sc qprivs dlp-agent` and confirm `SeSystemProfilePrivilege` is listed.
    10. Create the artifact directory tree: Run `New-Item -ItemType Directory -Path 'C:\UAT\v0.10.0' -Force` and create subdirectories A, B, C, D, E, F, G, H, I, J.

    If any critical prerequisite (items 1-4, 6, 7) fails, abort and document the failure. Do NOT proceed to UAT execution until all critical prerequisites pass.
  </action>

  </verify>
