# Phase 58.3: Close gap: OPS-04 — execute physical Windows 11 UAT - Context

**Gathered:** 2026-06-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 58.3 executes the v0.10.0 UAT plan on physical Windows 11 hardware and records actual results in `.planning/milestones/v0.10.0-UAT.md`. This phase does **not** write new product code — it is the manual execution and evidence-capture step that unblocks the v0.10.0 ship decision.

**What Phase 58.3 builds:**
1. **Executed UAT scenarios** — all 36 scenarios across categories A-J run on a real Windows 11 host with real peripherals, cloud clients, and EDR.
2. **Captured artifacts** — environment data, agent log snippets, screenshots, SIEM payloads, CRIT-04 benchmark measurements, and per-scenario pass/fail notes.
3. **Recorded results** — actual results populated in `.planning/milestones/v0.10.0-UAT.md`, plus machine-readable `results.json` and `crit04_results.json`.
4. **Ship/no-ship input** — documented blocking failures, major/minor issues, and engineering/QA sign-off.

**What Phase 58.3 does NOT build:**
- New product features or code changes (those belong in Phases 48–58.2 and 58.4).
- Automated CI-driven UAT (no Windows CI runner is available).
- Peripheral robotic automation.
- New UAT scenario definitions (the scenario matrix is locked in `.planning/milestones/v0.10.0-UAT.md`).

**Depends on:** Phases 48–58.2 (the v0.10.0 milestone body of work must be complete and installed on the test host).
**Requirements:** OPS-04

</domain>

<decisions>
## Implementation Decisions

### Execution approach

- **D-01:** Use the committed `scripts/Uat-Execute-v0.10.0.ps1` exactly as-is from the repository. Host-specific adjustments (drive letters, paths) are handled manually during execution, not by modifying the script.
- **D-02:** Run the script in full interactive mode immediately; do not preview with `-WhatIf` first. The tester is expected to be familiar with the scenarios from `.planning/milestones/v0.10.0-UAT.md`.
- **D-03:** Execute on a dedicated physical Windows 11 test host, not the developer's primary workstation. Document host details in `C:\UAT\v0.10.0\environment.json`.
- **D-04:** Use Windows Defender as the EDR under test. Allowlist procedures from `docs/operations/deployment-guide.md` must be applied before UAT.
- **D-05:** Use real signed-in cloud clients (OneDrive, Google Drive, Dropbox, Box) for scenarios C01-C04. Any missing client is marked N/A with justification.
- **D-06:** Execute all 36 scenarios in a single extended UAT session. The tester works solo and records results directly via the script prompts.
- **D-07:** Prepare dedicated UAT test data under `C:\UAT\v0.10.0\TestData\` (T1/T2/T4 files and protected paths). Clean up after UAT completes.

### Scope and prioritization

- **D-08:** Run all 36 scenarios across categories A-J. Do not cut scenarios unless a required peripheral or cloud client is genuinely unavailable.
- **D-09:** Prioritize blocking ship scenarios during execution so they are tested when the host is freshest: B01-B06 (file blocking), G01 (ETW bypass), H02 (Block mode), I01-I02 (CRIT-04 performance), J01-J02 (Authenticode and EDR allowlist), J04-J05 (Secure Boot and hash verification).
- **D-10:** Mark scenarios N/A per the UAT plan protocol when peripherals (USB/SD/optical/printer) or cloud clients are unavailable. If a category has >50% N/A scenarios, escalate to the engineering lead for a partial-ship decision.

### Test isolation

- **D-11:** Use relaxed isolation: restart the `dlp-agent` service between scenarios within a category, but skip reboots between categories unless a failure indicates contamination. Archive agent logs between categories to preserve per-category artifacts.

### Failure handling

- **D-12:** Continue through non-blocking failures and capture them in the script prompts. Triage and root-cause analysis happen after the full UAT run.
- **D-13:** Pause execution immediately for investigation if a blocking scenario fails (B01-B06, G01, H02, I01-I02, J01-J02, J04-J05). Document the failure with scenario ID, notes, and captured artifacts before deciding whether to proceed.

### Result recording

- **D-14:** The script generates the canonical machine-readable artifacts in `C:\UAT\v0.10.0\`: `results.json`, `crit04_results.json`, `environment.json`, and `UAT-Summary.md`.
- **D-15:** After UAT completes, copy the populated results into `.planning/milestones/v0.10.0-UAT.md` (filling Actual Result, Pass/Fail, Notes, and Artifacts Captured for each scenario) and append the sign-off section.
- **D-16:** Commit the updated `.planning/milestones/v0.10.0-UAT.md` and any companion summary as the Phase 58.3 deliverable.

### Prerequisites

- **D-17:** Perform strict pre-checks before starting the script: Windows 11, administrator rights, `dlp-agent` service installed, `signtool.exe` in PATH, required peripherals available, cloud clients signed in. Abort if critical prerequisites are missing.

### Claude's Discretion

- If the dedicated test host cannot be provisioned in time, the fallback is the best available physical Windows 11 host, with host details fully documented.
- If Windows Defender allowlisting cannot be completed, J02 is marked N/A and the absence is escalated; other UAT scenarios still proceed.
- The exact CRIT-04 cargo build project directory defaults to the current workspace; if the test host does not have the source tree, use a temporary benchmark project as the script already supports.

</decisions>

<specifics>
## Specific Ideas

- Use the committed script unmodified to avoid version drift between the execution harness and the milestone document.
- Run blocking scenarios early in the session when the test host is in the cleanest state.
- Capture at least one screenshot per scenario failure; capture agent log snippets for every scenario.
- For CRIT-04, ensure no other heavy processes run during measurement and document raw values, not just the overhead percentage.
- After the script finishes, the human tester copies `UAT-Summary.md` contents into `.planning/milestones/v0.10.0-UAT.md` and completes the sign-off table.

</specifics>
