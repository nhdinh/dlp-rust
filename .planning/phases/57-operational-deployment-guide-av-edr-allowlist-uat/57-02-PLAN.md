    ### Vendor: Microsoft Defender for Endpoint

    **Console URL:** `https://security.microsoft.com`
    **Required Role:** Security Administrator or Global Administrator
    **Propagation Time:** 15-30 minutes typical
    **Supported Methods:** File hash indicator (preferred), Certificate indicator, Path indicator
    **Defender SKU Detection:** Before attempting hash indicators, verify the endpoint is enrolled in Microsoft Defender for Endpoint (not just Windows Security / built-in Defender). Run:
    ```powershell
    $status = Get-MpComputerStatus
    if ($status.AMServiceEnabled -and $status.OnAccessProtectionEnabled) {
        Write-Host "Defender AV is active."
    }
    # For MDE onboarding state, check the registry:
    $mde = Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows Advanced Threat Protection" -ErrorAction SilentlyContinue
    if ($mde.OnboardingState -eq 1) {
        Write-Host "Microsoft Defender for Endpoint is onboarded."
    } else {
        Write-Warning "This endpoint may only have built-in Defender AV. Hash indicators require MDE. Use path-based exclusions or certificate indicators instead."
    }
    ```

    #### Method 1: File Hash Indicator (Preferred)
    1. Enable file hash computation (one-time per tenant):
       ```powershell
       Set-MpPreference -EnableFileHashComputation $true
       ```
    2. Navigate to: `https://security.microsoft.com`
    3. Go to: **System** > **Settings** > **Endpoints** > **Indicators** (under Rules)
    4. Select the **File hashes** tab
    5. Click **Add item**
    6. Enter the SHA-256 hash of `dlp_hook_dll.dll` (from RELEASE_NOTES.md)
    7. Set **Action** to **Allow**
    8. Set **Scope** to the device groups where DLP will deploy
    9. Click **Save**

    #### Method 2: Certificate Indicator
    Use this method if hash indicators are not viable (e.g., rotating signing certificates).
    1. Navigate to the same **Indicators** page
    2. Select the **Certificates** tab
    3. Click **Add item**
    4. Upload or paste the thumbprint of the DLP Authenticode signing certificate
    5. Set **Action** to **Allow**
    6. Set **Scope** and **Save**

    #### Method 3: PowerShell (Alternative)
    ```powershell
    # Add a file hash indicator via PowerShell
    # NOTE: The Windows Defender PowerShell module is not installed by default
    #       on Windows Server. Install it first:
    #       Install-WindowsFeature -Name Windows-Defender-Features
    $hash = "SHA256_HASH_FROM_RELEASE_NOTES"
    New-MpThreatIntelIndicator -FileHash $hash -Action Allow -SeverityInformational
    ```

    #### Verification
    ```powershell
    # List all active indicators
    Get-MpThreatIntelIndicator | Where-Object { $_.Indicator -eq "SHA256_HASH_FROM_RELEASE_NOTES" }

    # Check that the indicator shows Action = Allow
    # Verify in portal: Indicators list shows "Allow" in the Action column
    ```

    #### Attack Surface Reduction (ASR) Rules
    Even with file hash indicators, certain ASR rules may independently block DLL injection:
    - **Rule: Block Office applications from injecting code into other processes** -- may block the hook DLL from injecting into Office processes
    - **Rule: Block executable files from running unless they meet a prevalence, age, or trusted list criterion** -- may block newly-signed binaries
    - If DLP hook injection into Office or other applications is blocked by ASR, add an ASR exclusion for `C:\Program Files\DLP\*` via: **Endpoint security** > **Attack surface reduction** > **ASR rules** > **Add exclusion**

    #### IOC Exclusion Example
    If Defender flags the hook DLL as suspicious before allowlisting:
    1. Go to **Incidents** or **Alerts**
    2. Find the alert naming `dlp_hook_dll.dll`
    3. Click **Manage indicator** > **Allow**
    4. Select **File hash** and enter the SHA-256
    5. This creates both the indicator and suppresses the alert

    Document the assumption from 57-RESEARCH.md A1: "Microsoft Defender for Endpoint supports SHA-256 file hash indicators with Allow action. If policy changes, operator may need certificate-based or path-based exclusion instead."

    ### Vendor: CrowdStrike Falcon

    **Console URL:** `https://falcon.crowdstrike.com`
    **Required Role:** Falcon Administrator or Falcon Prevent Administrator
    **Propagation Time:** Up to 40 minutes
    **Supported Methods:** Machine Learning Exclusion (path-based), Certificate Exclusion, Hash Exclusion (via IOA rules)

    #### Method 1: Machine Learning Exclusion (Primary)
    1. Navigate to: `https://falcon.crowdstrike.com`
    2. Go to: **Configuration** > **Detections Management** > **Exclusions**
    3. Select the **Machine Learning Exclusions** tab
    4. Click **CREATE EXCLUSION**
    5. Set **Scope**: All hosts or specific Host Groups
    6. Set **EXCLUDED FROM**: Detections and preventions
    7. Set **Pattern**: `C:\Program Files\DLP\*`
    8. (Optional) Click **Pattern Test** to validate the pattern
    9. Enter **Comment**: "DLP v0.10.0 hook DLL exclusion"
    10. Click **Create Exclusion** > **Enable**

    #### Method 2: Certificate Exclusion
    1. In the same **Exclusions** page, select the **Certificate Exclusions** tab
    2. Click **CREATE EXCLUSION**
    3. Upload the DLP Authenticode certificate or enter the certificate hash
    4. Set **Scope** and **Enable**

    #### Method 3: FalconPy API (Python)
    ```python
    # Requires FalconPy module: pip install crowdstrike-falconpy
    from falconpy import MLExclusions
    falcon = MLExclusions(client_id="YOUR_CLIENT_ID", client_secret="YOUR_SECRET")
    response = falcon.create_ml_exclusions(
        value="C:\\Program Files\\DLP\\*",
        excluded_from=["detect", "prevent"],
        groups=["all"]
    )
    print(response)
    ```
    **API Key Scopes Required:** `ml_exclusions:write` (create exclusions) and `ml_exclusions:read` (verify). Generate API credentials in the Falcon console under **Support > API Clients and Keys**.

    #### PowerShell Alternative (Invoke-RestMethod)
    ```powershell
    # Direct API call via Invoke-RestMethod (no Python required)
    # NOTE: Use the correct API base URL for your tenant region:
    #   US-1:  https://api.crowdstrike.com
    #   US-2:  https://api.us-2.crowdstrike.com
    #   EU-1:  https://api.eu-1.crowdstrike.com
    #   US-GOV-1: https://api.laggar.gcw.crowdstrike.com
    $baseUrl = "https://api.crowdstrike.com"   # <-- change to your region
    $headers = @{
        "Authorization" = "Bearer $YOUR_API_TOKEN"
        "Content-Type" = "application/json"
    }
    $body = @{
        value = "C:\Program Files\DLP\*"
        excluded_from = @("detect", "prevent")
        groups = @("all")
    } | ConvertTo-Json
    Invoke-RestMethod -Uri "$baseUrl/policy/entities/ml-exclusions/v1" `
        -Method POST -Headers $headers -Body $body
    ```
    **Required API Token Scopes:** `ml_exclusions:write` and `ml_exclusions:read`. Obtain a bearer token via OAuth2 client credentials flow using your API client ID and secret.

    #### Verification
    ```powershell
    # In Falcon console: Configuration > Detections Management > Exclusions
    # Verify the exclusion appears in the list with Status = Enabled
    # Check that the pattern covers: dlp-agent.exe, dlp-user-ui.exe, dlp_hook_dll.dll

    # On the endpoint, verify CrowdStrike does not quarantine the DLL:
    Get-ChildItem "C:\Program Files\DLP\dlp_hook_dll.dll"
    # File should exist and not be moved to quarantine
    ```

    #### Important Notes
    - **Propagation delay is up to 40 minutes.** Do NOT install DLPAgent.msi immediately after creating the exclusion. Wait for propagation or verify on a test endpoint first.
    - CrowdStrike's ML exclusion is path-based, not hash-based. If the DLP binaries are updated to a new version in the same path, the exclusion remains valid.
    - If CrowdStrike flags the hook DLL as suspicious before exclusion propagation, the DLL may be quarantined. Restore from quarantine after the exclusion is active.

    Document the assumption from 57-RESEARCH.md A2: "CrowdStrike Falcon ML exclusions propagate within 40 minutes. If propagation takes longer, operator must wait longer before installing."

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator -> EDR Console | Operator authenticates to vendor console with admin credentials |
| EDR Console -> Endpoint | Exclusion policy propagates from cloud console to endpoint agent |
| Endpoint -> DLP Hook DLL | EDR must not quarantine the legitimate hook DLL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-05 | Denial of Service | EDR quarantines hook DLL before exclusion propagates | mitigate | Document propagation times; warn operator to wait 40 min for CrowdStrike before installing |
| T-57-06 | Information Disclosure | EDR console credentials exposed in documentation | accept | No credentials in docs; operator uses their own authenticated session |
| T-57-07 | Tampering | Vendor console UI changes, breaking documented steps | accept | Document console URLs and general navigation; note that exact UI may evolve |
</threat_model>
