    Add to deployment guide:
    1. **PPL Coverage Gap**:
       - Protected Process Light (PPL) processes CANNOT be injected via CreateRemoteThread
       - Affected processes: lsass.exe, MsMpEng.exe (Defender), EDR self-processes, other PPL-protected security software
       - List the process names that are allowlisted and WHY (they are PPL-protected)
       - Document that this is a Windows security feature, not a DLP limitation
       - Note: there may be timing windows where a process starts before PPL is applied; the agent handles this via the allowlist refresh interval
    2. **DACL Tripwire as Backstop**:
       - For T3/T4 paths, the DACL tripwire provides kernel-enforced protection EVEN when the hook cannot inject into a process
       - If a PPL-protected process (e.g., Defender scanning a T4 file) attempts to write/delete a protected path, NTFS returns ERROR_ACCESS_DENIED
       - The tripwire is defense-in-depth: hook catches most processes; DACL catches the rest
       - Document the two-phase staged update mechanism (operator removal via TUI does NOT trigger tamper alert)
       - Operator-visible signal: if a PPL-protected process attempts to access a T4 path, the access is denied silently (no alert) — this is expected behavior
    3. **Visual Diagram** (ASCII art in markdown):
       ```
       Process Type          | Injection Coverage | Backstop
       ----------------------|--------------------|------------------
       Normal user process   | Yes (hook DLL)     | DACL (T3/T4 only)
       System process        | Yes (if not PPL)   | DACL (T3/T4 only)
       PPL-protected process | No                 | DACL (T3/T4 only)
       Allowlisted process   | Skipped            | DACL (T3/T4 only)
       ```
    4. **Coverage Equivalence Note**: ETW Kernel-Process + CreateRemoteThread fallback has functionally identical coverage to AppInit_DLLs, with the following caveats:
       - Timing: ETW observes process creation and injects shortly after; AppInit_DLLs loads at process startup. The gap is typically <100ms.
       - Privilege: CreateRemoteThread requires appropriate privileges; the agent runs as a service with sufficient rights.
       - Protected process exclusions: both mechanisms skip PPL-protected processes.
  </action>

    1. **SeSystemProfilePrivilege**:
       - Required for ETW Kernel-File consumer (Phase 53)
       - Required for ETW Kernel-Process watcher (Phase 49)
       - Assignment methods:
         a) Group Policy: Computer Configuration → Windows Settings → Security Settings → Local Policies → User Rights Assignment → "Profile system performance" → Add `NT SERVICE\DlpAgent`
         b) Command line: `ntrights.exe +r SeSystemProfilePrivilege -u "NT SERVICE\DlpAgent"` (requires Windows Server 2003 Resource Kit Tools or equivalent)
         c) PowerShell (concrete, copy-pasteable):
            ```powershell
            $privilege = "SeSystemProfilePrivilege"
            $account = "NT SERVICE\DlpAgent"
            $tempFile = [System.IO.Path]::GetTempFileName()
            secedit /export /cfg $tempFile /quiet
            $content = Get-Content $tempFile
            $content = $content -replace "^(SeSystemProfilePrivilege.*)$", "`$1,$account"
            $content | Set-Content $tempFile
            secedit /configure /db $env:TEMP\secedit.sdb /cfg $tempFile /areas USER_RIGHTS /quiet
            Remove-Item $tempFile
            ```
       - Verification: `whoami /priv` when running as agent service account (or check via `sc query DlpAgent` to confirm service account)
       - Privilege MUST persist across agent upgrades (MSI installer preserves service account)
       - Domain policy refresh: if domain GPO overrides local settings, the privilege may be removed. Document that the privilege should be assigned via domain GPO for domain-joined hosts.
    2. **Post-Install Reboot Requirement** (mechanism-qualified):
       - If AppInit_DLLs is active (Secure Boot OFF): reboot REQUIRED for new processes to load hook DLL
       - If ETW fallback is active (Secure Boot ON): service restart is sufficient for hook activation
       - Even with Secure Boot ON, reboot is RECOMMENDED after first install to ensure ETW provider registration is clean
       - Reboot is NOT required for agent service restarts (hot reload works for config changes)
       - Reboot IS required for installer upgrades (MSI replaces DLLs that may be memory-mapped)
    3. **Upgrade Path**:
       - Document that MSI upgrade stops service, replaces files, and requires reboot
       - Privileges are preserved (service account unchanged)
       - Config and SQLite DB are preserved (stored in ProgramData, not Program Files)
