    ## Hash Publishing and Verification

    Every v0.10.0 release publishes SHA-256 and SHA-512 hashes for all shipped binaries in `docs/RELEASE_NOTES.md`. Operators must verify hashes before installation.

    ### Hash Verification Steps

    1. Download the release artifacts and `RELEASE_NOTES.md`
    2. Run the PowerShell hash generation command (documented in RELEASE_NOTES.md)
    3. Compare generated hashes against the published values
    4. If any hash does not match, do NOT install -- the binary may be tampered

    ### Authenticode Signature Verification

    Every binary is signed with an organizational Authenticode certificate and RFC-3161 timestamped. Verify signatures before installation:

    ```powershell
    # Verify signature with verbose output
    signtool verify /pa /v "C:\Program Files\DLP\dlp-agent.exe"

    # Verify ALL signatures and identify timestamp types
    signtool verify /all /pa "C:\Program Files\DLP\dlp_hook_dll.dll"
    ```

    Expected output includes:
    - `Signing Certificate Chain` with valid root CA
    - `Timestamp` showing `RFC3161`
    - `Hash` algorithm showing `sha256`

    Notes:
    - If verification fails with "A certificate chain could not be built to a trusted root authority," install your organization's root CA certificate into the local machine trust store:
      ```powershell
      certutil -addstore -f "Root" "C:\Path\To\OrgRootCA.cer"
      ```
    - `signtool verify /all /pa` on a dual-signed DLL produces verbose multi-signature output. This is expected and normal.
    - If the organization's code signing certificate is renewed between releases, operators must update their local trust store with the new root CA certificate.

    ### Microsoft WDSI Submission

    If Microsoft Defender flags DLP binaries as suspicious, submit them to the Microsoft Windows Defender Security Intelligence (WDSI) portal for reputation whitelisting.

    **Portal:** `https://www.microsoft.com/en-us/wdsi/filesubmission`

    **Before submitting:**
    - Ensure the binary is Authenticode-signed (unsigned submissions are rarely approved)
    - Prepare a ZIP file with password `infected` containing the binary
    - Gather: company name, product name, file description, SHA-256 hash

    **Submission steps:**
    1. Go to the WDSI portal and sign in with a Microsoft work account
    2. Select "Software developer" as submission type
    3. Upload the password-protected ZIP file
    4. Fill in all required fields
    5. Submit and save the submission ID
    6. Check status after 24-48 hours

    **Troubleshooting:**
    - If status shows "pending" for 10+ days, contact Microsoft support with the submission ID
    - If rejected for "insufficient information," re-submit with a more detailed product description and company website
    - File size limit is 50MB per file
    - **Warning:** The ZIP password "infected" may trigger enterprise email gateway blocks. If email delivery fails, use an alternative file transfer method.

    Also update the placeholder `## UAT Test Matrix` section to reference the correct files:
