    ### Vendor: SentinelOne

    **Console URL:** SentinelOne Management Console (tenant-specific)
    **Required Role:** Site Admin or Account Admin
    **Propagation Time:** Up to 15 minutes
    **Supported Methods:** Hash Exclusion (preferred), Path Exclusion, Certificate Exclusion
    **Agent Requirement:** SHA-256 hash exclusions require SentinelOne agent S-25.1.1 or later

    #### Method 1: Hash Exclusion (Preferred)
    1. Navigate to your SentinelOne Management Console
    2. Go to: **Sentinels** > **Exclusions** (or **Policy Settings** > **Exclusions**)
    3. Click **New Exclusion** > **Create Exclusion**
    4. Set **Exclusion Type**: Hash
    5. Set **OS Type**: Windows
    6. Enter **Hash Value**: SHA-256 of `dlp_hook_dll.dll` (from RELEASE_NOTES.md)
    7. Enter **Description**: "DLP v0.10.0 hook DLL"
    8. Click **Save**

    #### Method 2: Path Exclusion
    1. In the same **Exclusions** page
    2. Set **Exclusion Type**: Path
    3. Enter **Path**: `C:\Program Files\DLP\*`
    4. Set **OS Type**: Windows
    5. Click **Save**

    #### Verification
    ```powershell
    # In SentinelOne console: Sentinels > Exclusions
    # Verify the exclusion appears with Type = Hash and Status = Active

    # On the endpoint, check SentinelOne agent version (robust across architectures):
    $sentinelPaths = @(
        "HKLM:\SOFTWARE\SentinelLabs\SentinelAgent",
        "HKLM:\SOFTWARE\WOW6432Node\SentinelLabs\SentinelAgent"
    )
    $version = $null
    foreach ($path in $sentinelPaths) {
        if (Test-Path $path) {
            $version = (Get-ItemProperty $path -Name "Version" -ErrorAction SilentlyContinue).Version
            if ($version) { break }
        }
    }
    if ($version) {
        Write-Host "SentinelOne agent version: $version"
        # Expected: 25.1.1 or higher for SHA-256 hash support
    } else {
        Write-Host "SentinelOne agent not detected via registry. Check Add/Remove Programs."
    }

    # Verify the hook DLL is not quarantined:
    Test-Path "C:\Program Files\DLP\dlp_hook_dll.dll"
    ```

    #### Important Notes
    - If your SentinelOne agent is older than S-25.1.1, hash exclusions are not supported. Use path exclusions instead.
    - SentinelOne hash exclusions are exact-match only. If the DLP hook DLL is updated, the new hash must be added to the exclusion list.

    ### Vendor: Carbon Black (VMware Carbon Black Cloud)

    **Console URL:** `https://[REGION].conferdeploy.net` (replace [REGION] with your tenant region, e.g., defense, prod, gov)
    **Required Role:** Custom role with "Reputation" permissions
    **Propagation Time:** 10-20 minutes typical
    **Supported Methods:** Reputation Approved List (hash), Path Exclusion (via policy)

    #### Method 1: Reputation Approved List (Primary)
    1. Navigate to: `https://[REGION].conferdeploy.net`
    2. Go to: **Enforce** > **Reputation**
    3. Click **Add**
    4. Set **Type**: Hash
    5. Set **List**: Approved List
    6. Enter **SHA-256**: SHA-256 hash of `dlp_hook_dll.dll` (from RELEASE_NOTES.md)
    7. Enter **Name**: "DLP v0.10.0 hook DLL"
    8. Enter **Comments**: "Data Loss Prevention agent hook"
    9. Click **Save**

    #### Method 2: Policy Exclusion
    1. Go to: **Enforce** > **Policies**
    2. Select the policy applied to DLP endpoints
    3. Go to the **Exclusions** tab
    4. Add a path exclusion: `C:\Program Files\DLP\*`
    5. Save the policy

    #### Verification
    ```powershell
    # In Carbon Black console: Enforce > Reputation
    # Verify the hash appears in the Approved List with Status = Active

    # Check that the file is "known" to Carbon Black (required before adding):
    # The file must have been observed on at least one endpoint before it can be added to reputation.
    # If the file is not known, deploy DLP to a test endpoint first, then add the hash.

    # Verify the hook DLL is not blocked:
    Test-Path "C:\Program Files\DLP\dlp_hook_dll.dll"
    ```

    #### Important Notes
    - **File must be known to Carbon Black Cloud before adding to reputation list.** If the file has never been observed, the console will reject the addition. To resolve this chicken-and-egg problem:
      1. Deploy DLP to a single pilot endpoint with a temporary path exclusion (`C:\Program Files\DLP\*`)
      2. Let Carbon Black observe the file on the pilot endpoint (may take 10-20 minutes)
      3. Add the SHA-256 hash to the Approved List
      4. Remove the temporary path exclusion after the hash is approved
    - Carbon Black reputation is global per tenant. Once added, the approved hash applies to all endpoints in the tenant.

    ### Vendor: Sophos

    **Console URL:** Sophos Central Admin (`https://central.sophos.com`)
    **Required Role:** Super Admin or Admin
    **Propagation Time:** 5-15 minutes typical
    **Supported Methods:** Path Exclusion ONLY (hash-based allowlisting is NOT supported in Sophos Central)

    #### Method 1: Path Exclusion (Primary -- Only Option)
    1. Navigate to: `https://central.sophos.com`
    2. Go to: **My Products** > **Endpoint Protection** > **Policies**
    3. Click the **Threat Protection** policy (or create a new one for DLP endpoints)
    4. Go to: **Settings** > **Scanning exclusions**
    5. Click **Add Exclusion**
    6. Set **Type**: File or folder
    7. Enter **Path**: `C:\Program Files\DLP\*`
    8. Set **Active for**: Real-time, Scheduled, or Both
    9. Click **Add** > **Save**

    #### Method 2: Submit to SophosLabs for Reclassification
    If Sophos flags the DLP hook DLL as suspicious:
    1. Go to: **My Products** > **Endpoint Protection** > **Alerts**
    2. Find the alert for `dlp_hook_dll.dll`
    3. Click **Submit for Reassessment**
    4. Select **I believe this is a false positive**
    5. Provide the DLP vendor details and business justification
    6. Submit and wait 24-48 hours for SophosLabs review

    #### Verification
    ```powershell
    # In Sophos Central: My Products > Endpoint Protection > Policies
    # Verify the Threat Protection policy shows the exclusion in Scanning exclusions

    # On the endpoint, verify Sophos does not block the DLL:
    Test-Path "C:\Program Files\DLP\dlp_hook_dll.dll"

    # Check Sophos endpoint logs for detections:
    Get-Content "C:\ProgramData\Sophos\Endpoint Defense\Logs\*.log" -ErrorAction SilentlyContinue | Select-String "dlp_hook_dll"
    # Should return no results if exclusion is active
    ```

    #### Important Notes
    - **Sophos Central does NOT support hash-based allowlisting.** Path exclusions are the only option. This means the exclusion covers ALL files in `C:\Program Files\DLP\`, which is acceptable for a trusted vendor directory.
    - If the DLP installation path changes, the exclusion must be updated.
    - SophosLabs reclassification is a fallback if the path exclusion does not prevent detection.

    ### Vendor: Trend Micro Apex One

    **Console URL:** Apex Central (tenant-specific) or local Apex One console
    **Required Role:** Administrator
    **Propagation Time:** 10-20 minutes typical
    **Supported Methods:** Application Control Hash Allow (preferred), Scan Exclusion (path-based)

    #### Method 1: Application Control Hash Allow (Preferred)
    1. Navigate to your Apex Central console
    2. Go to: **Policies** > **Policy Resources** > **Application Control Criteria**
    3. Click **Add Criteria** > **Allow**
    4. Enter **Name**: "DLP v0.10.0"
    5. Set **Match method**: Hash values
    6. Set **Hash type**: SHA-256
    7. Enter the SHA-256 hash of `dlp_hook_dll.dll` (from RELEASE_NOTES.md)
    8. Click **OK**
    9. Go to: **Policies** > **Policy Management**
    10. Select the policy applied to DLP endpoints
    11. Go to: **Application Control**
    12. Click **Assign criteria**
    13. Select the "DLP v0.10.0" criteria
    14. Click **Deploy**

    #### Method 2: Scan Exclusion (Path-Based)
    1. Go to: **Policies** > **Policy Resources** > **Scan Exclusion Lists**
    2. Click **Add**
    3. Enter **Name**: "DLP Exclusion"
    4. Add the path: `C:\Program Files\DLP\*`
    5. Click **Save**
    6. Assign the exclusion list to the DLP endpoint policy

    #### Verification
    ```powershell
    # In Apex Central: Policies > Policy Management
    # Verify the endpoint policy shows Application Control = Enabled
    # Verify the "DLP v0.10.0" criteria is assigned

    # On the endpoint, verify Apex One agent status (robust across versions):
    $apexService = Get-Service | Where-Object { $_.Name -like "*Apex*One*" -or $_.DisplayName -like "*Apex*One*" } | Select-Object -First 1
    if ($apexService) {
        Write-Host "Apex One service: $($apexService.Name) -- Status: $($apexService.Status)"
    } else {
        Write-Host "Apex One service not detected. Check installed services."
    }

    # Verify the hook DLL is not quarantined:
    Test-Path "C:\Program Files\DLP\dlp_hook_dll.dll"
    ```

    #### Important Notes
    - **Application Control supports PE files only** (.exe, .dll, .sys, etc.). Non-PE files (scripts, data) require path-based exclusions.
    - Trend Micro Application Control is a separate licensed feature. If your license does not include it, use Scan Exclusion instead.
    - Deploy the policy after assigning criteria. Un-deployed policies do not take effect.

    Document assumptions from 57-RESEARCH.md:
    - A5: Sophos Central does NOT support hash-based allowlisting; path-based is the only option
    - A6: Trend Micro Apex One Application Control supports SHA-256 for PE files; non-PE requires path exclusion
