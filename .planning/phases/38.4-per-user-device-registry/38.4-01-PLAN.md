<objective>
Extend the server-side device_registry table and admin API to support per-user USB device registration. This plan delivers the database schema changes, repository updates, and API handler modifications that enable machine-wide and per-user device entries to coexist.

Purpose: Foundation for Phase 38.4 — without these schema and API changes, the agent cannot store or retrieve per-user device policies.
Output: Updated DB schema with migration, repository with per-user-aware queries, admin API with owner_sid filter and owner fields.
</objective>

fn run_alter(conn: &SqliteConn, sql: &str, column: &str, table: &str) -> anyhow::Result<()> {
    match conn.execute(sql, []) {
        Ok(_) => Ok(()),
        Err(e) if e.to_string().contains(&format!("duplicate column name: {column}")) => Ok(()),
        Err(e) => Err(e).context(format!("running migration: add {column} column to {table}")),
    }
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin API -> DB | Admin-authenticated requests mutate device_registry; SQL injection is the primary threat |
| Agent -> Admin API (unauth GET) | Unauthenticated endpoint returns device trust tiers; information disclosure of owner SIDs is low-sensitivity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38.4-01 | Tampering | DB migration (ALTER TABLE) | mitigate | Use run_alter() idempotent pattern; duplicate-column errors swallowed safely |
| T-38.4-02 | Information Disclosure | Admin API returns owner_sid in PublicDeviceEntry | accept | Owner SIDs are not secrets; they are standard Windows identifiers visible to all processes on the endpoint |
| T-38.4-03 | Denial of Service | Upsert with very long owner_sid | mitigate | Length guard on trust_tier already exists; add same 256-char limit to owner_sid/owner_user in handler, rejecting with 422 |
| T-38.4-04 | Elevation of Privilege | Per-user entry could be created with arbitrary SID | mitigate | Admin API is JWT-protected; only dlp-admin can create entries. No additional authorization needed within admin role. |
</threat_model>
