# Phase 38.4 Plan 02: Per-User Device Registry Agent-Side Summary

**Agent-side per-user USB device registry lookup with most-restrictive tier merge and audit event owner identity enrichment**

## Performance

## Accomplishments
- DeviceRegistryCache now keys by (vid, pid, serial, owner_sid) with per-user and machine-wide entries
- trust_tier_for_with_sid returns most restrictive tier when both per-user and machine-wide entries exist
- ServerClient.fetch_device_registry_with_sid passes owner_sid as HTTP query parameter
- get_current_process_sid() queries process token and caches result in OnceLock (T-38.4-05)
- AuditEvent gains owner_sid/owner_user fields with skip_serializing_if=None and builder methods
- apply_tier_enforcement resolves current user SID and includes owner fields in all tracing spans

## Files Created/Modified
- `dlp-agent/src/device_registry.rs` - Per-user cache keys, TrustTierResult, tier merge, has_device_with_sid, seed_for_test_with_sid
- `dlp-agent/src/server_client.rs` - fetch_device_registry_with_sid, owner_sid/owner_user on DeviceRegistryEntry
- `dlp-agent/src/identity.rs` - get_current_process_sid() with OnceLock cache
- `dlp-agent/src/detection/usb.rs` - apply_tier_enforcement uses trust_tier_for_with_sid, owner fields in spans
- `dlp-common/src/audit.rs` - owner_sid/owner_user fields, with_owner_sid/with_owner_user/with_owner builders

## Decisions Made
- Tier merge uses cmp::min because Blocked=0 < ReadOnly=1 < FullAccess=2 per PartialOrd/Ord
- Empty owner_sid strings normalized to None at cache insert time to prevent cache key collision (T-38.4-06)
- get_current_process_sid returns None on any token query failure, safely falling back to machine-wide lookup (T-38.4-08)
- trust_tier_for marked #[deprecated] to guide callers toward the SID-aware version without breaking existing code

## Known Stubs

None. All data flows are wired:
- `trust_tier_for_with_sid` returns `owner_user: None` because the cache only stores `UsbTrustTier` values, not owner metadata. The caller (`apply_tier_enforcement`) could enrich `owner_user` from the server response if needed, but the current design stores only tier in the cache for memory efficiency. The `owner_sid` field is sufficient for audit traceability.

## Threat Flags

None beyond the planned mitigations already documented in the plan's threat_model:
- T-38.4-05 (Spoofing): mitigated by querying process token directly + OnceLock cache
- T-38.4-06 (Tampering): mitigated by normalizing empty owner_sid to None
- T-38.4-07 (Information Disclosure): accepted — SIDs are standard Windows identifiers
- T-38.4-08 (Denial of Service): mitigated by returning None on failure, falling back to machine-wide
