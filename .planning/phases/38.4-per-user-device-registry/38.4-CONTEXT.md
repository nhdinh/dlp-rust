# Phase 38.4: Per-User Device Registry - Context

**Gathered:** 2026-05-06
**Status:** Ready for planning
**Mode:** Smart discuss (autonomous)

<domain>
## Phase Boundary

Support per-user USB device registration for multi-user machines. Extend the existing Phase 24 `device_registry` table and APIs so that a single physical device can have different trust tiers for different users, plus a machine-wide fallback entry.

</domain>

<decisions>
## Implementation Decisions

### Schema Design

- **D-01:** Add TWO columns: `owner_sid` (TEXT, nullable) and `owner_user` (TEXT, nullable). `owner_sid` stores the Windows Security Identifier (stable canonical ID). `owner_user` stores the human-readable username for display purposes. Both are NULL for machine-wide entries.
- **D-02:** Expand the UNIQUE constraint from `(vid, pid, serial)` to `(vid, pid, serial, owner_sid)`. This allows both a machine-wide entry (NULL owner_sid) and multiple per-user entries for the same physical device.
- **D-03:** Existing rows with NULL owner_sid are treated as machine-wide entries (backward compatible).

### Lookup Semantics

- **D-04:** Agent lookup performs a tier-based merge: if both a per-user entry and a machine-wide entry exist for the same device, the **most restrictive** tier wins. Ordering: `Blocked > ReadOnly > FullAccess`.
- **D-05:** Lookup order: (1) query for exact match on `(vid, pid, serial, current_user_sid)`, (2) if not found, query for machine-wide match on `(vid, pid, serial, NULL)`, (3) if both exist, return the more restrictive tier.

### Admin API

- **D-06:** `GET /admin/device-registry` supports an optional `?owner_sid={sid}` filter. When omitted, returns ALL entries (both machine-wide and per-user). When provided, returns entries matching that SID plus machine-wide entries.
- **D-07:** `POST /admin/device-registry` accepts `owner_sid` and `owner_user` as optional fields. If omitted, creates/updates the machine-wide entry.
- **D-08:** `DELETE /admin/device-registry/{id}` continues to work by UUID; admins delete specific per-user or machine-wide rows individually.

### Admin TUI

- **D-09:** Show `owner_sid` and `owner_user` columns between `serial` and `trust_tier` (logical grouping: device identity -> owner -> policy).
- **D-10:** Machine-wide entries display as "(all users)" or blank in the TUI.

### Audit Events

- **D-11:** `AuditEvent` includes `owner_sid` and `owner_user` fields (nullable) when the enforcement decision was made against a per-user entry. Machine-wide decisions omit these fields (or set NULL).

### Claude's Discretion

- Exact TUI column width and truncation behavior for long SIDs.
- Whether to cache the current user SID lookup or query it on every USB event.
- SQL migration strategy for adding columns to existing DBs (simple ALTER TABLE vs migration script).

</decisions>

<specifics>
## Specific Ideas

- The tier-based merge (most restrictive wins) ensures defense-in-depth: a machine-wide "read_only" policy combined with a per-user "blocked" policy correctly results in "blocked" for that user.
- SIDs are the canonical identifier; usernames are for display only. This matches the `user_sid`/`user_name` pattern in `AuditEvent` and `AbacContext`.

</specifics>
