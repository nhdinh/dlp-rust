<objective>
Implement agent-side per-user device registry lookup with tier-based merge, and enrich audit events with owner identity when per-user decisions are made.

Purpose: The agent must evaluate USB device trust tiers against the current Windows user SID, falling back to machine-wide entries, and emit audit events that record whether a per-user or machine-wide policy was applied.
Output: Updated agent cache, server client, USB enforcement, and audit event types.
</objective>

          - Also stores a separate "machine-wide" lookup: entries with owner_sid=None are accessible via the old key (vid, pid, serial, None)
       d. Keep the old `trust_tier_for` as a convenience wrapper that calls `trust_tier_for_with_sid(vid, pid, serial, None)` for backward compat, but mark it `#[deprecated]` with note to use the SID-aware version.

          - test_refresh_with_sid_populates_cache: verify cache keys include owner_sid

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent process -> Registry cache | Agent resolves its own process SID; tampering requires local admin |
| Cache -> Server API | HTTP over localhost; owner_sid query param is not sensitive |
| USB enforcement -> Audit event | Owner fields reflect the policy decision source |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38.4-05 | Spoofing | get_current_process_sid returns wrong SID | mitigate | Query process token directly (not environment variable); cache in OnceLock to prevent race |
| T-38.4-06 | Tampering | Cache key collision between owner_sid=None and owner_sid=Some("") | mitigate | Use Option<String> correctly: None != Some(""); normalize empty string to None at insert time |
| T-38.4-07 | Information Disclosure | Audit events include owner_sid | accept | Owner SIDs are standard Windows identifiers; not sensitive. owner_user is also not sensitive (standard username). |
| T-38.4-08 | Denial of Service | get_current_process_sid fails (e.g., token query error) | mitigate | Return None on failure, which falls back to machine-wide lookup — safe default |
</threat_model>
