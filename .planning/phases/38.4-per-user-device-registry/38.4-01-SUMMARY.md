# Phase 38.4 Plan 01: Per-User Device Registry - Server Foundation Summary

**One-liner:** Extended device_registry table and admin API with nullable owner_sid/owner_user columns, COALESCE-based unique indexing, and per-user-aware queries with filtered listing.

| 2 | Admin API handlers and endpoint types | 1884a13 | dlp-server/src/admin_api.rs |

## What Changed

### Database Schema (dlp-server/src/db/mod.rs)

- `device_registry` table: added `owner_sid TEXT` and `owner_user TEXT` columns (both nullable)
- `UNIQUE` enforcement: `CREATE UNIQUE INDEX idx_device_registry_unique ON device_registry(vid, pid, serial, COALESCE(owner_sid, ''))`
  - This enforces at most one machine-wide entry (NULL owner_sid) per device while allowing multiple per-user entries with distinct SIDs
- Migration: `run_migrations()` adds both columns idempotently via `run_alter()`
- Tests: `test_device_registry_columns` asserts new columns exist; `test_device_registry_per_user_unique_constraint` verifies machine-wide + per-user coexistence and duplicate-SID rejection

### Repository (dlp-server/src/db/repositories/device_registry.rs)

- `DeviceRegistryRow`: added `owner_sid: Option<String>` and `owner_user: Option<String>`
- `list_all()`: now delegates to `list_all_filtered(pool, None)`
- `list_all_filtered(pool, owner_sid_filter)`: returns entries where `owner_sid = ? OR owner_sid IS NULL` when filter is provided; returns all when None
- `upsert()`: ON CONFLICT clause uses `COALESCE(owner_sid, '')` for conflict resolution; updates `owner_user` on conflict
- `get_by_device_key_and_owner()`: replaces `get_by_device_key`; accepts `owner_sid: Option<&str>` for exact match
- `get_by_device_key_fallback()`: returns ALL matching entries for a given (vid, pid, serial) regardless of owner_sid — used by agent for tier-based merge
- Tests: 9 repository tests covering filtered listing, per-user lookup, fallback, and machine-wide/per-user coexistence

### Admin API (dlp-server/src/admin_api.rs)

- `DeviceRegistryRequest`: added `owner_sid: Option<String>` and `owner_user: Option<String>` with `#[serde(default)]` for backward compatibility
- `DeviceRegistryResponse`: added `owner_sid` and `owner_user` fields
- `PublicDeviceEntry`: added `owner_sid` and `owner_user` fields (per D-11: SIDs are not secrets)
- `DeviceRegistryFilter`: new query param struct with optional `owner_sid`
- `list_device_registry_full_handler`: now accepts `?owner_sid={sid}` query param; returns matching SID entries plus machine-wide entries
- `upsert_device_registry_handler`: reads `owner_sid` and `owner_user` from request body; passes through to repository; uses `get_by_device_key_and_owner` for re-read after upsert
- Length guard: owner_sid and owner_user limited to 256 chars (T-38.4-03 mitigation)
- Tests: 4 new integration tests for per-user POST, backward-compat POST without owner fields, filtered GET, and machine-wide + per-user coexistence

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking Issue] SQLite NULL handling in UNIQUE constraints**
- **Found during:** Task 1 (schema design)
- **Issue:** SQLite treats NULL as distinct in UNIQUE constraints, so `UNIQUE(vid, pid, serial, owner_sid)` allows multiple rows with NULL owner_sid
- **Fix:** Replaced table-level UNIQUE with `CREATE UNIQUE INDEX idx_device_registry_unique ON device_registry(vid, pid, serial, COALESCE(owner_sid, ''))` and updated upsert ON CONFLICT to match
- **Files modified:** dlp-server/src/db/mod.rs, dlp-server/src/db/repositories/device_registry.rs

**2. [Rule 3 - Blocking Issue] Closure type mismatch in list_all_filtered match arms**
- **Found during:** Task 1 (repository implementation)
- **Issue:** Two identical closures in match arms have different types in Rust, causing E0308
- **Fix:** Unified the query using `WHERE (?1 IS NULL OR owner_sid = ?1 OR owner_sid IS NULL)` with a single closure
- **Files modified:** dlp-server/src/db/repositories/device_registry.rs

**3. [Rule 3 - Blocking Issue] params! macro lifetime in match expression**
- **Found during:** Task 1 (compilation)
- **Issue:** `params![sid]` creates a temporary that doesn't live long enough when returned from a match arm
- **Fix:** Unified query approach eliminated the need for match-based params
- **Files modified:** dlp-server/src/db/repositories/device_registry.rs
