# Phase 38.4 Plan 03: TUI Per-User Device Registry Display and Register Flow Summary

**One-liner:** Updated admin TUI to display per-user device registry entries with owner_sid/owner_user columns and support registering devices with optional owner assignment.

## Tasks Completed

| Task | Name | Commit | Files |
|------|------|--------|-------|
| 1 | TUI device list rendering with owner columns and register flow | 11aabe1 | dlp-admin-cli/src/app.rs, dlp-admin-cli/src/screens/render.rs, dlp-admin-cli/src/screens/dispatch.rs |

## What Changed

### dlp-admin-cli/src/app.rs

- Added `RegisterDeviceOwnerSid` and `RegisterDeviceOwnerUser` variants to `InputPurpose` enum
- Extended `Screen::DeviceTierPicker` with `owner_sid: Option<String>` and `owner_user: Option<String>` fields

### dlp-admin-cli/src/screens/render.rs

- Converted `draw_device_list` from `List` widget to `Table` widget with 6 columns: VID, PID, Serial, Owner, Tier, Description
- Owner column logic:
  - Both null: "(all users)" (machine-wide entry)
  - owner_user present: shows username
  - owner_sid only: truncated to 17 chars + "..." (T-38.4-11 mitigation)
  - owner_sid + owner_user: shows username
- Tier column shows BLOCKED/READ_ONLY/FULL_ACCESS
- Empty list renders centered message with hints

### dlp-admin-cli/src/screens/dispatch.rs

- Updated register flow: VID -> PID -> Serial -> Description -> Owner SID -> Owner User -> Tier Picker
- `handle_text_input` allows empty for new owner input steps
- `on_text_confirmed` chains through new input purposes to DeviceTierPicker
- `handle_device_tier_picker` extracts owner_sid/owner_user and includes them in POST body as optional JSON fields
- `build_registry_map` now filters to machine-wide entries only (skips rows with owner_sid set) for USB scan cross-reference
- Updated USB scan Enter handler to pass `owner_sid: None, owner_user: None` when opening DeviceTierPicker
