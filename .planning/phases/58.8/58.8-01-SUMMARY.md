## Decisions Made

- Pre-create the next pipe instance in the accept loop before handling the current connection. This lets fire-and-forget clients connect or queue while the server is still processing the prior request/response, eliminating the recreate window that caused intermittent connect timeouts.
- Keep `RequestOverride` strictly fire-and-forget on the agent side: after invoking the override handler, skip the response write entirely because the DLL closes its pipe handle immediately after `send_raw_oneway`.
- Fix the existing `hook_ipc_integration.rs` RequestOverride test to close the client pipe after writing the frame and assert handler invocation, rather than blocking on a response that is never sent.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Severe flakiness in override_request_test caused by named-pipe recreate race**
- **Found during:** Task 4 verification (integration test runs)
- **Issue:** The integration tests failed roughly 50% of the time with timeouts waiting for the first `RequestOverride`. After the `HookRequest` response completed, the server closed and recreated the named pipe; the DLL's subsequent `send_raw_oneway` had only a 50ms connect budget and frequently missed the new pipe instance.
- **Fix:** Modified `dlp-agent/src/hook_ipc.rs::accept_loop` to call `create_pipe` **before** `handle_connection`, so the next pipe instance already exists while the current connection is being handled. The old pipe is closed and `pipe` is advanced to the pre-created instance after the current handler returns.
- **Files modified:** `dlp-agent/src/hook_ipc.rs`
- **Verification:** `cargo test -p dlp-hook-dll --test override_request_test -- --test-threads=1` passed 15 consecutive runs (10 before the test-fix edit, 5 after).
- **Committed in:** `262b1623`

**2. [Rule 1 - Bug] hook_ipc_integration RequestOverride test deadlocked expecting a non-existent ACK**
- **Found during:** Full `dlp-agent` integration test run after the fire-and-forget change
- **Issue:** `dlp-agent/tests/hook_ipc_integration.rs::test_consolidated_server_routes_override_frame` wrote a `RequestOverride` frame and then called `read_frame`, expecting an ACK response. Because Task 3 made `RequestOverride` fire-and-forget (no response written), the client and server both blocked indefinitely on `read_frame`.
- **Fix:** Updated the test to close the client pipe after writing the `RequestOverride` frame, wait 100ms for the handler to run on the server thread, and assert `override_count == 1`. This matches the fire-and-forget contract.
- **Files modified:** `dlp-agent/tests/hook_ipc_integration.rs`
- **Verification:** `cargo test -p dlp-agent --test hook_ipc_integration -- --test-threads=1` passed (17/17 tests).
- **Committed in:** `262b1623`
