  <action>
    Add module-private helpers near the top of dlp-hook-dll/src/trampolines.rs.

    - Define a `struct OverrideCooldownMap` wrapping a `HashMap<String, Instant>` plus a `VecDeque<String>` LRU key queue and a `max_keys: usize` cap (set to 10_000). Expose `fn new() -> Self` and `fn should_emit(&mut self, key: &str, now: Instant, ttl: Duration) -> bool` that returns true only when the key is absent or its stored instant is older than `ttl`. When true, insert/update the key with `now`, push the key to the back of the LRU queue, and evict the oldest keys (removing expired entries opportunistically) until the map is at or below `max_keys`.
    - Define `static OVERRIDE_COOLDOWN: Mutex<OverrideCooldownMap>` (or `std::sync::LazyLock` if the workspace MSRV supports it) keyed by a composite string `"{path}\0{action}"`.
    - Implement `fn emit_override_request(path: &str, action: &str, handle_value: u64)`:
      - Build an `OverrideRequest` with:
        - `requester_sid`: `crate::get_current_user_sid()`
        - `data_object_id`: `path` if non-empty, otherwise `format!("handle:{handle_value}")`
        - `action`: the action argument
        - `destination_scope`: None
        - `justification`: empty String (the user fills this in the UI)
        - `resource_path`: `path` if non-empty, otherwise `format!("handle:{handle_value}")`
      - Wrap it in `IpcEnvelope::V1(IpcMessageV1 { payload: IpcPayloadV1::RequestOverride(req) })`, serialize with `bincode::serialize`, and send via `pipe_client::send_raw_oneway(crate::current_pipe_name(), &bytes)`.
      - Apply a 30-second cooldown via `OVERRIDE_COOLDOWN` so repeated DENYs on the same path/action do not spam the UI.
      - Log send failures with `tracing::warn!` and never block or unwrap.
    - Add a test-helpers entry point `#[cfg(any(test, feature = "test-helpers"))] pub fn reset_override_cooldown()` that clears `OVERRIDE_COOLDOWN` so integration tests start fresh.
    - Document each public/test-helper item with doc comments explaining fire-and-forget semantics, cooldown rationale, and bounded-memory rationale.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hook DLL -> agent named pipe | Untrusted user process sends override prompt request; agent must treat it as unauthenticated user intent. |
| agent -> server approval API | Internal service-to-service over authenticated HTTP. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58.8-01 | Tampering | hook DLL override request payload | accept | Request contains only user identity/path/action; server approval workflow verifies authorization before grant. |
| T-58.8-02 | Denial of Service | repeated DENY operations flooding UI | mitigate | 30-second per-path cooldown plus 10_000-key cap in emit_override_request limits UI spam and memory growth. |
| T-58.8-03 | Information Disclosure | override request content in logs | mitigate | Log only request_id and resource_path at info level; full request details at debug only per CLAUDE.md 9.13. |
| T-58.8-04 | Elevation of Privilege | fire-and-forget bypassing ABAC | accept | Original operation remains denied; approval only helps future operations via HookResponse.approval_override. |
| T-58.8-SC | Tampering | npm/pip/cargo installs | mitigate | No new external packages required; all dependencies already locked. |
</threat_model>
