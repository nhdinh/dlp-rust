    Extend `condition_matches` in `dlp-server/src/policy_store.rs`. Per D-07, addressing review concerns "Server-side path resolution may mismatch agent classification" and "Multiple classification implementations":

    1. Add `volume_class_matches(op: &str, expected: &VolumeClass, actual: Option<VolumeClass>) -> bool` helper function AFTER the existing compare_op helper:
       - If actual is None, return false (fails closed — no volume class means condition cannot be confirmed)
       - Match op:
         - "eq" => actual == *expected
         - "ne" => actual != *expected
         - "in" => actual == *expected (single-value semantics; the "in" operator with a list of values is handled by the TUI building multiple conditions, not by a single condition with a list)
         - _ => false (unknown operator fails closed)
       - Add doc comment explaining fail-closed behavior and referencing the VolumeClass FAIL-CLOSED INVARIANT

    2. Add two match arms to `condition_matches` (appended after existing arms):
       ```rust
       PolicyCondition::SourceVolumeClass { op, value } => {
           volume_class_matches(op, value, ctx.source_volume_class)
       }
       PolicyCondition::DestinationVolumeClass { op, value } => {
           volume_class_matches(op, value, ctx.destination_volume_class)
       }
       ```

    3. REMOVE any server-side volume class resolution from `evaluate()`. The original plan had:
       ```rust
       if ctx.source_volume_class.is_none() {
           if let Some(ref path) = ctx.resource_path {
               ctx.source_volume_class = resolve_volume_class_from_path(path, |_| None);
           }
       }
       ```
       DELETE this code. The server TRUSTS the agent-provided context. If `source_volume_class` or `destination_volume_class` is None, volume-class conditions evaluate to false (fail-closed). This eliminates the third source of truth (agent + hook + server) and prevents audit log divergence.

    4. Ensure the import for VolumeClass is present at the top of policy_store.rs (from dlp_common::abac or dlp_common::VolumeClass).

    5. Verify that the existing evaluate() function's policy iteration loop does NOT need changes — it iterates conditions and calls condition_matches generically.

    Do NOT modify existing match arms.
    Do NOT change the evaluate() function signature.
    Do NOT add server-side path resolution for volume class — the server trusts agent-provided context exclusively.
