    Rename UsbDetector to VolumeDetector and extend with volume classification capabilities. Addresses review concern "UsbDetector name is now a misnomer":

    1. Rename `UsbDetector` struct to `VolumeDetector` throughout `dlp-agent/src/detection/usb.rs`. Update all references, including:
       - Struct definition
       - impl blocks
       - `Default` impl
       - All method signatures
       - Documentation comments

    2. In `dlp-agent/src/detection/mod.rs`, update re-exports:
       - Change `pub use usb::UsbDetector;` to `pub use usb::VolumeDetector;`
       - Add any new exports needed for VolumeClass types

    3. Add `volume_class_map: RwLock<HashMap<char, (VolumeClass, Instant)>>` field to `VolumeDetector` struct, initialized to empty HashMap in Default impl. The tuple stores (class, timestamp) for stale detection.

    4. Add `classify_drive(&self, letter: char) -> Option<VolumeClass>` method (returns Option, not VolumeClass — addresses review concern "Fallback to LocalNTFS is fail-open"):
       - Call GetDriveTypeW on the drive root (format!("{}:\\", letter))
       - Map DRIVE_REMOTE (4) -> Some(NetworkShare)
       - Map DRIVE_CDROM (5) -> Some(Optical) (but per Pitfall 2, check WMI Model for "Virtual" or "Msft" first — if virtual indicator found, return Some(Virtual) even for DRIVE_CDROM)
       - Map DRIVE_REMOVABLE (2) -> call disambiguate_removable(letter)
       - Map DRIVE_FIXED (3) -> call disambiguate_fixed(letter)
       - Map DRIVE_RAMDISK (6) or unknown -> None (FAIL-CLOSED, not LocalNTFS)

    5. Add `disambiguate_removable(&self, letter: char) -> Option<VolumeClass>` private method with retry/backoff:
       - Attempt WMI query up to 3 times with backoff: 500ms, 1s, 2s
       - Query WMI Win32_DiskDrive for the physical disk associated with this drive letter
       - Map drive letter to disk via Win32_LogicalDiskToPartition -> Win32_DiskDrive association
       - If BusType/InterfaceType contains "SD" OR MediaType contains "SD" OR model contains "SD" or "MMC" -> Some(SDCard)
       - Otherwise -> Some(USBRemovable)
       - If ALL WMI queries fail after retries: log tracing::warn! and return None (FAIL-CLOSED)

    6. Add `disambiguate_fixed(&self, letter: char) -> Option<VolumeClass>` private method with retry/backoff:
       - Attempt WMI query up to 3 times with backoff: 500ms, 1s, 2s
       - Query WMI Win32_DiskDrive for the disk associated with this letter
       - If Model contains "Virtual" or "Msft" or "File-backed Virtual" -> Some(Virtual)
       - Otherwise -> Some(LocalNTFS)
       - If ALL WMI queries fail after retries: log tracing::warn! and return None (FAIL-CLOSED)

    7. Define a `WmiDiskDrive` struct with serde::Deserialize, #[serde(rename = "Win32_DiskDrive")], #[serde(rename_all = "PascalCase")], fields: DeviceID (String), interface_type (Option<String>), media_type (Option<String>), model (Option<String>), pnp_device_id (Option<String>).

    8. WMI query helper: `query_disk_for_letter(letter: char) -> Result<Option<WmiDiskDrive>, VolumeClassError>` that:
       - Creates WMIConnection::with_namespace_path(r"ROOT\CIMV2")
       - Queries all Win32_DiskDrive rows
       - Maps the drive letter to the correct disk (via Win32_LogicalDiskToPartition association or by matching DeviceID to the drive letter)
       - Returns the matching WmiDiskDrive or None if not found

    9. Add `get_volume_class_for_pipe_query(&self, letter: char) -> Option<VolumeClass>` method:
       - Check volume_class_map: if entry exists and Instant::elapsed() < 5 minutes, return cached class
       - If expired or missing, call classify_drive(letter), store result in map with current Instant, return result
       - This is the method called by the agent's named pipe handler when HookMessage::VolumeClassQuery arrives

    Error handling: WMI failures must not panic. Log via tracing::warn! and return None (fail-closed). NEVER default to LocalNTFS on failure.

    Do NOT query WMI on every classify_drive call in the hot path — this method is called from the agent's WM_DEVICECHANGE handler (not the hook DLL), so WMI latency is acceptable here.

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-56-05 | Denial of Service | WMI query timeout | mitigate | Retry/backoff (3 attempts: 500ms, 1s, 2s); fallback to None (fail-closed); no blocking of agent main thread |
| T-56-06 | Information Disclosure | VolumeArrival audit events | accept | Volume class is not sensitive information |
| T-56-07 | Tampering | volume_class_map poisoning | mitigate | Map is agent-local only; hook DLL receives data via trusted named pipe from agent |
