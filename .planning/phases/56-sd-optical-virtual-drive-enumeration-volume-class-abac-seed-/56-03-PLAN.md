<objective>
Implement hook DLL volume-class resolution at trampoline time using a thread-local cache (no WMI in hot path). Wire volume class into AbacContext before the pipe round-trip and shared-memory cache evaluation. Use named pipe queries to agent for cache misses. Implement cache invalidation on device removal.

Purpose: The hook DLL must resolve volume class fast enough to stay within the 50 us p95 hot-path budget. WMI is too slow (~10-100ms), so a thread-local cache populated by the agent via named pipe is required. Addresses review concerns: cache TTL too long, no cache invalidation, shared-memory IPC undefined, fail-closed fallback.
Output: volume_class_cache.rs module, trampoline integration for path-based and copy/move operations, named pipe query integration.
</objective>

    Create `dlp-hook-dll/src/volume_class_cache.rs` as a new module. Per D-08 and addressing review concerns "Hook DLL cache TTL (30s) creates stale classification window", "Shared-memory IPC mentioned but not designed", and "Fallback to LocalNTFS is fail-open":

    1. Define `VOLUME_CLASS_TTL: Duration = Duration::from_secs(10)` constant (reduced from 30s per review).

    2. Define thread-local cache:
       ```rust
       thread_local! {
           static VOLUME_CLASS_CACHE: RefCell<HashMap<char, (VolumeClass, Instant)>> =
               RefCell::new(HashMap::new());
       }
       ```

    3. Implement `pub fn resolve_volume_class(letter: char) -> Option<VolumeClass>`:
       - Check cache: if entry exists and Instant::elapsed() < TTL, return Some(cached class)
       - Cache miss/expired: call `query_volume_class_from_agent(letter)` (see below), insert into cache if Some, return result
       - NOTE: Returns Option<VolumeClass>, not VolumeClass — fail-closed

    4. Implement `pub fn resolve_volume_class_from_path(path: &str) -> Option<VolumeClass>`:
       - Delegate to dlp_common::abac::resolve_volume_class_from_path(path, resolve_volume_class)
       - This handles UNC -> NetworkShare, drive letter -> cache/agent query, volume GUID -> None (fail-closed)

    5. Implement `pub fn invalidate_cache()` to empty the thread-local HashMap:
       - Called on device-change notification or agent reconnect
       - This addresses review concern "No cache invalidation on device removal"

    6. Implement `pub fn invalidate_cache_for_letter(letter: char)` to remove a single entry:
       - Called when DBT_DEVICEREMOVECOMPLETE is received for a specific drive letter

    7. Implement `fn query_volume_class_from_agent(letter: char) -> Option<VolumeClass>`:
       - Send HookMessage::VolumeClassQuery { drive_letter: letter } via the named pipe client
       - Receive VolumeClassResponse { class }
       - Return class (which may be None — agent's fail-closed behavior propagates)
       - If pipe is unreachable (agent stopped), return None (FAIL-CLOSED)
       - NEVER return LocalNTFS as fallback
       - Document: pipe round-trip is ~1-5ms, acceptable for cache miss (rare with 10s TTL)

    8. In `dlp-hook-dll/src/lib.rs`, add `pub mod volume_class_cache;` alongside existing modules.

    9. Add device-change notification handler integration:
       - In the existing WM_DEVICECHANGE handler (or device notification callback), add:
         - On DBT_DEVICEARRIVAL: no action needed (cache will refresh on next access)
         - On DBT_DEVICEREMOVECOMPLETE: call `volume_class_cache::invalidate_cache_for_letter(letter)` for the removed drive
       - If no device-change handler exists in the hook DLL, document that cache invalidation relies on TTL expiration (10s is short enough)

    Do NOT use a global Mutex or RwLock — thread_local RefCell is required per D-08.
    Do NOT call WMI from this module — that would violate the hot-path budget.
    Do NOT use shared-memory cache for volume classes — named pipe only per Plan 01 protocol.
    Do NOT default unclassifiable paths to LocalNTFS — always return None (fail-closed).
  </action>
