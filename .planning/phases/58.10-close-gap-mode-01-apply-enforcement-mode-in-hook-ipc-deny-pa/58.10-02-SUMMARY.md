# Phase 58.10 Plan 02: Global-Mode Byte in Shared-Cache Header Summary

**Threaded the global enforcement mode into the shared-memory classification cache header via `_reserved[0]` (agent writer + fail-closed DLL reader), with a `CACHE_LAYOUT_VERSION` 1->2 bump for fail-closed back-compat — the ABI/foundation half of the MODE-01 full-chain fix.**

## Accomplishments

- `CacheHeader._reserved[0]` is now defined (dlp-common doc) as the global enforcement mode byte (0=Block, 1=Audit, 2=AuditAndBlock, 3=PerPolicy); `_reserved[1..24]` remain reserved. The 128-byte size assertion still holds (no new named field).
- `CACHE_LAYOUT_VERSION` bumped 1 -> 2 in BOTH dlp-agent (writer) and dlp-hook-dll (reader). A v1 reader rejects a v2 header via `full_validation` (layout mismatch) -> fail-closed to pipe, never fail-open.
- dlp-agent writes `_reserved[0] = mode_to_u8(current_global_mode())` in `init_header` AND at the end of `build_in_buffer` (before the checksum), so the byte is refreshed on every rebuild — including the existing Reinit path that fires on a server-pushed `global_enforcement_mode` change (no new trigger/channel, D-10).
- dlp-hook-dll `CacheView::global_mode()` reads `_reserved[0]` and defaults any unrecognized byte to 0 (Block) — fail-closed per ASVS V5 for an untrusted shared-memory byte.
- No checksum-logic change: `compute_checksum` already folds `_reserved` via `chunks_exact(8)` on both writer and reader, so the mode byte is integrity-protected automatically.

## Decisions Made

- **Reused `_reserved[0]` instead of adding a named field.** A new field would change `size_of::<CacheHeader>()` and break the 128-byte static assertion, forcing a full layout redesign. Reusing the byte keeps the assertion green and — because `compute_checksum` already folds `_reserved` on both sides — the mode byte is integrity-protected with zero checksum-logic change.
- **Layout-version bump in both crates for fail-closed back-compat.** During a rolling upgrade a v1 DLL reading a v2 header (or vice versa) must never misread the mode byte. The version bump makes `full_validation` reject the mismatched header -> all lookups miss -> fail-closed to pipe.
- **Fail-closed defaults at every layer.** `current_global_mode()` defaults to Block when config is uninitialized; `CacheView::global_mode()` defaults any unrecognized byte to Block. An untrusted shared-memory byte can never relax enforcement.
