## Cache-miss semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Global-Audit only (Rec.) | Fail-open ONLY when global_mode==Audit. PerPolicy cache-miss stays fail-closed DENY — preserves T-17 when per-policy mode can't be resolved offline. | ✓ |
| Per-policy Audit too | Fail-open whenever effective mode is Audit, incl. per-policy Audit on a miss. Requires caching policy mode or failing open for all T3/T4 misses (breaks T-17). | |
| Never / narrow SC#2 | Never fail-open on miss; narrow Success Criterion #2 to cache-hit/interception only (beads option (b)). | |

**User's choice:** Global-Audit only
**Notes:** Maps cleanly onto `compute_effective_mode` — on a miss `policy_mode` defaults to `Block`, so only a global Audit override yields `Audit`. Limitation recorded: per-policy Audit on a cache miss still blocks (fail-safe). Block/AuditAndBlock global modes still fail-closed.

## Gate placement + scope

**Q1 — placement:**

| Option | Description | Selected |
|--------|-------------|----------|
| service.rs closure (Rec.) | Apply the gate in the service.rs hook IPC closure (~line 2236), mirroring interception/mod.rs:419. Keeps offline.rs/cache.rs pure. | ✓ |
| Inside offline helpers | Centralize inside offline_decision/fail_closed_response; threads global mode into shared helpers, changing behavior for the online evaluate() fallback. | |

**User's choice:** service.rs closure
**Notes:** `fail_closed_response` is a pure T-17 helper with no config access; `offline_decision` is shared with the online `evaluate()` fallback. Gating in the closure avoids side effects on other callers.

**Q2 — flip scope:**

| Option | Description | Selected |
|--------|-------------|----------|
| Flip any Audit DENY (Rec.) | Mirror interception exactly: if effective mode is Audit, physical decision is ALLOW regardless of cache-hit/miss, with would_have_denied audit. | ✓ |
| Cache-miss only | Only relax the fail-closed miss heuristic; leave cached DENYs alone (a stale cached DENY could still block under global Audit). | |

**User's choice:** Flip any Audit DENY
**Notes:** Verified the agent decision cache stores the full `EvaluateResponse` incl. `enforcement_mode`, populated from the engine (offline.rs:122) — so a per-policy Audit on an agent cache-hit also flips correctly.

## Scope fence

**Q1 — coverage:**

| Option | Description | Selected |
|--------|-------------|----------|
| Full chain (Rec.) | Make BOTH paths mode-aware (agent IPC cache-miss + DLL cache-hit fast-path). | ✓ |
| Agent IPC only | Fix only service.rs cache-miss path; cache-hit T3/T4 writes still denied by DLL fast-path — SC#2 fails on second write to a cached file. | |

**User's choice:** Full chain
**Notes:** The DLL cache-hit fast-path (classification_cache.rs:217-224) autonomously denies T3/T4 writes with no IPC/mode. The shared cache (Phase 50) makes cache-hits the common case, so an agent-only fix would ALLOW the first write (miss) but DENY subsequent writes (hit).

**Q2 — DLL mechanism:**

| Option | Description | Selected |
|--------|-------------|----------|
| Global mode in header (Rec.) | Store global effective mode in the shared-cache header (synced from agent). On global Audit, DLL skips the autonomous T3/T4 deny and pipes to the agent. Block/AuditAndBlock/PerPolicy keep the fast-path deny. | ✓ |
| Per-path mode in cache | Store per-path mode in the cache; enables per-policy Audit on cache-hit, but requires a checksummed schema change. | |
| Always pipe on non-Block | Always pipe T3/T4 writes on non-Block global mode; simpler but adds pipe latency and still can't do per-policy. | |

**User's choice:** Global mode in header
**Notes:** The shared cache is per-machine; on a hit the DLL knows tier but not policy, so only the global mode is knowable without a schema change. Consistent with the Area-1 "global-Audit only" decision. Limitation: per-policy Audit on a DLL cache-hit still blocks.
