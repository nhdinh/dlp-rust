# Phase 58.10 Plan 03: DLL Fast-Path Mode-Awareness + Hook Decision-Path E2E Summary

**One-liner:** Made the hook-DLL cache-hit fast-path mode-aware (global Audit skips the autonomous T3/T4 write-deny and pipes to the agent at HEALTHY/DEGRADED/RESYNC via a single `should_skip_autonomous_deny` predicate) and added end-to-end `evaluate_hook_request` tests proving Audit -> ALLOW + parity audit and Block -> DENY in one process.

## What Was Built

This plan completes the full-chain MODE-01 fix on the DLL side. Prior plans built the
agent-side mode gate (58.10-01: `evaluate_hook_request` flips an Audit DENY to ALLOW
with a full-parity audit) and the shared-memory mode byte (58.10-02:
`CacheView::global_mode()` reader, `CACHE_LAYOUT_VERSION=2`). This plan wires the DLL
fast-path to honor that byte so a global Audit override no longer autonomously denies
T3/T4 cache-hits — it falls through to the agent pipe, which applies the mode
authoritatively and emits the parity audit.

### Task 1 — DLL fast-path skip (commit `bd6023dc`)

- Added `pub(crate) fn should_skip_autonomous_deny(global_mode_byte: u8) -> bool` in
  `dlp-hook-dll/src/trampolines.rs` — returns `true` only for byte `1` (Audit);
  `0`/`2`/`3` and any unrecognized byte (e.g. `0xFF`) return `false` (fail-closed,
  mirroring `CacheView::global_mode`). Doc comment cites D-10 and the pipe-reachable
  precondition.
- **HEALTHY** cache-hit branch: computes `skip` from `cache_lookup.global_mode()`;
  when `skip` the branch no longer calls `decide()`/early-returns — it falls through
  to the `classify_path` pipe round-trip. When not `skip`, the existing deny+return is
  byte-for-byte unchanged.
- **DEGRADED** cache-hit branch: same skip, plus a `force_pipe` flag that bypasses the
  `if fail_state.should_retry_pipe()` throttle (A3) so the agent is always reached under
  global Audit. When not `skip`, DEGRADED behavior is unchanged.
- **RESYNC** branch: same skip applied to the inline re-run deny (which executes after
  flush-LRU/reset/set-Healthy), falling through to the pipe retry — closes the D-09
  full-chain gap where RESYNC would ALLOW the first write (pipe) but DENY every
  subsequent one (now-Healthy cache hit).
- `decide_isolated` / `decide_degraded` (fail_mode.rs) and the ISOLATED branch are NOT
  touched — they stay fail-closed under global Audit (A1).
- Unit test `should_skip_autonomous_deny_only_for_global_audit` covers bytes
  0/1/2/3/0xFF/0x7F (cross-platform-testable core).

### Task 2 — end-to-end decision-path tests (commit `e2b03441`)

Added two tests to `dlp-agent/tests/hook_ipc_integration.rs` that call the REAL
`evaluate_hook_request` (the function the production hook-IPC closure delegates to)
directly with an EXPLICIT `global_mode`:

- `global_audit_returns_allow_for_sensitive_write_with_parity_audit` — cached DENY +
  `EnforcementMode::Audit` -> `HookResponse.decision == ALLOW` + a full-parity `Access`
  audit (`would_have_denied == true`, `policy_mode == "Audit"`).
- `global_block_preserves_deny_for_sensitive_write` — same request +
  `EnforcementMode::Block` -> `DENY` (T-17 control). Runs in the SAME process because
  `global_mode` is an explicit parameter (no CONFIG OnceLock, no live pipe).

These are NOT `#[cfg(windows)]`-gated (no named pipe) and NOT `#[serial]` (local
fixtures only), so they run on any platform in parallel.

**2. [Rule 2 - Clarification] e2e test drives a cached DENY rather than a T3 fail-closed miss**
- **Found during:** Task 2 implementation
- **Issue:** The plan's behavior text described driving a T3 classification so
  `offline_decision` fail-closed-DENYs on a cache miss. However,
  `hook_request_to_evaluate_request` builds the `Resource` with `..Default::default()`,
  so `resource.classification` is always `T1` (the `Classification::default()`), and a
  T1 cache-miss fail-closed-ALLOWs (nothing to flip). The classification is not settable
  via the `HookRequest`.
- **Fix:** Mirrored the existing `service.rs` unit-test mechanism — pre-populate the
  agent cache with a real DENY (a cache HIT) so `offline_decision` returns a genuine
  denial that the mode gate flips. This faithfully exercises the same code path the plan
  intends (real `offline_decision` -> mode gate -> flip/preserve) and satisfies the done
  criteria (Audit -> ALLOW + parity audit; Block -> DENY, both in one process).
- **Files modified:** `dlp-agent/tests/hook_ipc_integration.rs`
- **Commit:** `e2b03441`
