# Phase 58.10: Close gap MODE-01 — apply enforcement mode in hook IPC deny path - Research

**Researched:** 2026-07-12
**Domain:** Windows user-mode DLP enforcement — hook DLL shared-memory cache + agent hook IPC decision path (Rust)
**Confidence:** HIGH

## Summary

Phase 58.10 closes gap **MODE-01**: the agent hook IPC deny path and the hook DLL shared-cache fast-path ignore enforcement mode, so Audit-mode hook-mediated file operations (WriteFile/CopyFileExW/MoveFileExW/DeleteFileW/ReplaceFileW/NtWriteFile) are physically blocked instead of ALLOWed-with-audit. This contradicts Phase 55 Success Criterion #2. The fix spans two autonomous deny paths: (1) the agent hook IPC closure (`service.rs:2236` → `offline.offline_decision`) on cache **miss**, and (2) the DLL shared-cache fast-path (`classification_cache.rs::decide()` called from `trampolines.rs:554` HEALTHY and `:621` DEGRADED) on cache **hit**.

The reference implementation already exists and is verified: `interception/mod.rs:408-524` is the ONLY production caller that applies `compute_effective_mode`. This phase mirrors that exact pattern onto the hook path. All machinery needed — `compute_effective_mode`, `EnforcementMode::{is_audit,is_blocking}`, the audit builders (`with_policy`, `with_policy_mode`, `with_would_have_denied`, `enrich_audit_with_app_identity`, `set_destination_application`), and the config reader (`with_config(|cfg| cfg.enforcement.global_mode)`) — already exists and is reused verbatim (DRY, per CLAUDE.md §9).

The DLL-side mechanism threads the global enforcement mode into the shared-cache header via one byte of the existing `_reserved: [u8; 24]` field. Critically, the checksum already folds `_reserved` in (both writer `compute_checksum` and reader `compute_checksum` iterate `_reserved.chunks_exact(8)`), so **no checksum logic change is needed** — only a `CACHE_LAYOUT_VERSION` bump (1 → 2) and a reader/writer agreement on the byte offset. The agent-side re-publish path already exists: `apply_payload_to_config` detects `global_enforcement_mode` changes → `signal_dacl_reinit_if_needed` fires `DaclManagerCommand::Reinit` → the Reinit handler reads `cfg.enforcement.global_mode` and calls `prepopulate_t3_t4_roots` → `rebuild`. The mode byte is written during `init_header`/`rebuild`.

**Primary recommendation:** Mirror `interception/mod.rs:413-465` in the `service.rs` hook IPC closure (compute effective mode, flip any Audit DENY → ALLOW, emit full-parity audit), and add a global-mode byte to `CacheHeader._reserved[0]` (bump layout version to 2) so the DLL cache-hit fast-path skips the T3/T4 write-deny under global Audit and falls through to the pipe. No new crates required.

## User Constraints (from CONTEXT.md)

### Locked Decisions

**Cache-Miss Semantics**
- **D-01:** On a T3/T4 classification-cache miss, the hook fails open to ALLOW+audit **only when `global_mode == Audit`**. In `Block`, `AuditAndBlock`, or `PerPolicy` global mode, the cache-miss path stays fail-closed DENY (preserves the T-17 guarantee when the per-policy mode cannot be resolved offline).
- **D-02:** Mechanism: on a cache miss the response's `enforcement_mode` is `None` → default to `Block`; then `compute_effective_mode(global_mode, Block)` yields `Audit` only under a global Audit override. Reuses the existing helper with no new logic.
- **D-03:** Documented limitation: a **per-policy** Audit policy on a cache miss still blocks (the policy mode is unresolvable without a cache entry). Only a global Audit override relaxes the miss path. Fail-safe and intentional.

**Gate Placement + Scope**
- **D-04:** The mode gate lives in the **`service.rs` hook IPC closure** (near line 2236), mirroring `interception/mod.rs:419` — NOT inside `offline_decision`/`fail_closed_response`. Those shared helpers stay pure: `fail_closed_response` is a pure T-17 function with no config access, and `offline_decision` is shared with the online `evaluate()` fallback path.
- **D-05:** The Audit flip applies to **any** DENY returned by `offline_decision` (cache-hit or cache-miss), exactly mirroring the interception path (`if effective_mode.is_audit() { Decision::ALLOW } else { response.decision }`).
- **D-06:** Verified enabler: the agent decision cache stores the full `EvaluateResponse` including `enforcement_mode`, populated from the engine (`offline.rs:122`). So on a cache **hit** the policy mode IS known — a per-policy Audit policy on an agent-cache-hit correctly flips to ALLOW. (Does NOT extend to the DLL cache-hit fast-path — see D-09.)

**Audit Event Parity**
- **D-07:** The hook IPC path emits **full-parity** Audit-mode events matching the interception path: `EventType::Access` + `.with_policy(...)` + `.with_policy_mode("Audit")` + `.with_would_have_denied(true)` + app-identity enrichment, reusing the same builder methods (`interception/mod.rs:503-508`). SIEM must see identical Audit-mode events regardless of which path produced them.
- **D-08:** The would-be-deny reason carries into the audit's policy/reason field. No `BlockNotify` UI notification fires in Audit mode (consistent with `interception/mod.rs:529`).

**Scope Fence — Full Chain**
- **D-09:** Phase 58.10 covers the **full chain** (agent IPC path AND DLL cache-hit fast-path), not just the agent IPC handler. Rationale: cache-hits are the common case for classified files; an agent-only fix would ALLOW the first write (miss) but DENY every subsequent write (hit) to the same T3/T4 file.
- **D-10:** DLL mechanism: store the **global effective enforcement mode in the shared-cache header** (synced from the agent). On global `Audit`, the DLL cache-hit fast-path skips the autonomous T3/T4 write-deny and pipes to the agent. On `Block`/`AuditAndBlock`/`PerPolicy`, the DLL keeps the fast-path deny.
- **D-11:** Documented limitation (extends D-03): per-policy Audit on a **DLL cache-hit** still blocks — the DLL knows the file's tier but not its policy, so it can only honor a global Audit override.

### Pattern 1: Mirror the interception-path effective-mode gate (agent closure)

**What:** Compute the effective mode from global + policy mode, then flip any Audit DENY to ALLOW before building the `HookResponse`.

**When to use:** In the `service.rs` hook IPC closure, immediately after `offline.offline_decision(&evaluate_req)` (currently line 2236) and before constructing `HookResponse` (line 2237).

**Example (the exact pattern to mirror, from `interception/mod.rs:413-427`):**
```rust
// Source: dlp-agent/src/interception/mod.rs:413-427 (verified this session)
let global_mode = crate::service::with_config(|cfg| cfg.enforcement.global_mode)
    .unwrap_or(dlp_common::abac::EnforcementMode::Block);

let policy_mode = response
    .enforcement_mode
    .unwrap_or(dlp_common::abac::EnforcementMode::Block);
let effective_mode = dlp_common::abac::compute_effective_mode(global_mode, policy_mode);

// Audit mode: always ALLOW the physical operation, but record what would have happened.
let final_decision = if effective_mode.is_audit() {
    Decision::ALLOW
} else {
    response.decision
};
```

### Pattern 3: Global-mode byte in the shared-cache header (DLL + agent)

**What:** Repurpose `_reserved[0]` as the global enforcement mode byte (0=Block, 1=Audit, 2=AuditAndBlock, 3=PerPolicy). The agent writes it during `init_header`/`rebuild`; the DLL reads it on the cache-hit fast-path and skips the autonomous T3/T4 write-deny when it is `Audit`.

**Why `_reserved[0]` is safe:**
- The 128-byte `CacheHeader` size is unchanged (static assertion `size_of::<CacheHeader>() == 128` still holds) — `_reserved` shrinks conceptually from 24 to 23 usable bytes + 1 mode byte, but the field stays `[u8; 24]`.
- The checksum already folds `_reserved` in: both writer (`dlp-agent/src/classification_cache.rs:683-688`) and reader (`dlp-hook-dll/src/classification_cache.rs:279-284`) iterate `_reserved.chunks_exact(8)`. **No checksum logic change is needed.**
- A `CACHE_LAYOUT_VERSION` bump (1 → 2) in BOTH `dlp-agent/src/classification_cache.rs:58` and `dlp-hook-dll/src/classification_cache.rs:54` forces old readers/writers to reject the new header (fail-closed), satisfying the backward-compat requirement.

**Example (DLL reader — add a `global_mode` accessor on `CacheView`):**
```rust
// Source pattern: dlp-hook-dll/src/classification_cache.rs CacheView impl
impl CacheView {
    /// Read the global enforcement mode byte from the header (_reserved[0]).
    /// Defaults to Block (0) for any unrecognized value (fail-closed).
    pub fn global_mode(&self) -> u8 {
        let b = unsafe { (*self.header)._reserved[0] };
        match b {
            1 => 1, // Audit
            2 => 2, // AuditAndBlock
            3 => 3, // PerPolicy
            _ => 0, // Block (default / fail-closed)
        }
    }
}
```

**Example (DLL fast-path skip — at `trampolines.rs:554` HEALTHY and `:621` DEGRADED):**
```rust
// Source pattern: dlp-hook-dll/src/trampolines.rs:547-557 (HEALTHY cache-hit branch)
if let Some(classification) = cache_classification {
    classification_source = ClassificationSource::CacheHit;
    // NEW: under global Audit, skip the autonomous T3/T4 write-deny and
    // fall through to the pipe so the agent applies the mode + emits audit.
    let global_audit = cache_lookup.map(|c| c.global_mode() == 1).unwrap_or(false);
    if !global_audit {
        if let Some(deny) = cache_lookup.and_then(|c| c.decide(classification, op)) {
            return Some(deny);
        }
        return None;
    }
    // global_audit == true: do NOT return here; fall through to the pipe
    // round-trip below (the cache-miss path), which reaches the agent.
}
```

> **Note on fall-through mechanics:** In the current HEALTHY branch, a cache hit `return`s early (either the deny or `None`). To make a global-Audit cache hit reach the pipe, the branch must NOT return on hit when `global_audit` is set — instead it must clear `cache_classification` (or use a flag) so execution continues into the `classify_path` pipe round-trip at `trampolines.rs:561`. The planner should implement this as: on `global_audit` cache-hit, treat it as a miss (skip the early return, let the pipe path run). The DEGRADED branch (`:612-625`) needs the same treatment, and must still respect `should_retry_pipe()` — under global Audit, force the pipe attempt regardless of the retry counter so the agent (not the DLL) makes the mode-aware decision.

### Anti-Patterns to Avoid
- **Gating inside `offline_decision` or `fail_closed_response`:** These are shared, pure helpers. `fail_closed_response` is a pure T-17 function with no config access; `offline_decision` is shared with the online `evaluate()` fallback. Gating there would change behavior for other callers. Gate in the closure (D-04).
- **Changing the checksum to exclude `_reserved[0]`:** Unnecessary and risky. The checksum already covers `_reserved`; leaving it as-is means the mode byte is integrity-protected like every other header field.
- **Adding a new named header field:** Breaks the 128-byte `size_of` static assertion and forces a full layout redesign. Reuse `_reserved[0]`.
- **DLL emitting its own audit on the global-Audit fall-through:** Keep audit emission centralized in the agent (DRY, SIEM consistency). The DLL pipes to the agent; the agent emits the parity audit. (CONTEXT discretion prefers agent-only.)
- **Forgetting the DEGRADED/ISOLATED fail-mode paths:** `decide_degraded`/`decide_isolated` also deny T3/T4 writes autonomously. See Pitfall 3.

The risk is not in novel logic but in *missing a deny call site* (see Pitfalls).

## Common Pitfalls

### Pitfall 1: Gating only the cache-miss path and forgetting the DLL cache-hit fast-path
**What goes wrong:** An agent-only fix makes the first write to a T3/T4 file (cache miss) ALLOW under Audit, but every subsequent write to the same file (cache hit) is still autonomously denied by the DLL `decide()` — SC#2 fails in any realistic scenario.
**Why it happens:** The shared-memory cache (Phase 50) makes cache-hits the common case for classified files. The DLL `decide()` at `classification_cache.rs:212-224` returns `Some(DenyReturn::BoolFalse)` for `(T3|T4, Write)` with no IPC round-trip and no mode check.
**How to avoid:** Implement the full-chain fix (D-09/D-10): add the global-mode byte to the header and skip the `decide()` deny on global Audit at BOTH `trampolines.rs:554` (HEALTHY) and `:621` (DEGRADED).
**Warning signs:** A test where the second write to the same Audit-mode T3 file is denied; `record_cache_hit()` telemetry increments while the op is blocked.

### Pitfall 2: Breaking the checksum or the 128-byte header assertion when adding the mode byte
**What goes wrong:** Adding a new named field to `CacheHeader` changes `size_of::<CacheHeader>()`, failing the compile-time `assert!(size_of == 128)` in `dlp-common/src/classification_cache.rs:102-105`. Or, modifying `compute_checksum` inconsistently between writer and reader causes `full_validation` to reject every cache → all lookups miss → silent perf collapse + fail-mode flapping.
**Why it happens:** The header is a shared ABI with a hard size contract and a checksum that must be computed identically on both sides.
**How to avoid:** Reuse `_reserved[0]` (no size change). Do NOT touch `compute_checksum` — it already folds `_reserved` in. Bump `CACHE_LAYOUT_VERSION` to 2 in BOTH crates so mismatched old/new binaries reject each other (fail-closed).
**Warning signs:** `cargo build` fails on the size assertion; DLL logs "cache: full validation failed on init"; `record_cache_miss()` spikes.

### Pitfall 3: Forgetting `decide_degraded`/`decide_isolated` also deny T3/T4 writes
**What goes wrong:** Even with the HEALTHY/DEGRADED cache-hit branches patched, when the pipe is unreachable the fail-mode functions `decide_degraded` (`fail_mode.rs:441`) and `decide_isolated` (`fail_mode.rs:409`) STILL deny `(T3|T4, Write)` and `(None, Write)` autonomously — so under global Audit with a down agent, writes are still blocked.
**Why it happens:** These are separate deny paths from `CacheView::decide()`. `decide_degraded` delegates to `decide_isolated` for cache-hits; `decide_isolated` denies unknown writes too.
**How to avoid:** This is a **design decision the planner must surface**, not a silent fix. CONTEXT D-01/D-10 scope the global-Audit relaxation to the *cache-hit fast-path* (pipe reachable). When the pipe is DOWN (DEGRADED/ISOLATED), the agent cannot apply the mode or emit the audit — so relaxing `decide_isolated`/`decide_degraded` would ALLOW writes with NO audit trail, violating D-07 parity. **Recommendation: keep `decide_isolated`/`decide_degraded` fail-closed (deny T3/T4 writes) even under global Audit**, because the audit cannot be emitted without the agent. Document this as an explicit limitation: global Audit relaxes the hook path only when the agent pipe is reachable; a down agent still fails closed. This preserves T-17 and audit parity. The planner should confirm this scoping with the user if CONTEXT is ambiguous.
**Warning signs:** UAT with the agent stopped shows Audit-mode writes blocked; this is *intended* under the recommended scoping, not a bug.

### Pitfall 4: Audit-mode flip firing on the approval-override path or double-emitting audits
**What goes wrong:** The closure already has an approval-cache early return (`service.rs:2213-2222`) and an existing blocked-write audit (`service.rs:2247-2285`). Naively inserting the mode gate could (a) flip an approval-override DENY, or (b) emit both a Block audit and an Access audit for the same op.
**Why it happens:** The closure has three decision sources (approval cache, offline_decision, hash-evidence audit) that interact.
**How to avoid:** Mirror the interception ordering exactly (`interception/mod.rs:432-465`): the Audit flip short-circuits BEFORE the approval-override check (`if effective_mode.is_blocking() && final_decision.is_denied()`). Emit exactly ONE audit: the parity Access audit when the flip fires, the existing Block audit when it doesn't. The approval-cache early return at `:2213` is upstream of the mode gate and is unaffected (it returns ALLOW on override, which is already correct).
**Warning signs:** Two audit rows for one file op; an approval override that is ignored under Audit mode.

### Pitfall 5: Reading `global_mode` from a stale config snapshot in the closure
**What goes wrong:** The closure captures config at server-construction time; if it reads a captured `global_mode` instead of the live `with_config`, a runtime mode change (server push) won't take effect until restart.
**Why it happens:** `with_config` reads the live `CONFIG` OnceLock (updated in-place by `config_poll_loop`), but a closure that captured a mode value at init would be stale.
**How to avoid:** Call `crate::service::with_config(|cfg| cfg.enforcement.global_mode)` INSIDE the closure body on every request (as `interception/mod.rs:413` does), not once at construction. The `with_config` read is a cheap lock + copy of a `Copy` enum.
**Warning signs:** Changing `[enforcement] global_mode` at runtime doesn't change hook behavior until the agent restarts.

## Open Questions (RESOLVED)

1. **Should `decide_isolated`/`decide_degraded` honor global Audit when the pipe is down?**
   - What we know: These functions deny T3/T4 (and unknown) writes autonomously with no IPC. Under global Audit with a reachable pipe, the cache-hit fast-path pipes to the agent. With a DOWN pipe (DEGRADED/ISOLATED), there is no agent to apply the mode or emit the audit.
   - What's unclear: Whether CONTEXT's "global Audit relaxes the hook path" extends to the pipe-down fail-mode states. D-01/D-10 language centers on the cache-hit fast-path (pipe reachable).
   - Recommendation: Keep them fail-closed (A1). Surface to the user during planning; document as an explicit limitation either way.
   - **RESOLVED (2026-07-12, Plan 03):** A1 locked — `decide_isolated`/`decide_degraded` are NOT modified; ISOLATED:675 stays fail-closed under global Audit (no agent = no parity audit, so fail-closed preserves T-17 + audit parity). Documented as a limitation in Plan 03 and its threat model (T-58.10-09).

2. **DEGRADED-mode pipe throttle under global Audit (A3).**
   - What we know: `should_retry_pipe()` only attempts the pipe every 10th call in DEGRADED. A global-Audit cache-hit that skips `decide()` must reach the pipe to get the agent's mode-aware decision.
   - What's unclear: Whether to force the pipe attempt (bypass throttle) or accept that 9/10 DEGRADED hits fall to `decide_degraded` (deny).
   - Recommendation: Force the pipe attempt under global Audit (the whole point is to reach the agent). Confirm during planning.
   - **RESOLVED (2026-07-12, Plan 03):** A3 locked — under global Audit the DEGRADED cache-hit FORCES the pipe attempt (bypasses the `should_retry_pipe()` throttle) so the agent applies the mode + emits the audit. Accepted tradeoff documented in Plan 03 threat model (T-58.10-11).

3. **Exact fall-through mechanics in the HEALTHY/DEGRADED cache-hit branches.**
   - What we know: The current branches `return` early on a cache hit. To reach the pipe, the global-Audit hit must NOT return.
   - What's unclear: The cleanest implementation (clear `cache_classification` vs. a `force_pipe` flag) without disturbing the `classification_source` telemetry or the `override_tier` mirror at `trampolines.rs:529`.
   - Recommendation: Planner picks the minimal-diff approach; a `force_pipe` boolean that skips the early return and routes into the existing `classify_path` block is likely cleanest.
   - **RESOLVED (2026-07-12, Plan 03 Task 1):** adopted the `force_pipe`/`should_skip_autonomous_deny(global_mode_byte)` predicate approach — a single pure predicate (== 1/Audit) reused at all three skip sites (HEALTHY:554, DEGRADED:621, RESYNC:705), skipping the early return and routing into the existing `classify_path` pipe block without disturbing `classification_source`/`override_tier`.

### Known Threat Patterns for {Windows user-mode hook DLL + shared-memory cache}

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Malicious process writes a forged mode byte to relax enforcement | Tampering | The shared-memory mapping is SDDL-restricted (`D:(A;;GA;;;SY)(A;;GR;;;BA)` — only SYSTEM writes; Admins read). The DLL maps `FILE_MAP_READ` only. A non-SYSTEM process cannot write the header. |
| Old DLL (v1) reads a new (v2) header and misinterprets the mode byte | Tampering / Spoofing | `CACHE_LAYOUT_VERSION` bump → old reader's `full_validation` rejects the header (layout mismatch) → all lookups miss → fail-closed to pipe. New byte never misread. |
| Audit-mode flip ALLOWs a write with no audit trail (accountability loss) | Repudiation | The flip ALWAYS emits the full-parity audit (D-07) before returning ALLOW. Pipe-down fail-mode paths stay fail-closed (A1) precisely because no audit can be emitted without the agent. |
| Fail-open on cache miss under a non-Audit global mode | Elevation of Privilege | D-01/D-02: cache miss defaults `enforcement_mode` to Block; only a global Audit override relaxes it. Block/AuditAndBlock/PerPolicy stay fail-closed (T-17 preserved). |
| Config-change race: mode byte stale after a server push | Tampering | The existing `signal_dacl_reinit_if_needed` fires on `global_enforcement_mode` change → Reinit → `rebuild` rewrites the byte. The sequence-lock protocol (odd/even `version_word`) ensures readers never see a half-written header. |
