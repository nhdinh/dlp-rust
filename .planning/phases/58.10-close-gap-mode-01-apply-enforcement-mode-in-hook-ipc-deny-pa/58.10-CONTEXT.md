# Phase 58.10: Close gap MODE-01 — apply enforcement mode in hook IPC deny path - Context

**Gathered:** 2026-07-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 58.10 closes gap **MODE-01** (v0.10.0 milestone, beads `dlp-rust-k7j`, P1): the agent hook IPC deny path ignores enforcement mode, so Audit-mode hook-mediated file operations are physically blocked instead of ALLOWed-with-audit — contradicting Phase 55 Success Criterion #2 ("a policy in Audit mode ... the hook returns ALLOW; the file operation succeeds").

The gap lives on **two** autonomous deny paths, both of which this phase makes mode-aware:

1. **Agent hook IPC handler** (`dlp-agent/src/service.rs:2236` → `offline.offline_decision`) — the cache-**miss** pipe path. Returns `fail_closed_response(classification)` (DENY for T3/T4) with no `compute_effective_mode`.
2. **Hook DLL shared-cache fast-path** (`dlp-hook-dll/src/classification_cache.rs:217` `decide()` → `trampolines.rs` HEALTHY:554 / DEGRADED:621) — the cache-**hit** path. Autonomously denies T3/T4 writes with no IPC round-trip and no mode gating.

Only the **interception path** (`dlp-agent/src/interception/mod.rs:413-465`) applies `compute_effective_mode` today; it is the reference implementation this phase mirrors on the hook path.

**In scope:**
- Make the agent hook IPC closure mode-aware (flip Audit DENY → ALLOW + audit).
- Make the DLL cache-hit fast-path mode-aware via a global-mode byte in the shared-cache header.
- Full-parity Audit-mode audit events on the hook path (SIEM consistency with interception).
- Hook-path test evidence that closes MODE-01's verification gap.

**Out of scope (deferred):**
- Per-policy Audit on paths where the policy mode is not locally resolvable (agent cache-miss, any DLL cache-hit) — remains fail-closed by design (documented limitation, not a bug).
- Hook DLL volume-class `None` gaps (DRIVE-03/04) — separate gap.
- `handle_hook_request` legacy stub hygiene — separate hygiene item.

**Depends on:** Phase 58 (milestone audit that surfaced MODE-01); builds on Phase 55 (enforcement mode) and Phase 50 (shared-memory cache).
**Requirements:** MODE-01

</domain>

<decisions>
## Implementation Decisions

### Cache-Miss Semantics
- **D-01:** On a T3/T4 classification-cache miss, the hook fails open to ALLOW+audit **only when `global_mode == Audit`**. In `Block`, `AuditAndBlock`, or `PerPolicy` global mode, the cache-miss path stays fail-closed DENY (preserves the T-17 guarantee when the per-policy mode cannot be resolved offline).
- **D-02:** Mechanism: on a cache miss the response's `enforcement_mode` is `None` → default to `Block`; then `compute_effective_mode(global_mode, Block)` yields `Audit` only under a global Audit override. This reuses the existing helper with no new logic.
- **D-03:** Documented limitation: a **per-policy** Audit policy on a cache miss still blocks (the policy mode is unresolvable without a cache entry). Only a global Audit override relaxes the miss path. This is fail-safe and intentional.

### Gate Placement + Scope
- **D-04:** The mode gate lives in the **`service.rs` hook IPC closure** (near line 2236), mirroring `interception/mod.rs:419` — NOT inside `offline_decision`/`fail_closed_response`. Those shared helpers stay pure: `fail_closed_response` is a pure T-17 function with no config access, and `offline_decision` is shared with the online `evaluate()` fallback path. Gating in the closure avoids changing behavior for other callers.
- **D-05:** The Audit flip applies to **any** DENY returned by `offline_decision` (cache-hit or cache-miss), exactly mirroring the interception path (`if effective_mode.is_audit() { Decision::ALLOW } else { response.decision }`).
- **D-06:** Verified enabler: the agent decision cache stores the full `EvaluateResponse` including `enforcement_mode`, populated from the engine (`offline.rs:122`). So on a cache **hit** the policy mode IS known — a per-policy Audit policy on an agent-cache-hit correctly flips to ALLOW. (This does NOT extend to the DLL cache-hit fast-path, which never reaches the agent — see D-09.)

### Audit Event Parity
- **D-07:** The hook IPC path emits **full-parity** Audit-mode events matching the interception path: `EventType::Access` + `.with_policy(...)` + `.with_policy_mode("Audit")` + `.with_would_have_denied(true)` + app-identity enrichment, reusing the same builder methods (`interception/mod.rs:503-508`). SIEM must see identical Audit-mode events regardless of which path produced them.
- **D-08:** The would-be-deny reason (fail-closed reason, or the cached policy's deny reason) carries into the audit's policy/reason field. No `BlockNotify` UI notification fires in Audit mode (nothing is physically blocked — consistent with `interception/mod.rs:529`).

### Scope Fence — Full Chain
- **D-09:** Phase 58.10 covers the **full chain** (agent IPC path AND DLL cache-hit fast-path), not just the agent IPC handler. Rationale: the shared-memory cache (Phase 50) makes cache-hits the common case for classified files, so an agent-only fix would ALLOW the first write (miss) but DENY every subsequent write (hit) to the same T3/T4 file — SC#2 would still fail in any realistic scenario.
- **D-10:** DLL mechanism: store the **global effective enforcement mode in the shared-cache header** (synced from the agent, like the allowlist/version words). On global `Audit`, the DLL cache-hit fast-path skips the autonomous T3/T4 write-deny and pipes to the agent (which applies the mode and emits the full-parity audit). On `Block`/`AuditAndBlock`/`PerPolicy`, the DLL keeps the fast-path deny (preserves T-17 and performance).
- **D-11:** Documented limitation (extends D-03): per-policy Audit on a **DLL cache-hit** still blocks — the DLL knows the file's tier but not its policy, so it can only honor a global Audit override. Per-policy Audit on the hook path is honored only at the agent level on an agent-cache-hit (D-06).

### Claude's Discretion
- Exact shared-cache header field layout, offset, checksum/version-word handling for the new global-mode byte — follow the existing `CacheHeader` conventions in `classification_cache.rs` and bump the layout version if the structure changes.
- How the agent syncs the global mode into the shared-cache header (piggyback on the existing cache-publish/allowlist-sync path is preferred over a new channel).
- Whether the DLL, on a global-Audit cache-hit, emits a lightweight local audit in addition to piping to the agent, or relies solely on the agent's piped audit (prefer agent-only to keep audit emission centralized and DRY).
- Test implementation details (fixtures, pipe harness) — but see Specifics for the required evidence.

</decisions>

## Existing Code Insights

### Reusable Assets
- **`compute_effective_mode(global, policy)`** (`dlp-common/src/abac.rs:450`): exact helper the interception path uses. Call it in the hook IPC closure with `global_mode` from config and `policy_mode = response.enforcement_mode.unwrap_or(Block)`.
- **`EnforcementMode::is_audit()` / `is_blocking()`** (`dlp-common/src/abac.rs`): drive the ALLOW flip and the approval-override gate.
- **Audit builders** (`.with_policy`, `.with_policy_mode`, `.with_would_have_denied`, `enrich_audit_with_app_identity`, `set_destination_application`): reuse verbatim from `interception/mod.rs:499-524` for full parity.
- **`crate::service::with_config(|cfg| cfg.enforcement.global_mode)`** (`interception/mod.rs:413`): the existing way to read the global mode from agent config — use the same in the hook closure.
- **Agent decision cache** (`dlp-agent/src/cache.rs`): stores full `EvaluateResponse` incl. `enforcement_mode` (from engine, `offline.rs:122`); enables the per-policy-Audit-on-hit flip.

### Established Patterns
- **Two-path hook deny**: cache-hit → DLL `decide()` (autonomous, no IPC); cache-miss → pipe to agent (`classify_path`). Any mode fix must address both.
- **Fail-mode state machine** (HEALTHY/DEGRADED/ISOLATED): the DLL cache-hit deny fires in HEALTHY and DEGRADED; the global-mode skip must be applied at both `decide()` call sites (trampolines.rs:554, :621) and respected in `fail_mode::decide_degraded`/`decide_isolated` if those also deny T3/T4 writes.
- **Shared-cache header conventions**: `CacheHeader` carries magic, layout_version, checksum, version word, allowlist offset/count. A new global-mode byte must be folded into the checksum and layout-version handling.

### Integration Points
- `dlp-agent/src/service.rs` — hook IPC closure: add effective-mode computation + Audit flip + full-parity audit emission.
- `dlp-agent` shared-cache publish path — sync global mode into the cache header (alongside allowlist/version).
- `dlp-hook-dll/src/classification_cache.rs` — `CacheHeader` + `decide()` (or the `decide` call sites): read global mode; skip T3/T4 write-deny on global Audit.
- `dlp-hook-dll/src/trampolines.rs` — HEALTHY/DEGRADED cache-hit branches: on global Audit, fall through to the pipe round-trip instead of returning the autonomous deny.

<specifics>
## Specific Ideas

- **Required evidence (closes MODE-01's verification gap):** 55-VERIFICATION's "Audit mode returns ALLOW to DLL" row is currently proven only by an interception-path unit test (`test_compute_effective_mode_audit_overrides_block`). This phase MUST add hook-path evidence:
  - An agent hook-IPC test: global `Audit` + T3/T4 classification-cache **miss** → `offline_decision` path returns ALLOW to the DLL and emits an audit with `would_have_denied = true` and `policy_mode = Audit`.
  - A DLL fast-path test: global `Audit` in the shared-cache header + T3/T4 write cache **hit** → the autonomous deny is skipped (falls through to pipe / allow), and `Block` global still denies.
  - A control test: global `PerPolicy` + T3/T4 cache miss → still fail-closed DENY (T-17 preserved).
- The flip logic should be a single, testable expression mirroring `interception/mod.rs:423`: `let final_decision = if effective_mode.is_audit() { Decision::ALLOW } else { response.decision };`
- Reuse `compute_effective_mode` and the audit builders directly — do not re-implement mode logic or audit field construction in the hook path (DRY, per CLAUDE.md §9).

</specifics>
