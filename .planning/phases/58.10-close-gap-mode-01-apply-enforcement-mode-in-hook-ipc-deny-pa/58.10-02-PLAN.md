<objective>
Add the global enforcement mode byte to the shared-memory classification cache header so the DLL cache-hit fast-path can become mode-aware (Plan 03). This plan is the ABI/foundation half of the full-chain MODE-01 fix: it threads the global mode from the agent into the header and exposes a fail-closed reader on the DLL side, with a layout-version bump for fail-closed backward compatibility.

Purpose: CONTEXT D-10 mandates storing the global effective enforcement mode in the shared-cache header, synced from the agent. RESEARCH verified that `_reserved[0]` is safe to repurpose: the 128-byte size assertion holds, and `compute_checksum` already folds `_reserved` on BOTH writer and reader, so no checksum change is needed — only a `CACHE_LAYOUT_VERSION` bump (1->2) in both crates, which also gives fail-closed back-compat (a v1 reader rejects a v2 header).

Output: `_reserved[0]` documented as the global-mode byte in dlp-common; `CACHE_LAYOUT_VERSION=2` + a `mode_to_u8` helper + the `_reserved[0]` write in the agent's `init_header`/`build_in_buffer`; `CACHE_LAYOUT_VERSION=2` + `CacheView::global_mode()` in the DLL; ABI and DLL unit tests proving the byte survives checksum, the version bump rejects mismatched readers, and the reader defaults unrecognized values to Block.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent (writer) -> shared-memory header -> DLL (reader) | The global-mode byte is written by the agent into a shared-memory mapping that is mapped read-only into every hooked (potentially compromised) user process; the DLL reads it on the hot path. |
| v1 binary <-> v2 binary (mixed-version rollout) | During a rolling upgrade an old DLL may read a new header (or vice versa); a misread mode byte could weaken enforcement. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58.10-05 | Tampering | forged _reserved[0] mode byte in shared memory | mitigate | The mapping is SDDL-restricted (`D:(A;;GA;;;SY)(A;;GR;;;BA)` — only SYSTEM writes, Admins read) and the DLL maps `FILE_MAP_READ` only, so a non-SYSTEM process cannot write the header. Additionally `CacheView::global_mode()` defaults ANY unrecognized byte to 0 (Block) — fail-closed (ASVS V5). The byte is inside the checksummed region (compute_checksum folds _reserved on both sides), so corruption is detected by full_validation. |
| T-58.10-06 | Spoofing / Tampering | v1 reader misreads a v2 header's mode byte | mitigate | CACHE_LAYOUT_VERSION bump 1->2 in BOTH crates: a v1 reader's full_validation rejects a v2 header (layout mismatch at classification_cache.rs:236) -> all lookups miss -> fail-closed to pipe. The new byte is never misread by a mismatched binary. ABI test in Task 2 proves the rejection. |
| T-58.10-07 | Elevation of Privilege | fail-open on a stale/forged mode byte | mitigate | Fail-closed is the default at every layer: unrecognized byte -> Block (Task 3); layout mismatch -> reject header (Task 2); the DLL fast-path skip (Plan 03) only relaxes the deny when global_mode()==Audit AND the pipe is reachable so the agent emits the parity audit. |
| T-58.10-08 | Tampering | config-change race leaves a stale mode byte after a server push | mitigate | The existing signal_dacl_reinit_if_needed fires on global_enforcement_mode change -> DaclManagerCommand::Reinit -> reads cfg.enforcement.global_mode -> prepopulate_t3_t4_roots -> rebuild rewrites _reserved[0]. The sequence-lock protocol (odd/even version_word) ensures readers never see a half-written header. No new trigger/channel (D-10). |
| T-58.10-SC | Tampering | cargo installs | accept | No new packages this phase (in-tree crates only); Package Legitimacy Gate trivially satisfied per RESEARCH. |
</threat_model>
