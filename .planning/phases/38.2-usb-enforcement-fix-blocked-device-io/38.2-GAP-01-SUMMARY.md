# Plan 38.2-GAP-01: Deferred Disk-Arrival Retry for Volume-Mount Race

**500ms deferred `GUID_DEVINTERFACE_DISK` arrival processing via tokio runtime handle bridge, so volume manager mounts before drive letter lookup**

## Accomplishments
- Added `RUNTIME_HANDLE: OnceLock<tokio::runtime::Handle>` static to device_watcher.rs
- Added `set_runtime_handle()` public setter wired in service.rs before device watcher spawn
- Modified `device_watcher_wndproc` DISK arrival path to defer `on_disk_arrival` by 500ms via `handle.spawn(async move { ... })`
- Added 2 unit tests verifying handle storage and deferred spawn pattern

## Decisions Made
- 500ms chosen as a balance: long enough for volume manager to mount most USB NVMe devices, short enough that rapid plug-unplug is handled gracefully (enumerate_fixed_disks on retry will not find removed disk)
- `std::mem::drop(handle.spawn(...))` used explicitly to satisfy clippy::let_underscore_future
