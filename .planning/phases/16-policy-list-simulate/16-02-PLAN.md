# Phase 16 — Wave 2: Policy Simulate Enhancements + Planning Artifact Alignment

## Objective

Close the remaining gaps identified in the cross-AI review (16-REVIEWS.md) and align all planning artifacts with the shipped implementation. The shipped Wave 1 implementation is functional and UAT-passed. This plan:

1. **Revises planning artifacts** — Update 16-CONTEXT.md, 16-RESEARCH.md, 16-PATTERNS.md to match the 5-column shipped reality and create 16-VALIDATION.md for retrospective validation.
2. **Adds four enhancements** to the simulate screen:
   - Loading state — `SimulateOutcome::Loading` variant with visual feedback during the blocking HTTP request
   - Client-side validation — reject empty `user_sid` and `path` before hitting the server
   - Group normalization — dedupe (preserving order) + lowercase on the comma-separated groups field
   - Granular error classification — distinguish timeout, connection, decode, and server errors

**Purpose:** Improve UX and robustness of the simulate feature while ensuring all planning documents reflect the actual shipped code.
**Output:** Enhanced simulate screen with loading feedback, validation, normalized groups, precise error messages, and aligned planning artifacts.

- **Loading state (MEDIUM):** Added. The original plan specified `SimulateOutcome::Loading` but the shipped code only had `None`/`Success`/`Error`. The TUI freezes during the blocking HTTP call with no visual feedback. This plan adds the variant and renders it.
- **Advanced section dropped (MEDIUM):** The original Wave 2 plan described `timestamp_override`, `session_id_override`, and `advanced_visible` toggle. The review correctly identified these as unimplementable without server-side changes (the `/evaluate` endpoint auto-generates `timestamp` and `session_id`). These are removed from planning per review consensus.
- **Client-side validation (LOW):** Added. Empty `user_sid` and `path` are now rejected with an inline error before the server request. The original plan claimed "no client-side validation" (D-24) but the review identified this as a UX gap. This plan revises D-24 to permit validation.

    /// Builds an EvaluateRequest from the current form state, validates required fields,
    /// normalizes groups, POSTs to /evaluate, and stores the outcome.
    ///
    /// On validation failure: result = SimulateOutcome::Error("Validation error: ...").
    /// On success: result = SimulateOutcome::Success(response).
    /// On reqwest timeout: result = SimulateOutcome::Error("Timeout: ...").
    /// On reqwest connection failure: result = SimulateOutcome::Error("Connection error: ...").
    /// On reqwest decode failure: result = SimulateOutcome::Error("Decode error: ...").
    /// On server 4xx/5xx: result = SimulateOutcome::Error("Server error: ...").
    fn action_submit_simulate(app: &mut App) {
        // Clone form out of the screen to avoid borrow conflicts.
        let form = match &app.screen {
            Screen::PolicySimulate { form, .. } => form.clone(),
            _ => return,
        };

        // --- Client-side validation ---
        let mut validation_errors: Vec<String> = Vec::new();
        if form.user_sid.trim().is_empty() {
            validation_errors.push("User SID is required".to_string());
        }
        if form.path.trim().is_empty() {
            validation_errors.push("Path is required".to_string());
        }
        if !validation_errors.is_empty() {
            if let Screen::PolicySimulate { result, .. } = &mut app.screen {
                *result = SimulateOutcome::Error(format!(
                    "Validation error: {}",
                    validation_errors.join("; ")
                ));
            }
            return;
        }

        // --- Normalize groups (trim, dedupe preserving order, lowercase) ---
        let mut seen = std::collections::HashSet::new();
        let groups: Vec<String> = form
            .groups_raw
            .split(',')
            .map(|s| s.trim().to_lowercase())
            .filter(|s| {
                if s.is_empty() {
                    return false;
                }
                seen.insert(s.clone())
            })
            .collect();

        // Map select indices to typed ABAC enums.
        use dlp_common::abac::{
            AccessContext, Action, DeviceTrust, Environment, EvaluateRequest, NetworkLocation,
            Resource, Subject,
        };
        use dlp_common::Classification;

        let device_trust_vals: [DeviceTrust; 4] = [
            DeviceTrust::Managed,

        fn normalize_groups(raw: &str) -> Vec<String> {

            raw.split(',')
