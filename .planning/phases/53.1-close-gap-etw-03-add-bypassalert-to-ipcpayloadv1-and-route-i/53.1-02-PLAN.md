## Phase 53.1 — Plan 02: Route BypassAlert in Agent IPC Handler to BypassCorrelator

**Objective:** Update the agent's pipe server to deserialize `IpcEnvelope` and route `BypassAlert` payloads to the bypass correlator via a channel, while keeping `HookRequest` on the existing ABAC path. Add agent-side enrichment for hook-derived alerts. Handle legacy raw `HookRequest` frames for backward compatibility during the transition.

**Purpose:** Closes the INT-BLOCK-01 gap where hook-emitted bypass alerts are silently dropped because the agent deserializes every frame as `HookRequest`. Per D-02 (Agent Routing decision) and D-03 (BypassCorrelator entry point decision). Per REVIEW-H-01, the agent must support both envelope-wrapped and legacy raw `HookRequest` frames during the transition.

**Output:** `dlp-agent/src/hook_ipc.rs` with envelope deserialization and payload routing; `dlp-agent/src/bypass_correlator.rs` with `submit_bypass_alert` and enrichment; channel wiring in `service.rs`.

**Production wiring note:** `HookIpcServer` is NOT currently constructed in `service.rs` (there is a TODO at line 1267: "When HookIpcServer is constructed for the hook DLL IPC path..."). This plan updates the type and test wiring. The actual production startup call site will be wired in a follow-up phase (WORKFLOW-04-followup). Per REVIEW-M-06.
