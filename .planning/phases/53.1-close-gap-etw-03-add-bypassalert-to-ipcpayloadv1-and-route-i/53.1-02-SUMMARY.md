# Phase 53.1 Plan 02: Route BypassAlert in Agent IPC Handler to BypassCorrelator

**One-liner:** Agent IPC handler now deserializes IpcEnvelope, routes BypassAlert to the bypass correlator via crossbeam_channel, and preserves legacy HookRequest backward compatibility.

---

## What Was Done

### Task 1: Add submit_bypass_alert entry point with enrichment to BypassCorrelator

Added `pub async fn submit_bypass_alert(&self, mut alert: BypassAlert)` to `BypassCorrelator` in `dlp-agent/src/bypass_correlator.rs`. This method:

- Enriches hook-derived alerts with agent-side fields before batching (per REVIEW-H-03):
  - `agent_id` from `self.agent_id`
  - `severity` via `severity_for_alert()` mapping (HookOverwritten -> crit, PatchRaced -> info)
  - `correlation_reason` set to "Hook self-reported: {reason:?}"
  - `image_path` via best-effort `get_image_path_for_pid()` lookup
- Wraps enriched alert in `PendingAlert::new()` (generates fresh UUID batch_id)
- Locks `alert_batch` (tokio::sync::Mutex) and pushes the pending alert
- Does NOT trigger ETW correlation, journal lookup, or path-hash computation
- The existing batch flush task (every 5s) picks it up automatically

**Tests added:** 3 async tests replacing the Wave 0 stub:
- `test_submit_bypass_alert_batches` — verifies batch population, UUID batch_id, retry_count=0, severity mapping, correlation_reason text, and no journal/pending_journal side effects
- `test_submit_bypass_alert_severity_mapping` — verifies HookOverwritten -> crit, PatchRaced -> info
- `test_submit_bypass_alert_no_etw_correlation` — verifies journals and pending_journals remain empty after submit

### Task 2: Update handle_connection to deserialize IpcEnvelope with legacy fallback

Updated `dlp-agent/src/hook_ipc.rs` to support the new envelope protocol while preserving backward compatibility:

- Changed `handle_connection` signature to accept `bypass_tx: Option<&crossbeam_channel::Sender<BypassAlert>>`
- Added `IpcEnvelope` deserialization first, then falls back to legacy `HookRequest` (per REVIEW-H-01)
- Payload routing:
  - `IpcPayloadV1::Request(req)` -> calls handler, serializes envelope-wrapped response
  - `IpcPayloadV1::BypassAlert(alert)` -> `bypass_tx.send(alert).ok()` (best-effort; unbounded per REVIEW-M-01)
  - `IpcPayloadV1::VolumeClassQuery` -> debug log "not yet implemented, continuing" (per REVIEW-M-05)
  - `IpcPayloadV1::VolumeClassResponse` -> warning "unexpected from hook DLL"
  - `IpcPayloadV1::Response` -> warning "unexpected Response payload"
- Legacy fallback: raw `HookRequest` frames deserialize directly, raw `HookResponse` written back (NOT envelope-wrapped)
- Malformed frames: warning "neither IpcEnvelope nor legacy HookRequest" and continue

**HookIpcServer constructors added:**
- `with_bypass_channel()` — accepts bypass sender
- `with_approval_cache_and_bypass()` — full constructor with cache + approval cache + bypass

**Tests added:** 6 tests replacing the Wave 0 stub:
- `test_handle_connection_routes_bypass_alert` — verifies BypassAlert envelope serialization
- `test_handle_connection_routes_envelope_request` — verifies Request envelope round-trip
- `test_handle_connection_legacy_fallback` — verifies raw HookRequest deserialization
- `test_handle_connection_malformed_frame_logged` — verifies neither envelope nor legacy deserializes garbage
- `test_handle_connection_volume_class_response_warned` — verifies VolumeClassResponse envelope
- `test_handle_connection_volume_class_query_debug` — verifies VolumeClassQuery envelope
- `test_with_bypass_channel_constructor` — verifies constructor builds struct with bypass_tx

### Task 3: Wire BypassCorrelator to consume bypass_rx channel in run()

Updated `BypassCorrelator::run` in `dlp-agent/src/bypass_correlator.rs` and `service.rs`:

- Added `bypass_rx: Receiver<BypassAlert>` parameter to `run()`
- Added 4th spawned task inside `run()` that loops on `bypass_rx.recv()` and calls `submit_bypass_alert(alert).await`
- Wrapped blocking `recv` loop in `tokio::task::spawn_blocking` (per REVIEW-M-09, matching existing ETW/process channel pattern)
- Bridged sync recv to async via `tokio::runtime::Handle::try_current().block_on()`
- Updated `tokio::select!` to wait for any of 4 tasks to complete

Updated `dlp-agent/src/service.rs`:
- Created `crossbeam_channel::unbounded::<BypassAlert>()` pair in the bypass correlator startup block
- Passed `bypass_rx` to `correlator.run(etw_rx, process_rx, bypass_rx, sc)`
- Stored `_bypass_tx` (with underscore prefix since it's not yet wired to HookIpcServer — the production call site is TODO at line 1267 / WORKFLOW-04-followup)

**Tests added:** 2 async tests:
- `test_bypass_channel_consumed_by_run` — verifies send/recv/submit pipeline works end-to-end
- `test_bypass_channel_concurrent_with_etw` — verifies bypass alerts and ETW events can be processed concurrently without interference
