# Phase 58.1: Close v0.10.0 ship-gap verification items - Context

**Gathered:** 2026-06-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 58.1 closes the verification and integration gaps that block v0.10.0 ship readiness. It does **not** add new product capabilities — it hardens and documents the capabilities already delivered by Phases 47–58.

**What Phase 58.1 builds:**
1. **Hook DLL ETW journal writes** — ensure every mutating file operation is journaled before the OS kernel sees it, so the Phase 53 bypass correlator does not produce false-positive bypass alerts.
2. **BypassCorrelator routing fix** — wire `BypassCorrelator::run()` to consume `bypass_rx` events submitted by the hook DLL/agent over the named pipe (the Phase 53.1 `IpcPayloadV1::BypassAlert` variant).
3. **Missing VERIFICATION.md artifacts** — create auditable verification documents for v0.10.0 phases that lack them.
4. **OPS-04 UAT handoff** — produce the executable checklist/script that a human operator can run on a physical Windows 11 host; actual physical execution is outside this phase.

**What Phase 58.1 does NOT build:**
- New enforcement layers or ABAC conditions.
- New admin TUI screens.
- New server-side storage schemas.
- Automated physical-device testing (no Windows CI runner or robotic peripherals).
- New product capabilities from Phase 58 (override/diagnostic/hash/self-health) — those are in Phase 58; 58.1 only verifies/adjusts their integration.

**Depends on:** Phases 47–58 (the v0.10.0 milestone body of work).
**Requirements:** TBD / derived from ROADMAP.md success criteria.

<decisions>
## Implementation Decisions

### Hook DLL Journal Write Scope
- **D-01:** The hook DLL writes a journal entry for **all mutating file operations**: writes (`WriteFile`, `WriteFileEx`, `NtWriteFile`), deletes (`DeleteFileW`), moves/renames (`MoveFileExW`, `SetFileInformationByHandle`, `NtSetInformationFile`), and copies (`CopyFileExW`, `CopyFile2`). Pure opens/create calls that do not mutate data are not journaled.
- **D-02:** The journal entry stays **minimal**: `seq`, `file_object`, `op`, `path_hash`, `ts_qpc` (56-byte `JournalEntry` from Phase 53). Content hashes and approval override tokens are **not** duplicated in the journal; the named-pipe audit path already carries that evidence.
- **D-03:** The journal entry is written **before calling the original Win32/NT API**, regardless of whether the ABAC decision is ALLOW or DENY. This guarantees ETW cannot observe an operation the hook has not yet recorded.
- **D-04:** If the journal mapping is lost or the ring buffer cannot accept an entry, the hook **preserves the ABAC decision** and emits a `HookJournalLost`/`JournalDegraded` alert through the named pipe. It does **not** fail the operation closed, to avoid productivity loss from a journal-only fault.

### BypassCorrelator Routing Design
- **D-05:** `BypassCorrelator::run()` spawns a **dedicated tokio task** to drain `bypass_rx` (crossbeam `Receiver<BypassAlert>`). The existing single-threaded `run()` loop continues to focus on ETW-to-journal correlation.
- **D-06:** Agent/hook-submitted bypass alerts go **directly to `BypassAlertRepository::insert` / `insert_batch`** and skip ETW correlation. They carry their own `correlation_reason` set by the hook DLL (e.g., `HookOverwritten`, `HookError`).
- **D-07:** ETW-derived alerts and agent-submitted alerts share the same `bypass_alerts` table and the same SIEM/alert-router routing logic. No separate storage or schema is created.
- **D-08:** Ordering/deduplication: agent-submitted alerts use the same `batch_id` + composite-unique dedup semantics as ETW-derived alerts (WR-08 from Phase 53). Failed retries generate a new `batch_id` per attempt.

### VERIFICATION.md Scope and Template
- **D-09:** Create `VERIFICATION.md` for **every v0.10.0 phase 48–58.1** that does not already have one.
- **D-10:** Each `VERIFICATION.md` follows a **strict template**: phase goal, requirement traceability table, PASS/FAIL verdict per success criterion, evidence (test names, log excerpts, commit SHAs), and a caveats/notes section.
- **D-11:** Lightweight checklists are **not** acceptable for this ship gate. The milestone audit requires auditable evidence of each success criterion.
- **D-12:** The Phase 58.1 plan must include a discovery step that lists which phases already have `VERIFICATION.md` and which need one created.

### OPS-04 UAT Execution Split
- **D-13:** Phase 58.1 produces a **manual execution script/checklist** for OPS-04 UAT on physical Windows 11 hardware, derived from `.planning/milestones/v0.10.0-UAT.md`.
- **D-14:** Actual execution on physical hardware is **deferred to a separate manual task** outside Phase 58.1. Claude cannot operate physical devices, and fabricated evidence is unacceptable.
- **D-15:** The handoff artifact must be self-contained enough that an operator can run it without further research: exact PowerShell snippets, expected outputs, pass/fail criteria, and CRIT-04 benchmark protocol.
- **D-16:** Phase 58.1 may generate simulated/automated evidence only for portions that do not require physical hardware (e.g., unit-test coverage reports, clippy/fmt reports, build artifact hashes). Physical-device scenarios remain unexecuted and explicitly marked PENDING.

### Claude's Discretion
- Journal writes before the original API call is the safest ordering for the correlation invariant; if measurable overhead grows, revisit after profiling rather than weakening the invariant now.
- The dedicated tokio task for `bypass_rx` should use the same structured logging conventions as the rest of the correlator (`tracing::warn!` on dropped events, `metric = "bypass_rx_dropped"` counter).
- For VERIFICATION.md, reuse the same markdown table style already used in `57-VERIFICATION.md` to keep the milestone audit consistent.

</decisions>

<specifics>
## Specific Ideas

- Journal write placement: insert the write immediately after the ABAC decision is computed and before calling the original API. For `WriteFile`/`WriteFileEx`, this means before the buffer is passed to the OS; for `MoveFileExW`/`CopyFileExW`, before the path mutation occurs.
- Mutating-op classification per trampoline:
  - **Journaled**: `WriteFile`, `WriteFileEx`, `NtWriteFile`, `DeleteFileW`, `MoveFileExW`, `CopyFileExW`, `CopyFile2`, `SetFileInformationByHandle`, `NtSetInformationFile`.
  - **Not journaled**: `CreateFileW/A`, `NtCreateFile`, `NtOpenFile` (pure opens).
- If a mutating op internally calls another mutating op (e.g., `CopyFileExW` → `CreateFile` + `WriteFile`), the inner writes are also journaled by their own trampolines; this is acceptable and even desirable for correlation.
- `bypass_rx` task should log a counter `metric = "bypass_rx_processed"` per alert and `metric = "bypass_rx_dropped"` if the channel is full or the receiver is closed.
- VERIFICATION.md discovery step: produce a checklist file `.planning/phases/58.1-close-v0-10-0-ship-gap-verification-items/verification-matrix.md` listing phases 48–58.1 and whether each already has a `VERIFICATION.md`.
- OPS-04 handoff artifact: a PowerShell-driven checklist at `scripts/Uat-Execute-v0.10.0.ps1` plus a markdown companion `.planning/milestones/v0.10.0-UAT-EXECUTION.md` with the exact CRIT-04 `Measure-Command` protocol.
</specifics>
