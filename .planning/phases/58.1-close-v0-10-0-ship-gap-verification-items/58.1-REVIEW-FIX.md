## Fixed Issues

### CR-01: Hardcoded SYSTEM SID Fallback Bypasses ABAC Identity Checks

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** ba45da3
**Applied fix:** Replaced `get_process_user_sid(req.pid).unwrap_or_else(|| "S-1-5-18".to_string())` with a `match` that returns `DENY` when SID resolution fails, logging a warning. This prevents silent privilege escalation to SYSTEM on identity resolution failure.

### CR-02: Shutdown Watchdog Calls `std::process::exit(1)` — Kills Agent Without Cleanup

**Files modified:** `dlp-agent/src/service.rs`
**Commit:** c4faf70, 7a9291e
**Applied fix:** Replaced `std::process::exit(1)` with `std::process::abort()` and updated the log message to indicate threads failed to join. `abort()` triggers a core dump and is the safer last-resort escalation compared to `exit()`, which skips destructors. (Note: duplicate commit 7a9291e was an artifact of worktree recovery; the fix is present in c4faf70.)

### CR-03: JWT Signature Validation Disabled in Approval Poll Loop

**Files modified:** `dlp-agent/src/approval_cache.rs`, `dlp-agent/src/service.rs`
**Commit:** 9073839
**Applied fix:** Removed `insecure_disable_signature_validation()` and `DecodingKey::from_secret(&[])`. Added `get_decoding_key()` to `ApprovalCache` to expose the cached server public key as a `DecodingKey`. The approval poll loop now verifies EdDSA signatures using the cached key with `set_issuer(&["dlp-server"])`.

### CR-04: `resolve_proc` Passes Non-Null-Terminated Rust String to `GetProcAddress`

**Files modified:** `dlp-hook-dll/src/lib.rs`
**Commit:** 52778b5
**Applied fix:** Replaced `PCSTR::from_raw(fn_name.as_ptr())` with `CString::new(fn_name)` to ensure null termination before passing to `GetProcAddress`. This eliminates undefined behavior from reading past the end of the Rust string.

### CR-05: Stub Functions `get_creation_time_for_pid` and `get_image_path_for_pid` Return Hardcoded None/Empty

**Files modified:** `dlp-agent/src/bypass_correlator.rs`
**Commit:** 648938e
**Applied fix:** Implemented real Windows API calls:
- `OpenProcess` + `GetProcessTimes` for creation time (enables PID reuse detection)
- `OpenProcess` + `QueryFullProcessImageNameW` for image path (enables image SHA256 enrichment)
Both functions now return meaningful data instead of stubs.

### WR-01: `JournalDegraded` Alerts Are ACKed But Never Forwarded to Bypass Correlator

**Files modified:** `dlp-agent/src/hook_ipc.rs`
**Commit:** 43ee08c
**Applied fix:** In the `JournalDegraded` handler, after sending the ACK response, the alert is now forwarded to `bypass_tx` as a `BypassAlert` with `reason = BypassReason::EdrDetected` and `correlation_reason` set to the degradation error. This ensures server-side tracking of journal health.

### WR-02: Hook DLL Closes `CreateFileMapping` Handle After `MapViewOfFile`, Leaking View Lifetime Management

**Files modified:** `dlp-hook-dll/src/hook_journal.rs`
**Commit:** b5bfd70
**Applied fix:** Removed the `CloseHandle(handle)` call after `MapViewOfFile`. The mapping handle is now intentionally leaked for the process lifetime, ensuring the section object stays alive while the view is in use. Added a comment documenting this intentional leak.

### WR-03: `spawn_blocking` Bypass Handler Uses `block_on` Inside Loop — Risk of Thread Pool Exhaustion

**Files modified:** `dlp-agent/src/bypass_correlator.rs`
**Commit:** aa565c4
**Applied fix:** Replaced the `block_on` anti-pattern with a bridge:
- `spawn_blocking` task reads from `crossbeam_channel` and forwards to `tokio::sync::mpsc`
- A separate `tokio::spawn` task receives from the async channel and calls `submit_bypass_alert().await`
This avoids blocking the `spawn_blocking` thread pool and eliminates nested `block_on`.

### WR-04: `flush_batch` Uses `alerts.first().map(...).unwrap_or_default()` for batch_id — Empty Batch Panic Risk

**Files modified:** `dlp-agent/src/bypass_correlator.rs`
**Commit:** 322594b
**Applied fix:** Replaced `unwrap_or_default()` with `expect("flush_batch: alerts non-empty after early return check")`. If the batch is empty after the early-return guard, this is a logic bug and should panic immediately rather than silently sending an empty batch_id to the server.

### WR-05: `test_batch_insert_max_100` Test Name Is Misleading — Batch Size Is a Flush Boundary, Not Submission Boundary

**Files modified:** `dlp-agent/tests/bypass_rx_batch_test.rs`
**Commit:** 0af315f
**Applied fix:** Renamed `test_batch_insert_max_100` to `test_batch_insert_unbounded` to accurately reflect that the test verifies the batch Vec grows without limit, not a 100-alert submission boundary. The assertion and comment were already correct; only the function name was misleading.
