## Skipped Issues

### WR-07: Handle-Based Classification Bypasses Fail-Mode State Machine

**File:** `dlp-hook-dll/src/trampolines.rs:584-676`
**Reason:** The requested refactor would merge the handle-based classification pipeline into the path-based pipeline, including handle-to-path resolution and shared fail-mode/cache state. This is a large cross-cutting change that exceeds the safe, atomic-fix scope of this review-fix pass and is better addressed as a dedicated follow-up issue.
**Original issue:** `classify_and_log_handle` always performs a synchronous pipe round-trip and fail-closes on any error, ignoring `Degraded`/`Isolated`/`Resync` states and the shared-memory cache.

### WR-09: IAT Patching Is Performed Inside DllMain Under Loader Lock

**File:** `dlp-hook-dll/src/lib.rs:578-588`
**Reason:** Moving IAT patching out of `DllMain` requires either a safe worker-thread spawn during attach or deferral to the first trampoline invocation, both of which have broad implications for injection orchestration, shutdown ordering, and the existing active-call counter. This is deferred to a dedicated hardening issue rather than bundled into this review-fix pass.
**Original issue:** `DllMain` calls `init()` directly from `DLL_PROCESS_ATTACH`, walking and patching the IAT while the Windows loader lock is held.
