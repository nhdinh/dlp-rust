### BL-01: IAT Patching Runs Inside `DllMain` Under the Loader Lock

**Files modified:** `dlp-hook-dll/src/lib.rs`, `dlp-hook-dll/src/trampolines.rs`
**Commit:** adee7f57
**Applied fix:** Replaced the direct `init()` call from `DllMain(DLL_PROCESS_ATTACH)` with deferred initialization. `DllMain` now sets `LAZY_INIT_REQUIRED` and spawns a one-shot worker thread that performs IAT patching outside the Windows loader lock. `DllMain(DLL_PROCESS_DETACH)` waits for the init thread before calling `UnhookAll()`. A `lazy_init()` fallback was also added at the entry of `classify_and_log_path` and `classify_and_log_handle` for tests and the unlikely case where the worker thread fails to start.
**Verification:** `cargo check -p dlp-hook-dll` and `cargo clippy -p dlp-hook-dll -- -D warnings` passed.
**Note:** This is a logic change involving Windows loader-lock behavior and thread lifetime; human verification is recommended before production deployment.

### BL-02: Handle-Based Classification Bypasses Cache and Fail-Mode Logic

**Files modified:** `dlp-hook-dll/src/trampolines.rs`
**Commit:** c2aa0af3
**Applied fix:** Refactored `classify_and_log_handle` to evaluate the global `FailState` (Healthy, Degraded, Isolated, Resync) before deciding whether to round-trip the pipe, mirroring the pipeline used by `classify_and_log_path`. Pipe successes/failures now update the fail-mode counters, Degraded state uses periodic retry, Isolated state uses `decide_isolated`, and Resync flushes the LRU and retries. Because handle-to-path resolution is not yet implemented, shared-memory cache consultation is still a TODO; the function falls back to cache-less fail-mode decisions for handle-based operations.
**Verification:** `cargo check -p dlp-hook-dll` and `cargo clippy -p dlp-hook-dll -- -D warnings` passed.
**Note:** This is a logic change affecting deny/allow behavior when the agent pipe is unavailable; human verification is recommended.
