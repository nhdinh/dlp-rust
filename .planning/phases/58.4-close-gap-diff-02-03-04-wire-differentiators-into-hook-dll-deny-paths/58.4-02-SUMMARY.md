## Decisions Made

- **Used global EMITTER.emit() instead of emit_audit(ctx, event):** The handler closure in spawn_hook_ipc_server does not have access to an EmitContext. The global EMITTER singleton provides best-effort emission without blocking the IPC handler.
- **Used handle_value=0 as fallback cache key:** HookRequest does not include handle_value, so the cache lookup uses (pid, 0) as a fallback. The hook DLL sends the actual handle_value in the HashEvidence frame. Precise correlation requires a future schema change to forward handle_value in HookRequest.
- **Did not implement HandleHookRequest processing:** The agent's handle_connection does not process raw HandleHookRequest bytes (only IpcEnvelope and legacy HookRequest). This is a pre-existing architectural gap outside this plan's scope.

## Issues Encountered

- **HandleHookRequest not processed by agent:** The hook DLL's `classify_handle` sends raw `HandleHookRequest` bytes, but the agent's `handle_connection` only handles `IpcEnvelope` and legacy `HookRequest`. This means handle-based classification (used by `HookWriteFile`, `HookWriteFileEx`, `HookNtWriteFile`) does not work end-to-end. This is a pre-existing architectural gap documented in the plan's CONTEXT.md and outside the scope of this plan.
- **EmitContext unavailable in handler closure:** The `spawn_hook_ipc_server` handler closure cannot access `EmitContext` because it is constructed deep in the service startup flow. The global `EMITTER` singleton is the practical fallback for best-effort audit emission.
