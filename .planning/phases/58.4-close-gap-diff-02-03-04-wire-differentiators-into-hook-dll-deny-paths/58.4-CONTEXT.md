# Phase 58.4: Close gap DIFF-02/03/04 — wire differentiators into hook DLL deny paths - Context

**Gathered:** 2026-06-26
**Status:** Ready for planning

## Phase Boundary

Phase 58.4 is a **gap-closure phase**. The goal is to make the differentiator infrastructure built in Phase 58 actually produce real data by invoking it from the hook DLL deny paths and the consolidated hook IPC handler built in Phase 58.2.

**What Phase 58.4 builds:**
1. **DIFF-02 (Diagnostic snapshots)** — `classify_and_log_path` / `classify_and_log_handle` deny branches call `DiagnosticRing::push_snapshot` with the full decision context; `PullDiagnostics` returns non-empty snapshots.
2. **DIFF-03 (Content SHA-256 hash evidence)** — `HookWriteFile` / `HookWriteFileEx` deny branches call `hash_compute::compute_content_hash` and attach the resulting SHA-256 to the audit event / `HookResponse`.
3. **DIFF-04 (Hook DLL self-health)** — The hook DLL populates and sends `HookHealthSnapshot` to the agent health handler at regular intervals and on state transitions; the Self-Health Dashboard shows live counters.

**What Phase 58.4 does NOT build:**
- New approval workflow schema or UI (DIFF-01 wiring was handled in Phase 58.2).
- New admin TUI screens (Phase 58 already created DiagnosticList and SelfHealthDashboard).
- New server-side endpoints or SQLite schema beyond what Phase 58 already shipped.
- New ring-buffer, hash-compute, or health-counter modules (they exist; this phase wires them to deny paths).

**Depends on:** Phase 58 (differentiator modules exist), Phase 58.2 (consolidated `HookIpcServer` and ABAC handler wired).

**Requirements:** DIFF-02, DIFF-03, DIFF-04

## Implementation Decisions

### Diagnostic Snapshots (DIFF-02)
- **D-01:** Push a `DiagnosticSnapshot` on **every DENY decision** returned by `classify_and_log_path` and `classify_and_log_handle`, regardless of the intercepted operation (`WriteFile`, `CopyFileExW`, `MoveFileExW`, `DeleteFileW`, etc.). This maximizes false-positive triage value without adding ALLOW-path overhead.
- **D-02:** The snapshot must include: `hook_function`, `classification_source` (`CacheHit` / `CacheMiss` / `Pipe`), `classification_age_ms`, `abac_subject` (resolved SID), `abac_resource` (path), `abac_action`, `abac_environment` (volume class, device health), `matched_policy_id`, `enforcement_mode`, `decision_latency_us`, `timestamp_qpc`, and `user_sid`.
- **D-03:** Reuse the existing in-memory `DiagnosticRing` (1000-entry lock-free buffer). If the ring is full, silently drop the oldest entry via `ArrayQueue::push` semantics.

### Content Hash Evidence (DIFF-03)
- **D-04:** Compute SHA-256 **only for blocked `WriteFile` and `WriteFileEx`** operations. ALLOW paths and non-write DENY paths (copy/move/delete) do not hash content.
- **D-05:** Hash from the original `lpBuffer` / `nNumberOfBytesToWrite` parameters directly in the trampoline. No second file open.
- **D-06:** Apply the existing 100 MB cap: if `nNumberOfBytesToWrite > 100 MB`, hash only the first 100 MB and set `hash_truncated = true`.
- **D-07:** Use the existing 2-thread rayon hash pool. If the pool is saturated (queue depth > 4 pending hashes), skip hashing and set `hash_skipped = true`; the DENY still occurs.
- **D-08:** Attach the computed hash to the `AuditEvent` via `content_sha256`, `hash_truncated`, and `hash_skipped` fields. Because the hash is computed in the hook DLL AFTER the agent has returned the `HookResponse`, the hash cannot be returned in that response. Instead, the hook DLL sends a one-way `HashEvidence` IPC frame to the agent, which stores it in a short-lived `HashCache` keyed by `(pid, handle_value)`. When the agent constructs the `AuditEvent` for a handle-based deny, it looks up the matching hash in the cache and attaches it.

### Hook DLL Self-Health (DIFF-04)
- **D-09:** Emit a `HookHealthSnapshot` every **100 pipe round-trips** by reusing the existing `PerfTelemetry` emission cadence, plus on every `FailState` transition (`Healthy → Degraded → Isolated → Resync`).
- **D-10:** The snapshot includes: `injected_pids`, `patched_modules`, `pipe_round_trips_60s`, `cache_hit_rate_60s`, `current_fail_state`, and `timestamp_secs`.
- **D-11:** `PullHealth` returns **only the current snapshot**. The agent maintains the 12-snapshot / 12-minute rolling history in its `HealthAggregator`.
- **D-12:** Health counters are updated lock-free with `AtomicU64` / `AtomicU8`; snapshot emission resets the 60-second counters atomically.

### Consolidated Hook IPC Handler (Phase 58.2 baseline)
- **D-13:** Keep `HookResponse` minimal. Do not bloat it with diagnostic or health data. Hash data is NOT returned in `HookResponse`; it flows via the separate `HashEvidence` one-way IPC frame. Diagnostic and health data continue to be retrieved via the existing `PullDiagnostics` / `PullHealth` IPC requests.
- **D-14:** Verify that the consolidated `HookIpcServer` routes `PullDiagnostics`, `PullHealth`, and `RequestOverride` to the correct Phase 58 handlers without re-introducing duplicate initialization.

### Verification Strategy
- **D-15:** Unit tests in `dlp-hook-dll` prove: snapshot is pushed on DENY, hash matches known value for a test buffer, 100 MB truncation works, health counters increment and emit correctly.
- **D-16:** Integration tests in `dlp-agent` prove: `PullDiagnostics` returns non-empty snapshots after a DENY; `PullHealth` returns a valid snapshot; blocked write audit events contain `content_sha256`.

### Claude's Discretion
- Exact field ordering inside `DiagnosticSnapshot` and `HookHealthSnapshot` is left to the implementer; the fields listed above are the minimum required set.
- The hash pool saturation threshold (4 pending hashes) may be tuned if load testing shows contention.
- Diagnostic snapshots may be filtered by age during drain to implement the 1-hour lazy eviction; the exact eviction mechanism is left to the implementer.

## Existing Code Insights

### Reusable Assets
- `DiagnosticRing::push_snapshot` — already exists; this phase calls it from deny branches.
- `hash_compute::compute_content_hash` — already exists; this phase calls it from `HookWriteFile` / `HookWriteFileEx` deny branches.
- `HealthCounters` / `HookHealthSnapshot` — already exists; this phase populates and emits them.
- `PerfTelemetry` cadence — every 1000 calls; health snapshot cadence is reduced to every 100 pipe round-trips for fresher dashboard data.
- `HookIpcServer::with_diagnostics_handler`, `with_health_handler`, `with_override_handler` — builder methods already present from Phase 58.

### Established Patterns
- Deny paths in `trampolines.rs` return fail-closed values (`BOOL(0)`, `INVALID_HANDLE_VALUE`, `STATUS_ACCESS_DENIED`) after logging/classification.
- `AuditEvent` uses builder methods like `.with_content_hash(...)` to attach optional fields.
- Hook DLL `OnceLock`-initialized singletons must be initialized from the first trampoline invocation, never from `DllMain`.
- Agent-side aggregation uses `VecDeque` for rolling history and `DashMap` for per-DLL state.

### Integration Points
- `dlp-hook-dll/src/trampolines.rs` deny branches → `DiagnosticRing::push_snapshot`, `hash_compute::compute_content_hash`, `HealthCounters` updates.
- `dlp-hook-dll/src/pipe_client.rs` → sends `HookHealthSnapshot` and responds to `PullDiagnostics` / `PullHealth`.
- `dlp-agent/src/hook_ipc.rs` → receives diagnostic/health/override frames, routes to `DiagnosticAggregator` / `HealthAggregator` / override sender.
- `dlp-agent/src/service.rs` → assembles the consolidated `HookIpcServerConfig` with all handlers.
- `dlp-common/src/audit.rs` → carries `content_sha256` from agent to server.

## Specific Ideas

- The deny branch in `HookWriteFile` should compute the hash synchronously for buffers < 64 KiB and offload to the rayon pool for larger buffers, matching the Phase 58 research recommendation.
- Diagnostic snapshots should include the resolved volume class from the ABAC environment so operators can triage false positives caused by volume-class misclassification.
- Health snapshots should transition the agent's per-host health status to `Degraded` when `cache_hit_rate_60s < 80%` or `fail_state != Healthy`, and to `Critical` when `fail_state == Isolated` or zero pipe round-trips in 5 minutes.

## Deferred Ideas

- User-facing diagnostic screen (self-service false-positive triage) — future operational-efficiency phase.
- Cross-endpoint health aggregation (fleet-wide hook health view) — future fleet-management phase.
- Content hashing for ALLOW decisions — deferred; only blocked writes are hashed for v0.10.0.
- SHA-512 hash option — deferred; SHA-256 is sufficient for v0.10.0 forensic needs.
- Diagnostic data persistence to SQLite or SIEM long-term storage — deferred; in-memory only for v0.10.0.
