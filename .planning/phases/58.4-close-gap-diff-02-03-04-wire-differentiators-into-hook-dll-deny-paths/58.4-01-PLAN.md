Wire diagnostic snapshot capture into every DENY branch of classify_and_log_path and classify_and_log_handle so that each blocked file operation produces a full decision-context snapshot in the lock-free DiagnosticRing. Agent-side PullDiagnostics must return non-empty snapshots.

Purpose: DIFF-02 requires operational visibility into why the hook DLL denied an operation. Without snapshots, administrators cannot triage false positives or audit policy decisions.
Output: deny branches that populate DiagnosticSnapshot and push it to the ring; agent-side routing verified.
</objective>

  <name>Task 1: Implement get_current_user_sid() helper in dlp-hook-dll/src/sid.rs</name>
  <files>dlp-hook-dll/src/sid.rs</files>
  <action>
    Per D-02, DiagnosticSnapshot requires a user_sid field. No existing helper resolves the current process SID.

    Create a new file dlp-hook-dll/src/sid.rs that exports:
    ```rust
    pub fn get_current_user_sid() -> String
    ```

    Implementation steps:
    1. Call OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY) to obtain a process token handle.
    2. Call GetTokenInformation(token, TokenUser, ...) to retrieve the TOKEN_USER structure. Use a two-pass approach: first call with null buffer to get required size, allocate a Vec<u8> of that size, then call again.
    3. Cast the buffer pointer to PTOKEN_USER and read the User.Sid field.
    4. Call ConvertSidToStringSidA(sid, &mut string_ptr) to obtain a C-string SID.
    5. Convert the C-string to a Rust String, free it with LocalFree, close the token handle, and return the string.
    6. If any step fails, return "S-1-5-18" (SYSTEM) as a safe fallback.

    Add the module to dlp-hook-dll/src/lib.rs (mod sid; pub use sid::get_current_user_sid;).

    Use windows-rs types: windows::Win32::Security::Authentication::Identity::ConvertSidToStringSidA, windows::Win32::Security::GetTokenInformation, windows::Win32::Security::TOKEN_QUERY, windows::Win32::System::Memory::LocalFree, windows::Win32::Foundation::CloseHandle, windows::Win32::System::Threading::GetCurrentProcess, windows::Win32::Security::OpenProcessToken.

    Ensure all unsafe blocks have SAFETY comments explaining the invariant.
  </action>
  <verify>
    <automated>cargo test -p dlp-hook-dll --lib -- sid::tests --nocapture</automated>
  </verify>
  <done>
    - get_current_user_sid() returns a non-empty SID string on Windows.
    - On failure, returns "S-1-5-18" fallback.
    - Unit test verifies the returned string starts with "S-1-".
  </done>

    Per D-02, the snapshot must include:
    - hook_function: fn_name.to_string()
    - classification_source: CacheHit if cache_classification.is_some(), otherwise Pipe (CacheMiss is not used here because CacheMiss leads to a pipe round-trip; use Pipe for pipe-based decisions)
    - classification_age_ms: 0 for now (cache age not tracked in this closure; acceptable per D-02 discretion. Documented as deferred limitation — see Deferred Ideas below)
    - abac_resource: path.to_string()
    - abac_action: action.to_string()
    - abac_environment: format!("{:?}", source_volume_class) (or "unknown" if None)
    - matched_policy_id: None (not available in hook DLL without pipe response parsing; acceptable per D-02. Documented as deferred limitation)
    - enforcement_mode: None (same reason)
    - decision_latency_us: elapsed_qpc converted to microseconds (use qpc_to_us helper or approximate; if QPC frequency unavailable, store elapsed_qpc as-is and document)
    - timestamp_qpc: current QPC value from crate::perf_telemetry::query_performance_counter() or equivalent
    - user_sid: resolved from current process token via crate::sid::get_current_user_sid()

    Call crate::diagnostic_ring::push_snapshot(snapshot) after construction.

    The snapshot push is fire-and-forget: it must never block, panic, or alter the deny decision. Wrap in a let _ = ... to ignore Result.
