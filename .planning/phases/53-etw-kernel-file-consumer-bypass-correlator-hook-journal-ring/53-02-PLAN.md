    5. Define `#[repr(C, align(8))] pub struct JournalEntry` with fields:
       - `seq: u64` — monotonic sequence number
       - `handle_value: u64` — HANDLE value from trampoline
       - `op: u8` — operation type (1=Create, 2=Write, 3=Delete, 4=SetInfo)
       - `_pad: [u8; 7]` — padding
       - `path_hash: u64` — FNV-1a 64-bit of normalized path
       - `ts_qpc: u64` — QueryPerformanceCounter timestamp
       - `etw_timestamp: u64` — ETW timestamp in 100ns units (for correlation forensics)
       Total: 56 bytes. Addresses review concern CR-05.

    6. Define `pub struct HookJournal` with fields:
       - `header: *mut JournalHeader`
       - `entries: *mut JournalEntry`
       - `capacity: usize`
       - `next_seq: u64`

    7. Implement `HookJournal::try_init() -> Option<HookJournal>` (unsafe):
       - Build name: `format!("Global\\DlpHookJournal_{}", std::process::id())`
       - Call `CreateFileMappingW` with:
         - `INVALID_HANDLE_VALUE` (pagefile-backed)
         - null security attributes (default descriptor per D-01)
         - `PAGE_READWRITE`
         - size = JOURNAL_SIZE
         - name = formatted wide string
       - If `CreateFileMappingW` succeeds: call `MapViewOfFile` with `FILE_MAP_ALL_ACCESS`
       - If `CreateFileMappingW` fails with `ERROR_ALREADY_EXISTS`:
         - Call `OpenFileMappingW(FILE_MAP_ALL_ACCESS, ...)` to open the EXISTING mapping
         - If open succeeds: call `MapViewOfFile` with `FILE_MAP_ALL_ACCESS`
         - If open fails: return None per D-25
       - If mapping fails: return None per D-25
       - Initialize header: version=1, write_index=0
       - Return `HookJournal { header, entries, capacity: ENTRY_CAPACITY, next_seq: 1 }`
       - Addresses review concern CR-04: ERROR_ALREADY_EXISTS falls through to OpenFileMappingW.

    8. Implement `pub fn journal_write(handle_value: u64, op: u8, path: &str, ts_qpc: u64, etw_timestamp: u64)`:
       - Get journal via `JOURNAL.get_or_init(|| unsafe { HookJournal::try_init() })`
       - If None, return silently per D-25
       - Compute `path_hash = dlp_common::path_hash::fnv1a_64(path.as_bytes())`
       - Read current `write_index` with `Ordering::Relaxed`
       - Compute slot index: `write_index as usize % capacity`
       - Write entry fields via `ptr::write_volatile` for each field (seq, handle_value, op, path_hash, ts_qpc, etw_timestamp)
       - Increment `next_seq`
       - **CRITICAL:** Add `std::sync::atomic::fence(Ordering::Release)` AFTER all write_volatile calls and BEFORE the write_index store
       - Store `write_index.wrapping_add(1)` with `Ordering::Release`
       - Document in SAFETY comment:
         ```rust
         // SAFETY: SPSC ring buffer. Write entry fields first via write_volatile,
         // then Release fence publishes them to the consumer before the write_index
         // bump. The consumer reads write_index with Acquire, then reads the entry.
         // This ensures the consumer never sees a new write_index with stale entry data.
         ```
       - Addresses review concern CR-03: Release fence prevents CPU-level reordering on ARM64.

    9. Implement `pub fn journal_write_from_trampoline(handle_value: u64, op: u8, path: &str)`:
       - Calls `QueryPerformanceCounter` to get current QPC timestamp
       - Calls `journal_write(handle_value, op, path, ts_qpc, etw_timestamp=0)`
       - `etw_timestamp=0` because the hook DLL does not have access to ETW timestamps; the correlator uses QPC for matching

    10. Add `static JOURNAL: OnceLock<Option<HookJournal>> = OnceLock::new();`

    11. In `dlp-hook-dll/src/lib.rs`, add `mod hook_journal;` after existing module declarations.

    Per D-25: ALL failure paths in `try_init()` must return None silently. Never panic, never log error. A single `debug_log` on successful init is acceptable.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hook DLL -> shared memory | Producer writes with PAGE_READWRITE; consumer (agent) opens with FILE_MAP_READ only |
| Trampoline -> journal write | Every file operation crosses this boundary; must not crash host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-05 | Denial of Service | Journal creation failure crashes host | mitigate | Silent continue (return None) per D-25; hook operates without journaling |
| T-53-06 | Tampering | Attacker overwrites journal to hide bypass | mitigate | Agent opens with FILE_MAP_READ only; DLL writes with PAGE_READWRITE in its own address space |
| T-53-07 | Information Disclosure | Journal contains path hashes | accept | Path hashes are one-way (FNV-1a); no reversible path data in journal |
| T-53-08 | Denial of Service | Journal fills and overwrites old entries | accept | Ring buffer design; old entries overwritten naturally; correlator reads behind write_index |
| T-53-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] |
</threat_model>
