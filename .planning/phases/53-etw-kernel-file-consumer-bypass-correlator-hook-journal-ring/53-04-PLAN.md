<objective>
Implement the bypass correlator that matches ETW Kernel-File events against hook DLL journal entries within +/-5ms QPC tolerance. When no matching journal entry is found, the correlator constructs a BypassAlert with severity mapped by correlation reason and protected path status, batches alerts with UUID batch_id and retry tracking, and flushes them to the server via POST /audit/bypass.

Addresses review concerns: CR-01 (QPC calibration pair), CR-02 (on-demand journal discovery), CR-05 (file_object from ETW), WR-01 (exact filename allowlist), WR-03 (cap crit->warn not info), WR-04 (version field), WR-06 (SHA cache TTL), WR-07 (PID reuse), WR-08 (retry limit + dedup), IN-01 (stub_name doc), IN-02 (batch_id).

Purpose: Turn hook-vs-ETW divergence into auditable bypass alerts that route through SIEM and the alert router.
Output: `bypass_correlator.rs` module with `BypassCorrelator` struct, `JournalReader` type, alert batching with retry limits, and flush task.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ETW event -> correlator | Kernel-generated events enter user-mode; must validate fields |
