<objective>
Implement the ETW Kernel-File consumer module that subscribes to Microsoft-Windows-Kernel-File events via ferrisetw 1.2.0, parses CREATE/WRITE/DELETE_PATH/OP_END events, and pushes them through a crossbeam channel for downstream correlation. This is the detection backbone that sees file operations the hook DLL may have missed.

Purpose: Provide real-time kernel-level file operation telemetry that the bypass correlator (Plan 04) will compare against hook DLL journal entries.
Output: `etw_kernel_file.rs` module with `EtwKernelFileConsumer` struct, `EtwFileEvent` type, `FileOp` enum, and full ProcessWatcher-mirroring architecture.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ETW callback -> crossbeam channel | Untrusted kernel callback pushes to user-mode channel; must not block or panic |
| Agent service -> ETW session | Requires SeSystemProfilePrivilege; agent runs as SYSTEM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | Denial of Service | ETW callback blocking | mitigate | Callback only parses and pushes to channel; all correlation work happens in tokio task per D-15 |
| T-53-02 | Information Disclosure | FileName field in ETW events | accept | File paths are metadata only; no file content in ETW events |
| T-53-03 | Denial of Service | Channel overflow under stress | mitigate | Bounded channel with overflow counter; lost-event monitoring alerts operator |
| T-53-04 | Tampering | ETW session stopped by attacker | mitigate | Agent restart recreates session; missing ETW events detected by correlator (no events = no bypass detection, but DACL tripwire still protects) |
</threat_model>
