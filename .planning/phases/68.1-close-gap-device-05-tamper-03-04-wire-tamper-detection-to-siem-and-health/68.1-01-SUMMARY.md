# Plan 68.1-01 Summary

## Phase

68.1-close-gap-device-05-tamper-03-04-wire-tamper-detection-to-siem-and-health

## Plan

01

## Objective

Close the server-side gaps for DEVICE-05 and TAMPER-03 by:
1. Extending the `POST /audit/events` response to report chain-break detection back to the requesting agent.
2. Routing synthetic `ChainBreakDetected` events to both SIEM relay and syslog queue.

## Tasks Completed

### Task 1: Extend server ingest response with tamper detection flag

- Added `IngestEventsResponse` struct (Serialize) with `tamper_detected_for_agent: Option<String>` and `chain_break_count: usize`.
- Changed `ingest_events` return type from `Result<StatusCode, AppError>` to `Result<(StatusCode, Json<IngestEventsResponse>), AppError>`.
- `tamper_detected_for_agent` is populated when at least one chain break in the batch belongs to the requesting agent (derived from the first event's `agent_id`).
- `chain_break_count` is the deduplicated count per `(agent_id, ChainBreakReason)`.
- Added 3 unit tests:
  - `test_ingest_response_contains_tamper_flag` — valid batch returns `None` and `0`.
  - `test_ingest_response_tamper_flag_for_same_agent` — broken batch returns `Some(agent-x)` and `1`.
  - `test_ingest_response_other_agent_break` — break for different agent returns `None`.

### Task 2: Route synthetic ChainBreakDetected events to SIEM and syslog

- Refactored `spawn_blocking` closure to return `Result<Vec<AuditEvent>, AppError>` containing the deduplicated synthetic `ChainBreakDetected` events.
- `relay_events` extended with `synthetic_events.clone()` before the SIEM relay spawn.
- `syslog_events` extended with `synthetic_events.clone()` before the syslog queue spawn.
- The `alert_router` spawn block is unchanged — it already receives its own synthetic events from `chain_breaks`.
- Added unit test `test_synthetic_events_in_relay_list` verifying synthetic events are persisted.

### Task 3: Agent-side IngestResponse type and send_audit_events return type

- Added `IngestResponse` struct (Deserialize, Default) with `#[serde(default)]` on both fields for backward compatibility with older server builds.
- Changed `send_audit_events` return type from `Result<(), ServerClientError>` to `Result<IngestResponse, ServerClientError>`.
- Changed `send_audit_events_json` return type from `Result<(), ServerClientError>` to `Result<IngestResponse, ServerClientError>`.
- Updated `AuditBuffer::flush` to check `response.tamper_detected_for_agent == Some(self.client.agent_id())` and call `crate::device_identity::report_tamper_detected()` with `tracing::error!` logging when matched.
- Updated `offline.rs` drain loop to handle the new return type.
- Added 5 unit tests:
  - `test_ingest_response_deserialization_full` — all fields present.
  - `test_ingest_response_deserialization_missing_fields` — empty JSON (backward compat).
  - `test_ingest_response_deserialization_partial` — only `chain_break_count` present.
  - `test_send_audit_events_empty_returns_default` — empty slice returns default.
  - `test_send_audit_events_json_empty_returns_default` — empty JSON slice returns default.

## Decisions

1. `#[serde(default)]` on all new `IngestResponse` fields ensures backward compatibility with older server builds that return an empty body or omit the new fields.
2. `requesting_agent_id` is derived from the first event's `agent_id` in the batch (not JWT claims), matching the existing convention where the batch is homogeneous per-agent.
3. `chain_break_count` is deduplicated per `(agent_id, ChainBreakReason)` to match the deduplication applied to synthetic event persistence, ensuring consistency between the response count and the number of synthetic events generated.
