# 49-02 — Server-Side Allowlist: SQLite Schema + Repository + Admin API

## Objective

Build the server-side persistence and admin API for process allowlist entries. Operators can CRUD allowlist entries via `/admin/allowlist` endpoints. The agent polls these entries through the existing config sync mechanism (extended in Plan 49-04).

## Background (from Reviews)

Cross-AI review identified these MEDIUM-priority gaps:
1. **No audit/version semantics**: Operator allowlist changes are security-sensitive. Need audit events, actor identity, optimistic concurrency, and monotonically increasing config version for agents.
2. **Schema lacks glob semantics**: `path` field is ambiguous — need explicit `match_type` with validation per type.
3. **No normalization**: Windows paths are case-insensitive; need canonicalization.
4. **cert_subject substring is weak**: Prefer thumbprint over subject substring.
5. **No precedence/conflict resolution**: Overlapping rules need deterministic ordering.
6. **No "disabled" flag**: Hard delete is unsafe for ops.

All concerns are addressed in this revised plan.

<must_haves>
- `allowlist_entries` table with `match_type`, `value`, `category`, `priority`, `enabled`, `version`
- Admin audit table `allowlist_audit_log` tracking create/update/delete with actor, old/new values
- Config version monotonically increases on every mutation (agents use for cheap change detection)
- CRUD endpoints: GET /admin/allowlist, POST /admin/allowlist, GET /admin/allowlist/:id, PUT /admin/allowlist/:id, DELETE /admin/allowlist/:id
- Validation: match_type enum, non-empty value, valid category
- Optimistic concurrency via `version` field (ETag-style)
</must_haves>

### Task 1: Create allowlist_entries table in dlp-server/src/db/mod.rs

**Files:** dlp-server/src/db/mod.rs

**Action:**
Add to `init_tables()`:

```sql
CREATE TABLE IF NOT EXISTS allowlist_entries (
    id          TEXT PRIMARY KEY,
    match_type  TEXT NOT NULL CHECK(match_type IN ('exact_path', 'path_glob', 'path_prefix', 'cert_subject', 'cert_thumbprint')),
    value       TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    category    TEXT NOT NULL CHECK(category IN ('self', 'avedr', 'system_critical', 'operator_defined')),
    priority    INTEGER NOT NULL DEFAULT 100,
    enabled     INTEGER NOT NULL DEFAULT 1,
    version     INTEGER NOT NULL DEFAULT 1,
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_allowlist_category ON allowlist_entries(category);
CREATE INDEX IF NOT EXISTS idx_allowlist_enabled ON allowlist_entries(enabled);
CREATE INDEX IF NOT EXISTS idx_allowlist_version ON allowlist_entries(version);
```

Add audit log table:
```sql
CREATE TABLE IF NOT EXISTS allowlist_audit_log (
    id          TEXT PRIMARY KEY,
    entry_id    TEXT NOT NULL,
    action      TEXT NOT NULL CHECK(action IN ('create', 'update', 'delete', 'enable', 'disable')),
    actor       TEXT NOT NULL,
    old_value   TEXT,
    new_value   TEXT,
    timestamp   TEXT NOT NULL,
    FOREIGN KEY (entry_id) REFERENCES allowlist_entries(id)
);
CREATE INDEX IF NOT EXISTS idx_allowlist_audit_entry ON allowlist_audit_log(entry_id);
```

use rusqlite::{params, OptionalExtension};

    pub enabled: bool,

    pub fn create(uow: &UnitOfWork<'_>, row: &AllowlistEntryRow) -> rusqlite::Result<()> { ... }

### Task 3: Add /admin/allowlist CRUD endpoints

**Files:** dlp-server/src/admin_api.rs

**Action:**
Add routes to the admin router:

```rust
.route("/admin/allowlist", get(list_allowlist).post(create_allowlist_entry))
.route("/admin/allowlist/:id", get(get_allowlist_entry).put(update_allowlist_entry).delete(delete_allowlist_entry))
.route("/admin/allowlist/:id/disable", post(disable_allowlist_entry))
.route("/admin/allowlist/:id/audit", get(list_allowlist_audit))
```

Implement handlers:
- `list_allowlist`: Returns all enabled entries + current_version header
- `create_allowlist_entry`: Validates match_type, value, category; sets version = current_version + 1; logs audit
- `get_allowlist_entry`: Returns single entry
- `update_allowlist_entry`: Validates input; checks version for optimistic concurrency (if client sends `If-Match: <version>`); increments version; logs audit with old/new values
- `delete_allowlist_entry`: Hard delete (admin only); logs audit
- `disable_allowlist_entry`: Soft-disable (sets enabled=0); logs audit
- `list_allowlist_audit`: Returns audit log for an entry

Request/response types:
