# Phase 54 — Admin TUI Protected Paths + Bypass Alerts Screens

> Visual and interaction contract for Phase 54 TUI screens. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This is a **ratatui 0.29 + crossterm 0.28** terminal UI phase — no web stack, no shadcn.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (TUI) |
| Preset | not applicable |
| Component library | ratatui 0.29 widgets (Table, List, Paragraph, Block, Clear) |
| Icon library | text glyphs only (`> ` highlight symbol, `[A]`/`[M]` badges) |
| Font | terminal monospace (inherited from host terminal) |

## Spacing Scale

TUI spacing is implicit via widget borders and layout constraints. No explicit pixel spacing tokens are used.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 0 | No internal padding in table cells |
| sm | 1 cell | Border thickness, inter-cell gaps |
| md | 1 line | Header bottom margin, hint bar separation |
| lg | 2 lines | Block title padding, section breaks |

Exceptions: Table cell widths use `Constraint::Percentage` for responsive distribution.

---

## Typography

Terminal UI uses the host terminal font. All text is rendered via ratatui `Span`/`Line`/`Text` with explicit styles.

| Role | Style | Modifier |
|------|-------|----------|
| Body | default fg (White) | none |
| Label | default fg (White) | BOLD |
| Heading / Title | White | BOLD |
| Display (badges) | per semantic color | BOLD for severity |

---

## Color

All colors are ratatui `Color` enum values. The TUI background is the terminal default (typically black).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Color::Black` (terminal default bg) | Screen background, table fill |
| Secondary (30%) | `Color::DarkGray` | Dimmed/acknowledged rows, auto-derived entries, hints |
| Accent (10%) | `Color::Cyan` | Row highlight background, selected menu items |
| Destructive | `Color::Red` | Errors, T4 tier, crit severity, delete confirmations |

Semantic colors (not part of 60/30/10, but fixed by convention):

| Semantic | Color | Usage |
|----------|-------|-------|
| Success | `Color::Green` | Success toasts, approved status |
| Warning | `Color::Yellow` | T3 tier, warn severity, pending status |
| Info | `Color::Blue` | info severity |
| Manual source | `Color::Cyan` (bright) | `[M]` badge for manual protected paths |
| Auto source | `Color::DarkGray` | `[A]` badge for auto-derived protected paths |

Accent reserved for: row highlight background only (`Color::Black` fg on `Color::Cyan` bg with BOLD).

## Screens

### Screen 1: ProtectedPathList

**Layout:** Full-screen scrollable table with title block, header row, data rows, and footer hints.

**Widget types:**
- `Block` — titled border: `" Protected Paths ({count}) "`
- `Table` + `TableState` — scrollable list with row selection
- `Row` — each row is a 4-column table row
- `Paragraph` (fallback) — empty state centered message

**Columns (left to right):**

| Column | Width | Content | Style Rules |
|--------|-------|---------|-------------|
| Source | 8 chars | `[A]` or `[M]` | `[A]` = `DarkGray`, `[M]` = `Cyan` (bright) |
| Path | 45% | Full or truncated path | Truncate at 40 chars with `...` suffix |
| Tier | 10% | `T3` or `T4` | `T3` = `Yellow`, `T4` = `Red` + BOLD |
| Label ID | remaining | `label_id` or `-` | default White |

**Title suffixes:** None (no filter on this screen).

**Footer:** `PROTECTED_PATH_LIST_HINTS` + ` | Page {N} of {M}`.

**Navigation flow:**
- SystemMenu (index 10) -> Enter -> ProtectedPathList
- ProtectedPathList -> `a` -> TextInput (AddProtectedPath)
- ProtectedPathList -> `d` on manual entry -> Confirm (DeleteProtectedPath)
- ProtectedPathList -> `s` -> sync action (stays on list, toast)
- ProtectedPathList -> `r` / PgUp / PgDn -> reload / page
- ProtectedPathList -> Esc -> SystemMenu (index 10)
- TextInput -> Enter (submit) -> ProtectedPathList (refreshed)
- TextInput -> Esc -> ProtectedPathList (no refresh)
- Confirm -> Enter (yes) -> ProtectedPathList (refreshed)
- Confirm -> Esc / Enter (no) -> ProtectedPathList

### Screen 2: BypassAlertList

**Layout:** Full-screen scrollable table with title block (including active filter suffixes), header row, data rows, and footer hints.

**Widget types:**
- `Block` — titled border with filter indicators
- `Table` + `TableState` — scrollable list with row selection
- `Paragraph` (fallback) — empty state centered message

**Columns (left to right):**

| Column | Width | Content | Style Rules |
|--------|-------|---------|-------------|
| Severity | 10% | `crit`/`warn`/`info` | `crit` = `Red`+BOLD, `warn` = `Yellow`, `info` = `Blue` |
| Time | 12% | Relative timestamp | e.g. "2m ago", default White |
| Image Path | 28% | Truncated image_path | Truncate at 25 chars with `...` suffix |
| File Path | 28% | Truncated file_path | Truncate at 25 chars with `...` suffix |
| Reason | 22% | Human-friendly correlation reason | default White; ack'd rows = `DarkGray` |

**Human-friendly correlation_reason mapping:**
- `NoHookJournal` -> `"No Hook Journal"`
- `OpMismatch` -> `"Operation Mismatch"`
- `HookOverwritten` -> `"Hook Overwritten"`
- unknown -> raw value

**Title suffixes:**
- Severity filter active: `" [Severity: {crit|warn|info}]"`
- Hide-acknowledged active: `" [Hide Ack'd]"`

**Footer:** `BYPASS_ALERT_LIST_HINTS` + ` | Page {N} of {M} ({total} total)`.

**Acknowledged row styling:** All cells in an ack'd row use `Color::DarkGray` fg.

**Navigation flow:**
- SystemMenu (index 11) -> Enter -> BypassAlertList
- BypassAlertList -> `a` -> optimistic ack (stays on list, toast)
- BypassAlertList -> `f` -> cycle severity filter + reload page 1
- BypassAlertList -> `h` -> toggle hide-acknowledged + reload page 1
- BypassAlertList -> `r` / PgUp / PgDn -> reload / page
- BypassAlertList -> Enter on row -> BypassAlertDetail
- BypassAlertList -> Esc -> SystemMenu (index 11)
- BypassAlertDetail -> Enter / Esc -> BypassAlertList (preserves list state)

| T3 tier text | Yellow | inherited | none |
| T4 tier text | Red | inherited | BOLD |
| `crit` severity | Red | inherited | BOLD |
| `warn` severity | Yellow | inherited | none |
| `info` severity | Blue | inherited | none |
| Error toast | Red | inherited | none |
| Success toast | Green | inherited | none |
| Info toast | White | inherited | none |
| Hints bar | DarkGray | inherited | none |

### Typography Rules

- All table headers use `Modifier::BOLD` with `bottom_margin(1)`.
- Path truncation: max 40 chars display, suffix `...` if truncated.
- SHA-256 display: first 16 chars + `...` in list; first 16 chars + ellipsis + full value on second line in detail.
- `file_object` display: formatted as `0x{uppercase_hex}` (e.g., `0x00007FF6A1B2C3D4`).

### Spacing Rules

- Table block has `Borders::ALL`.
- Header row has `bottom_margin(1)` for visual separation.
- Hints are drawn at the bottom of the screen via `draw_hints()` (shared helper).
- Empty state is centered with `Alignment::Center`.

## Interactions

### Keyboard Shortcuts — ProtectedPathList

| Key | Action | Guard |
|-----|--------|-------|
| Up / Down | Navigate selection | Only if list non-empty |
| `a` | Add new path (TextInput) | Always |
| `d` | Delete selected (Confirm) | Only if `source == "manual"` |
| `s` | Sync policy-derived paths | Always |
| `r` | Refresh list (current page) | Always |
| PgUp | Previous page | Only if `page > 0` |
| PgDn | Next page | Only if more pages exist |
| Esc | Back to SystemMenu | Always |

### Keyboard Shortcuts — BypassAlertList

| Key | Action | Guard |
|-----|--------|-------|
| Up / Down | Navigate selection | Only if list non-empty |
| `a` | Ack selected alert | Only if not already ack'd |
| `f` | Cycle severity filter + reload | Always (resets to page 1) |
| `h` | Toggle hide-acknowledged + reload | Always (resets to page 1) |
| `r` | Refresh list (current page) | Always |
| PgUp | Previous page | Only if `page > 0` |
| PgDn | Next page | Only if more pages exist |
| Enter | Open detail view | Only if list non-empty |
| Esc | Back to SystemMenu | Always |

### Keyboard Shortcuts — BypassAlertDetail

| Key | Action |
|-----|--------|
| Enter / Esc | Return to BypassAlertList |

### Confirmation Flows

**Delete Protected Path:**
1. Operator presses `d` on a manual entry.
2. TUI checks `source == "manual"`. If auto, shows error toast: `"Only manual entries can be deleted"`.
3. If manual, transitions to `Screen::Confirm` with `ConfirmPurpose::DeleteProtectedPath { id }`.
4. Confirm message: `"Delete protected path '{path}'?"`.
5. Operator selects Yes + Enter -> `action_delete_protected_path()` -> reload list -> success toast.
6. Operator selects No / Esc -> return to ProtectedPathList without reload.

### Optimistic UI Behavior

**Ack Bypass Alert:**
1. Operator presses `a` on an unacknowledged alert.
2. TUI immediately sets `alert["acknowledged"] = true` in local state and re-renders (row dims).
3. TUI shows success toast: `"Alert acknowledged"`.
4. TUI calls `ack_bypass_alert(id)` asynchronously (via `block_on`).
5. On server error: revert local `acknowledged` to `false`, show error toast: `"Failed to acknowledge alert: {error}"`.

## Responsive Behavior

### Terminal Size Adaptation

| Scenario | Behavior |
|----------|----------|
| Width < 80 cols | Path columns truncate more aggressively; table may clip right edge |
| Width < 60 cols | Minimum viable width; some columns overlap — acceptable degradation |
| Height < 10 rows | Table renders with scrollable area; header + at least 3 data rows visible |
| Height < 5 rows | Not supported; ratatui will clip content |

| Field | Max Display | Suffix | Minimum Width |
|-------|-------------|--------|---------------|
| Path (Protected Paths) | 40 chars | `...` | 20 chars |
| Image Path (Alerts list) | 25 chars | `...` | 10 chars |
| File Path (Alerts list) | 25 chars | `...` | 10 chars |
| SHA-256 (detail) | 16 chars | `...` | 16 chars |
| SID / long identifiers | 30 chars | `...` | 15 chars |

## Accessibility

### Keyboard-Only Operation

- All actions reachable without mouse (inherent to TUI).
- Navigation uses arrow keys, letter keys, Enter, Esc, PgUp/PgDn.
- No action requires more than 2 keypresses from list state.

### Focus Indicators

- Selected row: `Color::Black` fg on `Color::Cyan` bg with `Modifier::BOLD`.
- Highlight symbol: `> ` prefix on selected row.
- Menu items: same cyan highlight pattern.

### Color-Independent Cues

- Source badges use explicit text `[A]` and `[M]`, not color alone.
- Severity uses text labels (`crit`, `warn`, `info`), not color alone.
- Tier uses text labels (`T3`, `T4`), not color alone.
- Acknowledged state uses dimmed text + can be filtered; not color-only.

| Scenario | Toast Style | Message Pattern |
|----------|-------------|-----------------|
| Load failed | Error (Red) | `"Error loading protected paths: {error}"` |
| Add failed | Error (Red) | `"Error adding protected path: {error}"` |
| Delete failed | Error (Red) | `"Error deleting protected path: {error}"` |
| Sync failed | Error (Red) | `"Error syncing protected paths: {error}"` |
| Alert load failed | Error (Red) | `"Error loading bypass alerts: {error}"` |
| Ack failed | Error (Red) | `"Failed to acknowledge alert: {error}"` |

### Validation Error Display

- Path validation happens server-side. TUI shows server's 400 response body as error toast.
- No inline validation in TextInput; empty input is blocked client-side with toast `"Input cannot be empty"`.

## Loading States

### Async Operation Behavior

| Operation | UI Behavior | Duration Indicator |
|-----------|-------------|-------------------|
| List load (initial) | Screen transitions to list with empty vec; `block_on` blocks render briefly | None (synchronous feel) |
| List refresh (`r`, PgUp, PgDn) | Same screen, data updates in-place after `block_on` | None |
| Add path | TextInput -> `block_on` POST -> transition back to list | None |
| Delete | Confirm -> `block_on` DELETE -> reload list | None |
| Sync | `block_on` POST -> toast with count -> list refresh | None |
| Ack | Optimistic update immediately, `block_on` in background | None |

### Blocking Behavior

All HTTP calls use `app.rt.block_on()` which blocks the TUI event loop. This is the established project pattern. The UI does not show spinners or progress bars for these operations — they are expected to complete in <1s on a local network.
