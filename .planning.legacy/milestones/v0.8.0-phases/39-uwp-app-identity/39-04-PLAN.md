# Plan 39-04: Audit Enrichment and Cross-Crate Integration

## Objective

Ensure the extended `AppIdentity` with UWP fields flows correctly through all interception paths: clipboard, file, USB, and browser. Update audit enrichment to populate the new fields.

## Background

`dlp-agent/src/audit_emitter.rs` has `get_application_metadata(pid)` which currently uses `GetModuleFileNameExW` to get the image path. For UWP processes, this returns the proxy path. We need to ensure audit events include the AUMID when available.

The clipboard monitor in `dlp-user-ui` already calls `resolve_app_identity()` which now populates UWP fields. Audit events from clipboard interception will automatically include AUMID.

Browser interception (Chrome Enterprise Connector) passes origin information, not process identity. No changes needed there.

USB interception doesn't involve application identity at the device level. No changes needed.

File interception in `dlp-agent` may need audit enrichment updates.

<action>
In `dlp-agent/src/audit_emitter.rs`, review `get_application_metadata(pid)`:

Currently it likely does:
```rust
OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION) -> GetModuleFileNameExW -> image_path
```

This function returns only the image path. It does NOT return a full `AppIdentity`. Check how the caller uses this metadata.

If `get_application_metadata` is used to populate `source_application`/`destination_application` in `AuditEvent`, verify that the caller constructs an `AppIdentity` from the returned path. In that case, the UWP fields will be missing (set to defaults).

**Decision**: For dlp-agent audit enrichment, keep the current lightweight approach. The full `AppIdentity` (with UWP fields) is resolved in `dlp-user-ui` for clipboard events. For file/USB events where dlp-agent emits audits, the `image_path` is sufficient — UWP app identity for file operations is a future enhancement (APP-10 deferred).

Document this in a code comment:
```rust
// NOTE: UWP AUMID resolution is handled by dlp-user-ui's resolve_app_identity()
// for clipboard events. File/USB audit enrichment uses Win32 image path only.
```

If there is any place in dlp-agent that constructs a full `AppIdentity` (not just gets the path), update it to set `is_uwp: false`, `aumid: None`, `package_family_name: None` explicitly.
</action>
